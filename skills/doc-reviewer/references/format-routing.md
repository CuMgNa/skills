# 文档格式只读路由

格式工具只用于恢复文档内容和可靠位置。审核目标是语义、严谨性、内部一致性和跨岗位理解，不把任务扩展为格式取证平台。

## 一、通用规则

1. 确认文件存在并记录扩展名；
2. 全程只读，不修改、保存或覆盖源文件；
3. 有条件时在审核前后记录源文件哈希，确认内容未变化；
4. 保留标题、段落、表格、工作表、单元格和页边界；
5. 标记不可读、截断或未提供区域；
6. 提取不完整时不得宣称完成了全文审核；
7. 长文按章节、工作表或完整表格分块，最后执行全局一致性复核；
8. 提取阶段标记潜在敏感动态值，正式报告只做最小引用并脱敏。

## 二、Markdown 和纯文本

使用文件读取能力直接读取。

保留：

- 标题层级；
- 1 基行号或段落顺序；
- 表格行和字段关系；
- 列表、引用块、HTML 风格信息块；
- 对测试语义有意义的代码块和模板字段。

推荐定位方式：

```text
绝对路径 > 标题路径 > 行号范围 > 稳定业务键
```

例如：

```text
三、模板逐项测试明细 > advanceH5SmsTemplate > 第 78 行
```

注意：

- `#3885` 可能是缺陷编号，不应仅因以 `#` 开头就当作标题；
- `#code#`、`#name#`、`#lat#` 可能是模板占位符；
- 宽表格按完整行或关键单元格读取，不能按字符截断；
- 为证明局部问题时引用最小单元格，不复制整张宽表；
- Markdown 没有稳定页码，不使用“第几页”定位。

## 三、DOCX

先加载现有 `officecli` 或 `docx` 技能，优先使用只读、高层提取能力。

可使用的只读路线包括：

```text
officecli view <file> outline
officecli view <file> text
officecli view <file> annotated
officecli get <file> <path> --depth N --json
```

检查正文、标题和表格。页眉、页脚、批注和修订文字只有在影响当前文档含义时才纳入。

禁止：

- `set`、`add`、`remove` 等写操作；
- 接受或拒绝修订；
- 保存或覆盖源文件；
- 把修订历史扩展为单独审计，除非用户明确要求。

定位应包含标题、段落/表格位置、可用的稳定元素路径和最小原文。

## 四、PDF

使用 PDF 读取能力；提取困难时加载现有 `pdf` 技能。

保留页码和表格边界。

页面为图片、乱码、裁切或无法可靠读取时：

- 标明受影响页码；
- 说明无法可靠提取的内容；
- 不把无法读取推断为空白；
- 不把 OCR 伪影直接判为作者错别字；
- 关键页面不可读时，不给出无条件的全文一致或可用结论。

定位使用页码和最小原文。

## 五、XLSX

先加载现有 `officecli` 或 `xlsx` 技能，使用只读提取。

审核可见内容中的语义：

- 工作表名称；
- 表头和字段标签；
- 文本和显示值；
- 测试步骤、预期结果、实际结果、状态、备注和结论；
- 同一明确范围下的汇总与明细关系。

定位使用：

```text
工作表!单元格
工作表!范围
```

注意合并单元格，一个可见陈述可能跨越多个坐标。

禁止：

- 保存或修改工作簿；
- 重算公式；
- 刷新外部链接；
- 执行宏；
- 宣称公式本身正确或错误；
- 未经用户要求扩展到隐藏工作表或工作簿取证。

公式结果可以作为当前显示内容引用。若矛盾可能来自计算行为而非文字，应列为“待作者确认”或“覆盖限制”，不能直接宣称公式错误。

## 六、用户粘贴内容

用户直接粘贴文字时：

- 按标题、段落顺序、表格和最小摘录定位；
- 明确无法提供原生页码、段落号或单元格；
- 不宣称审核了未粘贴的附件、表格或上下文；
- 原文出现“见后文表格”但表格未提供时，记录为覆盖限制或悬空引用。

## 七、长文与大表格

长文分块时：

1. 标题和完整表格优先作为原子区段；
2. 相邻区段保留少量标题上下文；
3. 大表格拆分时，每块重复表头；
4. 单行不得截断；
5. 使用缺陷 ID、模板字段、用例 ID 等稳定业务键去重；
6. 每块先产出事实，不直接形成最终结论；
7. 全部区段完成后重新核对总数、状态、范围、结论和重复实体。

## 八、敏感内容

提取时识别：

- 实际验证码；
- 手机号、邮箱、账号；
- 姓名或个人标识；
- 完整经纬度；
- 通信码、令牌或认证值。

这些值可以在内部判断格式，但不得在正式报告中无必要地原样复制。模板占位符、字段名和缺陷 ID 可按证据需要保留。

## 九、提取失败报告

材料存在不可读区域时，在正式报告中加入：

```markdown
## 审核边界
- 文件或区域：
- 无法提取的内容：
- 对审核结论的影响：
- 需要补充的资料或替代格式：
```

没有实际读取的内容，不得给出“严谨、完整、一致、可上线”等无条件判断。
