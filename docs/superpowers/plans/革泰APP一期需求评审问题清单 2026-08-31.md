## 二、总体评审结论

**当前 HTML 需求文档不能直接作为革泰 App 一期唯一的开发与测试验收基线。**

主要依据：

1. Word 与 HTML 的一期屏幕数、功能点及部分核心需求不一致；
2. 一期正文、功能需求、字段字典和操作规格中混有大量二期能力；
3. 围栏、设备状态、告警和远程指令的状态模型仍存在冲突；
4. 弱网是产品核心场景，但离线启动、缓存时效和恢复联网流程没有闭环；
5. 轨迹里程、移动时长、停留点和异常点处理缺少统一算法；
6. 多项验收标准引用一期不交付的页面或不存在的业务规则；
7. 高风险远程操作、本地凭据保存、设备资源越权等安全要求目前证据不足。

# 三、P0 评审阻断项

## P0-01：一期范围基线不唯一

**事实依据：**

- Word 标注为 34 屏、87 个功能点；
- HTML 活动模块计算为 33 屏、85 个可见功能点；
- HTML 告警模块为 3 屏、9 个功能点，Word 为 4 屏、11 个功能点。

**待明确：**

1. HTML 是否正式替代 Word；
2. 一期最终屏幕和功能点清单是什么；
3. 被删除或调整的需求是否有变更记录；
4. 测试应以哪个版本作为唯一验收基线。

## P0-02：低电阈值是固定规则还是用户可配置

**事实依据：**

- Word 要求用户可设置 5%～50% 的低电告警阈值；
- HTML 业务规则固定为正常、预警、低电和极低电四档；
- HTML 活动模块中已没有独立低电阈值页面。

**待明确：**

1. 低电阈值是否允许用户配置；
2. 如果允许配置，用户阈值与固定四档如何共同生效；
3. 阈值是账号级、设备级还是型号级；
4. 阈值保存到项圈、服务端还是 App 本地。

## P0-03：远程指令清单和语义不一致

**事实依据：**

- Word 为找牛、找定位器、查询状态、远程重启、远程关机、恢复出厂六项；
- HTML 为 `UPLOAD / ZONE / VERNO / CR / POWEROFF / RESET / FIND` 七项。

**待明确：**

1. `RESET` 是重启还是恢复出厂；
2. 找牛、找定位器分别对应哪个协议指令；
3. `UPLOAD` 和 `ZONE` 是快捷指令还是设备设置；
4. 每个指令的中文名、协议码、参数、支持型号和风险等级；
5. 哪些指令需要二次确认或重新认证。

## P0-04：离线地图是否属于一期存在直接冲突

**事实依据：**

- “一期不做”明确包含离线地图；
- “联网与离线”表又称提前下载离线地图是唯一完全离线能力；
- 字段、弹窗及操作规格中仍存在离线地图相关定义。

**待明确：**

1. 离线地图最终属于一期还是二期；
2. 如果一期不做，是否彻底删除入口、字段、弹窗和操作规格；
3. 如果一期做，需补充下载范围、缩放级别、容量上限、过期策略、断点续传和磁盘不足处理。

## P0-05：整群轨迹所属端不一致

**事实依据：**

- 用户章节称整群轨迹和围栏统计主要在牧场监控台网页；
- App 一期模块及关键流程又完整包含整群轨迹、轨迹日历和围栏统计。

**待明确：**

1. 整群轨迹和围栏统计是在 App、Web，还是两端均交付；
2. 如果 App 交付，最大设备数、最大轨迹数和性能目标是什么；
3. 如果只在 Web 交付，App 是否删除页面和入口。

## P0-06：离线启动主流程没有闭环

**事实依据：**

- 产品目标强调弱网下可以查看缓存位置；
- 有 Token 时进入登录后加载页；
- 登录后加载页必须联网；
- 拉取设备失败后只提供 Retry，没有进入缓存首页的路径。

**待明确：**

1. 无网但有缓存时是否允许进入只读首页；
2. Token 过期但当前离线时是否允许临时查看缓存；
3. 没有缓存时展示什么；
4. 恢复联网后如何自动刷新且不打断用户操作。

## P0-07：设备连接状态和告警状态被压缩为互斥三态

**事实依据：**

- 设备字段仅有 `online / offline / alert`；
- 规则规定 Alert 优先级最高；
- 一台离线设备可以同时存在低电、围栏或健康告警。

**风险：**

如果设备因告警显示为 Alert，可能无法出现在 Offline 筛选和离线数量中，用户无法准确识别真正失联设备。

**待明确：**

1. 是否拆分连接状态 `online/offline` 与告警状态 `hasOpenAlert`；
2. 设备筛选是否允许同时满足离线和告警；
3. 列表颜色、地图颜色和统计数字如何组合显示。

## P0-08：在线判定存在未覆盖区间

**事实依据：**

- 快速档超过 15 分钟无上报判离线；
- 30 分钟～3 小时档按“设定间隔×2+10分钟”判断；
- GPS Off 单独处理；
- 10～30 分钟及大于 3 小时的上报间隔未定义。

**待明确：**

1. 给出完整的在线判定分段函数；
2. 明确等于 10、15、30 分钟及 3 小时时的边界；
3. 明确使用设备上报时间还是服务端接收时间；
4. 修改上报模式时使用旧间隔还是新间隔。

## P0-09：首页区内和区外在多围栏下无法唯一统计

**事实依据：**

- 首页要求区内+区外=已绑定围栏设备数且去重；
- 同一设备可以绑定多个围栏；
- 同一设备可能同时位于一个围栏内、另一个围栏外。

**待明确：**

1. 首页按当前围栏、主围栏、任意围栏还是综合状态统计；
2. 同时满足区内和区外时如何归类；
3. 安全区和禁入区是否采用同一“区内/区外”展示语义。

## P0-10：围栏缓冲公式互相冲突

**事实依据：**

- 一条规则使用 `max(50m, 半径×5%)`；
- 另一条规则使用固定 30m；
- 最小半径 50m 时，第一种公式会令回归阈值变成 0m。

**待明确：**

1. 最终唯一缓冲公式；
2. 是否结合定位精度动态调整；
3. 半径为 50m、999m、1000m、20km 时的明确出栏和回归阈值；
4. 等于阈值时判定在内、在外还是缓冲区。

## P0-11：围栏安全区和禁入区状态机不完整

**缺失场景：**

- 禁入区设备离开后的恢复；
- 关闭围栏后重新启用；
- 修改圆心或半径；
- 删除围栏；
- 解绑设备；
- 定位过期或无效；
- 冷却期内回归后再次越界。

**待明确：**

需提供安全区和禁入区的完整状态转换表，包括触发条件、基线、推送、冷却和恢复消息。

## P0-12：远程指令存在多套状态枚举

**事实依据：**

- 业务规则：`pending / sent / acked / timeout / rejected`；
- 字段字典和页面字段：`pending / success / failed`；
- 用户文案为 `Command delivered`。

**待明确：**

1. 服务端权威状态枚举；
2. `sent`、`acked`、`success` 的映射；
3. `timeout` 和 `rejected` 是否都映射为 failed；
4. “已送达”和“执行成功”是否分开；
5. 迟到 ACK 如何更新状态。

## P0-13：离线拒发是否生成指令记录存在冲突

**事实依据：**

- 功能需求称离线拒发也保留失败记录；
- 规则称云端直接拒发、不进入 pending；
- 操作规格又称客户端直接阻断。

**待明确：**

1. 离线点击是否调用服务端；
2. 是否创建服务端审计记录；
3. 记录状态和值是什么；
4. 其他手机是否能看到这条失败记录。

## P0-14：设备绑定缺少并发和幂等状态机

**待明确：**

1. `unbound → binding → bound/failed` 的完整状态；
2. 两个账号同时绑定同一 IMEI 时如何原子抢占；
3. 请求成功但响应丢失后的查询与重试；
4. 同一账号重复提交是否幂等；
5. `Locating…` 最长持续多久，超时转为什么状态。

## P0-15：解绑和设备转让后的数据归属不清晰

**待明确：**

1. 历史轨迹、告警和围栏记录归账号、牲畜档案还是物理设备；
2. 解绑后旧账号是否还能查看；
3. 新主人能否看到绑定前历史；
4. 个人账号与企业账号之间如何转让；
5. 原账号不可用时如何申诉和强制解绑。

## P0-16：时区存在本地、账号和设备三套语义

**事实依据：**

- 时区页被定义为本地偏好；
- 区域规则又说账号设置优先；
- `ZONE` 指令还会修改设备时区；
- 定时开关机由项圈本地执行。

**待明确：**

1. App 显示时区；
2. 服务端查询和统计时区；
3. 设备执行时区；
4. 多端设置冲突时的优先级；
5. 今日、昨日、轨迹日历和告警时间分别使用哪个时区。

## P0-17：整数时区偏移无法覆盖澳大利亚和夏令时

**事实依据：**

- 设备 `zoneOffset` 是整数；
- 目标地区包括欧洲和澳大利亚；
- 澳洲存在多个时区、半小时时区和夏令时。

**待明确：**

1. 是否使用 IANA 时区 ID；
2. 设备协议是否支持分钟偏移；
3. 夏令时由服务端、App 还是设备处理；
4. 修改时区后是否自动重新下发定时计划。

## P0-18：健康告警缺少业务算法和能力矩阵

**事实依据：**

- 产品核心问题包含体温、活动、反刍异常；
- 告警类型也包含这三类；
- 文档没有阈值、持续时间、传感器能力和算法说明。

**待明确：**

1. 体温异常阈值和持续时长；
2. 活动异常和反刍异常的判断算法；
3. 哪些型号和固件支持；
4. 不支持健康监测的设备如何展示；
5. 算法升级后历史告警是否重算。

## P0-19：轨迹统计算法缺失

以下指标无法形成唯一测试预期：

- 总里程；
- 移动时长；
- 最高速度；
- 停留点；
- 停留时长；
- 异常点过滤；
- 轨迹抽稀。

**待明确：**

1. 距离算法及允许误差；
2. 移动速度阈值；
3. 停留半径和最短时长；
4. 异常速度、跳点、重复点和乱序点规则；
5. 长时间缺口是否断线；
6. 最大查询时间和最大点数；
7. 展示点、有效点和原始点的区别。

## P0-20：未读和未处理仍未形成唯一展示口径

**事实依据：**

- `unread` 是本地阅读状态；
- `open/resolved/ignored` 是服务端业务状态；
- 页面同时使用红点、数量、未处理和未读等说法。

**待明确：**

1. Alerts Tab 显示未读数还是未处理数；
2. 首页告警格显示什么；
3. 打开详情只消未读还是同时改变其他状态；
4. 已处理但未读是否可能存在；
5. 多手机的未读状态是否同步。

# 四、P1 主要需求疑问

## 4.1 登录、注册、隐私与会话

### P1-01：记住密码和保持登录不是同一概念

需明确 Token 有效时是否自动进入首页，以及“记住密码”是否只控制账号密码填充。

### P1-02：退出登录是否取消记住密码

业务规则称退出后需重新输入密码，与记住密码自动填充存在冲突。

### P1-03：隐私同意缺少版本管理

需补充协议版本、语言、地区、同意时间、协议升级后重新确认及撤回同意。

### P1-04：注册成功路径与普通登录路径不一致

注册成功直接进入地图，普通登录要经过设备加载。需明确新注册账号是否自动登录以及设备加载失败处理。

### P1-05：忘记密码操作字段错误

发送重置链接的操作规格同时要求邮箱和新密码；重置密码页面反而没有操作规格。应拆成两个独立操作。

### P1-06：重置链接安全边界缺失

需明确有效期、一次性、新旧链接关系、频控维度、未注册邮箱统一提示及重置后其他 Token 是否失效。

### P1-07：密码字符规则不足

需明确字符数还是字节数、是否允许空格和中文、首尾空格处理、复杂度、历史密码及失败锁定。

### P1-08：企业账号不能登录 App，现场多人协作没有替代方案

需明确企业现场人员是否允许使用 App，以及是否会被迫共享个人账号。

### P1-09：账号删除规则有定义但没有入口

欧洲和巴西用户的删除申请入口、处理状态和数据匿名化范围需要补充。

## 4.2 首页、地图与设备状态

### P1-10：首页在线数和设备列表在线数对象不同

首页按已绑定牲畜，设备列表按设备。建议文案明确为“在线牲畜”和“在线设备”。

### P1-11：地图点位数等于设备总数的验收条件不成立

未绑定、从未定位、无效坐标、服务到期和定位被过滤的设备可能没有地图点位。

### P1-12：异常牲畜的定义不清晰

需明确健康、围栏、低电、离线、故障和服务到期中哪些会触发红色大点。

### P1-13：“实时追踪”容易造成秒级实时的错误预期

一期实际为 30 秒或 60 秒刷新，应在 UI 中明确刷新间隔和最后上报时间。

### P1-14：地图刷新区的 Network 和 Updated 指代不清

需明确是手机网络、服务端连接、设备网络，还是列表最后刷新时间。

### P1-15：首页默认选中设备规则缺失

需明确最近查看、第一台在线、第一台告警设备或分组内第一台的优先级。

### P1-16：累计里程没有统计周期

需明确今日、本周、本次开机、绑定期间或设备生命周期。

### P1-17：多设备监控缺少容量边界

需定义最大设备数、聚类、分页、地址解析策略和低端手机性能目标。

### P1-18：地图气泡的导航入口未纳入一期范围

需明确调用系统地图还是 App 内导航，以及无地图应用和缓存位置过期时的处理。

## 4.3 地理围栏

### P1-19：连续两个有效定位点定义不足

需明确点位类型、精度、最大间隔、重复点、乱序点和恢复联网后的第一点。

### P1-20：30 分钟冷却语义不清

需明确起算点、冷却期内回归再越界、一直停留在告警区域及编辑围栏后的处理。

### P1-21：修改围栏几何后的基线不清

修改半径或圆心后，是立即重新判定还是按当前位置重建基线，需要唯一规则。

### P1-22：新建围栏预选设备与勾选即提交冲突

新建围栏尚无 ID，绑定应先本地暂存，保存围栏后批量提交，并定义部分失败回滚。

### P1-23：已有围栏绑定设备即时生效，缺少撤销和确认

需明确是否必须保存、解绑是否即时、网络失败如何回滚。

### P1-24：多边形围栏范围冲突

一期明确只做圆形，但字段允许 polygon。需明确监控台多边形是否返回 App 及其展示策略。

### P1-25：围栏停留分钟没有统计周期

需明确当前连续、今日累计、最近 24 小时或指定时间段，并处理跨午夜和离线。

### P1-26：删除围栏后的历史数据处理不清

需明确历史告警、停留记录、冷却状态和已删除围栏名称如何处理。

### P1-27：围栏三态循环点击容易误操作

建议改为明确的三选一面板，并提供安全区、禁入区的用户解释。

## 4.4 设备、分组与物联卡

### P1-28：扫码绑定异常场景缺失

需覆盖相机权限拒绝、二维码不合法、非本产品码、弱光、重复扫码和无摄像头。

### P1-29：设备列表主标题字段冲突

功能需求称主标题为牲畜编号；页面字段又把设备名称标为主标题。需确定唯一展示规则。

### P1-30：设备详情要求九项信息，但页面字段和编辑字段不完整

需要建立字段可见、可编辑、必填、只读和校验矩阵。

### P1-31：电话正则允许无数字内容

当前字符集约束可能让纯连字符通过，需要定义至少包含数字及区域号码规则。

### P1-32：LBS/Wi-Fi 开关语义冲突

需明确开关为启用辅助定位、过滤显示点，还是修改服务端定位策略，并说明是否影响围栏判定。

### P1-33：分组边界不完整

需定义最大分组数、空白名称、大小写重复、Emoji、多语言字符及删除后的页面筛选恢复。

### P1-34：Expired 未进入设备状态模型

需明确服务到期设备在列表、地图、在线数、告警和指令中的状态。

### P1-35：SIM 流量展示字段不一致

功能需求写流量余量，页面字段写已用流量，字段字典同时存在剩余、总量和已用。需确定最终展示。

### P1-36：“即将到期”阈值需统一

需明确页面提示、系统消息和推送是否均以 30 天为界，并定义重复提醒节奏。

### P1-37：“联系管理端”没有真实联系方式

只显示 Toast 无法完成用户任务。需要地区化的电话、邮箱、聊天或工单入口。

## 4.5 远程指令与定时任务

### P1-38：迟到 ACK 没有处理规则

需明确 timeout 后收到 ACK 是否改状态、是否通知用户及重复发送如何区分。

### P1-39：指令并发、覆盖和限流未定义

需明确同设备 pending 数量、POWEROFF 后其他指令、重复 UPLOAD 和重复点击处理。

### P1-40：高危指令安全控制目前证据不足

需补充权限、二次确认、重新认证、操作审计、频率限制和低电限制。

### P1-41：设备型号和指令能力矩阵缺失

需明确型号、固件与七项指令的支持关系；不支持功能应隐藏还是置灰。

### P1-42：定时开关机边界缺失

需覆盖开关机时间相等、跨午夜、设备当前关机、离线编辑、时区变化和 DST。

## 4.6 告警与通知

### P1-43：已忽略为二期能力，却进入一期页签规则

需明确一期 API 是否可能返回 ignored，以及已处理页签是否包含 ignored。

### P1-44：告警筛选枚举遗漏健康类型

功能需求有体温、活动、反刍，操作枚举却没有，应建立唯一告警类型表。

### P1-45：告警设置作用范围不清

需明确是账号级还是单设备级，当前设备如何选定。

### P1-46：关闭告警的真实含义不清

需明确是不生成、不推送、不展示，还是只对当前设备关闭。

### P1-47：告警合并可能导致事件信息丢失

需明确去重键、首次时间、最新时间、次数、严重度升级和完整事件明细。

### P1-48：“立刻收到提醒”缺少可测试 SLA

需拆分真实越界、第二个有效点、服务端判定、推送提交和手机展示的时间目标。

### P1-49：推送权限和系统限制没有闭环

需覆盖拒绝权限、永久拒绝、静音、勿扰、App 被杀、多手机、重复推送、乱序和 Token 过期。

### P1-50：离线查看告警时能否处理不明确

需明确按钮禁用、本地排队或恢复联网后同步策略。

### P1-51：设备告警记录不支持 ignored 状态

设备告警记录只有 open/resolved，告警中心有 open/ignored/resolved，无法保证同一条告警状态一致。

### P1-52：系统消息缺少已读、分页和保留规则

需定义角标、已读、保存周期、撤回、点击目标和离线缓存。

## 4.7 历史轨迹和回放

### P1-53：自定义时间范围没有边界

需定义最短、最长、未来时间、起止相等、跨时区和保留周期之外的提示。

### P1-54：轨迹脏数据缺少处理规则

需覆盖非法坐标、零坐标、重复点、同时间戳、时间倒序、迟到点、巨大跳点和设备时钟错误。

### P1-55：地图点数等于明细条数与性能优化冲突

需明确原始点、有效点和展示点；地图是否抽稀、列表是否分页。

### P1-56：轨迹统计验收引用一期不做的数据报表

应提供固定原始点集及预期总里程、移动时长和最高速度，作为一期事实源。

### P1-57：回放语义不明确

需明确 1x 是真实时间还是固定点速率、长停留如何播放、拖拽和切倍速后的状态。

### P1-58：整群轨迹容量和异常场景缺失

需定义最大设备数、每设备最大点数、颜色重复、部分加载失败和无轨迹设备处理。

### P1-59：轨迹日历的日期归属依赖时区

需明确有轨迹日按账号、设备还是牧场时区计算。

### P1-60：欧洲 90 天保留规则不完整

需补充其他地区保留周期、删除或匿名化方式、切换地区后的处理。

# 五、P2 文档、文案和用户理解问题

## 5.1 一期与二期内容污染

1. 活动模块外仍存在 24 个屏幕操作规格；
2. PayPal、IAP、批量续费、离线地图、POI、数据报表、兽医等能力仍出现在附录；
3. 建议所有屏幕、功能点、字段、弹窗和操作统一增加范围字段，并生成一期过滤清单。

## 5.2 需求追踪关系失效

1. 5 个一期屏幕没有操作规格：重置密码、整群轨迹、轨迹日历、围栏统计、围栏停留；
2. 4 个弹窗没有操作规格；
3. 20 处操作规格引用不存在的规则；
4. `FL-DEV-08` 字段 ID 重复；
5. `OP-DEV-GROUP-02` 操作 ID 重复。

## 5.3 专业术语用户难以理解

以下术语应区分用户文案和技术字段：

- S10U 二平台；
- UPLOAD、ZONE、VERNO、CR；
- IMEI、ICCID、GNSS、LBS；
- alarmType、deviceGroupId、Router.state。

## 5.4 “已定位或离线”混合两个维度

建议拆分：

- 连接状态：在线、离线；
- 定位方式：卫星、基站、Wi-Fi、无定位；
- 数据时效：实时、缓存、已过期。

## 5.5 中文版和海外版并非只换语言和底图

实际还涉及日期、时区、单位、周起始日、隐私规则、数据保留、官方耳标和货币，应修正产品描述。

## 5.6 一期没有统一 Settings 入口

语言、时区、单位、地图源、刷新间隔和振动均依赖设置，但活动模块没有完整设置页面，需要明确入口结构。

## 5.7 中文版文案表仍大量使用英文

应补齐中文版最终文案，不能只依赖运行时翻译。

## 5.8 颜色不能作为唯一状态识别方式

在线、告警、离线需同时使用图标、形状和文字，补充色盲及无障碍要求。

## 5.9 只定义 375×812 设计稿，不足以覆盖真实设备

需补充小屏、大屏、安全区、横屏、字体放大和葡萄牙语长文本适配。

## 5.10 Toast 固定 1.6 秒不适合长错误提示

建议区分短 Toast、可操作 Snackbar 和阻断弹窗。

## 5.11 用户信息字段含义模糊

需解释客户名、账号、用户 ID、联系人和版本号分别代表什么。

## 5.12 牧场名为必填字段，但注册流程没有收集

需明确是自动生成、管理端下发，还是注册后补充。

# 六、关键边界值清单

## 6.1 登录与密码

- 邮箱长度 5、64、65；
- 邮箱大小写、前后空格、国际化域名；
- 密码长度 7、8、64、65；
- Unicode 字符、中文、Emoji、空格；
- 重置频率第 5 次、第 6 次、跨整点；
- Token 到期瞬间、无网到期、多个并发接口同时返回未授权。

## 6.2 设备和分组

- IMEI 14、15、16 位；
- 全数字、带空格、前导零、非数字；
- 两账号同时绑定；
- 分组名 0、1、40、41 字符；
- 纯空格、首尾空格、大小写重名；
- 删除当前筛选分组；
- 设备正在移组时被另一端删除分组。

## 6.3 电量和设备状态

- 电量 0、5、5.1、20、20.1、35、35.1、100；
- `null`、负数、超过 100、小数和字符串；
- 电量在 20/21 或 35/36 之间反复波动；
- 在线阈值前后 1 秒；
- 修改上报模式后的首个判定周期。

## 6.4 围栏

- 半径 49、50、51、19999、20000、20001 米；
- 点位等于圆周、出栏阈值、回归阈值；
- 两个点时间间隔极短、极长；
- 定位精度大于围栏半径；
- 多围栏重叠；
- 修改圆心后设备瞬间变为区外；
- 冷却期第 1799、1800、1801 秒；
- 回归后立即再次越界。

## 6.5 轨迹

- 起止相等、结束早于开始；
- 跨午夜、跨 DST、跨日期变更线；
- 无点、1 个点、2 个点、大量点；
- 重复点、乱序点、异常速度点；
- LBS、Wi-Fi、GNSS 混合；
- 长时间无点后恢复；
- 查询超过保留周期。

## 6.6 定时开关机

- 开机时间等于关机时间；
- 跨午夜；
- DST 不存在时间和重复时间；
- 当前已关机；
- 设备离线；
- 保存后立刻修改时区；
- 下发超时但设备实际已保存。

## 6.7 告警和推送

- 同一设备同类型 5 分钟边界；
- 同一设备不同围栏同类型；
- 严重级别从 Low 升为 Critical；
- 告警已处理后立即重复；
- 两台手机同时处理；
- 推送重复、乱序、延迟和点击时会话过期；
- 通知权限关闭及系统勿扰。

# 七、建议需求方补充的标准产物

1. **一期功能白名单**：屏幕、功能点、弹窗、字段和操作均带唯一 ID；
2. **版本变更表**：明确 Word 到 HTML 的新增、删除和修改；
3. **设备状态矩阵**：连接、告警、绑定、服务到期、SIM 状态分维度定义；
4. **围栏状态机**：安全区和禁入区的完整转换及唯一缓冲公式；
5. **指令状态机**：发送、投递、送达、执行、超时和拒绝；
6. **设备生命周期**：入库、激活、绑卡、绑定、定位、解绑、转让和注销；
7. **告警模型**：类型、严重度、未读、处理、去重、推送和恢复；
8. **时区策略**：账号、App、设备及服务端 UTC 的关系；
9. **轨迹算法说明**：清洗、里程、移动、停留、最高速度和抽稀；
10. **离线能力矩阵**：每个页面可看、可操作、缓存时效和恢复联网行为；
11. **权限和安全矩阵**：用户、客服、企业角色及资源级授权；
12. **性能基线**：设备规模、轨迹点数、网络条件和 P95/P99 指标；
13. **国际化文案表**：中文、英文、葡萄牙语和变量占位符；
14. **固定测试数据集**：原始定位点和预期统计结果。

## 九、最终意见

当前需求已经覆盖登录、地图、设备、围栏、指令、告警和账号等主要页面，但**覆盖页面不等于形成可验收需求**。一期范围、核心状态、围栏判定、远程指令、弱网缓存、时区及轨迹算法仍未形成唯一事实源。

在上述 P0 问题关闭前，目前证据不足以判定需求达到以下条件：

- 开发实现无歧义；
- 测试结果可唯一判断通过或失败；
- 弱网牧场核心场景能够闭环；
- 高风险操作具备必要安全控制；
- 中文版与海外版具备一致且可理解的用户体验。
