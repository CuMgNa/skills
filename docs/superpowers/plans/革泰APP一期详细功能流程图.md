# 革泰 App 一期详细功能流程图

## 1. 文档说明

| 项目 | 内容 |
|---|---|
| 资料来源 | `S10U协议.docx`、[革泰 App 可点击需求文档](http://getai.pg8.ink/app/index.html#sec-app) |
| 分析视角 | 软件测试、需求评审、异常流程和边界值分析 |
| 流程范围 | 启动登录、地图首页、设备管理、地理围栏、告警中心、远程指令、历史轨迹、物联卡、设置与区域化 |
| 分支范围 | 正常成功、校验失败、网络失败、设备异常、服务端失败、降级处理、人工处理和待确认分支 |

> 说明：流程图中的“待确认”节点表示当前资料不足以确定唯一预期结果，不能直接作为测试验收结论。

## 2. 图例

- 绿色：成功或正常结束。
- 红色：失败、拒绝或阻断。
- 黄色：等待、降级或需要人工处理。
- 紫色：需求待确认，当前证据不足。

# 3. App 启动、隐私、注册、登录与会话流程

```mermaid
flowchart TD
    A[用户启动 App] --> B[显示品牌启动页]
    B --> C{约 2 秒后启动完成}

    C -- 启动异常 --> C1[停留启动页或显示重试]
    C1 --> C2{用户点击重试}
    C2 -- 重试成功 --> D
    C2 -- 仍失败 --> C3[结束本次启动]

    C -- 正常 --> D{本机是否已同意隐私政策}

    D -- 否 --> E[显示用户协议和隐私政策]
    E --> F{用户选择}

    F -- 不同意 --> F1[阻断注册和登录]
    F1 --> F2{后续操作}
    F2 -- 重新查看协议 --> E
    F2 -- 退出 --> F3[关闭 App]

    F -- 同意 --> G[保存本机隐私同意状态]
    D -- 是 --> H[进入登录页]
    G --> H

    H --> I{是否开启记住密码}
    I -- 是 --> I1[自动填充上次账号和密码]
    I1 --> I2[停留登录页 不自动提交]
    I -- 否 --> I3[账号密码输入框为空]
    I2 --> J
    I3 --> J

    J{用户选择操作}
    J -- 创建账号 --> K[进入邮箱注册]
    J -- 忘记密码 --> P[进入忘记密码]
    J -- 登录 --> U[执行登录校验]

    K --> K1[输入邮箱]
    K1 --> K2{邮箱格式是否合法}
    K2 -- 否 --> K3[提示邮箱格式错误]
    K3 --> K1
    K2 -- 是 --> K4[输入密码和确认密码]

    K4 --> K5{密码长度是否为 8 至 64 字符}
    K5 -- 否 --> K6[提示密码长度错误]
    K6 --> K4

    K5 -- 是 --> K7{两次密码是否一致}
    K7 -- 否 --> K8[提示两次密码不一致]
    K8 --> K4

    K7 -- 是 --> K9{是否已勾选隐私同意}
    K9 -- 否 --> K10[阻断提交并提示先同意协议]
    K10 --> K9

    K9 -- 是 --> K11[提交注册请求]
    K11 --> K12{网络是否可用}
    K12 -- 否 --> K13[提示网络不可用]
    K13 --> K14{用户重试}
    K14 -- 是 --> K11
    K14 -- 否 --> H

    K12 -- 是 --> K15{邮箱是否已存在}
    K15 -- 是 --> K16[提示邮箱已注册]
    K16 --> K17{用户选择}
    K17 -- 返回登录 --> H
    K17 -- 更换邮箱 --> K1

    K15 -- 否 --> K18{服务端注册是否成功}
    K18 -- 否 --> K19[显示服务端可读错误]
    K19 --> K14
    K18 -- 是 --> K20[创建个人账号成功]
    K20 --> K21[直接进入地图首页]

    P --> P1[输入注册邮箱]
    P1 --> P2{邮箱格式是否合法}
    P2 -- 否 --> P3[提示邮箱格式错误]
    P3 --> P1

    P2 -- 是 --> P4{一小时内是否已发送 5 次}
    P4 -- 是 --> P5[触发频率限制]
    P5 --> P6[提示稍后再试]
    P4 -- 否 --> P7[发送重置链接或验证码]

    P7 --> P8{发送是否成功}
    P8 -- 否 --> P9[提示发送失败]
    P9 --> P10{是否重试}
    P10 -- 是 --> P4
    P10 -- 否 --> H

    P8 -- 是 --> P11[用户打开链接或输入验证码]
    P11 --> P12{链接或验证码是否有效}
    P12 -- 否 --> P13[提示无效或已过期]
    P13 --> P10

    P12 -- 是 --> P14[输入新密码]
    P14 --> P15{新密码是否为 8 至 64 字符}
    P15 -- 否 --> P16[提示密码长度错误]
    P16 --> P14

    P15 -- 是 --> P17[提交重置]
    P17 --> P18{重置是否成功}
    P18 -- 否 --> P19[显示重置失败原因]
    P19 --> P14
    P18 -- 是 --> P20[返回登录页]
    P20 --> H

    U --> U1{邮箱和密码是否已填写}
    U1 -- 否 --> U2[提示必填项]
    U2 --> H

    U1 -- 是 --> U3{网络是否可用}
    U3 -- 否 --> U4[提示登录必须联网]
    U4 --> H

    U3 -- 是 --> U5[向服务端校验账号密码]
    U5 --> U6{账号密码是否正确}
    U6 -- 否 --> U7[提示账号或密码错误]
    U7 --> H

    U6 -- 是 --> U8{账号角色}
    U8 -- PersonalWebAdmin --> U9[允许进入 App]
    U8 -- WebAdmin 或 WebUser --> U10[拒绝进入 App]
    U10 --> U11[引导使用监控台 Web]
    U8 -- 未知角色 --> U12[提示账号无 App 权限]

    U9 --> V[获取 Token 和账号资料]
    V --> V1{初始化数据是否成功}
    V1 -- 是 --> V2[进入地图首页]
    V1 -- 部分失败 --> V3[进入首页并显示降级或重试提示]
    V1 -- 完全失败 --> V4[停留加载页并允许重试]

    V2 --> W{使用过程中接口是否返回未授权}
    V3 --> W
    W -- 否 --> X[保持登录状态]
    W -- 是 --> W1[判定 Token 过期]
    W1 --> W2[清空 Token 和本地登录态]
    W2 --> W3[跳转登录页]
    W3 --> W4[提示会话已过期 请重新登录]

    X --> Y{用户是否主动退出}
    Y -- 否 --> X
    Y -- 是 --> Y1[调用服务端使 Token 失效]
    Y1 --> Y2[清空设备列表和告警等展示缓存]
    Y2 --> Y3[下次需要重新输入密码]
    Y3 --> H

    classDef success fill:#e6f4ea,stroke:#2f7a38,color:#1a1f1c;
    classDef failure fill:#fce9ea,stroke:#d93a3f,color:#1a1f1c;
    classDef pending fill:#fff4d6,stroke:#f5a623,color:#1a1f1c;

    class K20,K21,P20,U9,V2,X success;
    class C3,F1,F3,K3,K6,K8,K10,K13,K16,K19,P3,P5,P9,P13,P16,P19,U2,U4,U7,U10,U12,W1,W2,W3,W4 failure;
    class V3,V4 pending;
```

# 4. 地图首页、缓存、在线状态与实时定位流程

```mermaid
flowchart TD
    A[用户进入地图首页] --> B{当前是否联网}

    B -- 否 --> C{本地是否存在缓存数据}
    C -- 否 --> C1[显示空状态]
    C1 --> C2[提示连接网络后获取设备位置]

    C -- 是 --> C3[显示缓存的设备和最后已知位置]
    C3 --> C4[明确标记数据更新时间]
    C4 --> C5[禁用实时定位 轨迹 围栏配置和远程指令]

    B -- 是 --> D[请求设备 牲畜 围栏和告警数据]
    D --> E{请求结果}

    E -- 全部成功 --> F[计算首页四格指标]
    E -- 部分成功 --> E1[显示可用数据]
    E1 --> E2[失败模块显示重试或降级状态]
    E -- 全部失败 --> E3{是否有缓存}
    E3 -- 是 --> C3
    E3 -- 否 --> C1

    F --> F1[区内]
    F --> F2[区外]
    F --> F3[告警]
    F --> F4[在线]

    F1 --> G[统计已绑定围栏且最新有效位置在区内的设备]
    F2 --> H[统计已绑定围栏且最新有效位置在区外的设备]
    G --> I{同一设备是否绑定多个围栏}
    H --> I
    I -- 是 --> I1[按设备去重后统计]
    I -- 否 --> I2[直接统计]

    I1 --> J{区内加区外是否等于已绑定设备数}
    I2 --> J
    J -- 是 --> J1[指标口径正常]
    J -- 否 --> J2[数据异常或存在未定义状态]
    J2 --> J3[需明确无定位 未绑定 多围栏冲突如何归类]

    F3 --> K[统计 status 等于 open 的告警总数]
    K --> K1{是否与告警中心未处理条数一致}
    K1 -- 是 --> K2[告警指标正常]
    K1 -- 否 --> K3[显示口径不一致问题]

    F4 --> L[统计已绑定终端且不是 offline 或 unbound 的牲畜]
    L --> L1{牲畜存在未处理告警}
    L1 -- 是 --> L2[状态显示 Alert 红色]
    L1 -- 否 --> L3{设备是否离线}
    L3 -- 是 --> L4[状态显示 Offline 灰色]
    L3 -- 否 --> L5[状态显示 Online 绿色]

    L4 --> L6[离线数量不在首页单独展示]
    L6 --> L7[通过设备列表 Offline 筛选和离线告警查看]

    F --> M[在地图显示设备点位]
    M --> M1{定位有效标志}
    M1 -- A 有效 --> M2[使用 GNSS 经纬度显示]
    M1 -- V 无效 --> M3{是否存在可用的基站或 WiFi 定位}
    M3 -- 是 --> M4[使用降级定位并显示精度]
    M3 -- 否 --> M5[显示最后已知位置]
    M5 --> M6[标记位置已过期或暂无有效定位]

    M2 --> N{用户点击设备点位}
    M4 --> N
    M5 --> N

    N --> N1[打开设备摘要]
    N1 --> N2{用户选择实时追踪}
    N2 -- 否 --> N3[查看设备详情]
    N2 -- 是 --> O{设备是否 Online}

    O -- 否 --> O1[拒绝实时追踪]
    O1 --> O2[提示设备离线]

    O -- 是 --> O3{当前模式是否 GPS Off}
    O3 -- 否 --> O4[发送立即定位 CR 指令]
    O3 -- 是 --> O5[临时唤醒设备并发送 CR 指令]

    O4 --> P[等待新定位上报]
    O5 --> P
    P --> P1{5 分钟内是否收到新定位}
    P1 -- 是 --> P2[更新点位和更新时间]
    P2 --> P3[实时追踪成功]
    P1 -- 否 --> P4[提示设备未响应]

    D --> Q[计算设备在线状态]
    Q --> Q1{上报间隔是否小于等于 10 分钟}
    Q1 -- 是 --> Q2{是否超过 15 分钟无上报}
    Q2 -- 是 --> Q3[判定 Offline 并产生离线告警]
    Q2 -- 否 --> Q4[判定 Online]

    Q1 -- 否 --> Q5{间隔是否为 30 分钟至 3 小时}
    Q5 -- 是 --> Q6{无上报时间是否超过 间隔乘 2 加 10 分钟}
    Q6 -- 是 --> Q3
    Q6 -- 否 --> Q4

    Q5 -- 否 --> Q7{是否为 GPS Off}
    Q7 -- 是 --> Q8[不按普通超时规则判定离线]
    Q7 -- 否 --> Q9[进入未定义间隔处理]
    Q9 --> Q10[需明确 10 至 30 分钟及大于 3 小时的规则]

    Q3 --> R{是否收到新的有效位置}
    R -- 是 --> R1[立即恢复 Online]
    R1 --> R2[不进行恢复去抖]
    R -- 否 --> Q3

    classDef success fill:#e6f4ea,stroke:#2f7a38,color:#1a1f1c;
    classDef failure fill:#fce9ea,stroke:#d93a3f,color:#1a1f1c;
    classDef pending fill:#fff4d6,stroke:#f5a623,color:#1a1f1c;
    classDef unclear fill:#f3e8ff,stroke:#7c3aed,color:#1a1f1c;

    class J1,K2,L5,M2,P2,P3,Q4,R1,R2 success;
    class C1,C2,E3,J2,K3,O1,O2,P4,Q3 failure;
    class C3,C4,C5,E1,E2,M4,M5,M6,Q8 pending;
    class J3,Q9,Q10 unclear;
```

# 5. 设备绑定、设备详情、档案关联与分组流程

```mermaid
flowchart TD
    A[用户进入设备 Tab] --> B{设备列表请求是否成功}

    B -- 否 --> B1{是否有缓存}

    B1 -- 无 --> B4[显示加载失败]
    B4 --> B5{点击重试}
    B5 -- 是 --> B
    B5 -- 否 --> B6[退出设备页]

    B -- 是 --> C[显示全部 在线 离线 告警统计]

    D -- 绑定定位器 --> E[打开绑定弹窗]

    E12 -- 否 --> E15{设备是否已在当前账号}
    E15 -- 是 --> E16[提示不可重复绑定]
    E15 -- 否 --> E17{设备服务是否已激活}

    E21 -- 是 --> E23[绑定成功]
    E23 --> E24[刷新设备列表]
    E24 --> P

    P --> P1[展示 IMEI 型号 固件 电量 信号 定位模式等]
    P1 --> P2{是否有关联牲畜档案}
    P2 -- 是 --> P3[展示牲畜档案摘要]
    P2 -- 否 --> P4[展示未关联档案]

    P4 --> P5{个人 App 是否允许自行关联档案}
    P5 -- 当前网页规则倾向否 --> P6[引导管理端或监控台维护]
    P5 -- 若允许 --> P7[进入档案选择]
    P7 --> P8{牲畜是否已绑定其他终端}
    P8 -- 是 --> P9[禁止选择该牲畜]
    P8 -- 否 --> P10[建立一牲畜一终端关系]

    P3 --> P11{用户修改设备名称或信息}
    P11 -- 否 --> P12[返回列表]
    P11 -- 是 --> P13[进入编辑页]
    P13 --> P14{输入内容是否合法}
    P14 -- 否 --> P15[提示字段错误]
    P15 --> P13
    P14 -- 是 --> P16[提交保存]
    P16 --> P17{保存是否成功}
    P17 -- 否 --> P18[显示失败原因并保留输入]
    P17 -- 是 --> P19[刷新设备详情]

    X --> X1[显示系统分组和自定义分组]
    X1 --> X2{用户操作}

    X2 -- 新建 --> Y[输入分组名]
    Y --> Y1{长度是否为 1 至 40 字符}
    Y1 -- 否 --> Y2[提示长度错误]
    Y2 --> Y
    Y1 -- 是 --> Y3{同账号是否重名}
    Y3 -- 是 --> Y4[提示分组名称已存在]
    Y4 --> Y
    Y3 -- 否 --> Y5[提交新建]
    Y5 --> Y6{创建是否成功}
    Y6 -- 否 --> Y7[提示创建失败]
    Y6 -- 是 --> Y8[刷新分组列表]

    Z -- 否 --> Z2[输入新名称]
    Z2 --> Z3{长度及重名校验是否通过}
    Z3 -- 否 --> Z4[提示字段错误]
    Z4 --> Z2
    Z3 -- 是 --> Z5[提交改名]
    Z5 --> Z6{改名是否成功}
    Z6 -- 否 --> Z7[保留原名称并提示失败]
    Z6 -- 是 --> Y8

    X2 -- 删除 --> AA{是否为系统分组}

    AA8 --> Y8

    P --> AB{修改设备分组}

    AB -- 是 --> AB1[选择目标分组]
    AB1 --> AB2[提交 groupId]
    AB2 --> AB3{修改是否成功}

    classDef success fill:#e6f4ea,stroke:#2f7a38,color:#1a1f1c;
```

# 6. 圆形地理围栏创建、绑定与告警判定流程

```mermaid
flowchart TD
    A[用户进入地理围栏] --> B{是否联网}
    B -- 否 --> B1[允许查看缓存围栏]
    B1 --> B2[禁止创建 编辑 删除和绑定设备]
    B -- 是 --> C[加载围栏列表]

    C --> D{加载是否成功}
    D -- 否 --> D1[显示加载失败]
```

# 12. 测试准入前必须澄清的关键问题

以下问题如果不明确，测试无法获得唯一预期结果，也不能据此给出上线通过结论。

## 12.1 P0：协议与核心业务冲突

1. 协议文件实际为旧版 OLE Word 格式，但文件扩展名为 `.docx`。
2. 协议写明 `UPLOAD` 只针对设备震动状态，静止时不上传位置；产品却按最后位置上报时间判断 Offline。必须明确：
   - 静止设备是否仍发送 `LK`；
   - `LK` 是否能维持 Online；
   - 静止多久会被误判离线；
   - 围栏跨界后设备静止时能否及时告警。
3. S10U 协议已有出围栏、进围栏状态位和报警位；网页又要求服务端根据圆形围栏重新判定。必须明确：
   - 最终以设备报警位还是服务端计算为准；
   - 两者同时上报是否生成两条告警；
   - 两者冲突时采用哪一个；
   - 协议 `AL` 是否参与 App 围栏告警。
4. 网页存在两套围栏缓冲描述：
   - `max(50m, 半径×5%)`；
   - 固定外扩 `30m`。

   两者无法同时作为唯一验收标准。
5. 网页包含体温、活动、反刍异常，但当前 S10U 协议没有对应字段。健康告警的数据源、设备型号、算法阈值和采样频率均未给出。

## 12.2 P0：S10U 指令协议问题

6. App 声明只有 7 项指令，但协议还包括：
   - `FACTORY`；
   - `SUPPER_POWER`；
   - `KEYTO`；
   - `BATTERY`；
   - `LED`；
   - `mSensitivity`。

   必须明确这些能力是一律隐藏、仅后台可用，还是一期需求遗漏。
7. `UPLOAD` 缺少合法范围、步长和档位映射。
8. `ZONE` 缺少合法范围，不明确是否支持 `-3`、`+5:30`、`+9:30` 等海外时区。
9. `CR` 只写“连续一段时间”，未明确持续时间和结束条件。
10. 协议部分长度字段出现 `0000C`、`0000B`，与“四位 ASCII 长度”描述冲突。
11. `3G` 与 `3g` 大小写混用，必须明确解析是否区分大小写。
12. 30 秒 ACK 是产品层规则，但协议没有：
    - 请求流水号；
    - 幂等键；
    - ACK 与具体请求的关联字段。

    多条同类指令并发时可能无法正确匹配回复。
13. “设备 Offline 直接拒发”与“指令记录保留失败条目”需要统一，明确拒发是否写入历史。
14. `FIND` 协议称响铃一分钟，但不明确：
    - 是否可提前停止；
    - 静音模式是否仍响；
    - 连续发送如何处理。

## 12.3 P1：功能边界问题

15. IMEI 长度、字符集、校验位和并发绑定规则未定义。
16. “App 添加设备”与“档案关联由管理端维护”的操作边界不够清晰。
17. 一个设备能否绑定多个围栏、一个围栏最多绑定多少设备，没有上限定义。
18. 首页“区内+区外=已绑”在以下场景如何成立未定义：
    - 无有效定位；
    - 刚绑定等待定位；
    - 同一设备绑定多个围栏；
    - 围栏关闭；
    - 设备已到期。
19. 在线状态只覆盖“≤10 分钟”和“30 分钟～3 小时”，`10～30 分钟`、`超过 3 小时`没有规则。
20. 轨迹最大查询范围、最大设备数、最大轨迹点数和数据保留期限未统一。
21. App 弱网时可以看缓存，但退出登录要求清空缓存；重新登录且无网络时能否看之前缓存需要明确。
22. “离线地图”同时出现在离线能力说明和一期不做清单中，范围互相冲突。
23. 修改密码后是否强制重新登录未定义。
24. App 在线刷新间隔 `m6` 的合法值未列出。
25. 定时开关机遇到夏令时、跨时区、重复计划冲突时没有规则。
26. 告警状态提到 `ignored`，但 Ignore 操作又被列为二期，需明确一期是否会展示后台产生的 ignored 数据。
27. 批量处理告警部分成功时，事务策略和失败提示未定义。
28. 到期时刻使用 UTC、账号时区还是设备所在地时区未定义。
29. 管理端续费后“下一上报周期恢复”，但没有最长恢复时限。
30. 海外版目标地区含欧洲、巴西、澳大利亚，但货币、日期、时区和地图切换后的历史数据展示规则还需要统一验收样例。
