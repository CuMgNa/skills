# 星联应急叫应平台 2 期 · 测试复盘（痛定思痛版）

> **视角**：测试工程师（自责向，不甩锅）  
> **写法**：不写「挑战与应对」，写「我哪里失职、差点造成什么后果、为什么不能再犯」  
> **事实底座**：对讲群长期以「消息是否接收/展示」判通过；测试环境与真机都忽略「语音是否可听、是否清晰」；真机后来打脸「有消息无声音」

---

## 写在前面：最该钉在墙上的一句

**对讲群测的是「通话」，我却把它测成了「聊天列表」。**

2 期核心能力之一是对讲群接收语音。我的断言长期停在：

- 列表里有没有这条消息  
- 状态是不是已接收 / 已展示  

几乎没有把下面这些当成**必过门槛**：

- 点开能不能出声  
- 实时推送能不能听  
- 历史分页拉回来还能不能听  
- 声音是否清晰可辨（而不是「有个播放控件」）

更糟的是：这不是某一轮疏忽——**测试环境日常回归忽略了，真机操作也忽略了**。直到线上真机冒烟出现「有消息无声音」，才被迫正视：我一直在用错误的通过标准给自己发毕业证。

对讲群场景下，**听不见、听不清 = 功能没有交付**。消息气泡在，用户依然等于没通话。这是本复盘第一钉。

---

## 一、我犯了什么错（不是「不足」，是失职）

### 1. 第一失职：只验「接收显示」，不验「语音可听/清晰」

这是方法错误，不是资源不够。

我把对讲群验收缩成了消息链路的半截：上行有记录、下行有气泡、状态机有流转，就勾「通过」。语音作为对讲群的**产品本体**，被我降级成了「附加体验」。

因此会出现一种最危险的假通过：

> 用例绿了，账也扣了，消息也在——但接收方听不到、或听不清。

测试环境里图省事不戴耳机、不逐条试听；真机上满足于「终端发得出、平台收得到」，照样不完成「听得见且清晰」的闭环。两边犯的是**同一个标准错误**。

**痛点**：我不是不知道要对讲，而是**擅自降低了「对讲成功」的定义**。标准错了，后面再勤奋也是在错误方向上加速。

### 2. 把「看过 PRD」当成「吃透规则」——计费域同样自欺

评审点了头，计费漏斗、归属快照、三种耗尽结果却没有变成断言矩阵。资金安全问题（余额负值、退款未扣减、重复扣费等）靠执行期专项才集中暴露。

**痛点**：缺陷多有时只说明你来晚了，不证明左移合格。

### 3. 规则变了仍用旧口径写用例

报位扣费口径、v1.2 变更到来时，没有强硬停表消化，边改边测。旧口径下的「通过」比失败更危险。

### 4. 文档打架却不先逼裁决

星豆不足判定、清欠路径、邀请退款等冲突，未先出唯一验收口径就开测，等于把裁决权让给运气。

### 5. 清欠三路径一度混验

套餐回填子池、星豆冲抵、线下核销账单不是同一本账；用「页面已结清」代替分层数据核对，会给重复核销开绿灯。

### 6. 用「忙」掩盖「浅」

多项目并行时，没有强制重建完整心智模型；资源不够应砍范围亮红灯，而不是默默降深度还装作覆盖了。

## 二、撞上了什么问题（以及为什么疼）

| 问题 | 为什么疼 |
| --- | --- |
| **「有消息无声音」被真机打脸** | 证明此前大量「接收/展示通过」是假通过。若上线前没撞上，客诉会替我们做验收。 |
| **听音标准从未写进冒烟门禁** | 所以测试环境与真机会系统性一起漏——不是偶发，是标准真空。 |
| **资金安全缺陷成批出现** | 退款未扣减、余额负值、重复扣费、该封未封；系统一度不具备上线资格。 |
| **计费与 SOS 边界耦合** | 无我的 + 耗尽可导致含 SOS 上行停发；另一条命相关红线，同样不能后置。 |
| **关闭率约 88.1% 仍在进行** | 复盘不是庆功；底线还在补。 |

## 三、痛定思痛：以后不许再犯的军规

### 军规零（置顶）：对讲群通过 = 可听且清晰，不是可见

对讲群 / PTT / 短音相关用例，最低断言必须同时满足：

1. **可见**：消息到达、状态正确  
2. **可听**：实时可播、历史可播（含分页/重进会话）  
3. **可辨**：内容清晰可懂（至少人工抽检达标；环境嘈杂、音量、编码异常要能报失败）

任一缺失，冒烟失败。禁止再写「消息已接收」当作对讲通过。

测试环境与真机同一标准，不允许「环境就点点列表、真机再说」。

### 其余军规

1. **计费冲突未裁决 = 不许进入用例基线**  
2. **每个扣费动作：守恒 + 幂等 + 并发**  
3. **清欠拆三本账验，禁止页面感代替数据核对**  
4. **SOS×耗尽等安全边界进评审当日 P0**  
5. **并行只许缩范围 + 亮红灯，不许默默变浅**

## 四、我不接受的自我开脱

- 「列表都有消息了」→ **对讲群不是 IM 已读回执题，是听得见的问题。**  
- 「测试环境不方便听」→ **不方便听就不能判通过；最多登记阻断，不能装测完。**  
- 「真机后来才发现」→ **说明标准一开始就错了；真机是打脸，不是偶然。**  
- 「问题都拦下来了」→ 拦下来不证明设计期合格。  
- 「规则太复杂 / 变更太晚」→ 复杂与变更不能为错误通过标准辩护。

## 五、怎样才算真改了

| 必须落地 | 验收自己 |
| --- | --- |
| **听音门禁写入冒烟** | 实时 + 历史；可见不可听 / 听不清 → 直接失败 |
| **用例断言改写** | 凡对讲群短音用例，必须有「可听/清晰」步骤与记录，不能止于「已接收」 |
| **环境与真机同标准** | 测试环境同样试听；不能把试听只留给上线前真机 |
| 口径裁决表 | 开测前「冲突→唯一断言」；无表不开 P0 |
| 计费三件套留痕 | 资金用例附账本/流水核对 |
| 未覆盖清单 | 未测项进上线评估正文，不进附录 |
