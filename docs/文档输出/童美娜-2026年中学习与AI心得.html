四个我觉得最好用的工具

各自独立 · 每个一个真实案例 · 绿框讲怎么好用 · 红框讲踩过的坑

GF

graphify · 把散落的需求建成可查询的知识图谱

一句话：最适合把一堆散乱的需求/文档变成能查的知识图谱
真实案例：星联应急救援平台知识图谱 · 132 节点 / 187 有向边 / 51 源页
我是这样用的：把应急救援平台的 51 个需求/文档页喂进去 → AST+语义抽取成图 → 社区聚类 → graphify 吐出 God Nodes（星豆账户、常驻对讲群、计费漏斗）和 Surprising Connections → 我据此前置识别计费资金安全风险，反哺"账本核对 + 幂等/并发"专项测试设计。
好处 · 好在哪
  • 跨域发现人想不到的耦合：图谱直接揭示"SOS 安全与计费归属耦合""设备归属变更搬运历史负账"——这些光读单页需求根本串不起来。
  • 风险前置：不用等测试执行到一半才发现，需求评审后建图就能出风险初判，支持测试左移。
  • 持久可查：图存下来跨会话复用，`graphify query` 随时问，比每次重读 51 页省太多事。
坑 · 必须知道
  • 候选边不能自动晋升：我专门写了 ADR-001 禁止候选边自动并入正式图，否则脏边一旦进图会误导测试结论——必须人工 review。
  • 多语义合并不了：清欠的三种语义只能标 AMBIGUOUS，不能硬并，否则会生成错误的财务实现。
  • 维护成本：文档一改必须 `graphify update`，否则 stale 边累积（实测一次 12 页变更产生 3 条 stale）。
BU

browser-use · 缺陷回归的"AI 摄影师"

一句话：最适合接管已登录 Chrome 做截图取证，回归不用人工一条条点
真实案例：视觉回归采集器 regression-shoot.py · AI 截图 + 人判 PASS/FAIL
我是这样用的：提缺时用 CDP 录制复现路径（paths/bugs/bugId.json）→ 回归时批量回放导航 → browser-use 按"描述@选择器"截图取证 → 上传图床、生成带 PASS/FAIL 勾选位的 template.md → 响铃通知人来看图下结论 → 人勾完一条命令提交禅道。
好处 · 好在哪
  • 零登录成本：接管本地已登录 Chrome，复用 session，不碰账密不过验证码——这点比 Playwright 强太多。
  • 人机分工对：AI 只采集不断言（断言不可固化，数据验证过 11 条 bug 仅 1 条能确定性断言），主观视觉留给人判，不重新制造一次性代码。
  • 回归耗时 −60%：脚本批量回放替代人工逐条重新定位复现路径，人只需目测 PASS/FAIL。
坑 · 必须知道
  • 只覆盖视觉类约 27%：流程类（上拉加载、键盘弹起）、数据精确核对、主观样式都不适用，硬上等于自欺。
  • 选择器失效要人介入：页面一改版选择器就 miss，采集器报"区域未找到"——我定的是直接报错不重试，否则会掩盖改版信号。
  • session 过期要重登：Chrome 登录态失效时采集器会跳到登录页，必须人工重登后才能继续。
OC

officecli · 用命令行写 Word/Excel，不用开 Office

一句话：最适合用命令行写 Word/Excel，不用开 Office，批量改特别爽
真实案例：天地卫通小程序 V2.0 精简说明书（210 段）· 个人工作业绩与贡献表
我是这样用的：测试报告/说明书直接用 officecli 命令行增删改 docx 段落、表格、样式 → `watch` 开浏览器实时预览，所见即所得 → 大段重复内容用 `batch` 一次写多个段落 → 写完 `validate` 校验结构。全程不用打开 Word。
好处 · 好在哪
  • 不开 Office 就能改文档：命令行操作 docx/xlsx，对脚本化、批量生成特别友好，省去手动排版。
  • watch 实时预览：边写边在浏览器看渲染效果，还能点击选中元素拿路径再改，闭环很快。
  • batch 原子写入：多条命令一个事务，要么全成要么回滚，不会写出半截坏文档。
坑 · 必须知道
  • 文件被占用就锁死：文档只要在 Word/WPS 里开着就读不了、改不了——今天这份总结的 docx 就是这样，只能退回用 .md。
  • 属性太多要查 help：不查 `officecli help docx paragraph` 就猜属性名，基本必错，学习曲线在"查 schema"这一步。
  • 复杂排版得上 raw XML：DOM 层（L2）表达不了的，得退到 L3 裸改 XML，门槛陡升。
CV

Cursor canvas · 把聊天里的数据变成直观面板

一句话：上下文里一堆数据堆着看不清，面板化以后一眼就懂
真实案例：已累计 13 个面板 · 项目贡献 / QA 复盘 / 执行报告 / 回归评审 / 业务场景…
我是这样用的：聊天气泡里的数据（项目清单、缺陷统计、回归批次、复盘要点…）堆成一大坨很难看。我让 AI 直接把这些上下文面板化——Stat 统计卡 + 卡片网格 + 表格 + Pill 状态标，数据从"滚屏找"变成"一眼扫"。目前已累计做了 13 个面板，用途各不相同：项目贡献展示（tong-meina-project-contribution）、QA 痛定思痛复盘（phase2-qa-retrospective，含军规置顶）、测试执行报告（phase2-online-exec-report）、业务场景梳理（ptt-group-management-scenes）、回归评审（regression-review，点选 PASS/FAIL）。
好处 · 好在哪
  • 直观展示，胜过千言：同样的数据，面板里的 Stat + 卡片网格比聊天里一长串文字好读太多，汇报/复盘特别管用。
  • 什么都能面板化：不止回归——项目贡献、执行报告、业务场景、复盘要点，只要聊天里有数据就能摆成面板。
  • 状态能存能交互：useCanvasState 持久化，回归面板能点 PASS/FAIL、点完一键把结论发回 chat，不止是"看"。
坑 · 必须知道
  • 只在 Cursor 里跑：canvas 组件（Stat/Card/useCanvasState 等）依赖 IDE 环境，脱离 Cursor 面板就没了，不便直接分享给没用 Cursor 的同事。
  • 内联数据撑大体积：截图走 base64、大表内联进 tsx，面板文件容易到几十 KB，大批量数据要拆分。
  • 面板数据不能直接导出：面板里的数据没法一键导出成文件，只能让 AI 再转成 markdown 等其他格式才能带走，多一道转换。
怎么发现这些工具的
比单个工具更值得分享的，是找到它们的方法
多去 GitHub 找爆火的开源项目，装下来试用一下。graphify、browser-use、officecli 这些都是这么淘出来的——不是等别人推荐，而是主动去翻、去试。开源社区里总能撞到适合提升本岗位效率的工具或技能，试得多了，自然就攒出自己的工具箱。
🔥 关键词：trending / awesome-list / star 数 动手装，别只看 README 试错成本低，错过了就换
一句话心得
四个工具各管一摊，但有个共同点：把重复活固化下来、人只管判断。graphify 替我把散需求读懂、browser-use 替我跑截图、canvas 替我摆好评、officecli 替我排版——AI 干重复的，我来判风险和下结论。每个都有坑，但把坑记下来反而更敢用。
