# 2026下半年个人工作安排计划

> **岗位**：核心测试工程师
> **覆盖项目**：格泰海外1期（合作）、钒星应急叫应1期（自研）、星联应急叫应2期（自研）、钒星物联网1期（自研）
> **说明**：各项目可能并行推进，时间节点以最终项目计划为准。

---

## 一、工作定位与目标

作为核心测试工程师，下半年负责 4 个项目**从需求评审到上线验证的全链路质量把控**，主导各项目测试策略制定、用例设计、执行验证与上线门禁，并重点攻坚计费链路与应急叫应稳定性两类高风险专项，保障关键业务按期高质量上线。

**核心目标：**
- **质量把控**：保障 4 个项目按期高质量上线，关键上线 P0 漏测率 ≤5%、零回滚。
- **风险兜底**：计费链路与应急叫应稳定性两类高风险专项，关键业务零资损、零事故。

**关键结果指标：**

| 指标 | 目标值 | 关联项目 |
| --- | --- | --- |
| 关键上线 P0 缺陷漏测率 | **≤5%** | 格泰、钒星应急叫应 |
| 计费链路资损事故 | **= 0**（幂等用例覆盖主路+异常分支） | 格泰 M5 |
| 应急叫应三端互通 P0 清单 | 清零 | 钒星应急叫应 M2 |
| 应急叫应户外场景稳定性 | 关键场景达标 | 星联2期 |
| 核心模块用例覆盖率 | ≥ 目标值（待范围冻结后定基线） | 格泰、钒星物联网 |

## 二、各项目工作安排

### 项目1：格泰海外1期（合作，8–12月）

作为项目主测，主导全链路质量把控，并主控计费专项（订阅+PayPal）。

| 节点 | 测试工作 | 交付文档 |
| --- | --- | --- |
| M1 需求冻结 8/31 | 需求评审、可测性分析、测试策略制定 | 测试计划 |
| M2 原型+UI 9/18 | 用例设计（设计稿阶段，提前备弹） | 测试用例集 |
| M3 主链路连通 11/15 | 主链路验证（App+Web 两端信号连通） | — |
| M4 平台最小集 11/30 | 完整功能测试、回归、上线门禁 | 测试报告、上线检查单 |
| M5 订阅+PayPal 12/30 | 计费链路专项（主路+幂等+异常分支） | 计费专项测试报告 |
| 上线/交付 | 验收与交付保障 | 产品说明书/用户手册、验收报告 |
| M6 增值服务（明年） | 今年不涉及 | — |

**保障措施：**
- M2 后持续迭代滚测，不等 M3 主链路连通才动手，规避 M3→M4 仅 15 天的测试压力。
- 计费用例设计与 PayPal 沙箱验证**前置到 10 月**，12 月只做真实环境验证，确保计费零资损。
- 多端（App+Web）联调环境与测试数据提前规划，避免联调阶段卡环境。
