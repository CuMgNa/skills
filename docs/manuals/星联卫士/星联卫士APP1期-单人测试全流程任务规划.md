## 2. 项目目标与测试策略

### 2.1 一期核心目标

完成星联卫士APP一期功能开发及终端联调，重点实现：

1. Android手机通过BLE连接S1终端；
2. App发送文本；
3. App发送语音；
4. App发送图片；
5. App查看终端位置；
6. App接收下行文本和语音；
7. 终端通过卫星UDP接入平台；
8. Podium及Monitor Web能够接收和展示上行业务消息。

### 2.2 单人测试覆盖策略

完整PRD涉及Android、BLE、终端固件、UDP协议、Podium、WebSocket、Monitor Web和真实卫星外场。单人无法在现有周期内对所有模块进行同等深度的全面测试，因此采用以下策略：

| 层级 | 覆盖策略 |
|---|---|
| P0 | 深度测试并完成真实端到端验收 |
| P1 | 完成功能主流程、核心异常和必要回归 |
| P2 | 抽样验证或由开发自测提供证据 |
| 非一期 | 不纳入测试通过标准 |

### 2.3 P0核心流程

| 编号 | P0流程 | 主要链路 |
|---|---|---|
| P0-01 | 首次连接 | 启动→权限→扫描S1→GATT连接→三帧快照→消息页 |
| P0-02 | 文本上行 | App `$TITXT`→S1→UDP `0x12`→Podium→Monitor→`0x83`→App成功 |
| P0-03 | 语音上行 | 录音→250B分包 `$TIVOI`→UDP `0x10`→平台→回执 |
| P0-04 | 图片上行 | 拍照/相册→250B分包 `$TIIMG`→UDP `0x11`→Monitor图片展示 |
| P0-05 | 下行消息 | Monitor/Podium→UDP `0x81/0x82`→S1→`$TOTXT/$TOVOI`→App展示 |
| P0-06 | 位置查看 | `$TOLOC`→App地图打点→有效坐标和定位状态展示 |
| P0-07 | 卫星不可用与恢复 | `netStatus≠2`禁发/等待→卫星恢复→当前包续发 |
| P0-08 | 消息失败与回执 | `TODST`五态、三次失败、TOACK、迟到回执、seq隔离 |

### 2.4 P1功能

1. 标准地图/卫星图切换；
2. 离线地图下载；
3. 等待发送超时5/10/15/30/60分钟；
4. APP版本检测更新；
5. 设备断开与重新连接；
6. 语音库、图像库和APP许可证信息；
7. `$xxxx`指令调试页面；
8. 本地消息持久化和设备会话隔离；
9. BLE断开、设备占用、卫星未联网等异常状态。

### 2.5 明确不纳入一期

- iOS；
- 账号体系；
- 设备OTA；
- 固件版本查询；
- 取消发送；
- 多人地图和队员协议；
- 图片下行；
- APP直连卫星；
- APP组装或解析卫星UDP；
- APP保存卫星授权码；
- `$TIRD`蓝牙已读帧；
- APP未连接期间历史消息补推；
- 板级改造和硬件换料。

### 7.4 工时风险结论

1. 当前单人计划任务264人时，占理论产能的94.3%，仅预留16人时缓冲；
2. 16人时最多只能覆盖约2个工作日的延期或临时补测；
3. 当前大量协议和工程文档为404，如果9月11日前不能恢复，将直接消耗后续用例和联调工时；
4. 如果没有BLE/UDP故障模拟手段，TODST五态、丢包、乱序、迟到回执等异常只能依赖研发配合，排期风险较高；
5. 真实卫星外场受天气、场地、卫星SIM和搜星窗口影响，建议至少提前一周预约；
6. 如新增iOS、账号、OTA、图片下行或多人地图等范围，必须重新评估工时，不能直接占用现有缓冲；
7. 若完整承担UDP平台和Monitor Web详细测试，而不是P0端到端验收，单人工时将额外增加约15～25人日，无法在10月30日前完成。
