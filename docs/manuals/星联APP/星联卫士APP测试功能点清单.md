## 2. 测试范围说明

### 2.1 核心业务链路

```text
Android APP
    ↓ BLE
S1 / 应急救援终端
    ↓ 卫星 UDP / rstp
Podium 后端
    ↓ REST / WebSocket
Monitor Web
```

### 2.2 一期主要范围

1. APP 启动及系统权限申请。
2. BLE 设备扫描、连接、断开及重连。
3. 终端联网状态、电量、信号和位置展示。
4. 天通模块控制及消息发送门闩。
5. 文本、语音和图片上行。
6. 文本和语音下行。
7. 消息状态、回执、超时、重试和本地持久化。
8. 机身业务与 APP 业务互斥。
9. rstp、Podium 和 Monitor Web 的消息接收、路由及展示。
10. APP—终端—卫星—平台完整端到端验证。

### 2.3 一期明确排除范围

- iOS 客户端。
- APP 账号体系。
- 设备 OTA。
- 固件版本查询。
- APP 主动取消发送。
- 多人地图和队员协议。
- 图片下行。
- APP 直连卫星。
- APP 自行组装或解析业务 UDP。
- APP 保存卫星 authCode。
- `$TIRD` 蓝牙已读帧。
- 未连接期间历史下行消息补推。
- 板级改造和硬件换料。

## 3. 测试优先级定义

| 优先级 | 定义 |
|---|---|
| P0 | 核心业务、发布阻断、数据一致性或端到端主链路；失败时原则上不可发布 |
| P1 | 重要功能、异常恢复、配置能力和高风险工程功能；应在正式发布前覆盖 |
| P2 | 体验、兼容性、文档质量及低频场景；可按版本成本安排 |

# 4. 测试功能点

## M01 启动、首次引导与系统权限

### TP-001 APP 冷启动与首次引导【P0】

- 品牌启动页正常展示。
- 启动页在规定时间内自动进入权限引导。
- 用户点击启动页可提前进入下一页。
- 首次安装、二次启动、升级安装和清除数据后的启动流程正确。
- APP 从后台恢复时不重复展示首次引导。
- 进程被系统回收后恢复路径正确。
- 快速连续点击时只触发一次页面跳转。
- 引导完成状态能够持久化。
- 启动资源加载失败时存在可恢复路径，不出现白屏或卡死。

### TP-002 蓝牙、麦克风、相机和相册权限【P0】

- 蓝牙权限首次申请、同意、拒绝和永久拒绝。
- 麦克风权限单独控制语音录制能力。
- 相机权限单独控制拍照能力。
- 相册或媒体权限单独控制图片选择能力。
- 只授权部分权限时，文字、语音和图片能力分别降级。
- 运行过程中撤销权限后，页面状态和实际能力同步更新。
- 从系统设置恢复授权后，功能能够正常恢复。
- 重复进入页面时不出现权限弹窗死循环。
- Android 12 及以上版本“附近设备”权限兼容。
- Android 旧版本 BLE 扫描定位权限兼容。
- APP 不得使用手机 GPS 坐标替代终端位置。

## M02 BLE 扫描、连接与会话生命周期

### TP-003 BLE 设备扫描【P0】

- 开始扫描、停止扫描和重新扫描。
- 扫描中状态、空列表和扫描超时状态。
- 手机蓝牙关闭时的提示及开启引导。
- BLE 权限不足时的提示和恢复。
- 重复广播设备正确去重。
- 同名设备能够通过唯一标识区分。
- RSSI 值随广播刷新。
- 弱信号设备的展示和连接处理。
- 设备离开扫描范围后的列表更新。
- 扫描过程中选择设备并发起连接。
- 扫描和连接并发时资源正确释放。

### TP-004 BLE 设备过滤【P0】

- 按约定广播名称过滤目标设备。
- 非目标 BLE 设备不进入可连接列表。
- 验证 `S1`、`星联卫士`、`PD_`、`S1_PD_` 等现有命名差异。
- 无名称设备、名称乱码和名称过长设备处理。
- 设备名称发生变化后仍能通过稳定标识识别。

### TP-005 GATT 连接与 Notify 初始化【P0】

- APP 作为 Central 正常连接终端 Peripheral。
- Service 和 Characteristic 正确发现。
- Notify 订阅成功、失败和超时。
- MTU 协商成功、失败及回退。
- ATT 分片、半帧、粘包和连续多帧解析。
- 连接后依次接收 `TOSTA → TOLOC → TOSIG` 快照。
- 三帧快照缺失、重复和乱序处理。
- 首条合法 `$TI*` 指令触发快照补推。
- APP、烧录脚本和电脑探针连接互斥。
- 同一终端被其他客户端占用时给出明确提示。
- GATT 已连接但 Notify 未就绪时不得误判为业务可用。

### TP-006 BLE 断开与重连【P0】

- 用户主动断开及二次确认。
- 设备远离、手机蓝牙关闭和系统异常断连。
- APP 切后台、锁屏和进程被杀后的连接状态。
- 连接抖动和频繁断开重连。
- 断开后 30 秒内重连。
- 超过 30 秒后重连。
- 重连成功后重新获取终端状态快照。
- 断开时清理 APP 在途上行状态。
- 重连后不恢复未完成的旧发送任务。
- 旧 `$TODST/$TOACK` 不得推进重连后的新消息。
- 多次点击连接或重连时只建立一个有效会话。

### TP-007 BLE 与天通模块联动生命周期【P0】

- BLE 连接后天通模块按规则开启。
- BLE 断开后从断开时刻开始计算关闭宽限期。
- 30 秒内重连时天通模块保持开启。
- 超过宽限期后天通模块关闭。
- 在途包处于 `TODST=1/3` 时的模块关闭策略。
- 网络搜索、登录中和已联网状态切换正确。
- APP 进程异常退出后终端模块生命周期正确。

### TP-009 状态主动查询 `TIQRY/TOSTA`【P1】

### TP-010 终端位置 `TOLOC`【P0】

### TP-011 信号状态与信号格映射 `TOSIG`【P1】

## M04 天通模块与消息发送门闩

### TP-012 天通模块控制 `TITSM`【P1】

- 开启天通模块。
- 关闭天通模块。
- 开启后从初始化、搜星到联网的状态变化。
- 初始化失败和登录失败提示。
- 非法 sw 值处理。
- 操作后规定时间内返回完整 TOSTA。
- 在途消息期间关闭模块。
- 当前消息完成后延迟关闭。
- BLE 连接自动开启与 APP 显式发送 `TITSM,1` 的兼容。

### TP-013 每包发送门闩 `TIGAT/TOGAT`【P0】

- `ttMod=1` 时才具备发送前置条件。
- `netStatus=2` 时才具备发送前置条件。
- 每包发送前发起对应 kind 的 TIGAT 查询。
- 通道空闲、设备未禁用且额度允许时返回 TOGAT=1。
- 通道占用时返回不可发状态。
- 设备禁用时所有 APP 上行不可发。
- 语音额度用尽时仅语音不可发。
- 非法 kind 值处理。
- 5 秒内无 TOGAT 响应的超时处理。
- TOGAT 与 TOSTA 状态不一致时的最终判定。
- TOGAT=1 后通道被机身业务抢占。
- 多包消息的每一包均重新执行门闩检查。
- TOGAT 只作为预检，最终结果以 TODST 为准。

## M08 消息状态机、序号、回执和重试

### TP-022 `TODST/TOACK` 消息状态机【P0】

| 状态 | 业务含义 |
|---|---|
| TODST=0 | 等待发送条件，不计包失败 |
| TODST=1 | 当前包正在发送 |
| TODST=2 | 当前轮发送失败 |
| TODST=3 | 当前包已发出，等待平台回执 |
| TODST=4 | 当前包最终成功 |

需覆盖：

- 所有合法状态转换。
- 非法状态跳转和状态倒退。
- 重复 TODST 状态通知。
- 直接从 1 跳到 4 等异常序列。
- TOACK 先于 TODST、晚于 TODST 或缺失。
- TODST=4 先于 TOACK 的异常处理。
- 错误 seq 和错误 pktIdx。
- 同一时间只允许一条消息的一包在途。
- 多包全部成功后整条消息才成功。
- 已失败消息不得被迟到状态改为成功。

### TP-023 单包失败计数与自动重试【P0】

- TODST=2 计一次当前轮失败。
- 5 秒无 TODST 计一次当前轮失败。
- 同一轮超时与 TODST=2 同时出现只计一次。
- 第 1、2、3 次失败边界。
- 满 3 次后整条消息失败。
- 重试期间网络或门闩条件恢复。
- 只重发当前失败包。
- 同一条消息重试保持 seq 和 idx。
- 整条失败后用户手动重发才使用新 seq。
- 迟到 TODST 不得污染下一轮重试。

### TP-024 平台回执与回执超时【P0】

- TODST=3 后进入平台回执等待。
- 规定时间内收到 TOACK。
- 回执等待临界时间。
- 回执超时后的失败处理。
- 回执超时后收到迟到 TOACK。
- 重复 TOACK 幂等处理。
- `TOACK.termBizId` 等于 APP seq。
- `TOACK.pktIdx` 对应当前包。
- 错误消息或错误包的回执不得推进当前消息。

### TP-025 APP seq 号段与持久化【P0】

- APP seq 使用 32800～65535 号段。
- 首次发送从 32800 开始。
- 65535 后回绕到 32800。
- 32799、32800、65535 等边界。
- 按 deviceId 分别保存 seq。
- 同设备重连后继续递增。
- 切换设备后不得串号。
- 快速点击或多线程场景下原子分配 seq。
- 本地存储损坏后的恢复策略。
- 卸载重装后的初始化策略。
- 旧 seq 的 TODST/TOACK 不得驱动当前消息。

### TP-026 等待发送与等待超时【P0】

- TODST=0 或条件不满足时进入连续等待。
- 条件恢复后从当前包继续发送。
- 等待计时开始、暂停、恢复和清零。
- 达到配置时长后整条消息失败。
- 超时临界点处理。
- APP 前后台切换时计时正确。
- 系统时间变化不影响等待计时。
- 等待期间修改超时配置。
- 超时失败后不得自动续发。
- 超时后的迟到回执不得改变最终状态。

### TP-029 0x03、0x05 与 APP 本地已读语义【P0】

- 0x03 表示终端已接收下行消息。
- APP 已连接时，终端完整推送 APP 后上报 0x05。
- APP 未连接时，终端本机展示或播报完成后上报 0x05。
- APP 点击消息只修改本地已读状态。

# 6. 测试前待确认事项

## 6.1 P0 级需求冲突与阻塞项

| 编号 | 待确认项 | 当前问题 | 建议测试口径 |
|---|---|---|---|
| Q-001 | APP 协议版本 | PRD 和旧测试计划使用 v1.8，文档索引要求 v2.7 | 以文档索引指定的 v2.7 为当前真源 |
| Q-002 | 发送门闩 | PRD 仅定义 BLE+联网，v2.7 增加 ttMod、TOGAT、通道和后台状态 | 以 v2.7 三道门闩及后台状态为准 |
| Q-003 | 重试 seq | 协议个别位置写“更换 seq”，多数规则写“保持 seq” | 以《歧义项决议》的“同条重试保持 seq”为准 |
| Q-004 | 自动开启天通 | 一处要求 BLE 连接后自动开启，一处要求 APP 发送 TITSM,1 | 由产品和固件明确唯一行为 |
| Q-005 | BLE 广播名 | 文档出现 `S1`、`星联卫士`、`PD_`、`S1_PD_` | 冻结正式广播名及兼容过滤规则 |
| Q-006 | 分包大小 | 协议写 250B，实际 APP 配置为 200～240B | 明确 BLE 应用载荷与 UDP 载荷上限 |
| Q-007 | 重试和回执配置 | 协议固定 3 次、10 秒，APP 界面允许配置 | 明确配置是否允许改变正式协议状态机 |
| Q-008 | 设备禁用 | APP 和固件要求支持，Podium 文档描述当前恒 false | 明确真实状态数据源和联调方案 |
| Q-009 | GATT 信息 | Service UUID、TX/RX Characteristic 仍为 TBD | 联调前冻结 UUID、属性、MTU 和 Notify 方式 |
| Q-010 | 编解码 SDK | 语音和图片 SDK 名称、版本未冻结 | 提供正式 SDK、版本、授权和兼容矩阵 |
| Q-011 | 消息路由优先级 | SOS 与对讲群同时存在时规则未定义 | 明确求救群、对讲群、平台单聊的优先级和并行关系 |
| Q-012 | APK/固件/平台版本 | 缺少统一构建版本矩阵 | 每次测试记录构建号、commit、环境和发布时间 |

## 6.2 P1 级需求缺失项
