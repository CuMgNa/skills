# 联调与测试指南

> 跨 App / 固件 / rstp / Podium 分层测试。文档索引见 [../文档索引.md](../文档索引.md)。

## 第 1 层：单元测试（无硬件）

| 范围 | 命令 |
|------|------|
| Android 协议库 | `cd android && ./gradlew :rescuesat-ble-core:test` |
| rstp 终端状态 | `mvn test -Dtest=TerminalStatusPropertiesTest,TerminalStatusPullServiceTest,TerminalStatusResolveServiceTest` |
| rstp 协议/下发 | `ProtocolMessageParserV110Test`、`ProtocolMessageDispatcherTerminalStatusTest` |
| Podium 额度 | `cd pg-podium-monitor && mvn test -Dtest=TerminalQuotaStatusServiceTest` |

## 第 2 层：Mock / 本地联调

| 手段 | 用途 |
|------|------|
| `demo-app` + `useMock=true` | App BLE 组帧与上行 FSM |
| `POST /api/mock/terminal-status/batch` | 不连 Podium 时模拟五元状态 |
| rstp「上行模拟」页 | 模拟 UDP 0x10/0x11/0x12 |
| `POST /api/mock/push-receive` | 模拟 Podium 收 HTTP 推送 |
| 管理台「模拟终端状态」 | 本地 DB 覆盖状态 |

## 第 3 层：E2E 推荐顺序

1. **固件 ↔ rstp UDP**：登录 0x80、机身/APP 上行 0x10/0x11/0x12
2. **rstp ↔ Podium HTTP**：配置推送 + `terminal-status` batch；拉取记录来源 `REMOTE_PLATFORM`
3. **App ↔ 固件 BLE**：真机连接 → `TOSTA/TOLOC/TOSIG` → `$TITXT` → `TODST 1→3→4`
4. **Podium HTTP→WS→群 UI**：receive-event 后 Monitor Web 对讲群/求救群收到消息（见 [../前端/](../前端/) 联调清单）

## E2E 检查清单

- [ ] Podium 已部署含 terminal-status batch 的版本
- [ ] rstp `pull.batch-path` = `/api/rescuesat-tcp-platform/terminal-status/batch`
- [ ] 0x80/0x83 状态扩展 BYTE 与拉取结果一致
- [ ] App seq 32800～65535；机身 termBizId 0～32767（见 [../固件/固件工作范围说明.md](../固件/固件工作范围说明.md) §H）
- [ ] 机身 0x02 与 APP 0x10 不串包
- [ ] App 上行在 rstp 消息日志与 HTTP 推送可见
- [ ] Monitor Web：平台 type20/21、对讲 type103、求救 type100（见 [../前端/上行媒体前端对接说明.md](../前端/上行媒体前端对接说明.md) §8）
- [ ] UDP 中转：`$TIREL,1` 后顶栏「已联网」`net=2`，平台见 `0x83`，App 见 `$TODST=4` / `$TOACK`
- [ ] 空闲约 30s：`$TILGN,0` → `$TOLGN,1`；中转时随后 `$TOUDP` 登录包（首字节 `00`）
- [ ] 已连 BLE 按键录音：`$TOLVO` / `$TILVA` 成对，App 右侧出站语音；未连仅 `0x02`
