## 一、测试结论

**核心结论：救援棒与天地卫通小程序在「求救群聊」「对讲群聊」两大核心模块的平台侧主链路测试通过，通知侧「天通救援棒不扣额度但额度为 0 时电话/短信/邮件被拦截（#3886）」已修复并回归通过。但本轮真机测试新发现 4 项终端（硬件）与软硬联动问题，其中落水报警无法触发属核心应急能力阻断项；天翼物联求救短信模板格式问题仍未修复，通知模块尚有 12 项历史遗留问题待修复回归，且二期新增功能未完成国际化适配。当前不建议将终端侧与通知模块判定为可发布状态。**

- **【⚠️ 终端侧新发现】**：真机测试发现 4 项问题：联网阶段平台登录 / 联网 / 语音发送失败、终端播放对讲群语音声小且嘈杂、落水报警无法触发、语音发送链路耗时长且无法分辨对应哪条语音（详见第三节）。
- **【🆘 求救群聊】**：SOS 上报 → 自动建群 → 成员拉入 → 群内文本/语音互动 →  取消报警 / 救援完成收尾，平台侧主链路验证通过（终端落水报警除外）。
- **【🎙️ 对讲群聊】**：建群、邀请入群、换群保护、PTT 语音广播、SOS 消息镜像至对讲群、结束群，主链路验证通过。
- **【✅ 已修复】**：#3886 天通救援棒不扣额度场景下，额度为 0 时电话 / 短信 / 邮件不再被拦截，通知可正常下发，本轮回归通过。
- **【❌ 未修复】**：天翼物联求救短信模板格式问题（字段粘连 #3885、经纬度度分秒符号误用 #3884）本轮复测仍存在，短信可达但可读性差。
- **【⏳ 通知遗留】**：通知模块仍有 12 项三级历史遗留问题（触达失效 / 扣费归属 / 状态判定）需进一步修复后回归。
- **【🌐 国际化未适配】**：二期新增功能（对讲群、星豆与套餐、设备入库 / 激活、通知文案等）尚未完成国际化（多语言）适配，切换英文环境仍大量显示中文，本轮无法开展国际化测试，海外 / 外文用户场景不具备交付条件。

## 三、终端（硬件）与软硬联动问题（本轮新发现）

<aside>
🛠️

功能主链路在平台 / 小程序侧已走通，但本轮使用真机救援棒测试时，**终端侧仍存在 4 项影响实战可用性的问题**：「落水报警无法触发」属核心应急能力缺失，「联网 / 登录 / 语音发送失败」直接影响求救消息能否发出。建议优先由硬件与后端联合定位，未收敛前不具备对外交付条件。

</aside>

### 3.1 问题清单

| # | 问题描述 | 发生环节 | 影响 |
| --- | --- | --- | --- |
| 1 | 终端联网过程中出现平台登录失败、联网失败、标识 1（SOS）与语音发送失败等现象 | 联网 / 登录 / 上行发送 | 求救信息可能根本发不出去，属应急场景高风险 |
| 2 | 终端接收对讲群转发的语音时声音很小且嘈杂；同一条语音在小程序端播放质量明显更好 | 对讲群语音下发与终端播放 | 野外嘈杂环境下基本听不清，影响救援指挥沟通 |
| 3 | 终端无法触发落水报警（标识 2） | 落水报警触发 | 核心应急功能缺失，水上场景无法自动求救 |
| 4 | 终端录入语音 → 联网成功 → 发送成功整体链路等待时间较长，且无进度 / 序号提示，用户难以分辨当前发送成功的是哪一条语音 | 语音录制到发送回确全链路 | 用户反复重发、消耗额度，应急时易造成误判 |

## 四、通知问题状态说明（重点）

### 4.1 ✅ 已修复：额度为 0 时通知被拦截（#3886）

| 项 | 说明 |
| --- | --- |
| 问题描述 | 天通救援棒本身不扣额度，但当账号额度 / 星豆为 0 时，电话、短信、邮件三类通知均被发送策略拦截，导致紧急报警无法触达 |
| 原级别 | 三级（实际影响紧急触达，风险高于级别） |
| 本轮验证 | 构造额度为 0 的天通救援棒账号触发 SOS 报警 |
| 验证结果 | **✅ 修复通过**：电话、短信、邮件均正常发送，不再被拦截；不扣额度规则未被破坏 |

### 4.2 ❌ 未修复：天翼物联求救短信模板格式问题

| 缺陷号 | 级别 | 问题描述 | 本轮复测 |
| --- | --- | --- | --- |
| #3885 | 二级 | 【天地卫通-告警短信】模板字段无分隔符，来自 / 内容 / 位置信息 / 通信码全文粘连成一段 | ❌ 仍未修复 |
| #3884 | 二级 | SOS / 落水报警短信经纬度角秒符号误用角分符号（如 北纬39‘54’59） | ❌ 仍未修复 |

### 4.3 ⏳ 通知模块历史遗留问题汇总（12 项）

1. [三级] 【停港逻辑】PN07处于报警+离线+停港状态时，设备列表的离线状态数值统计错误
2. [三级] 【停港逻辑】非低电量报警设备到达离线间隔时未先判定停港逻辑，先误下线后延迟约20秒才更新为停港状态
3. [三级] 【消息管理】当前主账号与设备绑定关系非“我的 / 用户”时，非主账号设置仍生效，离线间隔未按预期取默认 30 分钟
4. [三级] 【消息通知】终端发微信给“仅有三级账号、无个人账号”的手机号，自动建号后未收到微信短信通知
5. [三级] 【消息通知】报警消息下发时，微信服务通知订阅次数已扣减但用户未收到通知，接口报错 43101
6. [三级] 【消息通知】报文携带者和紧急联系人关联的个人账号为同一账号，紧急联系人拒收设置失效
7. [三级] 【消息通知】同一手机号同时绑定个人账号与二级账号时，个人账号未收到微信服务通知且订阅数量未 -1
8. [三级] 【消息通知、97 协议中报文携带者为个人绑定者的紧急联系人时，目标手机号的邮箱通知扣除本人额度，而非绑定者额度
9. [三级] 【消息通知】协议模拟短信场景下，短信不足但邮件有余额时不会降级发邮件
10. [三级] 【消息通知、93 协议文本消息通知紧急联系人时，扣费错误地计入紧急联系人自身账号，应扣绑定者字段
11. [三级] 【消息通知】14 协议报文携带者为 A 的紧急联系人，邮箱字段误扣携带者自身账号而非设置者 A
12. [三级] 【消息通知】个人账号绑定者与紧急联系人为同一号码时，上线通知额外紧急联系人邮箱字段被误扣

## 五、二期新增功能国际化未适配（重点）

### 5.1 未适配范围

| # | 涵盖范围 | 具体表现 | 影响 |
| --- | --- | --- | --- |
| 1 | 🎙️ 对讲群相关页面 | 建群 / 邀请 / 换群 / 结束群的按钮、弹窗与提示文案均为中文 | 外文用户无法理解核心操作 |
| 2 | ⭐ 星豆与套餐体系 | 充值、套餐商城、订单与明细、计费单位文案未国际化 | 付费环节风险最高 |
| 3 | 📦 设备入库 / 绑定 / 激活 | 管理后台新增模块列表字段与校验提示为中文 | 运营 / 渠道人员使用受限 |
| 4 | 📨 通知与短信 / 邮件模板 | 报警、报平安、上线、验证码等模板仅有中文版本 | 紧急信息外文用户无法识别 |
| 5 | ⚠️ 错误与异常提示 | 接口报错、余额不足、权限不足等提示未提取文案 | 用户自助与排查因难 |

### 5.2 对测试与交付的影响

- 本轮国际化相关用例 **未执行**，不具备多语言质量结论，不能作为海外版交付依据。
- 国际化改造伴随大量文案提取与布局变更，适配完成后需 **重新回归全部新增模块 UI 与文案**，需提前预留测试工量。
- 建议开发侧先提供语言包与切换入口，再由 QA 按「文案完整性 → 布局适配 → 模板多语言 → 时间 / 单位 / 坐标格式」逐层验证。

## 七、后续计划与建议

1. **优先定位终端侧 4 项问题**：落水报警无法触发、联网 / 登录 / 语音发送失败优先处理；语音播放质量与发送链路时延 / 可辨识性同步优化，修复后均需真机全链路复测。
2. **优先修复求救短信模板格式**：#3885 字段间补充分隔符与换行，#3884 统一使用规范度分秒符号（° ′ ″），修复后由 QA 真机触发 SOS / 落水报警复测。
3. **推进历史通知问题修复**：12 项遗留与 #3882、#3883 需明确修复责任人与排期，修复完成后安排一轮通知专项回归（含短信、邮件、后台通知记录三端比对）。
4. **下周进行国际化适配**：二期新增功能的国际化适配安排在下周开展，开发侧完成文案提取与语言包后，QA 同步安排国际化专项测试，并重新回归新增模块 UI 与通知模板。
