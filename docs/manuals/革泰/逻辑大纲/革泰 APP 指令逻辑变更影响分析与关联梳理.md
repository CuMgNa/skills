# 革泰 APP 指令逻辑变更影响分析与关联梳理

> **文档用途**：记录普通队列类与高危会话绑定类指令对 APP 页面、S10U 链路、记录、设备管理、我的模块和测试用例的影响。
>
> **链路事实**：革泰指令实际通过 S10U 独立服务及网关下发。PN06/808 仅可作为普通队列思想参考，不是革泰接口、数据库、在线状态或高危控制的实现真源。
>
> **当前状态**：主大纲已完成口径对齐；本文只保留跨模块影响、剩余风险和后续测试范围，不重复维护页面完整流程。

---

## 1. 当前指令策略

| 指令 | 类别 | 离线提交 | 未写出生命周期 |
| --- | --- | --- | --- |
| CR、VERNO、FIND、UPLOAD、ZONE | 普通队列类 | 允许 | 最多待发 30 天，超期删除任务并同步 FAILURE |
| RESET、POWEROFF | 高危会话绑定类 | 不允许 | 绑定提交时的 S10U 当前可写会话；会话断开或变化立即 FAILURE |

共同约束：

1. 页面在线快照不能替代服务端校验。
2. 缺少 S10U 路由、权限失效、型号或参数不支持均应明确失败，不能伪装成设备离线。
3. SENT 只表示 TCP 写出，不表示设备业务动作成功。
4. `commandId` 表示用户可见逻辑记录，`attemptId` 表示一次发送尝试，S10U `businessId` 与 attemptId 一一映射；用户主动重发保留 commandId 并新建 attempt，网络安全重试复用原 attempt 的幂等标识。
5. 解绑、企业回收、改绑或账号失权后，未写出任务必须 FAILURE 并出队。

## 2. 三个下发入口

| 入口 | 记录归属 | 关键交互 |
| --- | --- | --- |
| 设备更多菜单 → Send Command | 设备指令记录 | 普通五类离线可选；高危两类离线置灰；结果使用 Toast 留在下发页 |
| 设备管理 → 指令下发 | 批量下发指令记录 | 所有状态可选；高危最终逐台复检；结果使用全部受理 / 部分受理 / 全部失败三状态弹窗 |
| 设备详情 Edit → Location Interval | 设备指令记录 | UPLOAD 离线可提交；资料与频率结果独立；成功反馈后才更新确认值 |

记录入口：

- 设备指令记录只从单设备下发页底部「指令记录」进入。
- 批量结果弹窗点击「查看记录」直接进入「我的 → 批量下发指令记录」L1，刷新全量记录，不定位、不高亮、不预置筛选。

## 3. 页面与数据模型影响

### 3.1 指令记录

- 批量记录采用 L1 批次列表 → L2 设备明细两级结构。
- 设备记录采用单层融合卡。
- 状态统一为 SENDING / SENT / FAILURE / CANCEL。
- 后台每次重发新增 attempt，前台在原卡更新并显示「已重发 N 次」。
- 普通五类与高危两类的重发准入必须分开。
- 严格按下发账号隔离，不因父子企业关系共享记录。

### 3.2 定位频率

至少区分：

| 值 | 含义 |
| --- | --- |
| confirmedValue | 最后一次由匹配成功反馈确认的生效值 |
| desiredValue | 用户最新提交目标 |
| processingValue | 当前排队或写出的任务值 |
| localEditValue | 尚未整页保存的本地选择 |

规则：

1. 列表只展示 confirmedValue。
2. 编辑页优先展示最新有效 desiredValue +「设置中」。
3. SENDING、SENT 或 TCP 写出不能直接覆盖 confirmedValue。
4. 多条 UPLOAD 全部保留并按 configSequence 顺序执行。
5. 旧任务回文不得覆盖更新目标。

### 3.3 批量数量守恒

```text
最终选中去重数量
= SENDING + SENT + FAILURE + CANCEL
```

提交反馈阶段同时满足：

```text
最终目标设备数
= submitted + failedToSubmit
```

任何设备不得被静默剔除或截断。

## 5. 关联测试影响

以下测试仍需按最新主大纲复核或重新生成：

1. 设备列表 / 更多菜单：删除“设备更多直接进入指令记录”，验证 Send Command 与底部记录入口。
2. 单设备下发：普通五类离线可提交，高危两类置灰且服务端防绕过。
3. 批量下发：所有状态可选择，高危最终逐台复检，三状态弹窗数量守恒。

7. 网络超时：验证原幂等键查询或安全重试，不重复创建任务。
8. 大批量与分片：验证无静默截断、逐设备明细完整。

## 6. 剩余风险与待确认事项

1. 高危任务在同一会话持续在线时是否增加最大有效时间及起算点。
2. UPLOAD / ZONE 前序 FAILURE / CANCEL 后的队列推进方式。
3. 单次设备上行允许写出的配置任务数量。
4. 服务重启后的普通队列恢复和 30 天过期补偿。
5. 服务到期设备及排队任务的处理。
6. S10U 会话查询接口、会话标识和错误码契约。
7. CR / FIND 长期排队的业务时效提醒与取消能力。
8. 回文近似匹配导致串扰的治理方案。
9. 单批上限、分片大小、并发数和限流码。
10. 型号 × 指令 × 参数 × 回文能力矩阵。

## 7. 验收红线

1. 普通五类不得因为设备离线或未连接被拒绝。
2. RESET / POWEROFF 不得进入普通 30 天队列。
3. 高危任务必须绑定具体当前会话，新会话不得执行旧任务。
4. 会话查询异常不得伪装成设备离线。
5. 缺少 S10U 路由不得作为普通离线任务成功受理。
6. 解绑、失权或改绑后，旧关系创建的未写出任务不得继续执行。
7. 普通任务 30 天过期后，队列清理与业务 FAILURE 必须最终一致。
8. SENT 不得解释为设备业务执行成功。
9. 旧配置回文不得覆盖更新目标。
10. 批量结果必须数量守恒并可逐设备追溯。
11. 用户主动重发与网络重试必须使用不同的 attempt / 幂等语义。
12. 页面不得继续用“设备离线，无法下发指令”概括全部失败原因。
