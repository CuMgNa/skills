## 1. 范围、对象与核心结论

### 1.1 本篇覆盖

- 模块拆分：批量下发指令记录（两级）与设备指令记录（单层）的边界与命名；
- 记录归属判定（按入口）：哪条记录进哪个页面；
- 批量下发指令记录：L1 列表页、L2 指令详情页、筛选、取消 / 重发 / 一键重发全部失败；
- 设备指令记录：单层融合卡版式、列表行为、筛选（状态 × 类型）、取消 / 重发；
- 两页共通的账号隔离、解绑 / 失权历史归属、异常与加载态；
- UPLOAD 指令与设备详情页定位频率的联动结论（仅结论，不展开设备管理细节）。

### 1.2 本篇不展开

- 指令投递通道、终端协议、回文产生与串扰匹配（见 S10U / PN06 文档）；
- 下发前的三道闸门细节（见下发 plan，本篇仅引用）；
- 失败原因文案的最终措辞（接口返回，本篇只定枚举占位）；
- 设备详情页「定位频率」编辑控件自身的展示与视觉方案（属设备管理文档，本篇仅记录联动结论）。

### 1.3 核心模型（一句话）

**指令记录按「下发入口」拆成两个独立模块**：设备管理批量下发流程（含只选 1 台）产生的记录进「批量下发指令记录」（两级：一次下发动作 = L1 一张卡，内含 N 台设备明细 = L2 设备卡）；单设备入口（卡片更多菜单 Send Command）产生的记录进「设备指令记录」（单层：一次下发动作 = 一张融合卡，无跳转）。重试是记录内部的生命周期，不产生新记录；重复下发则每次独立成记录。**（2026-09-20 意向口径，待产品确认 US-018：详情页 Location Interval 改纯字段展示，不再作为 UPLOAD 下发入口，见 §6 与设备管理 v1.8）**

## 2. 模块拆分、记录归属与入口落点

### 2.1 两个独立模块与页面命名

| 页面 | 层级 | 入口 |
|---|---|---|
| **批量下发指令记录**（L1） | 两级第一层 | 我的模块 → 批量下发指令记录；批量提交成功弹窗 → 查看记录 |
| **指令详情**（L2） | 两级第二层 | L1 点卡片进入 |
| **设备指令记录** | **单层，无跳转** | 设备更多菜单 → 指令记录；单设备下发页底部「指令记录」入口 |

原「我的-指令记录」**更名为「批量下发指令记录」**；原三入口统一模块（含设备指令页入口）**作废**（见 §9.3）。

### 2.2 记录归属判定（按入口，核心裁决）

**记录产生自哪个下发流程，就归哪个页面**，与设备数量无关：

| 下发动作 | 产生记录 | 归属页面 |
|---|---|---|
| 设备管理 → 指令下发批量流程（**含只选 1 台**） | 1 条批量记录 | 批量下发指令记录 |
| 设备卡片更多菜单 → Send Command（七类指令） | 每次下发 1 条单设备记录 | 设备指令记录 |
| ~~设备详情 → Edit → Location Interval → Save（UPLOAD）~~ | **意向口径（待产品确认 US-018）已删除该入口**：详情页 Location Interval 改纯字段展示 | — |

推论：

1. **批量页只收批量流程记录**，单设备页只收单设备入口记录；
2. **设备被批量下发波及（是 N 台之一），不因此在其设备指令记录页出现该记录**——原「参与制 + 详情页看全量」口径作废；
3. 批量流程只选 1 台设备，记录仍进批量页（按入口判定，不按台数判定）。

### 2.3 入口与页面落点

| 入口 | 行为 |
|---|---|
| 我的模块 → 批量下发指令记录 | 进入 L1，默认查询当前账号下发的全部批量记录 |
| 批量提交成功弹窗「指令已提交」 | 双按钮：「查看记录」→ 进入 L1 **只刷新不定位**（不滚动到本次记录）；「完成」→ 返回设备列表 |
| 设备更多菜单 → 指令记录 | 进入设备指令记录页；**设备离线时入口仍可用**（记录是历史事实，查看不依赖在线） |
| 单设备下发确认面板 | 仅「取消 / 确定」两个按钮，**无下发成功弹窗**；确定后**留在下发页** |
| 单设备下发页底部「指令记录」入口 | **始终显示**（常驻），点击进入设备指令记录页 |

### 2.4 账号隔离（最严口径，两页一致）

1. **两页均只能看到当前登录账号自己下发的记录**。依据设备管理文档的账号体系——同一设备可被 1 个个人账号 + 1 个企业一级账号双槽位绑定，并逐级分配给多个二级 / 三级账号，所有这些账号都具备指令控制权——若记录不按下发账号隔离，个人用户将看到陌生企业账号下发的指令与回文，构成跨账号泄露。
2. **父级看不到下级发的、下级看不到父级发的、个人与企业互不可见**；企业树不做记录共享。
3. **记录归属 = 下发账号 + 设备 ID**：换账号绑定设备不继承历史（见 §5）。

## 3. 批量下发指令记录（两级结构，原规则保留）

> 本章为 v1.1 已确认规则的整体保留，仅两处变化：页面更名 + 记录范围收窄为批量流程（§2.2）。

### 3.1 L1 批量下发指令记录页

**卡片版式（三行式）**：

```
┌────────────────────────────────┐
│ 上报间隔600秒（5台）              │ ← 行1：指令语义化内容 + 下发台数
│ 发送中 0 · 已发送 5 · 失败 0 · 已取消 0 │ ← 行2：四态统计（含 0 全显）
│ 创建时间 2026-09-18 15:00:21    │ ← 行3：创建时间
└────────────────────────────────┘
```

- **行1**：指令语义化内容（如「上报间隔600秒」），非 `<SPYT*...>` 原文；超长时**最多两行**，超出截断。
- **行2**：四态统计**全部显示含 0**（布局稳定）。
- **行3**：创建时间，精确到秒。

**列表行为**：

| 项 | 口径 |
|---|---|
| 排序 | 创建时间**倒序**（最新在下） |
| 刷新 | 进入页面刷新 + **下拉刷新**；无自动轮询 |
| 分页 | 上滑分页加载 |
| 手动筛选 | **无**——L1 不提供筛选入口 |
| 返回（自 L2） | 保留筛选与滚动位置 + **自动刷新一次**（取消/重发结果立刻反映到统计） |

**空态**：记录为空「暂无指令记录」；无结果场景「未筛选到相关指令记录」。

### 3.2 L2 指令详情页

```
┌────────────────────────────────┐
│ ←  指令详情                [筛选] │ ← 右上角筛选图标 → 底部弹窗
├────────────────────────────────┤
│ ┌──────────────────────────┐ │
│ │ 上报间隔600秒（5台）         │ │ ← 顶部汇总卡：镜像 L1 三行式
│ │ 发送中 1 · 已发送 3 · 失败 1 · 已取消 0 │ │
│ │ 创建时间 2026-09-18 15:00:21 │ │
│ └──────────────────────────┘ │
├────────────────────────────────┤
│ ┌──────────────────────────┐ │
│ │ 卡号 1064****1234    [发送中] │ │
│ │ 发送时间：—                  │ │
│ │ 反馈内容：—  反馈时间：—      │ │
│ │              [ 取消发送 ]    │ │
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ 卡号 1064****9012      [失败] │ │
│ │ 发送时间：—                  │ │
│ │ 反馈内容：—  反馈时间：—      │ │
│ │ 失败原因：设备离线，无法下发…  │ │
│ │              [ 重新发送 ]    │ │
│ └──────────────────────────┘ │
│              …                 │
│      [ 重发全部失败（1） ]       │ ← 存在失败设备时显示
└────────────────────────────────┘
```

**顶部汇总卡**：镜像 L1 三行式（内容+台数 / 四态统计 / 创建时间）。

**设备卡片字段（统一制）**——所有状态卡片字段统一，未发生的值显示占位「—」；仅失败卡片多一个失败原因：

| 字段 | 发送中 | 已发送 | 失败 | 已取消 |
|---|---|---|---|---|
| 设备卡号 | ✅ | ✅ | ✅ | ✅ |
| 发送状态 | ✅ | ✅ | ✅ | ✅ |
| 发送时间 | — 占位 | ✅ | — 占位 | — 占位 |
| 反馈内容 | — 占位 | 有回文填值，否则 — | — 占位 | — 占位 |
| 反馈时间 | — 占位 | 有回文填值，否则 — | — 占位 | — 占位 |
| 失败原因 | — | — | ✅（接口返回） | — |
| 操作按钮 | 取消发送 | 无 | 重新发送 | 无 |

补充口径：

1. **反馈内容超长**：默认截断，**点击可展开看全文**；
2. **取消回写**：已取消卡片被网关回写为已发送后（乐观取消回跳），自然显示发送时间，取消动作不留时间痕；
3. **重发标记**：原地更新的卡片保留「已重发 N 次」标记；
4. **失权设备**：明细保留展示，**操作按钮隐藏**，卡片标记「已解绑 / 无权限」（见 §5）。

**排序与刷新**：

| 项 | 口径 |
|---|---|
| 排序 | **状态优先**：发送中 → 失败 → 已取消 → 已发送；同状态内按发送时间/卡号次序；筛选不改变排序规则 |
| 刷新 | **手动下拉刷新** + 操作后**局部更新**（取消/重发只乐观更新该设备卡）；无自动轮询 |
| 空态（筛选无结果） | 「未筛选到相关设备」，保留筛选条件 |

### 3.3 L2 筛选弹窗

右上角筛选图标 → **底部弹出弹窗**。生效条件**仅在弹窗内可见**，页面其他位置不显示筛选标签。

| 规则 | 口径 |
|---|---|
| 维度 | **卡号（模糊/精确，用户可选）× 状态（4 态单选）**；两条件交集 |
| 指令类型维度 | **无**——一条记录只有一种指令类型，是死维度 |
| 初始状态 | 从空开始，无预填 |
| 按钮 | 重置 + 应用筛选 |
| 重置 | 清空本次勾选（回空） |
| 应用筛选 | 提交生效，按钮 loading 防重 |
| 关闭弹窗（未应用） | 丢弃未应用项 |
| 卡号存在性校验 | 无——筛不存在的卡号 → 空态 |
| 弹窗回显 | 重新打开时回显**当前生效**的条件 |

### 3.4 操作：取消与重发

**取消发送**：

- 发送中**恒可取消**（乐观取消语义，无时间窗口）；
- **二次确认**：弹；
- 乐观取消链路（引用 S10U）：点取消 → 卡片先置「已取消」；若网关实际已写出 TCP，回调回写为「已发送」，**无失败弹窗**；
- 取消后**局部更新**该设备卡。

**重新发送（单台）**：

- 入口：仅失败卡片；**二次确认**：弹；
- **原地更新 + 重发标记**：不新增 L1 记录；该设备卡状态 失败 → 发送中 → 已发送/失败，卡片保留「已重发 N 次」；
- 重发后字段口径：**创建时间不变，发送时间更新为最近一次**；反馈内容 / 反馈时间 / 失败原因**只展示最新一次的值**（历史次反馈不堆叠）；
- 技术口径：网关侧每次重发是新指令实例（新 businessId），展示层合并进原设备卡；回文按「最新已发送」匹配；
- **闸门**：与首次下发**全闸门一致**（列表快照离线置灰/Toast → 提交前校验 → 服务端逐台复核），无特例；
- **次数限制**：无上限自由重试（每次都过二次确认 + loading 防重）。

**一键重发全部失败**（仅批量 L2 有）：

- 详情页存在失败设备时显示「重发全部失败（N）」；**一次**二次确认 → 批量重发 N 台；闸门、防重、原地更新口径同上。设备指令记录页**无此按钮**（见 §4.5）。

**失败原因**：接口返回，前端原样展示。枚举占位仅供测试设计参考：

1. 设备离线，无法下发指令（已定统一文案，三道闸门命中）；
2. 测试环境限制，禁止下发（非 prod + 卡号未白名单，占位）；
3. 发送超时，已自动失效（待发超 30 天被网关丢弃后同步，占位）。

## 4. 设备指令记录（独立单层页）

### 4.1 页面结构

```
┌────────────────────────────────┐
│ ←  设备指令记录            [筛选] │ ← 返回设备列表（自动刷新一次）
│ 张三的车（1064****1234）          │ ← 设备身份行
├────────────────────────────────┤
│        （无汇总卡，融合卡平铺）     │
│ ┌────────────────────────────┐ │
│ │        融合卡 × N            │ │
│ └────────────────────────────┘ │
└────────────────────────────────┘
```

- **页头**：返回（→ 设备列表，列表**自动刷新一次**）+ 标题「设备指令记录」+ 右上筛选图标；
- **设备身份**：有备注显示「备注（卡号）」，无备注仅显示卡号（如 `1064****1234`）；**不显示在线状态 / 服务状态**——本页是历史记录页，不承担设备实时状态展示；
- **无顶部汇总卡**：单设备页没有四态统计汇总（统计属批量多台场景）；
- **单层无跳转**：点卡片不进任何二级页，所有信息在卡内呈现。

### 4.2 融合卡版式（全字段一卡通）

```
┌────────────────────────────────┐
│ 指令类型：设置上传间隔             │
│ 指令内容：上报间隔 600 秒          │
│ 状态：发送中                      │
│ 创建时间：2026-09-20 15:00:21    │
│ 发送时间：—                      │
│ 反馈内容：—                      │
│ 反馈时间：—                      │
│                    [ 取消发送 ]   │
└────────────────────────────────┘
┌────────────────────────────────┐
│ 指令类型：设置上传间隔             │
│ 指令内容：上报间隔 600 秒          │
│ 状态：失败                        │
│ 创建时间：2026-09-20 14:00:21    │
│ 发送时间：2026-09-20 14:02:05    │
│ 反馈内容：—                      │
│ 反馈时间：—                      │
│ 失败原因：设备离线，无法下发指令     │
│ 已重发 2 次                      │
│                    [ 重新发送 ]   │
└────────────────────────────────┘
```

**字段显隐（统一制 + 条件行）**：

| 字段 | 说明 | 显隐规则 | 空值 |
|---|---|---|---|
| 指令类型 | 七类指令的名称（见 §4.4） | 恒显 | — |
| 指令内容 | 语义化内容（非协议原文） | 恒显 | — |
| 状态 | 四态之一 | 恒显 | — |
| 创建时间 | 精确到秒 | 恒显 | — |
| 发送时间 | 实际发出时刻 | 恒显 | 未发出「—」 |
| 反馈内容 | 终端回文 | 恒显 | 无回文「—」 |
| 反馈时间 | 收到回文时刻 | 恒显 | 无回文「—」 |
| 失败原因 | 接口返回原样展示 | **仅失败态显示** | — |
| 已重发 N 次 | 重发标记 | **重发过才显示** | — |
| 操作按钮 | 发送中→取消发送；失败→重新发送 | 已发送 / 已取消**无按钮** | — |

**版式口径**：

1. **卡片高度不固定、内容不截断**：任何文字字段超出宽度即**完整换行显示**（追溯清晰优先，不做「最多两行」截断——与批量 L1 行1 的截断规则不同）；
2. **反馈内容超长**：默认收起显示部分，**点击在卡内原地展开 / 收起**看全文（设备回文可能很长，是唯一有折叠机制的字段；其余字段直接换行铺开）；
3. **重复下发不合并**：同一设备每次下发（含相同指令相同参数）各自独立成卡。

### 4.3 列表行为

| 项 | 口径 |
|---|---|
| 范围 | 仅当前账号通过单设备入口对该设备下发的记录（§2.2） |
| 排序 | 创建时间**倒序**；**同秒按服务端返回序列**（服务端定序，前端不自排） |
| 刷新 | 进入页面刷新 + **下拉刷新**；无自动轮询 |
| 分页 | 上滑分页加载 |
| 下拉刷新与筛选 | **保留当前筛选条件**重新查询 |
| 离开页面 | **筛选条件清空**（下次进入从空开始） |
| 新记录可见性 | 下发确认后**立即可见**（进入页面即出现新卡） |
| 新记录初始状态 | **以后端返回为准**（可能是发送中，也可能已快速流转为已发送 / 失败） |

### 4.4 筛选弹窗

右上角筛选图标 → **底部弹出弹窗**（与批量 L2 弹窗同风格）。生效条件**仅在弹窗内可见**，页面其他位置（含筛选图标）不显示角标 / 标签。

| 规则 | 口径 |
|---|---|
| 维度 | **状态（4 态单选）× 指令类型（七类单选）**；两条件**交集** |
| 七类类型 | 立即定位（CR）、查询版本（VERNO）、查找设备（FIND）、设置上传间隔（UPLOAD）、设置设备时区（ZONE）、远程重启（RESET）、远程关机（POWEROFF）——显示**类型名称** |
| 「全部」选项 | **无**——空选即代表不限该维度 |
| 初始状态 | 从空开始（空 = 不限 = 全部记录） |
| 按钮 | 重置 + 应用筛选 |
| 重置 | 清空本次勾选（回空） |
| 应用筛选 | 提交生效，按钮 loading 防重 |
| 关闭弹窗（未应用） | 丢弃未应用项 |
| 弹窗回显 | 重新打开时回显**当前生效**的条件 |
| 筛选无结果 | 「未筛选到相关指令记录」（保留条件可重筛） |
| 无任何记录 | 「暂无指令记录」 |

> 与批量 L2 筛选的差异：批量 L2 = 卡号 × 状态（无类型维度，死维度）；本页 = 状态 × 类型（**无卡号维度**——整页只有一台设备，卡号是死维度；类型跨七类，是活维度）。

### 4.5 操作：取消与重发

**沿用批量操作的全部语义，仅两处差异**：

| 项 | 口径 |
|---|---|
| 取消发送 | 发送中恒可取消 + 二次确认 + 乐观取消链路（引用 S10U）；局部更新该卡 |
| 重新发送 | 仅失败卡；二次确认；**原地更新 + 重发标记**（失败 → 发送中 → 已发送/失败，卡上保留「已重发 N 次」）；重发后创建时间不变、发送时间更新为最近一次、反馈 / 失败原因只展示最新；与首次下发**全闸门一致**；无次数上限 |
| 一键重发全部失败 | **无此按钮**（单设备页一卡一记录，逐卡操作） |
| 操作防重 | 确认后按钮 **loading 禁用**，防重复提交 |
| 操作接口失败 | **回滚到操作前状态** + Toast 提示（乐观更新被拒绝时恢复原卡） |
| 操作前复核 | 操作请求经**服务端复核权限与设备状态**；页面打开期间设备被解绑 / 失权的存量操作被拒绝，提示无权限（见 §5） |

### 4.6 空态、加载与查询异常

| 场景 | 口径 |
|---|---|
| 无记录 | 「暂无指令记录」 |
| 筛选无结果 | 「未筛选到相关指令记录」 |
| 首屏加载 | **骨架屏** |
| 分页加载 | 底部 loading |
| 首屏查询失败 | **错误态 + 重新加载按钮**（不展示残缺列表） |
| 已有列表时刷新 / 筛选失败 | **保留旧数据** + 提示重试（不清空已有内容） |

## 5. 解绑 / 失权与历史归属

记录的**数据归属 = 下发账号 + 设备 ID**，与设备当前绑定状态解耦的是数据本身；**可见性跟随入口**：

| 场景 | 批量下发指令记录 | 设备指令记录 |
|---|---|---|
| 正常 | 我的模块入口，随时可查 | 设备更多菜单入口，随时可查（离线也可查） |
| 设备解绑后 | **仍可查看**（入口在「我的」，记录是自己下发的历史事实）；L2 中该设备明细保留、**操作按钮隐藏**、标记「已解绑 / 无权限」 | **APP 内不可查**——入口挂在设备上，解绑后设备不在列表、入口不可达；数据仅后台保留 |
| 原账号重新绑定同设备 | 不受影响 | **恢复历史**（下发账号 + 设备 ID 双匹配，原记录回来） |
| 换新账号绑定同设备 | 只见自己下发的 | **看不到旧账号记录**（严格账号隔离，不继承） |

补充：

1. **查看保留、操作拦截**：失权不影响历史记录展示，但失权设备的操作按钮隐藏；存量操作请求由服务端复核兜底拒绝；
2. **记录永久保留**：业务库指令记录不清理，可无限回溯；30 天丢弃仅指网关待发队列（丢弃后该设备明细同步为失败，见 S10U 文档）；
3. 原 v1.1 结论 22「解绑 / 失权不影响历史记录可见」**修正**为上表分层口径（批量仍可查 / 单设备入口不可达）。

## 6. UPLOAD 记录联动（仅结论）

UPLOAD 指令（Send Command、批量下发、记录页重发）与设备详情页定位频率字段的联动：

> **2026-09-20 意向口径（待产品确认 US-018）**：详情页 Location Interval 为**纯字段展示**（只读二态：具体值 / `-`），不再是 UPLOAD 下发入口。产品否决则回滚双入口版本。

1. **记录归属**：Send Command / 重发进**设备指令记录页**（§2.2），批量下发进批量记录，**不加「来源」字段**；原「设备详情 Edit」入口已按意向口径删除。
2. **详情字段更新**：设备详情页定位频率字段**仅收到匹配且成功的反馈（ACK）后**才更新为该值；失败 / 异常反馈 / 指令在飞（SENDING / SENT 无回文 / CANCEL / 乐观取消回跳）**一律不更新**，字段保持旧确认值或 `-`；**确认值更新不分来源入口**——Send Command、批量下发、记录页重发产生的 UPLOAD，任一条匹配成功反馈都按其参数更新字段。
3. **取消 / 重发影响**：该 UPLOAD 记录在记录页的取消发送 / 重新发送操作，与详情字段的关系遵循同一规则——只有最终成功反馈（ACK）才更新字段；取消 / 失败不更新。重发创建的新记录在飞期间字段不动，其成功反馈到达后按新参数更新（重发即新设置意图）。
4. **并发与串扰**：指令入口平等、在线即可发，不做跨入口「同刻仅一条」拦截，并发后发优先，回文按「最新已发送」近似挂靠；**串扰导致详情字段写入错误值在纯展示模型下为必测探针**（S10U §3.1）。

| 边界 | 口径 |

| 批量 L1 统计 vs L2 明细 | **允许短暂不一致，最终一致**（两表异步更新）；测试断言最终一致，不强求实时 |
