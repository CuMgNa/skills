## 1. 范围、对象与核心结论

### 1.1 本篇覆盖

- 指令记录的三个入口及各自的预置查询口径；
- L1 指令记录页的卡片版式、排序、刷新、分页、空态；
- L2 指令详情页的顶部汇总卡、设备卡片字段、排序、刷新；
- L2 右上角筛选弹窗的全部规则；
- 取消发送、重新发送、一键重发全部失败三类操作；
- 单设备入口命中批量记录时的展示口径；
- 统计与明细的一致性、查询权限边界、记录保留期限。

### 1.2 本篇不展开

- 指令投递通道、终端协议、回文产生与串扰匹配（见 S10U / PN06 文档）；
- 下发前的三道闸门细节（见下发 plan，本篇仅引用）；
- 失败原因文案的最终措辞（接口返回，本篇只定枚举占位）。

### 1.3 核心模型（一句话）

**一次下发动作 = 一条指令记录 = L1 一张卡片**；一条记录内含 N 台设备的执行明细，L2 每台设备一张卡片。重试是记录内部的生命周期，不产生新记录。

## 2. 入口与预置查询

指令记录是**一个统一模块**，三个入口只区别在预置查询条件：

| 入口 | 路径 | L1 预置查询 |
|---|---|---|
| ① 我的-指令记录 | 我的模块 → 指令记录 | **当前账号下发的**全部记录（筛选为空） |
| ② 设备指令页 | 单设备 → 设备指令页 → 查看指令记录 | **当前账号下发的**且**含该设备参与**的记录 |
| ③ 批量下发完成 | 批量提交成功弹窗 → 查看指令记录 | **当前账号下发的**且**含本次所选设备参与**的记录 |

### 2.1 关键口径

1. **查询权限边界（账号隔离，最严口径）**：任何入口都只能看到**当前登录账号自己下发**的记录。依据设备管理文档的账号体系——同一设备可被 1 个个人账号 + 1 个企业一级账号双槽位绑定，并逐级分配给多个二级 / 三级账号，所有这些账号都具备指令控制权——若记录不按下发账号隔离，个人用户将看到陌生企业账号下发的指令与回文，构成跨账号泄露。**父级看不到下级发的、下级看不到父级发的、个人与企业互不可见**；企业树不做记录共享。
2. **参与制**：入口②/③命中记录的条件是「该记录包含所选设备」，命中后点开记录可见完整内容（见 §7 单设备入口特例）；因结论 1 的隔离，这些记录必然都是当前账号自己下发的，详情页看全量不产生跨账号泄露。
3. **同一动作同一内容**：一次下发内所有设备收到的指令内容一字不差；记录只存一份内容，重发也用这一份——不存在按设备差异内容的场景。
4. **记录永久保留**：业务库指令记录不清理，可无限回溯；30 天丢弃仅指网关待发队列（丢弃后该设备明细同步为失败，见 S10U 文档）。
5. **解绑 / 失权不影响历史记录**：记录是已发生的历史事实，按「下发账号」隔离查询，与账号当前是否仍可见该设备无关；设备解绑或分配收回后，历史指令记录仍可查。

## 3. L1 指令记录页

### 3.1 卡片版式（三行式）

```
┌────────────────────────────────┐
│ 上报间隔600秒（5台）              │ ← 行1：指令语义化内容 + 下发台数
│ 发送中 0 · 已发送 5 · 失败 0 · 已取消 0 │ ← 行2：四态统计（含 0 全显）
│ 创建时间 2026-09-18 15:00:21    │ ← 行3：创建时间
└────────────────────────────────┘
```

- **行1**：指令语义化内容（如「上报间隔600秒」），非 `<SPYT*...>` 原文；超长时**最多两行**，超出截断。
- **行2**：四态统计**全部显示含 0**（与 L2 设备卡字段统一制同风格，布局稳定）。
- **行3**：创建时间，精确到秒。

### 3.2 列表行为

| 项 | 口径 |
|---|---|
| 排序 | 创建时间**倒序**（最新在下） |
| 刷新 | 进入页面刷新 + **下拉刷新**；无自动轮询 |
| 分页 | 上滑分页加载 |
| 手动筛选 | **无**——L1 不提供筛选入口，只吃入口预置 |
| 返回（自 L2） | 保留预置筛选与滚动位置 + **自动刷新一次**（详情页取消/重发结果立刻反映到统计） |

### 3.3 空态

| 场景 | 文案 |
|---|---|
| 记录页本身为空 | 「暂无指令记录」 |
| 筛选 / 预置无结果 | 「未筛选到相关指令记录」（保留条件可重筛） |

## 4. L2 指令详情页

```
┌────────────────────────────────┐
│ ←  指令详情                [筛选] │ ← 右上角筛选图标 → 底部弹窗
├────────────────────────────────┤
│ ┌──────────────────────────┐ │
│ │ 上报间隔600秒（5台）         │ │ ← 顶部汇总卡：镜像 L1 三行式
│ │ 发送中 1 · 已发送 3 · 失败 1 · 已取消 0 │ │
│ │ 创建时间 2026-09-18 15:00:21 │ │
│ └──────────────────────────┘ │
├────────────────────────────────┤
│ ┌──────────────────────────┐ │
│ │ 卡号 1064****1234    [发送中] │ │
│ │ 发送时间：—                  │ │
│ │ 反馈内容：—  反馈时间：—      │ │
│ │              [ 取消发送 ]    │ │
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ 卡号 1064****9012      [失败] │ │
│ │ 发送时间：—                  │ │
│ │ 反馈内容：—  反馈时间：—      │ │
│ │ 失败原因：设备离线，无法下发…  │ │
│ │              [ 重新发送 ]    │ │
│ └──────────────────────────┘ │
│              …                 │
│      [ 重发全部失败（1） ]       │ ← 存在失败设备时显示
└────────────────────────────────┘
```

### 4.1 顶部汇总卡

**镜像 L1 三行式**（指令内容+台数 / 四态统计 / 创建时间），与列表认知无跳变。

### 4.2 设备卡片字段（统一制）

所有状态卡片字段**统一**，未发生的值显示占位「—」；仅失败卡片多一个失败原因：

| 字段 | 发送中 | 已发送 | 失败 | 已取消 |
|---|---|---|---|---|
| 设备卡号 | ✅ | ✅ | ✅ | ✅ |
| 发送状态 | ✅ | ✅ | ✅ | ✅ |
| 发送时间 | — 占位 | ✅ | — 占位 | — 占位 |
| 反馈内容 | — 占位 | 有回文填值，否则 — | — 占位 | — 占位 |
| 反馈时间 | — 占位 | 有回文填值，否则 — | — 占位 | — 占位 |
| 失败原因 | — | — | ✅（接口返回） | — |
| 操作按钮 | 取消发送 | 无 | 重新发送 | 无 |

补充口径：

1. **反馈内容超长**：默认截断，**点击可展开看全文**（设备回文可能很长）。
2. **取消回写**：已取消卡片被网关回写为已发送后（乐观取消回跳），自然显示发送时间，取消动作不留时间痕。
3. **重发标记**：原地更新的卡片保留「已重发 N 次」标记（见 §6.2）。

### 4.3 设备卡排序与刷新

| 项 | 口径 |
|---|---|
| 排序 | **状态优先**：发送中 → 失败 → 已取消 → 已发送；同状态内按发送时间/卡号次序；筛选不改变排序规则 |
| 刷新 | **手动下拉刷新** + 操作后**局部更新**（取消/重发只乐观更新该设备卡）；无自动轮询 |
| 空态（筛选无结果） | 「未筛选到相关设备」，保留筛选条件 |

## 5. L2 筛选弹窗

右上角筛选图标 → **底部弹出弹窗**。生效条件**仅在弹窗内可见**，页面其他位置不显示筛选标签。

| 规则 | 口径 |
|---|---|
| 维度 | **卡号（模糊/精确，用户可选）× 状态（4 态单选）**；两条件交集 |
| 指令类型维度 | **已移除**——一条记录只有一种指令类型，该维度在本页是死维度；L1 无筛选入口，类型筛选暂不出现（若日后需要属增强项） |
| 初始状态 | **从空开始，无任何预填**（旧结论「入口预置回显 / 重置=抹掉预置」**作废**——入口预置已下沉到 L1 查询本身） |
| 按钮 | 重置 + 应用筛选，两个 |
| 重置 | **清空本次勾选**（回空） |
| 应用筛选 | 提交生效，按钮 loading 防重 |
| 关闭弹窗（未应用） | **丢弃未应用项** |
| 卡号存在性校验 | **无**——筛不存在的卡号 → 空态「未筛选到相关设备」 |
| 弹窗回显 | 重新打开时回显**当前生效**的条件 |

## 6. 操作：取消与重发

### 6.1 取消发送

- **可用性**：发送中**恒可取消**（乐观取消语义，无时间窗口）。
- **二次确认**：**弹**（取消与重发均弹二次确认）。
- **乐观取消链路**（引用 S10U 已定）：点取消 → 卡片先置「已取消」；若网关实际已写出 TCP，回调回写为「已发送」，**无失败弹窗**。
- 取消后**局部更新**该设备卡。

### 6.2 重新发送（单台）

- **入口**：仅失败卡片。
- **二次确认**：弹。
- **记录语义**：**原地更新 + 重发标记**——不新增 L1 记录；该设备卡状态 失败 → 发送中 → 已发送/失败，卡片保留「已重发 N 次」。
- **技术口径**：网关侧每次重发是新指令实例（新 businessId），展示层合并进原设备卡；回文按「最新已发送」匹配，天然命中重试实例。
- **闸门**：与首次下发**全闸门一致**（列表快照离线置灰/Toast → 提交前校验 → 服务端逐台复核），无特例。
- **次数限制**：**无上限自由重试**（每次都过二次确认+loading 防重）。

### 6.3 一键重发全部失败

- 详情页存在失败设备时显示「**重发全部失败（N）**」。
- **一次**二次确认 → 批量重发 N 台；闸门、防重、原地更新口径同 §6.2。

### 6.4 失败原因

- **接口返回，前端原样展示**。枚举占位仅供测试设计参考，以接口实际为准：
  1. 设备离线，无法下发指令（已定统一文案，三道闸门命中）；
  2. 测试环境限制，禁止下发（非 prod + 卡号未白名单，占位）；
  3. 发送超时，已自动失效（待发超 30 天被网关丢弃后同步，占位）。

## 7. 单设备入口命中批量记录（已定口径）

**场景**：设备 A 的指令记录列表里出现批量记录「上报间隔600秒（5台）」（A 是 5 台之一）。

**口径**：**参与制 + 详情页看全量**——

1. L1 正常展示该批量卡片（A 参与了这次下发，且该记录是当前账号自己下发的，见 §2.1 结论 1）；
2. 点开后 L2 展示该次**全部 5 台**设备卡（审计完整：能看出是批量下发、还有谁收到；5 台都是同一账号下发动作内的设备，无跨账号信息）；
3. 想只看设备 A → 用 L2 筛选弹窗输卡号（弹窗从空开始，无预填）。

## 8. 一致性与异常边界

| 边界 | 口径 |
|---|---|
| L1 四态统计 vs L2 明细 | **允许短暂不一致，最终一致**（两表异步更新）；测试断言最终一致，不强求实时 |
| 服务过期设备 | 记录正常展示；记录内**不提供**新的下发入口（服务过期仍可下发的口径属于下发流程，见下发 plan） |
| 长期 SENDING | 记录与详情正常显示；取消恒可用；30 天后网关丢弃同步为失败（失败原因枚举占位 3） |
| 回文串扰 | 展示层如实显示接口返回的 feedbackText；串扰风险属平台匹配问题（见 S10U §3.1），记录模块不兜底 |
| 大批量卡片 | L2 设备卡同样分页/按需加载（随 L1 分页口径）；一键重发按钮固定在页面底部/顶部可见区 |
