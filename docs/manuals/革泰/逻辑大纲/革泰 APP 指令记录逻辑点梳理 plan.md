## 1. 范围、对象与核心结论

### 1.1 本篇覆盖

- 模块拆分：批量下发指令记录（两级）与设备指令记录（单层）的边界与命名；
- 记录归属判定（按入口）：哪条记录进哪个页面；
- 批量下发指令记录：L1 列表页、L2 指令详情页、筛选、取消 / 重发 / 一键重发全部失败；
- 设备指令记录：单层融合卡版式、列表行为、筛选（状态 × 类型）、取消 / 重发；
- 两页共通的账号隔离、解绑 / 失权历史归属、异常与加载态；
- UPLOAD 指令与设备详情页定位频率的联动结论（仅结论，不展开设备管理细节）。

### 1.2 本篇不展开

- 指令投递通道、终端协议、回文产生与串扰匹配（见 S10U / PN06 文档）；
- 下发前的三道闸门细节（见下发 plan，本篇仅引用）；
- 失败原因文案的最终措辞（接口返回，本篇只定枚举占位）；
- 设备详情页「定位频率」编辑控件自身的展示与视觉方案（属设备管理文档，本篇仅记录联动结论）。

### 1.3 核心模型（一句话）

**指令记录按「下发入口」拆成两个独立模块**：设备管理批量下发流程（含只选 1 台）产生的记录进「批量下发指令记录」（两级：一次下发动作 = L1 一张卡，内含 N 台设备明细 = L2 设备卡）；单设备入口（卡片更多菜单 Send Command、设备详情 Edit 定位频率）产生的记录进「设备指令记录」（单层：一次下发动作 = 一张融合卡，无跳转）。重试是记录内部的生命周期，不产生新记录；重复下发则每次独立成记录。**（2026-09-20 需求变更：详情页定位频率恢复可编辑，v2.2「纯字段展示」意向口径撤销）**

## 2. 模块拆分、记录归属与入口落点

### 2.1 两个独立模块与页面命名

| 页面 | 层级 | 入口 |
|---|---|---|
| **批量下发指令记录**（L1） | 两级第一层 | 我的模块 → 批量下发指令记录；批量提交结果弹窗 → 查看记录 |
| **指令详情**（L2） | 两级第二层 | L1 点卡片进入 |
| **设备指令记录** | **单层，无跳转** | 设备更多菜单 → Send Command → 单设备下发页底部「指令记录」 |

原「我的-指令记录」**更名为「批量下发指令记录」**；原三入口统一模块（含设备指令页入口）**作废**（见 §9.2）。

### 2.2 记录归属判定（按入口，核心裁决）

**记录产生自哪个下发流程，就归哪个页面**，与设备数量无关：

| 下发动作 | 产生记录 | 归属页面 |
|---|---|---|
| 设备管理 → 指令下发批量流程（**含只选 1 台**） | 1 条批量记录 | 批量下发指令记录 |
| 设备卡片更多菜单 → Send Command（七类指令） | 每次下发 1 条单设备记录 | 设备指令记录 |
| 设备详情 → Edit → Location Interval → Save（UPLOAD） | 1 条单设备记录 | 设备指令记录 |

推论：

1. **批量页只收批量流程记录**，单设备页只收单设备入口记录；
2. **设备被批量下发波及（是 N 台之一），不因此在其设备指令记录页出现该记录**——原「参与制 + 详情页看全量」口径作废；
3. 批量流程只选 1 台设备，记录仍进批量页（按入口判定，不按台数判定）。

统一建单边界：

- APP 本地格式校验未通过、请求未发出时，不创建后台记录；
- 用户已确认且请求到达服务端后，只要能够识别账号、设备和操作意图，无论后续校验成功或失败，均创建记录；
- 服务端权限、关系、路由、型号、参数、容量或高危会话复检失败时，记录直接进入 FAILURE；
- 批量最终目标范围内的每台设备必须建立明细，失败设备不得静默丢失。

### 2.3 入口与页面落点

| 入口 | 行为 |
|---|---|
| 我的模块 → 批量下发指令记录 | 进入 L1，默认查询当前账号下发的全部批量记录 |
| 批量提交结果弹窗 | 全部受理 / 部分受理 / 全部失败均显示「查看记录」与「完成」；「查看记录」→ 进入 L1 **刷新全量记录，不定位、不高亮、不预置筛选**；「完成」或关闭 → 清空本次操作并返回设备列表 |
| 设备更多菜单 → Send Command | 进入单设备下发页；设备离线时仍可进入，普通五类可提交；高危两类可按最近一次会话快照置灰，但页面状态变化后可刷新，最终以提交时服务端实时会话复检为准 |
| 单设备下发结果 | 成功、明确失败均留在下发页反馈；结果未知时进入“正在确认提交结果”，使用原幂等标识查询原操作，确认期间禁止重复创建新指令 |
| 单设备下发页底部「指令记录」入口 | **始终显示且为设备指令记录唯一入口**；点击进入记录页，返回时回到原下发页，不主动重置指令与参数 |

### 2.4 账号隔离（最严口径，两页一致）

1. **两页均只能看到当前登录账号自己下发的记录**。依据设备管理文档的账号体系——同一设备可被 1 个个人账号 + 1 个企业一级账号双槽位绑定，并逐级分配给多个二级 / 三级账号，所有这些账号都具备指令控制权——若记录不按下发账号隔离，个人用户将看到陌生企业账号下发的指令与回文，构成跨账号泄露。
2. **父级看不到下级发的、下级看不到父级发的、个人与企业互不可见**；企业树不做记录共享。
3. **记录归属 = 下发账号 + 设备 ID**：换账号绑定设备不继承历史（见 §5）。

## 3. 批量下发指令记录（两级结构，原规则保留）

> 本章为 v1.1 已确认规则的整体保留，仅两处变化：页面更名 + 记录范围收窄为批量流程（§2.2）。

### 3.1 L1 批量下发指令记录页

**卡片版式（三行式）**：

```
┌────────────────────────────────┐
│ 上报间隔600秒（5台）              │ ← 行1：指令语义化内容 + 下发台数
│ 发送中 0 · 已发送 5 · 失败 0 · 已取消 0 │ ← 行2：四态统计（含 0 全显）
│ 创建时间 2026-09-18 15:00:21    │ ← 行3：创建时间
└────────────────────────────────┘
```

- **行1**：指令语义化内容（如「上报间隔600秒」），非 `<SPYT*...>` 原文；超长时**最多两行**，超出截断。
- **行2**：四态统计**全部显示含 0**（布局稳定）。
- **行3**：创建时间，精确到秒。

**列表行为**：

| 项 | 口径 |
|---|---|
| 排序 | 创建时间**倒序**（最新在上） |
| 刷新 | 进入页面刷新 + **下拉刷新**；页面从后台恢复时刷新，并通过状态推送或低频轮询接收迟到状态修正 |
| 分页 | 上滑分页加载 |
| 手动筛选 | **无**——L1 不提供筛选入口 |
| 返回（自 L2） | 保留 L1 滚动位置 + **自动刷新一次**（取消/重发结果立刻反映到统计）；L1 无筛选条件，重新进入 L2 时筛选从空开始 |

**空态**：记录为空「暂无指令记录」；无结果场景「未筛选到相关指令记录」。

### 3.2 L2 指令详情页

```
┌────────────────────────────────┐
│ ←  指令详情                [筛选] │ ← 右上角筛选图标 → 底部弹窗
├────────────────────────────────┤
│ ┌──────────────────────────┐ │
│ │ 上报间隔600秒（5台）         │ │ ← 顶部汇总卡：镜像 L1 三行式
│ │ 发送中 1 · 已发送 3 · 失败 1 · 已取消 0 │ │
│ │ 创建时间 2026-09-18 15:00:21 │ │
│ └──────────────────────────┘ │
├────────────────────────────────┤
│ ┌──────────────────────────┐ │
│ │ 卡号 1064****1234    [发送中] │ │
│ │ 发送时间：—                  │ │
│ │ 反馈内容：—  反馈时间：—      │ │
│ │              [ 取消发送 ]    │ │
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ 卡号 1064****9012      [失败] │ │
│ │ 发送时间：—                  │ │
│ │ 失败时间：2026-09-18 15:00:25 │ │
│ │ 反馈内容：—  反馈时间：—      │ │
│ │ 失败原因：S10U 路由缺失…       │ │
│ │              [ 重新发送 ]    │ │
│ └──────────────────────────┘ │
│              …                 │
│      [ 重发全部失败（1） ]       │ ← 存在失败设备时显示
└────────────────────────────────┘
```

**顶部汇总卡**：镜像 L1 三行式（内容+台数 / 四态统计 / 创建时间）。

**设备卡片字段（统一制）**——所有状态卡片字段统一，未发生的值显示占位「—」；仅失败卡片多一个失败原因：

| 字段 | 发送中 | 已发送 | 失败 | 已取消 |
|---|---|---|---|---|
| 设备卡号 | ✅ | ✅ | ✅ | ✅ |
| 发送状态 | ✅ | ✅ | ✅ | ✅ |
| 发送时间 | — 占位 | ✅（实际 TCP 写出时间） | — 占位 | — 占位 |
| 失败时间 | — | — | ✅（明确进入 FAILURE 的时间） | — |
| 反馈内容 | — 占位 | 有回文填值，否则 — | — 占位 | — 占位 |
| 反馈时间 | — 占位 | 有回文填值，否则 — | — 占位 | — 占位 |
| 失败原因 | — | — | ✅（接口返回） | — |
| 操作按钮 | 取消发送 | 无 | 重新发送 | 无 |

补充口径：

1. **反馈内容超长**：默认截断，**点击可展开看全文**；
2. **取消回写**：已取消卡片被网关回写为已发送后（乐观取消回跳），自然显示实际 `sentAt`；后台必须保留 `cancelRequestedAt / cancelResolvedAt / cancelOutcome / statusCorrectedAt`，记录详情可追溯取消请求和状态修正过程；
3. **重发标记**：原地更新的卡片保留「已重发 N 次」标记；
4. **失权设备**：明细保留展示，**操作按钮隐藏**，卡片标记「已解绑 / 无权限」（见 §5）。

**排序与刷新**：

| 项 | 口径 |
|---|---|
| 排序 | **状态优先**：发送中 → 失败 → 已取消 → 已发送；同状态内按发送时间/卡号次序；筛选不改变排序规则 |
| 刷新 | **手动下拉刷新** + 操作后**局部更新**；页面从后台恢复时刷新，并通过状态推送或低频轮询接收迟到状态修正，避免长期停留在旧的 CANCEL |
| 空态（筛选无结果） | 「未筛选到相关设备」，保留筛选条件 |

### 3.3 L2 筛选弹窗

右上角筛选图标 → **底部弹出弹窗**。生效条件**仅在弹窗内可见**，页面其他位置不显示筛选标签。

| 规则 | 口径 |
|---|---|
| 维度 | **卡号（模糊/精确，用户可选）× 状态（4 态单选）**；两条件交集 |
| 指令类型维度 | **无**——一条记录只有一种指令类型，是死维度 |
| 初始状态 | 从空开始，无预填 |
| 按钮 | 重置 + 应用筛选 |
| 重置 | 清空本次勾选（回空） |
| 应用筛选 | 提交生效，按钮 loading 防重 |
| 关闭弹窗（未应用） | 丢弃未应用项 |
| 卡号存在性校验 | 无——筛不存在的卡号 → 空态 |
| 弹窗回显 | 重新打开时回显**当前生效**的条件 |

### 3.4 操作：取消与重发

**取消发送**：

- 发送中**恒可取消**（乐观取消语义，无时间窗口）；
- **二次确认**：弹；
- 乐观取消链路（引用 S10U）：点取消 → 卡片先置「已取消」；该展示表示取消请求已进入处理，不代表平台已绝对确认指令不会写出；
- 若网关确认未写出且删除成功，维持「已取消」；若实际已完成 TCP 写出，回调将卡片修正为「已发送/已下发」；
- CANCEL → SENT 后必须提示“取消未生效，指令已下发”；RESET / POWEROFF 使用高优先级提醒，并说明设备仍可能执行；
- 取消后先局部更新该设备卡，迟到状态修正到达后再次更新卡片、筛选结果及 L1 汇总。

**重新发送（单台）**：

- 入口：仅失败卡片；**二次确认**：弹；
- **原地更新 + 重发标记**：页面不新增记录；原 `commandId` 保持不变，后台生成新的 `attemptId`，并由 S10U 为该 attempt 分配一一映射的 `businessId`；展示层合并进原设备卡，状态 失败 → 发送中 → 已发送/失败，卡片保留「已重发 N 次」；
- 重发后字段口径：**创建时间不变**；新 attempt 实际完成 TCP 写出时更新为最近一次 `sentAt`，写出前失败时保持发送时间为「—」并更新 `failedAt`；反馈内容 / 反馈时间 / 失败原因只展示最新一次的值（历史 attempt 后台永久审计保留，并支持详情追溯）；
- **普通五类**（CR/VERNO/FIND/UPLOAD/ZONE）：设备离线也可重发并进入普通队列；
- **高危两类**（RESET/POWEROFF）：重发按钮保持可点；用户完成二次确认后创建新的 `attemptId`，再由服务端复检当前 S10U 可写会话；复检失败时，新 attempt 直接进入 FAILURE，重发次数增加并展示本次失败原因，禁止复活旧高危任务；
- 所有重发均复用首次下发的权限、关系、路由、型号、参数和幂等校验；
- **次数限制**：无上限自由重试（每次都过二次确认 + loading 防重）。

**一键重发全部失败**（仅批量 L2 有）：

- 详情页存在失败设备时显示「重发全部失败（N）」；**一次**二次确认 → 批量重发 N 台；普通指令允许离线设备进入队列，高危指令由服务端逐台复检当前会话；每台设备均在原卡更新并独立返回结果。设备指令记录页**无此按钮**（见 §4.5）。

**失败原因**：接口返回，前端原样展示。测试设计至少覆盖：

1. 权限 / 关系失效、S10U 路由缺失、型号或参数不支持；
2. 高危指令无当前可写会话、会话变化或查询异常（普通五类不得仅因离线失败）；
3. 测试环境限制，禁止下发（非 prod + 卡号未白名单，占位）；
4. 普通指令待发超过 30 天被网关丢弃并同步 FAILURE。

## 4. 设备指令记录（独立单层页）

### 4.1 页面结构

```
┌────────────────────────────────┐
│ ←  设备指令记录            [筛选] │ ← 返回上一层单设备下发页
│ 张三的车（1064****1234）          │ ← 设备身份行
├────────────────────────────────┤
│        （无汇总卡，融合卡平铺）     │
│ ┌────────────────────────────┐ │
│ │        融合卡 × N            │ │
│ └────────────────────────────┘ │
└────────────────────────────────┘
```

- **页头**：返回（→ 上一层单设备下发页，不主动重置指令与参数）+ 标题「设备指令记录」+ 右上筛选图标；
- **设备身份**：有备注显示「备注（卡号）」，无备注仅显示卡号（如 `1064****1234`）；**不显示在线状态 / 服务状态**——本页是历史记录页，不承担设备实时状态展示；
- **无顶部汇总卡**：单设备页没有四态统计汇总（统计属批量多台场景）；
- **单层无跳转**：点卡片不进任何二级页，所有信息在卡内呈现。

### 4.2 融合卡版式（全字段一卡通）

```
┌────────────────────────────────┐
│ 指令类型：设置上传间隔             │
│ 指令内容：上报间隔 600 秒          │
│ 状态：发送中                      │
│ 创建时间：2026-09-20 15:00:21    │
│ 发送时间：—                      │
│ 反馈内容：—                      │
│ 反馈时间：—                      │
│                    [ 取消发送 ]   │
└────────────────────────────────┘
┌────────────────────────────────┐
│ 指令类型：设置上传间隔             │
│ 指令内容：上报间隔 600 秒          │
│ 状态：失败                        │
│ 创建时间：2026-09-20 14:00:21    │
│ 发送时间：—                      │
│ 失败时间：2026-09-20 14:02:05    │
│ 反馈内容：—                      │
│ 反馈时间：—                      │
│ 失败原因：当前型号不支持该指令       │
│ 已重发 2 次                      │
│                    [ 重新发送 ]   │
└────────────────────────────────┘
```

**字段显隐（统一制 + 条件行）**：

| 字段 | 说明 | 显隐规则 | 空值 |
|---|---|---|---|
| 指令类型 | 七类指令的名称（见 §4.4） | 恒显 | — |
| 指令内容 | 语义化内容（非协议原文） | 恒显 | — |
| 状态 | 四态之一 | 恒显 | — |
| 创建时间 | 精确到秒 | 恒显 | — |
| 发送时间 | 实际完成 TCP 写出的时刻；只有 SENT 有值 | 恒显 | 未发出「—」 |
| 失败时间 | 明确进入 FAILURE 的时刻 | **仅失败态显示** | — |
| 反馈内容 | 终端回文 | 恒显 | 无回文「—」 |
| 反馈时间 | 收到回文时刻 | 恒显 | 无回文「—」 |
| 失败原因 | 接口返回原样展示 | **仅失败态显示** | — |
| 已重发 N 次 | 重发标记 | **重发过才显示** | — |
| 操作按钮 | 发送中→取消发送；失败→重新发送 | 已发送 / 已取消**无按钮** | — |

**版式口径**：

1. **卡片高度不固定、内容不截断**：任何文字字段超出宽度即**完整换行显示**（追溯清晰优先，不做「最多两行」截断——与批量 L1 行1 的截断规则不同）；
2. **反馈内容超长**：默认收起显示部分，**点击在卡内原地展开 / 收起**看全文（设备回文可能很长，是唯一有折叠机制的字段；其余字段直接换行铺开）；
3. **重复下发不合并**：同一设备每次下发（含相同指令相同参数）各自独立成卡。

### 4.3 列表行为

| 项 | 口径 |
|---|---|
| 范围 | 仅当前账号通过单设备入口对该设备下发的记录（§2.2） |
| 排序 | 创建时间**倒序**；**同秒按服务端返回序列**（服务端定序，前端不自排） |
| 刷新 | 进入页面刷新 + **下拉刷新**；页面从后台恢复时刷新，并通过状态推送或低频轮询接收迟到状态修正 |
| 分页 | 上滑分页加载 |
| 下拉刷新与筛选 | **保留当前筛选条件**重新查询 |
| 离开页面 | **筛选条件清空**（下次进入从空开始） |
| 新记录可见性 | 下发确认后**立即可见**（进入页面即出现新卡） |
| 新记录初始状态 | **以后端返回为准**（可能是发送中，也可能已快速流转为已发送 / 失败） |

### 4.4 筛选弹窗

右上角筛选图标 → **底部弹出弹窗**（与批量 L2 弹窗同风格）。生效条件**仅在弹窗内可见**，页面其他位置（含筛选图标）不显示角标 / 标签。

| 规则 | 口径 |
|---|---|
| 维度 | **状态（4 态单选）× 指令类型（七类单选）**；两条件**交集** |
| 七类类型 | 立即定位（CR）、查询版本（VERNO）、查找设备（FIND）、设置上传间隔（UPLOAD）、设置设备时区（ZONE）、远程重启（RESET）、远程关机（POWEROFF）——显示**类型名称** |
| 「全部」选项 | **无**——空选即代表不限该维度 |
| 初始状态 | 从空开始（空 = 不限 = 全部记录） |
| 按钮 | 重置 + 应用筛选 |
| 重置 | 清空本次勾选（回空） |
| 应用筛选 | 提交生效，按钮 loading 防重 |
| 关闭弹窗（未应用） | 丢弃未应用项 |
| 弹窗回显 | 重新打开时回显**当前生效**的条件 |
| 筛选无结果 | 「未筛选到相关指令记录」（保留条件可重筛） |
| 无任何记录 | 「暂无指令记录」 |

> 与批量 L2 筛选的差异：批量 L2 = 卡号 × 状态（无类型维度，死维度）；本页 = 状态 × 类型（**无卡号维度**——整页只有一台设备，卡号是死维度；类型跨七类，是活维度）。

### 4.5 操作：取消与重发

**沿用批量操作的全部语义，仅两处差异**：

| 项 | 口径 |
|---|---|
| 取消发送 | 发送中恒可取消 + 二次确认 + 乐观取消链路（引用 S10U）；局部更新该卡 |
| 重新发送 | 仅失败卡；二次确认；后台新增 attempt、前台**原地更新 + 重发标记**（失败 → 发送中 → 已发送/失败）；普通五类离线可重发，高危两类按钮可点但提交时必须由服务端复检当前会话；创建时间不变，只展示最近一次发送 / 反馈 / 失败信息；无次数上限 |
| 一键重发全部失败 | **无此按钮**（单设备页一卡一记录，逐卡操作） |
| 操作防重 | 确认后按钮 **loading 禁用**，防重复提交 |
| 操作接口失败 | **回滚到操作前状态** + Toast 提示（乐观更新被拒绝时恢复原卡） |
| 操作前复核 | 操作请求经**服务端复核权限与设备状态**；页面打开期间设备被解绑 / 失权的存量操作被拒绝，提示无权限（见 §5） |

### 4.6 空态、加载与查询异常

| 场景 | 口径 |
|---|---|
| 无记录 | 「暂无指令记录」 |
| 筛选无结果 | 「未筛选到相关指令记录」 |
| 首屏加载 | **骨架屏** |
| 分页加载 | 底部 loading |
| 首屏查询失败 | **错误态 + 重新加载按钮**（不展示残缺列表） |
| 已有列表时刷新 / 筛选失败 | **保留旧数据** + 提示重试（不清空已有内容） |

## 5. 解绑 / 失权与历史归属

记录的**数据归属 = 下发账号 + 设备 ID**，与设备当前绑定状态解耦的是数据本身；**可见性跟随入口**：

| 场景 | 批量下发指令记录 | 设备指令记录 |
|---|---|---|
| 正常 | 我的模块入口，随时可查 | 设备更多菜单 → Send Command → 下发页底部「指令记录」，离线设备仍可进入下发页查看 |
| 设备解绑后 | **仍可查看**（入口在「我的」，记录是自己下发的历史事实）；L2 中该设备明细保留、**操作按钮隐藏**、标记「已解绑 / 无权限」 | **APP 内不可查**——入口挂在设备上，解绑后设备不在列表、入口不可达；数据仅后台保留 |
| 原账号重新绑定同设备 | 不受影响 | **恢复历史**（下发账号 + 设备 ID 双匹配，原记录回来） |
| 换新账号绑定同设备 | 只见自己下发的 | **看不到旧账号记录**（严格账号隔离，不继承） |

补充：

1. **查看保留、操作拦截**：失权不影响历史记录展示，但失权设备的操作按钮隐藏；存量操作请求由服务端复核兜底拒绝；
2. **记录永久保留**：业务库指令记录不清理，可无限回溯；30 天丢弃仅指网关待发队列（丢弃后该设备明细同步为失败，见 S10U 文档）；
3. 原 v1.1 结论 22「解绑 / 失权不影响历史记录可见」**修正**为上表分层口径（批量仍可查 / 单设备入口不可达）。

## 6. UPLOAD 记录联动（仅结论）

设备详情 Edit → Location Interval → Save 产生的 UPLOAD 指令：

1. **记录归属**：进**设备指令记录页**（§2.2），**不加「来源」字段**——卡片展示与 Send Command 下发的记录完全一致（七类之一：设置上传间隔）；
2. **详情页确认值更新**：设备详情页定位频率**仅收到匹配且成功的反馈（ACK）后**才更新为该值；失败 / 异常反馈**不更新**（详情编辑目标值 ≠ 已生效值，仅成功反馈后确认值才对齐——控件自身展示属设备管理文档，本篇不展开）；**确认值更新不分来源入口**——详情编辑、Send Command、批量下发、记录页重发产生的 UPLOAD，任一条匹配成功反馈都按其参数更新确认值；
3. **取消 / 重发影响**：该 UPLOAD 记录在设备指令记录页的取消发送 / 重新发送操作，与详情页确认值的关系遵循同一规则——只有最终成功反馈（ACK）才更新确认值；FAILURE 或 `CANCEL + cancelResolution=CONFIRMED` 不更新确认值，乐观 CANCEL 期间服务端仍保留目标上下文。
4. **频率任务层完全绑定本篇四态**（2026-09-20 与设备管理大纲对齐，频率任务不设独立 30 秒超时终判）：
   - SENDING / SENT 无匹配回文 → 详情页显示目标文案 +「（设置中）」；
   - FAILURE（含 30 天网关丢弃）/ `CANCEL + cancelResolution=CONFIRMED` → 详情页恢复剩余有效目标或原确认值 / Unknown；
   - APP 乐观 `CANCEL + cancelResolution=PENDING` → 页面可暂时回退，但服务端保留目标参数和任务上下文；
   - CANCEL 回写 SENT（乐观取消回跳）→ 详情页恢复或维持设置中，继续等待回文；
   - 匹配成功回文 → 确认值更新为该记录参数；
   - 重新发送生成新的后台 attempt、展示层仍合并在原记录卡 → 频率任务重新挂起设置中（目标 = 原记录参数），**重发即新设置意图**；
   - 详情页频率设置、Send Command、批量下发、记录页重发四入口平等，**不做跨入口「同刻仅一条」拦截**；反馈先按 `businessId` 解析到唯一 `attemptId`，再归入对应 `commandId`；旧 attempt 回文不得覆盖更新目标，无法可靠关联时只展示回文、不更新确认值。

## 7. 一致性与异常边界（公共）

| 边界 | 口径 |
|---|---|
| 批量 L1 统计 vs L2 明细 | **允许短暂不一致，最终一致**（两表异步更新）；CANCEL → SENT 时取消数 -1、已发送数 +1，重复回调不得重复计数；测试断言最终一致，并按产品约定的同步时限校验 |
| 指令状态枚举 | **仅依赖契约**——后端契约保证指令只有四态（发送中/已发送/失败/已取消），前端**不定义**「未知状态」异常态；若出现契约外状态属后端缺陷（测试断言点） |
| 服务过期设备 | 记录正常展示；记录内不提供新的下发入口 |
| 长期 SENDING | 普通五类记录正常显示、取消恒可用，待发超过 30 天后网关丢弃并同步 FAILURE；高危两类绑定会话断开或变化时立即 FAILURE，不进入 30 天等待 |
| 回文关联 | 后端按 `businessId → attemptId → commandId` 关联反馈；无法可靠关联时只展示 feedbackText，不更新配置确认值；旧 attempt 回文不得覆盖更新目标 |
| 大批量卡片 | 批量 L2 设备卡分页/按需加载；一键重发按钮固定在可见区 |

## 9. 当前有效结论与作废口径

### 9.1 当前有效结论

1. 记录按下发入口拆分：批量入口 →「批量下发指令记录」两级页；Send Command / 设备详情 UPLOAD →「设备指令记录」单层页。
2. 设备指令记录唯一入口为单设备下发页底部「指令记录」；返回时回到原下发页，不主动重置指令与参数。
3. 批量结果弹窗的「查看记录」直接进入批量 L1，刷新全量记录，不定位、不高亮、不预置筛选；最新记录置顶。
4. 单设备提交的成功、明确失败、结果未知均以 Toast 反馈并留在下发页。
5. 普通五类允许离线首次下发和重发，待发超过 30 天同步 FAILURE；高危两类提交与重发均需服务端复检并绑定当前 S10U 会话，会话断开或变化立即 FAILURE。
6. 用户主动重发生成新的后台 attempt，前台仍在原卡更新并显示「已重发 N 次」，只展示最近一次发送、反馈与失败信息。
7. 两页均严格按下发账号隔离；批量记录失权后仍可查但不可操作，单设备记录在设备解绑后因入口不可达而仅后台保留。
8. 指令状态统一为 SENDING / SENT / FAILURE / CANCEL；反馈内容与发送状态分离。
9. UPLOAD 只有匹配成功反馈后才更新设备详情确认值；SENDING / SENT 无成功反馈时保持「设置中」。

### 9.2 作废口径

| 作废口径 | 当前替代 |
|---|---|
| 三入口统一为一个指令记录模块 | 批量记录与设备记录分拆，按下发入口归属 |
| 设备更多菜单直接进入设备指令记录 | 设备更多菜单进入 Send Command，记录仅从下发页底部进入 |
| 批量结果携带 batchId 自动定位本次记录 | 直接进入批量 L1 全量列表，不定位 / 不高亮 / 不筛选 |
| 七类指令统一在线限制和统一重发闸门 | 普通五类离线可排队；高危两类绑定当前会话 |
| 重发新增一条用户可见记录 | 后台新增 attempt，前台原卡更新 |
| L1 返回时保留筛选 | L1 无筛选，仅保留滚动位置并刷新统计 |
| 解绑 / 失权一律不影响历史入口 | 批量记录可查；单设备记录因设备入口消失而 APP 不可达 |
| 定位频率独立 30 秒终判或详情页纯字段展示 | 定位频率恢复可编辑，生命周期绑定指令四态 |
