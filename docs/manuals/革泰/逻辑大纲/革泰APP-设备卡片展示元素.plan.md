## 2. 设备卡片结构（已确认）

| 区域 | 展示内容 | 规则 |
| --- | --- | --- |
| 左侧设备图标 | 系统固定设备图标 | 按设备类型固定，添加及后续编辑时均不可修改图标形态 |
| 图标主体与角标 | 状态颜色＋右上角角标 | 在线绿色，离线／未连接灰色，存在未处理告警时红色；告警时通过角标保留在线／离线差异 |
| 第一行 | 备注优先，设备编号兜底 | 有备注就显示备注，备注为空时显示设备编号；不额外附加编号，不新增备注唯一性限制 |
| 第二行 | 电池图标＋电量 | 不再显示备注、分组名称及原有分隔符；电量未知时显示 `Unknown` |
| 第三行 | 定位频率及模式／离线提示 | 在线显示频率及模式；离线／未连接显示“离线，无法下发指令” |
| 右侧状态文字 | 取消 | 不展示独立的“在线／离线／告警”文字标签 |
| 更多入口 | 右上角竖向三点 | 所有设备状态均保留；独立于卡片本体点击 |
| 卡片本体点击 | 进入对应设备详情 | 在线、离线、未连接、告警状态均保持相同跳转目标 |

### 2.1 标题与设备身份

1. 第一行严格采用“备注优先，设备编号兜底”，不恢复固定展示设备卡号的旧规则。
2. 备注仍使用原设备资料中的同一份业务备注，不新建 APP 独立展示值。
3. 同名备注难以区分设备的可用性风险已经提出；本轮决定仍保持当前需求，不追加编号、不要求备注唯一。
4. 卡片跳转、更多操作与数据更新均须绑定设备唯一标识；不能以备注或当前列表位置代替设备身份。
5. 纯空白备注如何处理，以及备注和设备编号均缺失时的兜底，仍为待确认项。

### 2.2 分组展示边界

- 仅移除卡片内的分组名称。
- 列表上方的分组筛选保留，不因卡片精简而删除。
- 本稿不改变设备分组归属及账户间分组隔离规则。

## 3. 通信状态与告警展示

### 3.1 状态组合（已确认）

以下“告警”均指存在至少一条未处理告警。“无未处理告警”不代表从未产生过历史告警。所有组合均取消右侧状态文字标签。

| 设备实际情况 | 图标主体颜色 | 右上角角标 | 第三行 |
| --- | --- | --- | --- |
| 在线，无未处理告警 | 绿色 | 不展示 | 对应定位频率及模式 |
| 离线，无未处理告警 | 灰色 | 不展示 | 离线，无法下发指令 |
| 未连接，无未处理告警 | 灰色 | 不展示 | 离线，无法下发指令 |
| 在线，存在未处理告警 | 红色 | 在线角标 | 对应定位频率及模式 |
| 离线，存在未处理告警 | 红色 | 离线角标 | 离线，无法下发指令 |
| 未连接，存在未处理告警 | 红色 | 离线角标 | 离线，无法下发指令 |

- 未连接沿用原定义：初始化绑定后尚无有效通信／上报，在用户侧归入离线，不新增独立标签。
- 告警不替代设备的基础通信状态。
- 角标的业务含义已确认，但具体颜色、形状、尺寸与无障碍表达仍需视觉规范明确；不得仅凭截图中的灰色圆点推断全部角标规范。

### 3.2 告警进入与退出（已确认）

| 场景 | 卡片表现 |
| --- | --- |
| 至少存在一条未处理告警 | 图标变红，通过角标保留通信状态 |
| 处理部分告警，仍有未处理告警 | 保持红色 |
| 全部告警已处理，无新增未处理告警 | 退出告警态，按当前通信状态恢复绿色或灰色，取消告警态角标 |
| 异常仍持续，但不存在未处理告警 | 不仅凭异常持续保持红色 |
| 再次产生未处理告警 | 重新进入告警态 |
| 处理期间又产生未处理告警 | 仍保持红色，不能因某一条处理成功就误退红 |

直接关联口径：卡片告警态与设备列表“告警”筛选均依据存在未处理告警；同一设备有多条未处理告警仍只计一台告警设备。本稿不扩展告警中心其他页面的业务规则。

### 3.3 两种红色不能混用

- **红色设备主体图标**：由存在未处理告警决定。
- **红色电池图标**：由有效电量低于20%决定。
- 不能仅因电池图标变红就直接推断设备主体必须变红。
- 电量变化是否生成低电告警，继续以原告警生成规则为准，本轮未修改该规则。

## 4. 电量展示

### 4.1 有效电量及颜色（已确认）

有效范围沿用原文档第 8 节：0～100%。低电颜色边界以本轮确认为准。

| 电量情况 | 文字展示 | 电池图标 |
| --- | --- | --- |
| 有效电量＜20% | 实际百分比 | 红色 |
| 有效电量≥20% | 实际百分比 | 绿色 |
| 恰好0% | `0%`，不能当缺失 | 红色 |
| 恰好20% | `20%` | 绿色 |
| 恰好100% | `100%` | 绿色 |
| 未取得有效电量、缺失或越界 | `Unknown` | 未知态是否保留图标、颜色及填充形态待确认 |

- 电量未知不等于未绑定，不使用 `Unbound`。
- 不把未知或越界数据当作0%，不据此形成低电结论。
- 本轮确认的是电池图标颜色；未额外规定百分比文字必须同步变色。
- 小数电量是否支持、显示舍入及阈值判断方式，仍待确认。
- 当已有历史有效值又收到异常值时，两者的展示优先级待明确；异常值本身不得作为正常百分比展示。

### 4.2 离线历史电量（已确认）

| 情况 | 展示要求 |
| --- | --- |
| 离线且有最后一次有效电量 | 保留该电量，按对应数值使用红／绿电池图标，并标注历史值 |
| 离线／未连接且从未取得有效电量 | 显示 `Unknown`，不伪造百分比或上报时间 |
| 查看详情中的电量时间 | 展示所显示电量对应的上报时间，不使用离线时间或页面刷新时间代替 |

- 已确认“保留电量并标注历史值”；“上次上报”是候选措辞，不是已定稿的唯一文案。
- 提示具体位置、排版、是否换行及行高尚未确认。
- 本轮未设置电量过期时长，不新增“离线超过某时长就清空电量”的规则。
- 重新在线但尚未收到新电量时，历史标记如何保留或解除仍待确认。

## 5. 第三行定位频率与离线提示

### 5.1 对应关系（已确认／沿用原规则）

| 情况 | 展示文案 |
| --- | --- |
| 在线，1分钟 | 1分钟定位（耗电模式） |
| 在线，10分钟 | 10分钟定位（默认模式） |
| 在线，60分钟 | 1小时定位（省电模式） |
| 在线，自定义N分钟 | 自定义模式（N分钟） |
| 在线，无可确认频率 | 表达频率未知，确切占位文案待确认 |
| 离线／未连接，无论是否有已知频率 | 离线，无法下发指令 |

- 自定义N沿用原文档的1～1440整数分钟；N为1、10、60时，优先展示对应预设文案。
- 定位频率与APP刷新间隔不是同一概念，本稿不改变页面刷新设置。
- 耗电／默认／省电是展示文案，不据此改变低电阈值或承诺续航。

### 5.2 频率数据口径（引用现有第5.2节）

1. 展示可确认的当前生效配置；无新确认依据但已有仍可确认的原值时，保留原确认值。
2. 绑定时填写的目标值、编辑选择值、平台受理结果均不自动等于设备已生效值。
3. 没有可确认值时表达未知，不自行填入10分钟默认值。
4. 本稿仅约束卡片展示，不决定详情页是否允许编辑定位频率；详情编辑入口及生效流程不在本次范围。

### 5.3 截图不采纳的内容

- 灰色离线卡片继续显示定位频率：不采纳，替换为离线提示。
- 1分钟标为省电模式：不采纳，沿用1分钟耗电、10分钟默认、60分钟省电。
- `Locate in 1 min`：不是已确认的最终英文译文，需避免被理解为“一分钟后定位”的倒计时。

## 6. 布局与展示边界

### 6.1 继续适用的原布局约束

| 区域 | 约束 |
| --- | --- |
| 第一行备注／兜底编号 | 沿用单行尾部省略，不挤压更多入口 |
| 电量数值 | 优先完整展示，不截断；缺失时不再隐藏，改为`Unknown` |
| 第三行 | 沿用单行过长尾部省略；多语言及大字体下关键语义如何保护需补充设计 |
| 设备图标与角标 | 固定尺寸和位置，不被文本挤压或遮挡 |
| 更多入口 | 各状态保留，不被长文本遮挡 |

### 6.2 待确认项与建议

以下内容**未确认为正式需求**，不能直接作为开发实现或测试通过标准。

| 待确认项 | 具体缺口 | 建议，尚未采纳 |
| --- | --- | --- |
| 历史电量提示 | 最终文案、位置、换行、行高及溢出处理 | 可在第二行采用“电池图标 65% · 上次上报”，第三行保留离线提示；该示例不是固定格式 |
| Unknown图标 | 是否保留图标、颜色和填充形态 | 中性灰色未知态，避免像满电或低电 |
| 告警角标 | 在线／离线的具体颜色、形状和辨识方式 | 提供两种明确视觉稿，并补充非颜色提示与读屏语义 |
| 标题空值 | 纯空白备注归一化；备注和编号均缺失的异常兜底 | 纯空白按空处理，异常数据避免无标题卡片 |
| 电量精度与异常 | 小数、舍入、非法类型、历史有效值与新异常值优先级 | 避免显示20%却因原始小数值而标红，异常数据不当正常百分比 |
| 在线频率未知 | 确切占位文案 | 可使用“定位频率未知” |
| 离线整卡样式 | 是否弱化及弱化范围 | 建议只改变状态图标，不把整卡呈现为不可点击 |
| 长文案与多语言 | 历史电量提示及模式名称在窄屏、大字体下的显示 | 优先保留电量及关键状态含义，验证长备注、翻译膨胀和读屏 |
| 在线恢复后的历史电量 | 已恢复通信但尚无新电量时历史标记如何处理 | 不仅凭通信恢复就把旧电量表达为实时数据 |

列表默认排序、状态刷新机制等原有待确认事项未在本轮解决，也不纳入本稿新增设计。
