# US-015 设备列表筛选与快捷操作

## POINT-004 单设备更多操作菜单跳转

## [P1] 验证更多操作菜单七项跳转目标正确
- 测试类型
  - 功能
- 前置条件
  1. alice01名下P-001可见且在线。
- 测试步骤
  1. 点击P-001卡片右上角竖向三点打开操作面板。
  2. 依次点击Device Information、Real-Time Tracking、Track History、Device Alert History、IoT SIM Query、Send Command并逐一从列表重新进入验证。
- 预期结果
  1. 操作面板展示设备详情、实时追踪、历史轨迹、设备告警记录、物联网卡查询、发送指令、解除当前账户绑定七个菜单项。
  2. 每个菜单项分别进入当前设备对应的详情页、实时追踪页、历史轨迹页、告警记录页、物联网卡查询页、指令详情页，跳转目标与菜单语义一致。

## [P1] 验证所有跳转携带设备唯一标识
- 测试类型
  - 功能
- 前置条件
  1. P-001与P-002名称均为"牛群一号"，备注不同。
- 测试步骤
  1. 从P-001卡片更多菜单进入Device Information。
  2. 返回列表，从P-002卡片更多菜单进入Device Information。
  3. 对比两个详情页的Device ID。
- 预期结果
  1. P-001详情页Device ID为P-001的唯一标识。
  2. P-002详情页Device ID为P-002的唯一标识。
  3. 名称相同的两台设备不互相串页，身份以唯一标识为准，不以名称、备注或列表位置查询。

## [P2] 验证跳转前后设备名称变化仍指向原设备
- 测试类型
  - 功能
- 前置条件
  1. P-001当前备注为"改名前备注"。
- 测试步骤
  1. 在另一端将P-001备注修改为"改名后备注"。
  2. APP不刷新列表，直接从P-001卡片（仍显示旧名）更多菜单进入Real-Time Tracking。
- 预期结果
  1. 实时追踪页聚焦的仍是P-001唯一标识对应的设备。
  2. 页面设备身份不因名称在跳转前后变化而指向错误设备。

## [P2] 验证更多入口与卡片本体点击相互独立
- 测试类型
  - 易用性
- 前置条件
  1. 设备列表展示P-001。
- 测试步骤
  1. 点击P-001卡片右上角竖向三点。
  2. 观察是否触发设备详情跳转。
- 预期结果
  1. 仅打开当前设备的More操作面板。
  2. 不先触发设备详情跳转，两个点击区域相互独立。

## [P3][反向] 验证菜单项点击后只执行一次目标跳转
- 测试类型
  - 功能
- 前置条件
  1. 先从P-002更多菜单进入过一次IoT SIM Query后返回列表。
- 测试步骤
  1. 从P-001更多菜单点击IoT SIM Query。
  2. 快速连续点击该菜单项2次。
  3. 查看最终打开的页面与查询对象。
- 预期结果
  1. 操作面板关闭并执行一次跳转，进入P-001的物联网卡查询页。
  2. 不叠加打开两个页面，不重复入栈。
  3. 查询对象为P-001，不串到上一次操作的P-002。

## [P2] 验证离线与告警状态设备更多入口保留
- 测试类型
  - 功能
- 前置条件
  1. P-003离线、P-004未连接、P-005告警，均可见。
- 测试步骤
  1. 查看P-003、P-004、P-005卡片右上角更多入口。
  2. 点击P-003更多菜单任一项（如Device Information）。
- 预期结果
  1. 三种状态卡片均保留更多入口，不被长文本遮挡。
  2. 离线设备菜单跳转正常执行，不因通信状态隐藏入口。

## [P2] 验证从目标页返回不改变设备归属与状态
- 测试类型
  - 功能
- 前置条件
  1. P-001归属"天河区"分组，在线，无告警。
- 测试步骤
  1. 从P-001更多菜单依次进入实时追踪、历史轨迹、物联网卡查询后返回设备列表。
  2. 查看P-001的分组归属、在线状态、告警状态。
- 预期结果
  1. 沿设备模块已有导航状态正常返回列表。
  2. P-001仍归属"天河区"、仍在线、告警状态不变，查看扩展项不产生设备关系或状态副作用。
