# 用户故事

## [P1] 验证SENDING任务发起取消后乐观展示CANCEL
- 测试类型
  - 功能
- 前置条件
  1. CR任务CMD-20261015-050处于SENDING且尚未写出
  2. 账号qa_s10u_admin拥有取消权限
- 测试步骤
  1. 点击取消并确认操作
  2. 在网关返回结果前查看记录
- 预期结果
  1. APP立即将原记录乐观显示为CANCEL并隐藏取消入口
  2. 页面说明取消正在处理，不宣称平台已绝对确认不会写出

## [P1] 验证网关未写出且删除成功后确认取消
- 测试类型
  - 功能
- 前置条件
  1. ATT-20261015-050-A1已乐观显示CANCEL
  2. 网关确认任务未写出且队列删除成功
- 测试步骤
  1. 接收取消成功回调
  2. 查询记录、cancelResolution和队列
- 预期结果
  1. 状态维持CANCEL且cancelResolution为CONFIRMED
  2. 队列中不存在ATT-20261015-050-A1，未产生sentAt或TCP写出记录

## [P3][反向] 验证SENT和FAILURE任务不允许发起取消
- 测试类型
  - 功能
- 前置条件
  1. CMD-20261015-051状态为SENT，CMD-20261015-052状态为FAILURE
  2. 账号qa_s10u_admin打开两条记录
- 测试步骤
  1. 检查两条记录的可用操作
  2. 构造取消请求分别提交两个commandId
- 预期结果
  1. 两条记录均不展示取消入口
  2. 服务端拒绝取消且保持原状态，不新增CANCEL转换或取消副作用

## [P3][反向] 验证重复取消请求只执行一次队列删除
- 测试类型
  - 可靠性
- 前置条件
  1. ATT-20261015-053-A1处于SENDING且存在一个队列任务
  2. 客户端因网络抖动准备重复发送相同取消幂等请求
- 测试步骤
  1. 连续发送两次相同取消请求
  2. 网关返回两次相同确认回调后查询删除和通知计数
- 预期结果
  1. 两次请求关联同一次取消处理，状态保持CANCEL
  2. 队列删除、取消统计和用户通知均只发生一次，cancelResolution为CONFIRMED
