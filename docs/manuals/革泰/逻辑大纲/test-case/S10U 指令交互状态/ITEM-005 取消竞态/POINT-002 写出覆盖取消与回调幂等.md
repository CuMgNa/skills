# 用户故事

## [P1] 验证已写出事实将乐观CANCEL改写为SENT
- 测试类型
  - 功能
- 前置条件
  1. RESET任务CMD-20261015-054已乐观显示CANCEL
  2. 网关实际已通过绑定会话session-A完成TCP写出
- 测试步骤
  1. 接收ATT-20261015-054-A1写出成功回调
  2. 查看记录、cancelResolution和用户提醒
- 预期结果
  1. 状态由CANCEL改写为SENT，记录实际sentAt且cancelResolution为OVERRIDDEN_BY_SENT
  2. APP高优先级提示取消未生效，指令已下发，并说明设备仍可能执行

## [P3][反向] 验证迟到取消结果不能把SENT改回CANCEL
- 测试类型
  - 可靠性
- 前置条件
  1. CR任务CMD-20261015-055已由可靠写出回调进入SENT
  2. 取消成功回调随后迟到到达
- 测试步骤
  1. 投递迟到取消成功回调
  2. 查询状态、队列和统计
- 预期结果
  1. 状态仍为SENT且sentAt不变，cancelResolution不覆盖已写出事实
  2. 不新增CANCEL统计、不重复删除队列且不发送错误的取消成功通知

## [P3][反向] 验证重复写出和取消回调不产生重复副作用
- 测试类型
  - 可靠性
- 前置条件
  1. CMD-20261015-056当前为CANCEL且网关实际已写出
  2. 准备相同写出成功回调两次及迟到取消回调两次
- 测试步骤
  1. 按写出、取消、写出、取消顺序投递四个回调
  2. 查询最终记录、状态历史、通知和统计
- 预期结果
  1. 最终状态稳定为SENT且cancelResolution为OVERRIDDEN_BY_SENT，不发生状态反复
  2. 写出统计、覆盖通知和业务副作用各只发生一次

## [P3][反向] 验证关系失效与取消并发只结算一个最终结果
- 测试类型
  - 可靠性
- 前置条件
  1. ATT-20261015-057-A1处于SENDING
  2. 准备同时触发用户取消与设备关系失效事件
- 测试步骤
  1. 并发提交取消请求和关系失效事件
  2. 重复投递两类回调并查询记录
- 预期结果
  1. 最终记录只能稳定为CANCEL或FAILURE之一，不同时计入两个终态结果
  2. 队列删除、失败或取消通知和统计均按最终结果只执行一次
