# 用户故事

## [P1] 验证单设备普通指令提交成功仅反馈已受理
- 测试类型
  - 功能
- 前置条件
  1. S10U000001离线且CR校验均通过
  2. 账号qa_s10u_admin已登录
- 测试步骤
  1. 提交CR，使用CMD-20261015-040与ATT-20261015-040-A1
  2. 查看Toast与记录页
- 预期结果
  1. APP Toast明确反馈请求已受理或等待发送，不宣称设备已执行
  2. 记录页显示SENDING，sentAt和feedbackText均为空

## [P3][反向] 验证结果未知时APP不冒充提交成功或写出成功
- 测试类型
  - 可靠性
- 前置条件
  1. S10U000001具备合法CR提交条件
  2. 提交接口在服务端处理后响应链路超时
- 测试步骤
  1. 提交CR并触发客户端响应超时
  2. 查看Toast并按同一attemptId ATT-20261015-041-A1安全查询或重试
- 预期结果
  1. APP提示结果未知并提供可追踪处理，不显示已发送或设备已执行
  2. 后续查询或幂等重试复用ATT-20261015-041-A1，不创建重复任务

## [P3][反向] 验证前端置灰不能替代高危服务端复检
- 测试类型
  - 功能
- 前置条件
  1. 页面缓存显示S10U000001离线并将RESET按钮置灰
  2. 实际服务端当前会话已恢复为session-A
- 测试步骤
  1. 刷新当前会话状态后尝试RESET
  2. 提交CMD-20261015-042并观察服务端结果
- 预期结果
  1. 页面刷新后根据当前会话更新操作提示，不永久依赖旧快照
  2. 服务端实时复检session-A并独立裁决；满足其他条件时创建绑定session-A的SENDING任务

## [P3][反向] 验证绕过页面提交无会话高危请求仍失败
- 测试类型
  - 安全性
- 前置条件
  1. S10U000002无当前可写会话
  2. 攻击请求使用账号qa_s10u_admin的有效登录令牌
- 测试步骤
  1. 直接调用服务端提交RESET CMD-20261015-043
  2. 查询任务及失败审计
- 预期结果
  1. 服务端拒绝绕过前端的高危请求
  2. 创建FAILURE记录并保留无当前可写会话原因，不创建队列任务或TCP写出
