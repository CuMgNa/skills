# 用户故事

## [P1] 验证各失败类型保存可区分阶段原因和failedAt
- 测试类型
  - 功能
- 前置条件
  1. 准备七次可识别请求，分别触发关系失效、路由缺失、型号不支持、参数非法、环境白名单限制、高危无会话、系统异常
  2. 请求commandId为CMD-20261015-100至CMD-20261015-106
- 测试步骤
  1. 逐一提交七次请求
  2. 查询每条记录的状态、failureStage、failureReason、failedAt和sentAt
- 预期结果
  1. 七条记录均为FAILURE且不创建不应存在的写出任务
  2. 每条failureStage与failureReason对应真实失败点并可互相区分，failedAt非空且sentAt为空

## [P3][反向] 验证权限路由型号参数异常不统一伪装为离线
- 测试类型
  - 可维护性
- 前置条件
  1. 设备S10U000002页面通信状态为离线
  2. 准备权限失败、路由缺失、型号不支持、参数非法四个请求
- 测试步骤
  1. 分别提交四个请求
  2. 检查接口响应、记录页和日志中的失败文案
- 预期结果
  1. 四个请求均按真实校验阶段失败，离线状态不覆盖失败根因
  2. 接口、记录与日志至少可区分权限、路由、型号、参数四类原因，不统一显示设备离线

## [P1] 验证30天过期与高危会话失败可观测
- 测试类型
  - 功能
- 前置条件
  1. 普通CR任务ATT-20260914-001-A1已等待超过30天
  2. 高危RESET任务ATT-20261015-107-A1绑定session-A后发生会话替换
- 测试步骤
  1. 触发普通任务过期清理和高危会话变化处理
  2. 查询两条失败记录及队列
- 预期结果
  1. 普通任务FAILURE原因明确为待发超过30天，高危任务FAILURE原因明确为绑定会话变化
  2. 两条记录均有failedAt并完成出队，监控可按failureStage和failureReason分别统计

## [P3][反向] 验证未知系统异常保留系统失败而非虚构业务原因
- 测试类型
  - 可维护性
- 前置条件
  1. 服务端已创建CMD-20261015-108与ATT-20261015-108-A1
  2. 处理过程中发生可捕获的内部系统异常SYS-TRACE-108
- 测试步骤
  1. 触发异常并等待失败落库
  2. 查询记录和关联追踪日志
- 预期结果
  1. 记录进入FAILURE且failureStage指向服务端或系统处理阶段
  2. failureReason保留系统异常分类并关联SYS-TRACE-108，不改写为设备离线、无权限或参数错误

## [P2] 验证失败信息支持按command attempt和business链路追踪
- 测试类型
  - 可维护性
- 前置条件
  1. UPLOAD失败任务使用CMD-20261015-109、ATT-20261015-109-A1、BIZ-20261015-109-A1
  2. 网关返回明确系统失败
- 测试步骤
  1. 分别按三个标识检索日志与记录
  2. 比较检索结果的失败阶段和原因
- 预期结果
  1. 三个标识均可追踪到同一次发送尝试且映射关系一致
  2. 检索结果展示相同failureStage、failureReason和failedAt，不出现冲突归因
