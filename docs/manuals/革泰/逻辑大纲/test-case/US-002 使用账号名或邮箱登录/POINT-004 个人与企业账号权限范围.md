# US-002 使用账号名或邮箱登录

## POINT-004 个人与企业账号权限范围

## [P1] 验证四类账号均可通过统一登录入口登录
- 测试类型
  - 功能
- 前置条件
  1. 准备个人alice01、企业一级owner01、企业二级worker02、企业三级worker03，四个账号均状态正常且密码正确。
- 测试步骤
  1. 分别在同一登录入口使用四个账号登录。
  2. 每次登录完成设备加载后退出，再测试下一个账号。
- 预期结果
  1. 四个账号均通过账号或邮箱加密码校验。
  2. 四个账号均获得对应业务Token并进入设备加载流程。；不再执行旧版企业账号APP登录拦截。

## [P1] 验证企业一级账号设备范围和绑定入口
- 测试类型
  - 功能
- 前置条件
  1. owner01密码Owner1234，自己绑定E1-001，后台代绑E1-002，另有无权设备E2-001。
- 测试步骤
  1. 使用owner01登录。
  2. 进入设备列表并查看操作入口。
  3. 尝试访问E2-001。
- 预期结果
  1. 仅展示E1-001和E1-002。
  2. 展示绑定设备入口，不展示子账号管理和设备向下分配入口。
  3. 访问E2-001被服务端拒绝。

## [P1][反向] 验证企业二级和三级账号只能读取父级分配设备
- 测试类型
  - 功能
- 前置条件
  1. worker02分配E2-001，worker03分配E3-001，二者均不能直接绑定设备。
- 测试步骤
  1. 分别登录worker02和worker03。
  2. 查看设备列表和首页操作入口。
  3. 尝试构造绑定设备请求和访问越权设备。
- 预期结果
  1. worker02只看到E2-001，worker03只看到E3-001。
  2. 两个账号均不展示绑定设备入口、用户管理和向下分配入口。
  3. 越权绑定或越权访问请求均被服务端拒绝。

## [P3][反向] 验证账号层级判定不依赖本地缓存或界面选择
- 测试类型
  - 安全性
- 前置条件
  1. 本地曾缓存企业一级owner01的绑定入口，当前登录账号为worker02。
- 测试步骤
  1. 清理部分本地缓存后使用worker02登录。
  2. 通过调试方式修改本地账号类型字段为enterprise一级。
  3. 尝试打开绑定设备功能。
- 预期结果
  1. 服务端仍按worker02的真实账号层级下发权限。
  2. 本地字段修改不能使worker02获得企业一级权限。
  3. 绑定请求被拒绝并记录为无权操作。
