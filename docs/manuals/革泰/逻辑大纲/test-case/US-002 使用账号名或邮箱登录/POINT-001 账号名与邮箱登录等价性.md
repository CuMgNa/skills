# US-002 使用账号名或邮箱登录

## [P1] 验证个人账号使用账号名登录成功
[测试类型] 功能
[前置条件] 海外版个人账号 accountId=P1001，账号名 ranch_owner_01，邮箱 owner01@gmail.com，密码 Ranch#2026，状态正常，绑定设备 GT-S1-0001 和 GT-S1-0002
[测试步骤] 1. 打开海外版登录页，输入账号名 ranch_owner_01 和密码 Ranch#2026。2. 选择 GMT-7:00 Denver，勾选用户协议与隐私政策并点击 Sign In。3. 登录后查看当前账号资料、设备列表和业务 Token 对应身份
[预期结果] 1. 账号名和密码可正常录入，Sign In 满足启用条件。2. 服务端定位 accountId=P1001，签发该账号 Token 并进入设备加载流程。3. 当前账号为 P1001，仅显示 GT-S1-0001 和 GT-S1-0002，不混入其他账号数据

## [P1] 验证同一个人账号使用邮箱登录的数据范围与账号名登录一致
[测试类型] 功能
[前置条件] 海外版个人账号 accountId=P1001，账号名 ranch_owner_01，邮箱 owner01@gmail.com，密码 Ranch#2026，状态正常；已记录使用账号名登录时的 Token 主体、设备、围栏和告警清单
[测试步骤] 1. 退出账号名登录会话并确认业务页面缓存已清理。2. 输入邮箱 owner01@gmail.com、密码 Ranch#2026，选择 GMT-7:00 Denver，勾选协议后登录。3. 对比两种登录标识下的 accountId、设备、围栏、告警和可操作权限
[预期结果] 1. 原会话结束且不再展示 P1001 的旧页面数据。2. 邮箱解析到同一 accountId=P1001，并重新签发 P1001 的 Token。3. 两种登录方式的账号身份、设备、围栏、告警和权限完全一致

## [P1] 验证企业账号使用账号名和邮箱均登录到同一企业身份
[测试类型] 功能
[前置条件] 企业一级账号 accountId=E1101，账号名 corp_ranch_admin，邮箱 admin@northfarm.com.au，密码 Corp#Login2026，tenantId=T-AU-01，状态正常，具备设备 GT-S1-1101 和 GT-S1-1102
[测试步骤] 1. 使用账号名 corp_ranch_admin 登录海外版并记录 Token 中的 accountId、tenantId 与设备清单。2. 退出后使用邮箱 admin@northfarm.com.au 和同一密码再次登录。3. 对比两次登录后的企业身份、设备范围和绑定入口
[预期结果] 1. 第一次登录定位 E1101 和 T-AU-01，显示两台授权设备及绑定入口。2. 第二次登录仍定位 E1101 和 T-AU-01，不新建或误命中其他账号。3. 两次登录的权限与设备范围一致，均不因登录标识变化而扩权或降权

## [P3][反向] 验证不存在的账号名和未注册邮箱均返回通用登录失败
[测试类型] 安全性
[前置条件] 海外版不存在账号名 unknown_ranch_2026，邮箱 nobody2026@proton.me 未绑定任何账号，密码 Guess#2026
[测试步骤] 1. 使用 unknown_ranch_2026 和 Guess#2026 提交登录。2. 使用 nobody2026@proton.me 和 Guess#2026 提交登录。3. 对比两次失败响应、页面提示和输入保留情况
[预期结果] 1. 不签发 Token，停留登录页；提示按产品最终定稿文案（当前断言为通用登录失败）。2. 不签发 Token，停留登录页；提示按产品最终定稿文案（当前断言为通用登录失败）。3. 两次响应不泄露账号是否存在或账号类型，登录标识均保留；文案核对位置为登录页 UI 定稿及登录接口错误码映射

[测试类型] 兼容性
[前置条件] 国内版注册个人账号 accountId=P2001，手机号 13800138000，自动账号名 user13800138000，邮箱为空，密码 China#2026，状态正常

## [P2] 验证海外版统一输入框无需选择个人或企业类型
[测试类型] 易用性
[前置条件] 个人账号 ranch_owner_01 与企业账号 corp_ranch_admin 均状态正常且密码有效
[测试步骤] 1. 打开海外版登录页并检查登录表单。2. 分别使用 ranch_owner_01 和 corp_ranch_admin 完成登录。3. 观察登录过程是否要求用户选择账号类型
[预期结果] 1. 页面仅提供账号名或邮箱统一输入框、密码、时区、协议和记住密码等控件，不出现个人或企业类型选择。2. 两个账号均由服务端根据唯一登录标识定位并进入各自账号。3. 用户无需了解账号层级即可登录，客户端不依据本地类型选择判断身份
