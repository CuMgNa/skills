# US-017 管理账户内设备分组

## POINT-003 分组新增与重命名

## [P1] 验证新增一级分组成功
- 测试类型
  - 功能
- 前置条件
  1. alice01在分组管理页，当前无同名"牧场新区"分组。
- 测试步骤
  1. 点击「＋」打开新增弹窗。
  2. 输入"牧场新区"并保存。
- 预期结果
  1. 弹窗展示Group name (1–40 characters)范围提示。
  2. 保存成功，关闭弹窗并刷新分组数据，列表出现一级组"牧场新区"。

## [P4] 验证分组名称长度边界值
- 测试类型
  - 功能
- 前置条件
  1. 海外版APP（本大纲主口径1～40字符）。
  2. 准备1字符"a"、40字符、41字符三组名称。
- 测试步骤
  1. 新增分组输入"a"保存。
  2. 重命名某组输入40字符名称保存。
  3. 新增分组输入41字符名称保存。
- 预期结果
  1. 1字符边界保存成功。
  2. 40字符上点保存成功。
  3. 41字符离点被禁止并提示当前版本长度要求，不静默截断。

## [P5] 验证国内版分组名称长度边界
- 测试类型
  - 兼容性
- 前置条件
  1. 国内版APP（1～15字符）。
  2. 准备15字符与16字符名称。
- 测试步骤
  1. 新增分组输入15字符名称保存。
  2. 输入16字符名称保存。
- 预期结果
  1. 15字符上点保存成功。
  2. 16字符离点被禁止，弹窗展示1–15字符范围提示；上限由产品构建确定，不随界面语言动态变化。

## [P3][反向] 验证空名称与纯空格名称禁止保存
- 测试类型
  - 功能
- 前置条件
  1. alice01在新增/重命名弹窗。
- 测试步骤
  1. 新增分组名称留空直接保存。
  2. 输入4个空格保存。
  3. 重命名时输入纯空格保存。
- 预期结果
  1. 空字符串禁止保存。
  2. 纯空格名称禁止保存。
  3. 两种场景均提示补全，不创建无名分组。

## [P3][反向] 验证同账户跨层级全局判重
- 测试类型
  - 功能
- 前置条件
  1. alice01名下已有：一级"广东省"、二级"广州市"（属广东省）。
- 测试步骤
  1. 新增一级组输入"广州市"保存。
  2. 新增一级组输入"广州市 "（尾部1空格）保存。
  3. 新增一级组输入"广州market"（部分相同）保存。
- 预期结果
  1. 与二级组"广州市"完全同名，全局判重命中，禁止保存并提示分组名称已存在。
  2. 尾部空格参与比较，"广州市 "与"广州市"视为不同名称，保存成功。
  3. 部分相同名称保存成功，判重为完全精确匹配。

## [P2] 验证重命名未变化不误判重名
- 测试类型
  - 功能
- 前置条件
  1. alice01要将一级组"广东省"重命名。
- 测试步骤
  1. 打开重命名弹窗，不修改名称直接保存。
  2. 将名称改为"广东省"（与自身相同）保存。
- 预期结果
  1. 名称未变化时不把当前分组自身误判为重名。
  2. 保存成功（或按服务端实际行为记录），不提示"分组名称已存在"。

## [P2] 验证重命名不影响结构与归属
- 测试类型
  - 功能
- 前置条件
  1. "广东省"（一级）下有二级"广州市"、直属设备P-201。
- 测试步骤
  1. 将"广东省"重命名为"广东"。
  2. 查看分组结构、P-201归属与子组父组名称展示。
- 预期结果
  1. 只更新名称，分组ID、层级、父子关系、设备归属不变。
  2. "广州市"的父组名称展示同步更新为"广东"，存在直属设备或子组仍允许改名。

## [P3][反向] 验证保存失败保留输入并展示原因
- 测试类型
  - 可靠性
- 前置条件
  1. 使用mock使分组保存接口返回失败。
- 测试步骤
  1. 新增分组输入"测试失败组"提交。
  2. 查看弹窗状态。
- 预期结果
  1. 保存失败。
  2. 保留用户输入并展示服务端原因，不白屏不丢输入。
