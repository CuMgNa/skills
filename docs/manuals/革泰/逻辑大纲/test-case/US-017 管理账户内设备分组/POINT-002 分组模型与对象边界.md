# US-017 管理账户内设备分组

## POINT-002 分组模型与对象边界

## [P1] 验证三级父子体系分组结构展示
- 测试类型
  - 功能
- 前置条件
  1. alice01名下结构：广东省（一级）→ 广州市（二级）→ 天河区（三级）、深圳市（二级，属广东省）、浙江省（一级）。
- 测试步骤
  1. 打开Select Group查看列表结构。
  2. 查看各分组的Level与父组信息展示。
- 预期结果
  1. 平铺顺序为：广东省L1、广州市L2（属于：广东省）、天河区L3（属于：广州市）、深圳市L2（属于：广东省）、浙江省L1。
  2. 二、三级展示直接父组，一级不展示父组，业务数据保留层级与唯一标识。

## [P1] 验证虚拟全部分组固定置顶不可操作
- 测试类型
  - 功能
- 前置条件
  1. alice01可见设备总数为8台（含多关系去重后）。
- 测试步骤
  1. 打开Select Group查看首项。
  2. 尝试对"全部分组"进行重命名、删除。
- 预期结果
  1. "全部分组（8）"固定置顶，无Level标签，括号为账户全部可见设备去重数。
  2. 虚拟项不可增删改，不进入分组管理页。

## [P2] 验证我的分组为普通一级组可改名可删除
- 测试类型
  - 功能
- 前置条件
  1. alice01账号初始化自动创建"我的分组"（空组）。
- 测试步骤
  1. 在管理页重命名"我的分组"为"默认牧场"。
  2. 将其删除（空组满足删除条件）。
  3. 删除后再次新增名为"我的分组"的一级组。
- 预期结果
  1. 改名成功，分组ID、设备归属、子组关系不变。
  2. 空组删除成功，账户处于零业务分组状态，不自动重建。
  3. "我的分组"名称已释放，允许再次创建。

## [P3][反向] 验证设备必须归属真实分组不存在未分组
- 测试类型
  - 功能
- 前置条件
  1. alice01名下设备P-201当前归属"天河区"。
- 测试步骤
  1. 进入设备详情编辑页尝试清空Group字段保存。
  2. 查看设备列表与分组体系中的"未分组"入口。
- 预期结果
  1. 分组为空时保存被拦截，提示补全。
  2. 系统不存在"未分组"视图或归属状态，绑定和资料保存时分组不能为空。

## [P2] 验证分组按账户隔离
- 测试类型
  - 功能
- 前置条件
  1. alice01与bob02均可见设备P-202（双绑）。
  2. alice01将P-202归"广东省"，bob02归"浙江牧场"。
- 测试步骤
  1. alice01将P-202改组为"浙江省"并保存。
  2. 登录bob02查看P-202分组。
- 预期结果
  1. alice01侧改组成功。
  2. bob02侧P-202仍属"浙江牧场"，同一物理设备在不同账户下分组独立，一方改组不影响另一方。

## [P2] 验证同名真实一级组与虚拟项共存区分
- 测试类型
  - 功能
- 前置条件
  1. alice01创建了名为"全部分组"的真实一级组（直属设备2台）。
- 测试步骤
  1. 打开Select Group查看列表。
  2. 分别点击虚拟"全部分组"与真实"全部分组"。
- 预期结果
  1. 虚拟"全部分组（8）"固定置顶无Level；真实"全部分组（2）"按业务排序展示并标记Level 1。
  2. 虚拟项查询账户全部设备，真实项只查询直属2台，两者可区分不混淆。

## [P2] 验证APP仅能新增一级分组

## [P5] 验证仅分配设备自动复用或创建我的分组
- 测试类型
  - 功能
- 前置条件
  1. 一级owner01执行「仅分配设备」将P-210分配给二级worker02。
  2. worker02名下无名为"我的分组"的真实分组。
- 测试步骤
  1. owner01在Web执行仅分配设备将P-210分配给worker02。
  2. 登录worker02查看分组与设备。
- 预期结果
  1. worker02名下自动创建普通一级"我的分组"，P-210进入该组，原分组保留。
  2. 若目标账号已存在"我的分组"（如worker11）则直接复用，新设备进入该组。

## [P3][反向] 验证同步分组和设备全量覆盖二级分组
- 测试类型
  - 功能
- 前置条件
  1. worker02名下原有分组"旧A组""旧B组"并各有设备。
  2. owner01在Web执行「同步分组和设备」。
- 测试步骤
  1. owner01执行同步分组和设备。
  2. 登录worker02查看分组结构。
- 预期结果
  1. worker02原有分组被全量覆盖。
  2. 分组结构变为owner01同步的结构，属高破坏性操作，执行前需确认业务可接受。
