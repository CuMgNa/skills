# US-016 绑定牛马定位器

## POINT-003 绑定槽位双绑与配额

## [P1] 验证个人与企业一级双绑同一设备共存
- 测试类型
  - 功能
- 前置条件
  1. 个人账号alice01已绑定P-110。
  2. 企业一级账号owner01有剩余配额，P-110企业一级槽位空闲。
- 测试步骤
  1. owner01发起绑定P-110。
  2. 分别查看alice01与owner01的设备列表。
- 预期结果
  1. owner01绑定成功，已有个人绑定不单独阻断新的企业一级绑定。
  2. alice01与owner01均可见P-110，两个账户读取同一份位置、电量、运行状态事实。

## [P3][反向] 验证设备已有企业一级绑定时个人绑定不被阻断
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号owner01已绑定P-111。
  2. 个人账号alice01配额充足。
- 测试步骤
  1. alice01发起绑定P-111。
  2. 查看绑定结果。
- 预期结果
  1. alice01绑定成功，不以已有企业一级绑定为拒绝理由。
  2. 个人+企业一级各1个绑定共存，双绑成立。

## [P1] 验证同一设备一级分配多个二级不占绑定名额
- 测试类型
  - 功能
- 前置条件
  1. owner01绑定P-112后，已在Web将P-112分配给worker02、worker03两个二级。
- 测试步骤
  1. 分别登录worker02、worker03的APP查看设备列表。
  2. 查看P-112的绑定关系与个人/企业槽位占用。
- 预期结果
  1. 两个二级账号均可见P-112，各账号列表按设备唯一标识去重。
  2. worker02、worker03获得的是分配关系，不占用"1个个人+1个企业一级"直接绑定槽位，不产生直接绑定记录。

## [P2] 验证企业一级绑定配额随服务端配置
- 测试类型
  - 配置
- 前置条件
  1. 服务端当前配置owner01可绑定设备上限为5台，已绑定4台。
  2. P-113已入库牛马定位器且槽位空闲。
- 测试步骤
  1. owner01绑定P-113（第5台）。
  2. 再绑定P-114（第6台）。
  3. 管理端将上限调整为10台后再次绑定P-114。
- 预期结果
  1. 第5台绑定成功。
  2. 第6台被拦截，提示数量已达上限。
  3. 上限调整后P-114绑定成功，APP不写死配额上限，读取服务端当前配置。

## [P2] 验证重复请求不产生多条绑定关系
- 测试类型
  - 可靠性
- 前置条件
  1. alice01配额充足，P-115已入库牛马定位器。
- 测试步骤
  1. alice01在绑定确认页快速连续点击确认按钮3次。
  2. 弱网环境下重试同一绑定请求。
  3. 查看设备列表与绑定关系。
- 预期结果
  1. 网络重试、重复点击或重复请求均只产生一条绑定关系。
  2. 设备列表P-115仅一条记录。
  3. 配额只扣减一次，无重复副作用。

## [P5] 验证解绑后重新绑定分组围栏按原规则重建
- 测试类型
  - 功能
- 前置条件
  1. alice01曾绑定P-116并配置围栏，已解绑（原分组与围栏关联被清除）。
- 测试步骤
  1. alice01重新绑定P-116并选择分组。
  2. 查看原围栏关联与判定基线。
- 预期结果
  1. 重新绑定成功，分组关系重新建立。
  2. 原围栏关联不自动恢复，需重新关联；下一条有效定位只建立基线，不报警。
