- 业务真源：`docs/manuals/革泰/逻辑大纲/革泰 APP 指令单设备与批量下发逻辑点梳理 plan.md` v2.1-draft（2026-10-10）。

- 核心口径：普通五类允许离线受理；高危两类绑定提交时当前 S10U 可写会话；批量逐设备产生结果并保持数量守恒。

## Markdown v0.3 格式

每个 POINT 文件遵循固定树结构：

```text
# 用户故事：US-xxx ... - POINT-xxx ...
## [P1][可选反向标记] 验证……
- 测试类型
  - 12 种枚举之一
- 前置条件
  1. 具体条件
- 测试步骤
  1. 具体步骤
- 预期结果
  1. 与步骤一一对应的可验证结果
```

强制规则：

1. 用例标题必须包含 P1～P5，标题正文以“验证”开头；反向用例使用 `[反向]`。
2. 每条用例恰好包含测试类型、前置条件、测试步骤、预期结果四个同级字段。
3. 字段内容缩进两个空格；步骤和预期均从 1 连续编号且数量相等。
4. 测试类型只能取：功能、兼容性、易用性、性能、稳定性、安全性、可靠性、效果（AI类、资源类）、效果（硬件器件类）、可维护性、可移植性、埋点。
5. 测试数据必须具体，不使用占位符、TODO 或“同上”。
6. `all_cases.md` 层级固定为：一级用户故事 → 二级 POINT → 三级用例 → 四字段及内容。

## 执行提示

1. 先阅读 `plan.md` 的待确认项；未确认内容不得写死为执行通过标准。
2. 设备身份、权限和队列核对应使用稳定 `deviceId`、operationId、commandId、attemptId、businessId 和 configSequence。
3. 普通五类不得因离线或未连接被拒绝；缺路由、型号不支持、参数非法和关系失效不能伪装成普通离线排队。
4. 高危两类必须抓取提交时 S10U 当前可写会话证据，并验证绑定会话断开或变化后任务失败出队。
5. 批量执行必须核对最终去重设备全集、逐设备明细以及 `目标数 = submitted + failedToSubmit`。
6. 容量用例中的 100 台上限和 50 台分片是测试环境具体配置，执行前必须与最新服务端契约核对；配置变化时应更新数据，而非沿用旧结论。
7. `SENT` 只表示 TCP 写出，设备业务动作是否成功必须通过独立业务回文或专项验证。
8. Location Interval 页面级回归继续执行设备管理 US-018 POINT-019～026，本目录不重复维护。
