# 远程指令专项测试计划与 POINT 映射

## 1. 计划目标

本专项验证革泰 APP 单设备与批量指令下发从入口、设备选择、指令与参数选择、服务端受理、S10U 当前会话复检到即时反馈的完整链路，并覆盖普通队列、高危会话绑定、数量守恒、任务顺序、幂等与竞态红线。

覆盖用户故事：

- US-020「选择参数并向单设备发送指令」；
- US-021「批量下发并确认高风险指令」；
- US-022「查看指令状态、补发和覆盖结果」中与本次提交、队列、重发及配置顺序直接相关的边界。

## 2. 规则依据与优先级

1. 业务真源：`docs/manuals/革泰/逻辑大纲/革泰 APP 指令单设备与批量下发逻辑点梳理 plan.md` v2.1-draft（2026-10-10）。
2. 同步基线：S10U 指令交互状态、指令记录、设备管理和我的模块最新逻辑大纲。
3. 用户故事编号来源：`docs/manuals/革泰/革泰 APP 产品需求文档.md`；旧 PRD 仅用于编号和历史追溯，不覆盖最新业务规则。
4. 格式规则：`testcase-generator` Markdown v0.3 层级列表规范。
5. 冲突时按“本专项最新大纲 > 同步专项大纲 > 当前正式用例公共基线 > 旧 PRD / 旧测试计划 / PN06 参考”的顺序处理。

## 3. 核心业务口径

1. 革泰指令实际通过 S10U 独立服务及网关下发，PN06 仅作普通队列式交互参考。
2. `CR/VERNO/FIND/UPLOAD/ZONE` 为普通队列类，设备在线、离线、未连接均可提交。
3. `RESET/POWEROFF` 为高危会话绑定类，提交时必须存在当前可写 S10U 会话。
4. 高危任务绑定提交时会话，绑定会话断开或变化后立即 `FAILURE` 并出队，新会话不得执行旧任务。
5. 页面在线状态只是快照，不能替代服务端权限、关系、路由、型号、参数和当前会话复检。
6. 批量允许选择所有通信状态设备，高危指令不在确认前静默剔除离线设备，最终由服务端逐台复检。
7. 批量部分失败时有效设备继续受理，不做整批回滚，每个最终目标设备必须有明细。
8. `SENT` 只表示 TCP 写出，不表示设备业务动作成功。
9. 网络安全重试复用原 attempt；用户主动重发保留 commandId 并新建 attempt。
10. `UPLOAD/ZONE` 已受理任务全部保留，同设备同配置项按 `configSequence` 顺序执行，旧回文不得覆盖最新目标。

## 4. 测试范围

### 4.1 US-020 单设备指令下发

- 指令页初始化、稳定 `deviceId` 和页面目标锁定；
- 七类指令目录、普通与高危分类；
- 普通五类在线、离线、未连接受理；
- UPLOAD 预设、自定义边界和分钟转秒；
- ZONE 动态枚举、必选和 APP 展示时区隔离；
- 高危指令实时会话复检、绑定与会话变化；
- 权限、关系、路由、型号、参数和服务端兜底；
- 确认、取消、蒙层、成功与明确失败反馈；
- 网络超时结果未知、恢复核验和记录入口。

### 4.2 US-021 批量指令下发

- 多选模式、混合状态设备选择和批量单选语义；
- 状态、分组、关键词变化后的选择清空；
- 全选当前交集、取消全选和 `deviceId` 去重；
- 普通指令逐设备校验和部分失败；
- 高危指令逐台当前会话复检；
- 确认面板、二次确认和防误触；
- 全部受理、部分受理、全部失败三状态结果；
- submitted / failedToSubmit 及四态数量守恒；
- 批量记录 L1 跳转、Done 与关闭按钮一致性；
- 测试环境 100 台单批上限、50 台分片的边界、超限、分片和安全恢复。

### 4.3 US-022 任务状态、补发和覆盖

- 普通队列与高危会话绑定生命周期；
- 普通任务 30 天边界、过期清理和业务状态最终一致；
- `confirmedValue/desiredValue/processingValue` 分层；
- UPLOAD 与 ZONE 多任务保留、顺序和跨入口统一序列；
- 解绑、回收、改绑和失权后的未写出任务清理；
- 写出、断线、取消与关系失效竞态的唯一终态；
- operationId、commandId、attemptId、businessId、幂等键层级；
- 普通与高危用户主动重发差异。

## 5. 不覆盖与执行前待确认

以下内容不写死为当前验收通过标准：

1. 服务到期时的新提交和排队任务处理。
2. 高危任务在同一会话持续在线时的最大有效时间和起算点。
3. UPLOAD/ZONE 在 `SENT` 后还是收到业务回文后推进下一条。
4. 前一配置任务 `FAILURE/CANCEL` 后的具体推进时机。
5. 单次上行允许连续写出的配置指令数量。
6. 生产单批上限、分片大小、并发数和限流码；本用例中的 100/50 仅为可执行的测试环境配置。
7. CR/FIND 长期排队任务的取消能力与独立有效期。
8. Toast、图标、颜色、按钮和中英文逐字文案。
9. 完整指令记录页面的信息架构、筛选、分页和历史保留周期。
10. 设备业务回文解析、补偿、对账和协议编码实现。

## 8. 复用与去重策略

1. 设备列表入口、稳定 `deviceId`、返回列表上下文复用设备管理 US-015/US-020 公共基线，本专项只补指令页目标锁定和提交闭环。
2. Location Interval 已在设备管理 US-018 的 POINT-019～026 中形成 35 条核心用例，本目录不复制页面级用例，只验证各入口共用 UPLOAD 顺序体系。
3. 单设备记录入口权限复用设备管理 US-022 现有基线，本专项只补结果未知、任务状态、重发和覆盖边界。
4. RESET 与 POWEROFF 共用高危会话安全模型，分别保留代表性准入场景，不复制两套完整生命周期。
5. 解绑、企业回收、改绑、上级关系失效和账号失权按“关系失效”统一建模，同时保留关键不同副作用场景。
6. `all_cases.md` 只做结构化汇总，不增加新用例。

## 9. 冲突旧规则治理

以下旧规则不进入本用例集：

1. 七类指令统一要求在线。
2. 批量离线设备不可选择或被跳过且不建记录。
3. 批量关机长按 1 秒确认。
4. 批量结果仅分成功、拒绝、跳过。
5. 批量记录跳转携带 batchId 锁定本批次。
6. `QUEUED/COMPLETED/REJECTED/CANCELLED/EXPIRED` 作为 APP 状态。
7. `ACKED/TIMEOUT` 作为 APP 发送状态。
8. 配置新值覆盖并取消旧待发任务。
9. 我的模块统一展示所有单设备和批量指令记录。

现有旧文件本次不物理删除，详细原因和影响见 `quality-report.md`。
