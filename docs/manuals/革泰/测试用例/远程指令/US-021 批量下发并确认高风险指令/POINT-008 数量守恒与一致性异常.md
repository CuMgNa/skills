# 用户故事：US-021 批量下发并确认高风险指令 - POINT-008 数量守恒与一致性异常

## [P1] 验证最终去重数量等于批次设备明细数量
- 测试类型
  - 可靠性
- 前置条件
  1. 验证原始选择序列为GT-D001、GT-D001、GT-D002、GT-D003
  2. 验证4个原始条目对应3个唯一Device ID
- 测试步骤
  1. 提交普通指令CR
  2. 查询最终目标数量和批次设备明细数量
- 预期结果
  1. 服务端最终去重目标数量为3
  2. 批次设备明细数量为3，GT-D001、GT-D002、GT-D003各出现一次

## [P1] 验证提交阶段受理数与失败数保持数量守恒
- 测试类型
  - 可靠性
- 前置条件
  1. 验证RESET批次包含GT-D001、GT-D004、GT-D002、GT-D005、GT-D006、GT-D007共6台唯一设备
  2. 验证前2台有效，后4台分别存在会话、路由、型号和关系失败
- 测试步骤
  1. 完成RESET最终提交
  2. 汇总submitted、failedToSubmit和失败类别数量
- 预期结果
  1. submitted为2且failedToSubmit为4，最终目标数量6等于2加4
  2. 会话、路由、型号和关系失败各为1，全部失败分类之和为4

## [P1] 验证生命周期状态数量之和等于批次明细总数
- 测试类型
  - 可靠性
- 前置条件
  1. 验证BATCH-008-03包含GT-D001、GT-D002、GT-D003、GT-D004共4条明细
  2. 验证4条明细当前状态依次为SENDING、SENT、FAILURE、CANCEL
- 测试步骤
  1. 查询BATCH-008-03的设备明细总数
  2. 分别统计SENDING、SENT、FAILURE和CANCEL数量
- 预期结果
  1. 批次设备明细总数为4
  2. 4种状态数量均为1且总和为4，同一设备不存在两个互斥终态

## [P3][反向] 验证明细数量少于最终目标数量时判定一致性异常
- 测试类型
  - 可靠性
- 前置条件
  1. 验证最终目标为GT-D001、GT-D002、GT-D003、GT-D004、GT-D005共5台
  2. 验证模拟批次查询仅返回GT-D001至GT-D004共4条明细
- 测试步骤
  1. 执行批次数量核对
  2. 查看批次完成标记、服务日志和一致性监控记录
- 预期结果
  1. 核对结果明确为异常，最终目标数量5不等于明细数量4，不得判定批次完整成功
  2. 缺失的GT-D005可被追踪并产生可观测异常记录，不得静默忽略

## [P3][反向] 验证弹窗统计与服务端最终去重统计不一致时不得采用前端数量
- 测试类型
  - 可靠性
- 前置条件
  1. 验证前端原始勾选数为6，其中GT-D001重复出现一次
  2. 验证服务端最终去重统计为目标5台、submitted为3、failedToSubmit为2
- 测试步骤
  1. 完成提交并打开结果弹窗
  2. 对比弹窗数量、服务端统计和前端原始勾选数
- 预期结果
  1. 弹窗显示3 of 5 devices submitted和2 devices failed to submit
  2. 弹窗不得使用前端原始勾选数6，且5等于3加2
