# 用户故事：US-021 批量下发并确认高风险指令 - POINT-004 普通指令批量逐设备校验

## [P1] 验证混合状态设备提交普通指令全部受理
- 测试类型
  - 功能
- 前置条件
  1. 验证GT-D001在线、GT-D002离线、GT-D003未连接、GT-D004在线且告警
  2. 验证4台设备的关系、路由和型号均支持CR
- 测试步骤
  1. 选择4台设备并提交普通指令CR
  2. 查询批次统计和逐设备状态
- 预期结果
  1. 服务端不以在线状态作为CR提交条件，统计为4台submitted和0台failedToSubmit
  2. 4台设备均建立SENDING明细，离线或未连接设备进入普通队列等待后续通信

## [P3][反向] 验证普通指令部分设备失败时有效设备继续受理
- 测试类型
  - 功能
- 前置条件
  1. 验证已选GT-D001、GT-D002、GT-D005、GT-D006、GT-D007
  2. 验证GT-D005缺少路由、GT-D006型号不支持CR、GT-D007在提交前关系失效
- 测试步骤
  1. 提交普通指令CR
  2. 查询5台设备的状态、失败阶段和失败原因
- 预期结果
  1. GT-D001和GT-D002进入SENDING，3台无效设备分别因路由、型号和关系校验失败进入FAILURE
  2. 结果为2台submitted和3台failedToSubmit，不回滚有效设备且5台设备均有明细

## [P3][反向] 验证普通指令全部设备校验失败
- 测试类型
  - 功能
- 前置条件
  1. 验证已选GT-D005、GT-D006、GT-D007
  2. 验证3台设备分别存在路由缺失、型号不支持和关系失效问题
- 测试步骤
  1. 提交普通指令CR
  2. 查询结果弹窗、批次明细和普通队列
- 预期结果
  1. 结果为0台submitted和3台failedToSubmit，弹窗显示Submission Failed
  2. 建立批次及3条FAILURE明细，普通队列中不存在这3台设备的新任务

## [P3][反向] 验证普通指令不因页面状态未知而直接拒绝
- 测试类型
  - 可靠性
- 前置条件
  1. 验证GT-D011的页面在线状态查询超时并显示状态未知
  2. 验证GT-D011设备关系、Device ID、S10U路由和型号均有效
- 测试步骤
  1. 选择GT-D011并提交普通指令VERNO
  2. 查询受理结果和普通队列
- 预期结果
  1. 服务端不因在线状态未知拒绝VERNO，GT-D011建立SENDING明细
  2. 任务进入普通队列，记录中不得把状态服务异常写成路由失败或设备关系失败
