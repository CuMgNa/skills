# 用户故事：US-022 查看指令状态、补发和覆盖结果 - POINT-005 关系失效与写出前复检

## [P1] 验证设备解绑后普通未写出任务失败并出队
- 测试类型
  - 安全性
- 前置条件
  1. 账号GT-P-2205与设备GT-D-220501当前绑定有效
  2. 设备存在普通CR任务CMD-2205-001，状态为SENDING且尚未写出
- 测试步骤
  1. 解除GT-P-2205与GT-D-220501的绑定关系
  2. 查询CMD-2205-001的状态、队列和失败信息
  3. 使GT-D-220501重新上线并查询TCP写出日志
- 预期结果
  1. 解绑事件触发未写出任务清理
  2. CMD-2205-001转为FAILURE并从普通队列移除，失败阶段和原因明确表示关系失效
  3. 设备重新上线后不写出CMD-2205-001

## [P1] 验证企业回收后高危未写出任务失败并出队
- 测试类型
  - 安全性
- 前置条件
  1. 企业二级账号GT-E2-2205经分配关系控制设备GT-D-220502
  2. 设备存在绑定SESSION-220502-A的RESET任务CMD-2205-002，状态为SENDING且尚未写出
- 测试步骤
  1. 由企业一级账号回收GT-D-220502的分配关系
  2. 查询CMD-2205-002的状态、绑定会话和高危队列
- 预期结果
  1. 回收后GT-E2-2205失去设备控制关系
  2. CMD-2205-002转为FAILURE并从高危队列移除，不因SESSION-220502-A仍可写而继续发送

## [P3][反向] 验证设备改绑新账号后不执行旧账号创建的未写出任务
- 测试类型
  - 安全性
- 前置条件
  1. 旧账号GT-P-2205-A为设备GT-D-220503创建ZONE任务CMD-2205-003，参数UTC+08:00且尚未写出
  2. 设备随后解绑并改绑到新账号GT-P-2205-B
- 测试步骤
  1. 完成改绑并使GT-D-220503建立新会话SESSION-220503-B
  2. 触发设备通信并查询旧任务状态及TCP写出日志
  3. 使用GT-P-2205-B查询自身可见的设备指令记录
- 预期结果
  1. 新会话不继承旧关系下创建的CMD-2205-003
  2. CMD-2205-003保持FAILURE且无TCP写出记录
  3. 新账号看不到旧账号的CMD-2205-003，记录归属不因设备改绑转移

## [P1] 验证写出前关系版本复检阻止已失效任务

## [P3][反向] 验证重复关系失效事件不会重复变更和累计
- 测试类型
  - 可靠性
- 前置条件
  1. CMD-2205-006已因设备回收转为FAILURE并完成出队
  2. 首次关系事件标识为REL-EVT-2205-006，失败统计已累计1次
- 测试步骤
  1. 再次投递REL-EVT-2205-006
  2. 另投递同一关系版本的重复事件REL-EVT-2205-006-DUP
  3. 查询任务状态、队列、失败统计和通知记录
- 预期结果
  1. 相同事件被幂等识别，不重复执行状态迁移
  2. 同一失效事实的重复事件不会重建队列任务或生成第二条用户可见记录
  3. CMD-2205-006保持单一FAILURE，失败统计只累计一次且用户通知最多一次
