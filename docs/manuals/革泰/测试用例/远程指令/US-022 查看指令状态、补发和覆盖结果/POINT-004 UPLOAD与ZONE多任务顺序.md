# 用户故事：US-022 查看指令状态、补发和覆盖结果 - POINT-004 UPLOAD与ZONE多任务顺序

## [P1] 验证同设备连续UPLOAD任务全部保留并按提交序编号
- 测试类型
  - 功能
- 前置条件
  1. 设备GT-D-220401支持UPLOAD且当前离线，关系和S10U路由有效
  2. 当前设备UPLOAD序列为空
- 测试步骤
  1. 依次提交UPLOAD 600秒、3600秒、60秒，对应operationId为OP-2204-001-A、OP-2204-001-B、OP-2204-001-C
  2. 查询三条任务的commandId、参数、configSequence和队列顺序
- 预期结果
  1. 三次提交均各自受理为独立任务，不用最后一条覆盖或删除前两条
  2. 三条任务参数依次为600秒、3600秒、60秒且configSequence严格递增，队列顺序与提交顺序一致

## [P1] 验证同设备连续ZONE任务全部保留并按提交序编号
- 测试类型
  - 功能
- 前置条件
  1. 设备GT-D-220402支持ZONE，服务端当前返回可选值UTC+08:00、UTC+09:00、UTC-05:00
  2. 当前设备ZONE序列为空
- 测试步骤
  1. 依次提交ZONE UTC+08:00、UTC+09:00、UTC-05:00
  2. 查询三条任务的参数、configSequence和审计记录
- 预期结果
  1. 三条ZONE任务均被独立保留，不合并为一条UTC-05:00任务
  2. ZONE序列按UTC+08:00、UTC+09:00、UTC-05:00的提交顺序递增，每条任务均有独立审计记录

## [P2] 验证UPLOAD与ZONE使用独立顺序体系且互不覆盖
- 测试类型
  - 功能
- 前置条件
  1. 设备GT-D-220403同时支持UPLOAD和ZONE，两个配置序列初始为空
  2. 当前账号与设备关系有效且S10U路由合法
- 测试步骤
  1. 按UPLOAD 600秒、ZONE UTC+08:00、UPLOAD 60秒、ZONE UTC+09:00的顺序提交四个任务
  2. 分别查询UPLOAD和ZONE的configSequence、参数和队列记录
- 预期结果
  1. 四个任务全部受理且各自保留，不因跨配置项提交发生覆盖
  2. UPLOAD内部顺序为600秒后60秒，ZONE内部顺序为UTC+08:00后UTC+09:00，两个序列独立编号

## [P2] 验证不同入口提交的UPLOAD进入同一设备配置序列
- 测试类型
  - 可靠性
- 前置条件
  1. 设备GT-D-220404支持UPLOAD且当前配置序列最后编号为41
  2. 当前账号先后可通过单设备Send Command、设备管理批量流程和设备详情保存发起UPLOAD
- 测试步骤
  1. 从单设备Send Command提交UPLOAD 600秒
  2. 从批量流程仅选择GT-D-220404提交UPLOAD 3600秒
  3. 从设备详情保存Location Interval为1分钟并查询三条后台任务
- 预期结果
  1. 单设备入口创建参数600秒且configSequence为42的独立任务
  2. 批量入口创建参数3600秒且configSequence为43的独立任务
  3. 设备详情入口创建参数60秒且configSequence为44的独立任务，三条任务进入GT-D-220404同一UPLOAD序列，不按入口拆成相互覆盖的队列

## [P3][反向] 验证后提交任务不会静默删除尚未写出的前序任务
- 测试类型
  - 可靠性
- 前置条件
  1. 设备GT-D-220405存在尚未写出的UPLOAD任务CMD-2204-005-A参数600秒和CMD-2204-005-B参数3600秒
  2. 两条任务状态均为SENDING且configSequence分别为71和72
- 测试步骤
  1. 再次提交UPLOAD 60秒并获得CMD-2204-005-C
  2. 查询三个commandId的业务记录、队列任务和configSequence
- 预期结果
  1. 新提交创建CMD-2204-005-C且参数为60秒
  2. CMD-2204-005-A、CMD-2204-005-B、CMD-2204-005-C均存在且序号为71、72、73，不采用只保留最后一条未写出任务的实现

## [P3][反向] 验证乱序状态回调不改变配置任务既定顺序
- 测试类型
  - 可靠性
- 前置条件
  1. 设备GT-D-220406存在UPLOAD任务CMD-2204-006-A和CMD-2204-006-B，configSequence分别为91和92
  2. 模拟CMD-2204-006-B的状态回调先于CMD-2204-006-A到达业务服务
- 测试步骤
  1. 先提交CMD-2204-006-B的回调CB-2204-006-B
  2. 再提交CMD-2204-006-A的回调CB-2204-006-A
  3. 查询两条记录的configSequence、参数和回调关联关系
- 预期结果
  1. CMD-2204-006-B回调只更新自身记录，不把其序号改成91或覆盖前序任务
  2. CMD-2204-006-A回调只更新自身记录
  3. 两条任务仍保持configSequence 91、92及各自参数，回调到达顺序不改写既定提交顺序
