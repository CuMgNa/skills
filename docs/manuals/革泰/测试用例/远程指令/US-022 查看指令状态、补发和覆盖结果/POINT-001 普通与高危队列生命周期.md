# 用户故事：US-022 查看指令状态、补发和覆盖结果 - POINT-001 普通与高危队列生命周期

## [P1] 验证离线设备普通指令受理后进入发送中队列
- 测试类型
  - 功能
- 前置条件
  1. 当前账号GT-P-2201与设备GT-D-220101关系有效，设备具有合法S10U路由并支持CR
  2. 设备GT-D-220101处于离线状态且无当前可写会话
- 测试步骤
  1. 对GT-D-220101提交立即定位CR，operationId为OP-2201-001-01
  2. 查询commandId CMD-2201-001-01的发送状态、队列任务和失败原因
- 预期结果
  1. 服务端受理该普通指令并创建唯一记录及待写出任务，不因设备离线拒绝
  2. 记录状态为SENDING，队列存在一条对应任务，failureReason为空且sentAt为空

## [P1] 验证普通指令在设备恢复通信后写出并转为已发送
- 测试类型
  - 功能
- 前置条件
  1. 设备GT-D-220102存在SENDING状态的VERNO任务CMD-2201-001-02，当前处于普通队列
  2. 设备GT-D-220102恢复通信并建立可写会话SESSION-220102-B
- 测试步骤
  1. 触发S10U按当前生效策略处理CMD-2201-001-02
  2. 查询该任务的TCP写出记录、发送状态和sentAt
- 预期结果
  1. CMD-2201-001-02仅写入GT-D-220102的当前TCP通道一次
  2. 记录最终状态为SENT且sentAt有值，页面语义仅表示已完成TCP写出，不宣称设备业务动作成功

## [P1] 验证高危指令仅由提交时绑定的同一会话写出
- 测试类型
  - 安全性
- 前置条件
  1. 当前账号GT-E1-2201与设备GT-D-220103关系有效，设备支持RESET
  2. 设备GT-D-220103当前可写会话为SESSION-220103-A，会话标识包含sessionEpoch 18和channelId CH-220103-A
- 测试步骤
  1. 对GT-D-220103提交RESET并完成二次确认
  2. 查询新任务保存的会话标识
  3. 在SESSION-220103-A保持有效时触发TCP写出并查询最终状态
- 预期结果
  1. 服务端复检通过并创建SENDING任务
  2. 任务保存SESSION-220103-A、sessionEpoch 18和CH-220103-A，不只保存online=true
  3. 指令仅由SESSION-220103-A写出一次，记录转为SENT且不表示设备已完成重启

## [P3][反向] 验证高危任务绑定会话断开后失败且不迁移到新会话
- 测试类型
  - 安全性
- 前置条件
  1. 设备GT-D-220104存在绑定SESSION-220104-A的POWEROFF任务CMD-2201-001-04，状态为SENDING且尚未写出
  2. SESSION-220104-A断开后设备建立新会话SESSION-220104-B
- 测试步骤
  1. 断开SESSION-220104-A并查询任务状态与队列
  2. 建立SESSION-220104-B并触发设备通信
  3. 查询两个会话的TCP写出日志
- 预期结果
  1. CMD-2201-001-04转为FAILURE并从高危队列移除，失败原因可区分绑定会话断开或变化
  2. 新会话不恢复旧任务，CMD-2201-001-04保持FAILURE
  3. SESSION-220104-A和SESSION-220104-B均无该旧任务的TCP写出记录

## [P3][反向] 验证普通任务受理后断线不会按高危规则立即失败
- 测试类型
  - 可靠性
- 前置条件
  1. 设备GT-D-220105存在普通FIND任务CMD-2201-001-05，状态为SENDING且尚未写出
  2. 设备当前会话SESSION-220105-A即将断开，设备关系和S10U路由仍有效
- 测试步骤
  1. 断开SESSION-220105-A
  2. 查询CMD-2201-001-05的状态、队列任务和失败原因
- 预期结果
  1. 会话断开事件被S10U识别，但不套用高危任务立即失败规则
  2. CMD-2201-001-05继续保持SENDING并保留普通队列任务，不产生SESSION_NOT_ACTIVE失败原因

## [P2] 验证记录页以四态和明确语义展示普通与高危任务
- 测试类型
  - 易用性
- 前置条件
  1. 设备GT-D-220106存在SENDING普通任务CMD-2201-001-06、SENT高危任务CMD-2201-001-07、FAILURE高危任务CMD-2201-001-08和CANCEL普通任务CMD-2201-001-09
  2. CMD-2201-001-07尚未收到设备业务回文
- 测试步骤
  1. 打开GT-D-220106的设备指令记录页
  2. 查看四条记录的状态、发送时间、反馈内容和操作入口
  3. 查看CMD-2201-001-07的已发送文案
- 预期结果
  1. 页面仅使用发送中、已发送、失败、已取消四种发送状态
  2. SENDING记录可取消，FAILURE记录可重发，SENT和CANCEL记录不显示对应操作按钮，未发生字段显示为“—”
  3. CMD-2201-001-07只表达TCP已写出且反馈内容为“—”，不显示“执行成功”或“重启成功”
