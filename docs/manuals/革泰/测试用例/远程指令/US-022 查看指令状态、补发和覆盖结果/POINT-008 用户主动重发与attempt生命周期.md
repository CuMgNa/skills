# 用户故事：US-022 查看指令状态、补发和覆盖结果 - POINT-008 用户主动重发与attempt生命周期

## [P1] 验证普通失败指令离线重发生成新attempt并原卡更新
- 测试类型
  - 功能
- 前置条件
  1. 设备GT-D-220801的CR记录CMD-2208-001当前为FAILURE，已有首次attempt ATT-2208-001-A
  2. 设备当前离线，但账号关系、S10U路由和型号能力有效
- 测试步骤
  1. 在CMD-2208-001记录卡点击重新发送并完成二次确认
  2. 查询commandId、attempt列表、重发次数和用户可见卡片数量
- 预期结果
  1. 普通指令离线重发被受理并创建新attempt ATT-2208-001-B，状态进入SENDING
  2. commandId仍为CMD-2208-001，已重发次数更新为1，页面仍只有一张用户可见卡片

## [P1] 验证高危失败指令重发时绑定重发时的新当前会话
- 测试类型
  - 安全性
- 前置条件
  1. RESET记录CMD-2208-002的旧attempt ATT-2208-002-A因SESSION-220802-A断开而FAILURE
  2. 设备GT-D-220802现已建立可写会话SESSION-220802-B
- 测试步骤
  1. 对CMD-2208-002执行用户主动重发并完成二次确认
  2. 查询新attempt、businessId和boundSessionId
  3. 触发写出并查询会话日志
- 预期结果
  1. 系统创建新attempt ATT-2208-002-B和一一映射的新businessId，不复活ATT-2208-002-A
  2. 新attempt绑定SESSION-220802-B，不沿用SESSION-220802-A
  3. 指令仅可由SESSION-220802-B写出，原卡显示最近attempt结果并累计已重发1次

## [P3][反向] 验证高危重发会话复检失败仍记录新attempt和失败原因
- 测试类型
  - 安全性
- 前置条件
  1. POWEROFF记录CMD-2208-003当前为FAILURE，已有attempt ATT-2208-003-A
  2. 用户点击重发时页面仍显示在线快照，但服务端无当前可写会话
- 测试步骤
  1. 完成重发二次确认并提交operationId OP-2208-003-B
  2. 查询CMD-2208-003的attempt列表、最新状态、失败原因和重发次数
- 预期结果
  1. 服务端重新复检当前会话且不使用页面在线快照放行
  2. 新attempt ATT-2208-003-B直接进入FAILURE，失败原因明确表示无当前可写会话；已重发次数更新为1且旧attempt不被复活

## [P2] 验证多次主动重发形成连续attempt历史并只展示最近结果
- 测试类型
  - 可维护性
- 前置条件
  1. ZONE记录CMD-2208-004先后存在ATT-2208-004-A失败、ATT-2208-004-B失败和ATT-2208-004-C已发送
  2. 三个attempt分别映射BIZ-2208-004-A、BIZ-2208-004-B和BIZ-2208-004-C
- 测试步骤
  1. 打开CMD-2208-004用户可见记录卡
  2. 查询后台attempt审计链和businessId映射
- 预期结果
  1. 页面只保留一张CMD-2208-004卡片，显示已重发2次及ATT-2208-004-C的最近发送、反馈和失败字段
  2. 后台永久保留A、B、C三个attempt及各自businessId、状态和时间，不用最近结果覆盖历史审计

## [P3][反向] 验证主动重发连续点击复用同一新attempt而不重复创建
- 测试类型
  - 可靠性
- 前置条件
  1. FIND记录CMD-2208-005为FAILURE，重发确认操作使用operationId OP-2208-005-B和idempotencyKey IDEM-2208-005-B
  2. 模拟用户在网络卡顿时连续点击确认三次
- 测试步骤
  1. 并发提交三次OP-2208-005-B和IDEM-2208-005-B
  2. 查询CMD-2208-005的新增attempt数、队列任务数和已重发次数
- 预期结果
  1. 三次请求被识别为同一次用户重发意图，仅创建一个新attempt
  2. 队列仅新增一条任务，已重发次数只增加1，不产生三次通知或三张记录卡

## [P3][反向] 验证重发确认后关系失效时新attempt失败且旧记录不转移
- 测试类型
  - 安全性
- 前置条件
  1. UPLOAD记录CMD-2208-006参数600秒且当前为FAILURE
  2. 用户完成重发二次确认后，请求到达服务端时账号GT-E2-2208对设备GT-D-220806的关系已失效
- 测试步骤
  1. 提交重发请求OP-2208-006-B
  2. 查询新attempt、任务队列、重发次数和失败原因
- 预期结果
  1. 服务端复核最新关系并创建可审计的新attempt后将其置为FAILURE，不创建可写出队列任务
  2. CMD-2208-006保持原用户可见记录归属，已重发次数增加1，最新失败原因明确表示关系失效

## [P2][反向] 验证非失败状态不展示主动重发入口
- 测试类型
  - 易用性
- 前置条件
  1. 设备GT-D-220807存在SENDING记录CMD-2208-007-A、SENT记录CMD-2208-007-B、CANCEL记录CMD-2208-007-C和FAILURE记录CMD-2208-007-D
  2. 当前账号对设备仍有操作权限
- 测试步骤
  1. 打开GT-D-220807的设备指令记录页
  2. 查看四张卡片的操作按钮
  3. 尝试通过客户端构造对CMD-2208-007-B发起主动重发请求
- 预期结果
  1. 四张卡片状态和字段正常展示
  2. 仅CMD-2208-007-D显示重新发送；CMD-2208-007-A显示取消发送，SENT和CANCEL记录不显示重发按钮
  3. 服务端拒绝不符合记录状态的重发请求，不为CMD-2208-007-B创建新attempt
