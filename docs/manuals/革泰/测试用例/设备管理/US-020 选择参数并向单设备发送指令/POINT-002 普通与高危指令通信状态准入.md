# US-020 选择参数并向单设备发送指令

> 口径依据：设备管理大纲第 6.2、8、10 章。单设备下发页中，指令专项契约配置的五类普通队列指令允许离线或未连接设备提交；两类高危指令可按最近一次会话快照置灰并展示原因，页面状态变化后可刷新。无论页面初始状态如何，提交时均以服务端实时会话、当前设备关系和权限复检结果为最终准入依据。本文件不自行命名产品指令，使用测试契约编号验证类别行为。

## [P1] 验证离线设备的五类普通队列指令均可提交
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 GT-E1-2001 可见离线设备 deviceId=GT-D-200101，当前关系和操作权限有效
  2. 测试指令契约将 NORMAL-01、NORMAL-02、NORMAL-03、NORMAL-04、NORMAL-05 配置为五类普通队列指令
  3. 五条指令均使用合法具体参数，服务端队列容量可用
- 测试步骤
  1. 从 GT-D-200101 的 More 菜单进入单设备下发页。
  2. 依次检查 NORMAL-01 至 NORMAL-05 的可选择状态。
  3. 分五次分别选择一条普通指令并提交其合法参数。
  4. 查询五次提交请求、指令记录和设备配置队列。
- 预期结果
  1. 页面目标设备为 GT-D-200101，离线状态不改变单设备下发页类型。
  2. NORMAL-01 至 NORMAL-05 均可选择，不因设备离线统一置灰。
  3. 五次请求均到达服务端并按各自参数完成准入校验，离线不作为普通指令拒绝原因。
  4. 每次有效提交分别产生对应任务记录并进入普通队列，不把五次操作合并为一条或静默丢弃。

## [P1] 验证未连接设备的普通指令仍按服务端实时规则受理
- 测试类型
  - 功能
- 前置条件
  1. 个人账号 GT-P-2001 可见初始化未连接设备 deviceId=GT-D-200111，列表按离线口径展示
  2. NORMAL-03 为普通队列指令，参数值 600 已通过本地格式校验
  3. 当前账号、设备关系、型号、路由、幂等键和容量校验均满足
- 测试步骤
  1. 从 GT-D-200111 的 More 菜单进入单设备下发页。
  2. 选择 NORMAL-03，填写参数 600 并提交。
  3. 查询服务端实时复检结果和指令记录。
  4. 返回设备列表核对设备状态。
- 预期结果
  1. 未连接设备可进入对应单设备下发页。
  2. NORMAL-03 可选择并发送，页面不要求设备先建立在线会话。
  3. 服务端复检通过后受理本次请求并创建一条对应任务记录，不以未连接为失败原因。
  4. 提交指令不把设备基础通信状态伪改为在线，列表仍按实际状态展示。

## [P2] 验证高危两类按最近会话快照置灰并展示原因
- 测试类型
  - 易用性
- 前置条件
  1. 企业二级账号 GT-E2-2001 可见设备 deviceId=GT-D-200121
  2. 测试指令契约将 HIGH-RISK-01、HIGH-RISK-02 配置为两类需要在线会话的高危指令
  3. 服务端返回 GT-D-200121 最近一次会话快照为不可用，原因分别可归一化为「设备当前无可用在线会话」
- 测试步骤
  1. 进入 GT-D-200121 的单设备下发页。
  2. 查看 HIGH-RISK-01、HIGH-RISK-02 的控件状态。
  3. 点击或聚焦两条置灰指令的原因提示区域。
  4. 检查 NORMAL-01 的控件状态作为对照。
- 预期结果
  1. 页面读取当前设备最近一次会话快照，不串用其他设备状态。
  2. HIGH-RISK-01、HIGH-RISK-02 置灰且不能直接提交。
  3. 两条高危指令均展示可读原因「设备当前无可用在线会话」或服务端等价文案，不只用颜色表达不可用。
  4. NORMAL-01 仍保持可选择，页面不因高危指令不可用而禁用全部指令。

## [P3][反向] 验证高危指令提交时以服务端实时会话复检为最终准入
- 测试类型
  - 安全性
- 前置条件
  1. 企业一级账号 GT-E1-2002 可见在线设备 deviceId=GT-D-200131
  2. 打开单设备下发页时会话快照显示可用，HIGH-RISK-01 处于可选择状态
  3. 用户完成参数填写后、点击提交前，GT-D-200131 的有效在线会话已断开
- 测试步骤
  1. 在旧快照页面选择 HIGH-RISK-01 并填写合法参数。
  2. 点击提交并等待服务端实时准入结果。
  3. 查询是否进入实际执行队列及设备侧是否收到高危指令。
  4. 在页面刷新当前设备状态并再次查看 HIGH-RISK-01。
- 预期结果
  1. 客户端可以保留已填写参数，但旧快照不能作为最终放行依据。
  2. 服务端按提交时实时会话复检拒绝本次高危指令，并返回设备当前无可用在线会话的可读原因。
  3. HIGH-RISK-01 不进入实际执行队列，设备侧未收到该高危指令，不因客户端旧状态产生越权式放行。
  4. 刷新后页面同步最新会话状态，HIGH-RISK-01 变为置灰并展示原因；普通队列指令仍按自身规则可用。

## [P1] 验证两类高危指令在提交时在线会话有效时通过实时复检
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 GT-E1-2003 可见在线设备 deviceId=GT-D-200141，当前设备关系和操作权限有效
  2. HIGH-RISK-01、HIGH-RISK-02 均使用合法具体参数，页面快照和提交时服务端实时会话均有效
  3. 型号、路由、参数、幂等键和执行容量校验均满足
- 测试步骤
  1. 进入 GT-D-200141 单设备下发页并选择 HIGH-RISK-01 提交。
  2. 查询服务端实时会话复检、指令记录和执行队列。
  3. 返回页面后选择 HIGH-RISK-02 并提交。
  4. 查询第二条指令的准入和设备侧接收结果。
- 预期结果
  1. HIGH-RISK-01 可选择并提交，客户端不因指令类别自行拒绝有效在线设备。
  2. 服务端实时复检通过后创建对应记录并进入高危指令执行链。
  3. HIGH-RISK-02 同样以提交时实时会话为准完成校验。
  4. 两条高危指令分别形成可追踪记录并可发送到 GT-D-200141，不合并、不绕过权限或关系校验。

## [P1] 验证设备恢复在线并刷新后高危指令重新可选且成功提交
- 测试类型
  - 可靠性
- 前置条件
  1. 企业二级账号 GT-E2-2002 可见 deviceId=GT-D-200151，首次进入时最近会话快照不可用
  2. HIGH-RISK-01 初始置灰，随后设备建立新的有效在线会话
  3. 当前账号关系、权限及其他服务端准入条件保持有效
- 测试步骤
  1. 进入单设备下发页确认 HIGH-RISK-01 初始置灰及原因。
  2. 设备建立有效在线会话后点击页面刷新。
  3. 选择 HIGH-RISK-01，填写合法参数并提交。
  4. 查询实时复检、执行队列和页面最终结果。
- 预期结果
  1. 初始状态按不可用快照置灰并展示可读原因。
  2. 刷新读取最新会话状态，HIGH-RISK-01 重新变为可选择，不要求退出重进页面。
  3. 提交时服务端再次实时复检并确认会话有效，指令通过准入。
  4. 指令进入执行队列并显示明确受理结果，旧离线快照不得继续阻断本次有效提交。
