# US-018 编辑设备资料并查询物联网卡
> 口径依据：大纲第 5.3、5.6、5.8～5.9、10 章。返回或取消直接丢弃备注、分组和频率草稿，不自动保存且不二次确认；普通资料与定位频率结果相互独立；Save 期间禁用并以每次操作的唯一幂等键防止重复副作用，联系人及联系电话已从编辑能力移除。

## [P1] 验证返回或取消直接丢弃全部草稿且不自动保存
- 测试类型
  - 易用性
- 前置条件
  1. personal_31 可编辑设备 DEV-SAVE-4001，正式备注为「原备注」、分组为「原分组」、确认频率为 10 分钟
  2. personal_31 有权使用分组「新分组」
  3. 编辑页初始不存在在途频率目标
- 测试步骤
  1. 将备注改为「未保存备注」、分组改为「新分组」，在频率弹层确认自定义 30 分钟后点击系统返回键。
  2. 观察返回过程并查询设备资料、分组关系和 UPLOAD 记录。
  3. 再次进入编辑页完成相同三项修改后点击取消。
  4. 重新进入编辑页核对三项正式值。
- 预期结果
  1. 三项修改仅形成当前页面草稿，系统返回直接离开编辑页。
  2. 返回时不弹二次确认、不自动保存；正式备注、分组和确认频率不变，且不创建 UPLOAD 记录。
  3. 点击取消同样直接离开，不弹二次确认、不提交普通资料或频率请求。
  4. 页面仍回显「原备注」「原分组」和 10 分钟确认值，不残留两次已丢弃草稿。

## [P1] 验证已有在途目标时只保存资料不得重复创建频率任务
- 测试类型
  - 可靠性
- 前置条件
  1. personal_31 可编辑设备 DEV-SAVE-4008，正式备注为「在途资料旧值」、分组为「在途资料组」、确认频率为 10 分钟
  2. DEV-SAVE-4008 已有 60 分钟在途目标，唯一任务为 commandId CMD-UPLOAD-4008、状态 SENDING、参数 3600 秒，保存前 UPLOAD 记录总数为 3
- 测试步骤
  1. 进入独立编辑页，确认展示 60 分钟目标值与「设置中」，仅把备注改为「在途资料新值」。
  2. 不打开或重新确认 Location Interval，点击 Save 并等待资料保存成功。
  3. 退出后重新进入编辑页，核对备注、分组和在途目标展示。
  4. 查询保存前后 UPLOAD 记录、commandId、attemptId 和 configSequence。
- 预期结果
  1. 页面正确恢复既有在途目标，但本次只形成备注资料意图；读取到 desiredValue 不等于用户重新选择频率。
  2. 备注更新为「在途资料新值」，分组仍为「在途资料组」，资料保存不得借已有目标再次提交 UPLOAD。
  3. 编辑页继续展示原 60 分钟目标与「设置中」，不出现第二个相同目标或重复提示。
  4. UPLOAD 总数仍为 3、新增数为 0；CMD-UPLOAD-4008 及其 attemptId、configSequence 不因资料保存被复制、重建或推进。

## [P1] 验证 Save 禁用与唯一幂等键阻止重复副作用
- 测试类型
  - 可靠性
- 前置条件
  1. personal_33 可编辑 DEV-SAVE-4005，正式备注为「幂等旧值」、分组为「幂等组」、确认频率为 10 分钟
  2. 可延迟 Save 响应并模拟首次响应丢失，但服务端已受理 60 分钟频率任务
  3. 可记录普通资料请求、频率请求及幂等键
- 测试步骤
  1. 将备注改为「幂等新值」，明确选择 60 分钟频率后连续快速点击 Save 三次。
  2. 在请求处理中观察 Save 按钮状态并统计发出的业务保存请求。
  3. 模拟首次响应丢失，客户端使用原幂等键查询或重试本次操作。
  4. 本次结果明确后重新进入编辑页，将备注改为「第二次保存值」，再次明确选择并确认 60 分钟，然后执行一次新的 Save。
- 预期结果
  1. 首次点击触发保存，后两次点击无效，不产生并行重复提交。
  2. Save 在请求期间禁用；本次用户操作只使用一个唯一幂等键，普通资料最多更新一次、60 分钟 UPLOAD 最多创建一条。
  3. 受理结果未知时复用原幂等键查询或重试，不自动生成新键或第二条同参数任务，最终可恢复已受理结果。
  4. 第二次用户操作生成不同于上次的唯一幂等键，备注更新为「第二次保存值」并新建另一条独立的 3600 秒 UPLOAD；两条同值任务均保留并按 configSequence 顺序执行，不按“设备加秒数”错误去重。
