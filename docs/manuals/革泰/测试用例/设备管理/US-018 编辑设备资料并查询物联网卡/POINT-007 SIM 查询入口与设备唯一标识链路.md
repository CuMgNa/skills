# US-018 编辑设备资料并查询物联网卡

> 口径依据：唯一业务真源《革泰 APP 设备管理逻辑点梳理 plan.md》2.4.2、2.4.4，以及第 10 章第 1 条。SIM 查询从设备卡片更多菜单进入，首次进入自动查询，刷新始终查询同一设备；APP 只提交设备唯一标识，设备切换或重名时不得串卡。

## [P1] 验证从设备更多菜单进入后按唯一标识自动查询
- 测试类型
  - 功能
- 前置条件
  1. 账号 GT-P-5101 可见设备 GT-DEV-SIM-0001，设备显示名为“北场定位器”，型号为 GT-CATTLE-4G
  2. GT-DEV-SIM-0001 当前关联 ICCID 89860400123456789001，服务端可成功返回该卡资料
- 测试步骤
  1. 在 GT-DEV-SIM-0001 设备卡片右上角点击更多，选择 IoT SIM Query。
  2. 记录 APP 发起的查询身份参数并等待页面完成加载。
  3. 核对页面设备摘要和 ICCID。
- 预期结果
  1. 当前操作面板关闭并进入标题为 IoT SIM Query 的页面，页面自动发起一次查询。
  2. APP 仅提交设备唯一标识 GT-DEV-SIM-0001，不提交前端输入或拼接的 MSISDN、ICCID、IMSI。
  3. 页面展示“北场定位器”、GT-CATTLE-4G 和 ICCID 89860400123456789001，卡归属与设备关联关系一致。

## [P1] 验证连续快速刷新三次时乱序响应不覆盖最新结果
- 测试类型
  - 可靠性
- 前置条件
  1. 已打开 GT-DEV-SIM-0002 的 IoT SIM Query 页面，设备显示名为“南场定位器”，ICCID 为 89860400123456789002
  2. 三次刷新响应均属于 GT-DEV-SIM-0002：第一次延迟 3 秒返回测试期，第二次延迟 1 秒返回停机，第三次延迟 200 毫秒返回正使用
- 测试步骤
  1. 在 1 秒内连续点击刷新按钮三次，并记录三次请求携带的设备标识与请求顺序。
  2. 等待第三次、第二次、第一次响应按设定顺序依次返回。
  3. 核对加载反馈、最终设备摘要、ICCID 和卡状态。
- 预期结果
  1. 三次请求均只携带设备唯一标识 GT-DEV-SIM-0002，不切换或串到其他设备；页面不新增未确认的冷却倒计时规则。
  2. 页面按请求时序识别最新有效结果，第二次和第一次旧响应不得覆盖第三次响应。
  3. 最终页面保持“南场定位器”、ICCID 89860400123456789002 和“正使用”，连续刷新期间具有基础加载反馈且不出现新旧字段混合。

## [P1] 验证同名设备连续查询不按名称串卡
- 测试类型
  - 可靠性
- 前置条件
  1. 账号 GT-E1-5201 同时可见设备 GT-DEV-SIM-0003 和 GT-DEV-SIM-0004，两台设备显示名均为“1号定位器”
  2. GT-DEV-SIM-0003 关联 ICCID 089860400123456789003，GT-DEV-SIM-0004 关联 ICCID 89860400123456789004
- 测试步骤
  1. 从 GT-DEV-SIM-0003 的更多菜单进入 IoT SIM Query 并等待加载完成。
  2. 返回设备列表，从 GT-DEV-SIM-0004 的更多菜单进入 IoT SIM Query。
  3. 核对两次请求身份以及第二个页面的设备摘要、ICCID、状态和流量。
- 预期结果
  1. 第一次请求使用 GT-DEV-SIM-0003，页面展示 ICCID 089860400123456789003。
  2. 第二次请求使用 GT-DEV-SIM-0004，不以相同显示名复用 GT-DEV-SIM-0003 的查询身份。
  3. 第二个页面全部 SIM 字段属于 GT-DEV-SIM-0004，不残留 GT-DEV-SIM-0003 的 ICCID、状态或流量。

## [P3][反向] 验证设备无可用卡号时仍进入统一失败链路
- 测试类型
  - 可靠性
- 前置条件
  1. 账号 GT-P-5101 可见设备 GT-DEV-SIM-0005，设备显示名为“备用定位器”，型号为 GT-HORSE-4G
  2. GT-DEV-SIM-0005 未关联可用的 MSISDN、ICCID 或 IMSI
- 测试步骤
  1. 从 GT-DEV-SIM-0005 的更多菜单进入 IoT SIM Query。
  2. 等待自动查询结束并查看页面状态。
  3. 点击刷新按钮再次查询。
- 预期结果
  1. APP 仍按设备唯一标识 GT-DEV-SIM-0005 发起查询，不在前端阻断或要求输入卡号。
  2. 页面保留“备用定位器”和 GT-HORSE-4G 摘要，SIM 明细均显示“—”，展示可读失败原因和可用刷新入口；失败不强制伪装成第三方 502。
  3. 刷新仍查询 GT-DEV-SIM-0005，失败态可结束且不出现无限加载。

## [P1] 验证服务端按当前关联关系选择 MSISDN ICCID 或 IMSI 查询
- 测试类型
  - 功能
- 前置条件
  1. 设备 GT-DEV-SIM-0006 仅关联可用 MSISDN 8613800000006
  2. 设备 GT-DEV-SIM-0007 的 MSISDN 不可用，仅关联可用 ICCID 89860400123456789007
  3. 设备 GT-DEV-SIM-0008 的 MSISDN、ICCID 不可用，仅关联可用 IMSI 460001234567008
  4. 三台设备均在当前账号可见范围，第三方单卡接口可记录实际路径参数
- 测试步骤
  1. 分别从三台设备 More 菜单进入 IoT SIM Query。
  2. 核对 APP 提交参数和服务端解析的当前卡关联关系。
  3. 核对三次第三方请求使用的必填路径参数。
  4. 将 GT-DEV-SIM-0007 当前关联卡切换为新 ICCID 89860400123456789997 后刷新查询。
- 预期结果
  1. APP 三次均只提交对应设备唯一标识，不由前端选择或拼接卡号。
  2. 服务端分别取得当前关系中的 MSISDN、ICCID、IMSI 可用值，不使用其他设备或历史卡标识。
  3. 三次第三方请求路径参数依次为 8613800000006、89860400123456789007、460001234567008，并返回对应设备卡资料。
  4. 关联切换后刷新使用新 ICCID 89860400123456789997，旧 ICCID 不再用于查询或回显。
