# US-018 编辑设备资料并查询物联网卡
> 口径依据：设备管理逻辑大纲第 1.3、2.4.2～2.4.4、4.1、4.8、5.1、5.3、9～10 节。设备与分组按当前登录账号重新鉴权和加载；连续查看不同设备必须按唯一标识清理上一个对象的数据；查询失败或失权不得展示旧账号、旧设备或旧 SIM 缓存。

## [P1] 验证切换登录账号后设备、分组筛选和数量缓存全部隔离
- 测试类型
  - 安全性
- 前置条件
  1. 个人账号 GT-P-13201 仅可见 GT-D-13201，分组为“个人北场”，设备总数为 1
  2. 企业二级账号 GT-E2-13201 仅可见 GT-D-13202、GT-D-13203，分组为“企业南场”，设备总数为 2
  3. GT-P-13201 上次停留在“个人北场”筛选并搜索关键词“13201”
- 测试步骤
  1. 使用 GT-P-13201 登录 APP，确认设备、筛选条件、分组和数量后退出登录。
  2. 使用 GT-E2-13201 登录同一 APP 实例并进入设备列表。
  3. 打开分组选择器并检查默认选择、分组列表及设备数量。
  4. 通过搜索和设备唯一标识直访尝试访问 GT-D-13201。
- 预期结果
  1. 个人账号仅显示 GT-D-13201、“个人北场”和总数 1。
  2. 企业账号仅显示 GT-D-13202、GT-D-13203，不短暂闪现 GT-D-13201 或个人账号数量。
  3. 新账号从虚拟“全部分组”开始，只加载“企业南场”等当前账号分组，总数为 2，不复用“个人北场”和关键词“13201”。
  4. 搜索与直访均不能读取 GT-D-13201，响应不泄露个人账号的备注、位置、SIM 或到期信息。

## [P1] 验证连续打开同备注设备时详情抽屉不串用上一设备数据
- 测试类型
  - 功能
- 前置条件
  1. 当前账号可见 GT-D-13204 与 GT-D-13205，两台设备共享备注“东栏定位器”
  2. GT-D-13204 型号 S18、电量 81%、到期日期 2026-11-30、ICCID 898600001320000004
  3. GT-D-13205 型号 S19、电量 36%、到期日期 2027-03-15、ICCID 898600001320000005
- 测试步骤
  1. 点击 GT-D-13204 卡片本体并等待详情抽屉加载完成。
  2. 关闭抽屉后立即点击 GT-D-13205 卡片本体。
  3. 在 GT-D-13205 请求返回前观察抽屉内容区。
  4. 请求成功后核对标题身份、型号、电量、到期日期和 ICCID。
- 预期结果
  1. 首次抽屉展示 GT-D-13204 对应的 S18、81%、2026-11-30 和 ICCID 898600001320000004。
  2. 第二次查询携带 GT-D-13205 唯一标识，不以相同备注或列表位置确定设备。
  3. 加载期间已清理 GT-D-13204 的详情字段，不用上一设备数据填充 GT-D-13205。
  4. 最终只展示 GT-D-13205 对应的 S19、36%、2027-03-15 和 ICCID 898600001320000005。

## [P1] 验证连续查询不同设备物联网卡时 SIM 缓存按设备唯一标识隔离
- 测试类型
  - 功能
- 前置条件
  1. 当前账号可见 GT-D-13206 与 GT-D-13207
  2. GT-D-13206 关联 ICCID 898600001320000006，active 为 true，account_status 为 00
  3. GT-D-13207 关联 ICCID 898600001320000007，active 为 false，account_status 为 02
- 测试步骤
  1. 从 GT-D-13206 更多菜单进入 IoT SIM Query 并记录页面字段。
  2. 返回设备列表，从 GT-D-13207 更多菜单进入 IoT SIM Query。
  3. 在第二次请求加载期间检查设备摘要与 SIM 明细。
  4. 第二次请求完成后核对 ICCID、激活标识和卡状态。
- 预期结果
  1. 第一次页面显示 ICCID 898600001320000006、Active、正使用。
  2. 第二次查询只提交 GT-D-13207 唯一标识，服务端按其当前卡关系查询。
  3. 加载期间不残留 GT-D-13206 的 ICCID、激活标识或卡状态冒充 GT-D-13207 数据。
  4. 最终显示 ICCID 898600001320000007、Inactive、停机，三个字段全部切换为 GT-D-13207 的结果。

## [P3][反向] 验证新设备查询失败时清空旧设备缓存并限制失败影响范围
- 测试类型
  - 可靠性
- 前置条件
  1. 当前账号已成功查看 GT-D-13208，缓存含电量 72%、到期日期 2026-12-20、ICCID 898600001320000008
  2. 当前账号可见 GT-D-13209，详情接口可模拟 HTTP 500
  3. 设备列表及其他设备 GT-D-13210 的查询接口保持正常
- 测试步骤
  1. 打开 GT-D-13208 详情抽屉并确认缓存字段后关闭。
  2. 打开 GT-D-13209 详情抽屉，使本次详情请求返回 HTTP 500。
  3. 查看失败抽屉的标题身份、内容区、失败提示和重试入口。
  4. 关闭失败抽屉并打开 GT-D-13210，随后恢复 GT-D-13209 接口并重试。
- 预期结果
  1. GT-D-13208 的有效详情仅归属于该设备缓存。
  2. GT-D-13209 查询失败，不生成该设备的有效详情快照。
  3. 抽屉保留 GT-D-13209 的设备身份，清空 GT-D-13208 的电量、到期日期和 ICCID，展示可读失败原因与重试入口。
  4. GT-D-13210 可正常加载且不受失败影响；GT-D-13209 重试成功后只展示自身最新数据。
