# US-018 编辑设备资料并查询物联网卡

> 口径依据：大纲第 5.1、5.3、5.8～5.9、8、10 章。每次打开抽屉都按设备唯一标识请求最新详情，停留期间复用列表刷新周期且不新增轮询；失败时保留标题、清空旧内容并可重试；设备切换不得串缓存，失权或解绑后立即清理受保护数据、关闭抽屉并刷新列表。

## [P1] 验证每次打开抽屉均重新请求当前设备最新详情
- 测试类型
  - 功能
- 前置条件
  1. DEV-LOAD-001 初始电量为 45%，型号为 S18，ICCID 为 08986001000000001001
  2. 可统计 DEV-LOAD-001 详情接口请求次数并在两次打开之间将服务端电量更新为 62%
- 测试步骤
  1. 第一次点击 DEV-LOAD-001 卡片本体打开抽屉并记录详情和请求次数。
  2. 关闭抽屉，将服务端电量更新为 62%。
  3. 第二次点击同一卡片本体打开抽屉并记录详情和请求次数。
- 预期结果
  1. 第一次按 DEV-LOAD-001 唯一标识发起详情请求并显示 45%。
  2. 抽屉关闭不阻止服务端数据更新，也不把首次快照固定为后续结果。
  3. 第二次再次发起 DEV-LOAD-001 最新详情请求并显示 62%，累计详情请求次数增加 1，不直接复用首次旧内容。

## [P2] 验证抽屉停留期间复用列表刷新周期且不新增独立轮询
- 测试类型
  - 性能
- 前置条件
  1. 设备列表当前刷新周期为 30 秒，DEV-LOAD-002 详情抽屉可持续停留 95 秒
  2. 可分别统计列表刷新请求、详情首次打开请求和抽屉独立定时请求
- 测试步骤
  1. 打开 DEV-LOAD-002 详情抽屉并开始 95 秒网络请求统计。
  2. 在第 35 秒将服务端电量从 40% 更新为 41%，在第 65 秒更新最后有效定位。
  3. 保持抽屉打开至第 95 秒并观察字段更新。
  4. 汇总 95 秒内列表刷新和抽屉详情请求时间线。
- 预期结果
  1. 打开时仅发起一次 DEV-LOAD-002 最新详情请求。
  2. 电量和最后有效定位分别在后续列表既有刷新周期内同步到抽屉。
  3. 抽屉持续可用，状态、电量和最后有效定位以列表刷新结果更新。
  4. 除首次打开请求外，不出现以抽屉为来源的额外周期轮询；详情刷新频率不叠加或短于列表既有周期。

## [P3][反向] 验证加载失败保留设备标题、清空旧内容并支持重试
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-LOAD-003 标题为「北场设备（898600100000001003）」且上次成功详情电量为 70%
  2. 本次详情请求可模拟超时，随后恢复并返回电量 68%、型号 S18
- 测试步骤
  1. 点击 DEV-LOAD-003 卡片本体并触发详情请求超时。
  2. 查看抽屉标题、内容区、失败原因和重试入口。
  3. 点击重试并等待成功响应。
  4. 核对重试后的详情字段。
- 预期结果
  1. 抽屉保持打开，不因加载失败自动关闭。
  2. 标题仍为「北场设备（898600100000001003）」；内容区不显示旧电量 70% 或其他旧字段，展示可读失败原因和重试入口。
  3. 重试仍按 DEV-LOAD-003 唯一标识请求，不创建其他设备查询。
  4. 成功后显示电量 68% 和型号 S18，失败态被本次成功结果替换。

## [P1] 验证快速切换设备 A 与 B 时缓存和异步响应完全隔离
- 测试类型
  - 可靠性
- 前置条件
  1. 设备 A 为 DEV-LOAD-A，标题「共享备注（898600100000001101）」、电量 31%、ICCID 08986001000000001101
  2. 设备 B 为 DEV-LOAD-B，标题「共享备注（898600100000001102）」、电量 82%、ICCID 08986001000000001102
  3. DEV-LOAD-A 详情响应延迟 800 毫秒，DEV-LOAD-B 详情响应延迟 100 毫秒
- 测试步骤
  1. 点击 DEV-LOAD-A 卡片，50 毫秒后立即点击 DEV-LOAD-B 卡片。
  2. 等待 DEV-LOAD-B 响应完成并查看标题、电量和 ICCID。
  3. 继续等待延迟的 DEV-LOAD-A 响应到达。
  4. 关闭 B 后重新打开 A 并核对详情。
- 预期结果
  1. 切换到 B 时先清理 A 的详情内容，当前抽屉身份变为 DEV-LOAD-B。
  2. B 显示卡号 898600100000001102、电量 82%、ICCID 08986001000000001102。
  3. A 的迟到响应不得覆盖 B 的标题、状态、位置、电量、到期时间或 ICCID。
  4. 重新打开 A 时按 DEV-LOAD-A 唯一标识重新请求并显示 A 的 31% 和 08986001000000001101，不复用 B 缓存。

## [P1][反向] 验证抽屉打开期间失权或解绑立即清除数据并丢弃迟到响应
- 测试类型
  - 安全性
- 前置条件
  1. ent_l2 通过父级分配可见 DEV-LOAD-004，个人账号 person_01 直接绑定 DEV-LOAD-005；两台设备详情均包含型号、位置、电量、到期时间和 ICCID
  2. DEV-LOAD-004 的详情请求延迟 800 毫秒，响应载荷包含型号 S18、电量 66%、位置 116.397128、39.916527、到期时间 2027-12-31、ICCID 08986001000000001004
  3. 企业一级账号可回收 ent_l2 对 DEV-LOAD-004 的分配关系，管理后台可解绑 person_01 与 DEV-LOAD-005 的直接绑定关系
- 测试步骤
  1. ent_l2 打开 DEV-LOAD-004 抽屉，在延迟详情响应返回前由企业一级账号回收分配关系并触发 APP 权限刷新。
  2. 等待失权前发出的 DEV-LOAD-004 延迟详情响应到达，检查抽屉、列表和本地缓存。
  3. person_01 打开 DEV-LOAD-005 详情抽屉后，由管理后台解除该直接绑定关系并触发 APP 刷新。
  4. 检查 person_01 的抽屉、提示、列表和 DEV-LOAD-005 本地缓存。
  5. 两个账号分别尝试从原列表位置或本地缓存重新打开对应设备详情。
- 预期结果
  1. 服务端使 ent_l2 对 DEV-LOAD-004 的可见关系失效；APP 立即清空型号、位置、电量、到期时间和 ICCID，关闭抽屉，提示设备不可用并刷新列表移除该设备。
  2. 迟到响应被丢弃，不回写 S18、66%、位置、到期时间或 ICCID，不写入详情缓存，也不重新打开抽屉。
  3. 服务端删除 person_01 与 DEV-LOAD-005 的直接绑定关系，不再返回受保护详情。
  4. APP 清空 DEV-LOAD-005 的型号、位置、电量、到期时间和 ICCID，关闭抽屉，提示设备不可用并刷新列表移除该设备。
  5. 两台设备均无法通过旧列表位置或本地缓存重新打开，页面不短暂闪现失权或解绑前的数据。
