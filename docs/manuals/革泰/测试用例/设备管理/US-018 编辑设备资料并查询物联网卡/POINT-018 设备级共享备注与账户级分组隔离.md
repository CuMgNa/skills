# US-018 编辑设备资料并查询物联网卡
> 口径依据：大纲第 5.8～5.9、9、10 章。设备备注由管理端和所有关联账户读取同一份设备级数据，列表标题、搜索和详情抽屉必须同源；分组只更新当前账户关系；并发编辑采用后写覆盖先写且不做版本冲突拦截。

## [P1] 验证关联账户与管理端读取同一份共享备注
- 测试类型
  - 功能
- 前置条件
  1. 设备 DEV-SHARE-2001 同时直接绑定个人账号 personal_11 与企业一级账号 corp_l1_11
  2. personal_11、corp_l1_11 和管理端当前均显示共享备注「牧场一号」
  3. 三端均可按设备唯一标识 DEV-SHARE-2001 查询设备
- 测试步骤
  1. personal_11 将备注修改为「北区设备一号」并保存成功。
  2. corp_l1_11 刷新设备列表并使用关键词「北区设备一号」搜索。
  3. corp_l1_11 打开 DEV-SHARE-2001 详情抽屉，管理端重新查询该设备。
  4. personal_11 使用旧关键词「牧场一号」和新关键词「北区设备一号」分别搜索。
- 预期结果
  1. 服务端设备级备注更新为「北区设备一号」，不创建 personal_11 私有覆盖值。
  2. 企业账户列表标题同步为新备注，搜索新备注命中 DEV-SHARE-2001。
  3. 企业账户抽屉标题与管理端设备备注均为「北区设备一号」，三端读取同一份值。
  4. 使用旧完整备注作为关键词不再命中该设备，新完整备注命中且结果身份为 DEV-SHARE-2001。

## [P1] 验证逐级获配企业二级可编辑共享备注且失权后被拒绝
- 测试类型
  - 安全性
- 前置条件
  1. 设备 DEV-SHARE-2005 卡号为 898600100000002005，直接绑定企业一级 corp_l1_15，初始共享备注为「二级编辑前」
  2. corp_l1_15 已在 Web 将该设备分配给直属二级 corp_l2_15，corp_l2_15 又分配给直属三级 corp_l3_15；三者均可见但二、三级不产生直接绑定
  3. corp_l2_15 已打开独立编辑页，corp_l1_15 与 corp_l3_15 可按设备唯一标识读取同一设备
- 测试步骤
  1. corp_l2_15 将 Device Name 改为「二级共享新值」并保存成功。
  2. corp_l1_15、corp_l3_15 和管理端分别刷新 DEV-SHARE-2005。
  3. corp_l1_15 在 Web 回收 corp_l2_15 的设备分配关系，等待 corp_l2_15 及其下 corp_l3_15 失权。
  4. corp_l2_15 使用失权前仍打开的编辑页尝试把备注保存为「二级越权值」，随后由 corp_l1_15 和管理端重新查询。
- 预期结果
  1. 服务端按 corp_l2_15 当前逐级分配关系鉴权通过，共享备注更新为「二级共享新值」，不创建二级账户私有备注。
  2. corp_l1_15、corp_l3_15 与管理端均读取纯备注「二级共享新值」；两端 APP 列表和抽屉标题均为「二级共享新值（898600100000002005）」。
  3. 回收二级分配后 corp_l2_15 和其下 corp_l3_15 均失去设备可见与编辑权限，corp_l1_15 仍保持直接绑定和读取权限。
  4. 失权后的保存被服务端拒绝且不写入「二级越权值」；corp_l1_15 和管理端继续读取「二级共享新值」，证明权限按保存时实时校验。

## [P1] 验证逐级获配企业三级可编辑共享备注且失权后被拒绝
- 测试类型
  - 安全性
- 前置条件
  1. 设备 DEV-SHARE-2006 卡号为 898600100000002006，直接绑定企业一级 corp_l1_16，初始共享备注为「三级编辑前」
  2. corp_l1_16 已在 Web 将该设备分配给直属二级 corp_l2_16，corp_l2_16 再分配给直属三级 corp_l3_16，三级可见链路完整
  3. corp_l3_16 已打开独立编辑页，corp_l1_16 与 corp_l2_16 保持有效读取权限
- 测试步骤
  1. corp_l3_16 将 Device Name 改为「三级共享新值」并保存成功。
  2. corp_l1_16、corp_l2_16 和管理端分别刷新 DEV-SHARE-2006。
  3. corp_l2_16 在 Web 仅回收 corp_l3_16 的设备分配关系，保留一级和二级可见关系。
  4. corp_l3_16 使用失权前仍打开的编辑页尝试把备注保存为「三级越权值」，随后由 corp_l1_16、corp_l2_16 和管理端重新查询。
- 预期结果

  2. corp_l1_16、corp_l2_16 与管理端均读取纯备注「三级共享新值」；两端有权 APP 列表和抽屉标题均为「三级共享新值（898600100000002006）」。
  3. 仅 corp_l3_16 失去设备可见与编辑权限，corp_l1_16、corp_l2_16 仍保持有效关系并继续读取同一共享值。
  4. 失权后的保存被服务端拒绝且不写入「三级越权值」；其他有权账号和管理端继续读取「三级共享新值」，无越权副作用。

## [P1] 验证个人与企业分组关系相互隔离且不影响共享备注
- 测试类型
  - 功能
- 前置条件
  1. DEV-SHARE-2002 同时关联 personal_12 与 corp_l1_12，共享备注为「东坡设备」
  2. personal_12 下设备位于分组「个人牧场」，corp_l1_12 下设备位于分组「企业东区」
  3. personal_12 有权使用分组「个人北区」
- 测试步骤
  1. personal_12 进入独立编辑页，只将 Group 从「个人牧场」改为「个人北区」并保存。
  2. personal_12 刷新分组列表及相关分组设备数量。
  3. corp_l1_12 刷新设备列表和分组「企业东区」。
  4. 两个账户分别打开 DEV-SHARE-2002 详情与编辑页。
- 预期结果
  1. 仅 personal_12 的设备关系更新到「个人北区」，共享备注仍为「东坡设备」。
  2. personal_12 的「个人牧场」直属设备数减少 1，「个人北区」直属设备数增加 1。
  3. corp_l1_12 下分组仍为「企业东区」，其直属设备数不因个人侧改组变化。
  4. 两端备注均为「东坡设备」，但各自 Group 分别回显「个人北区」与「企业东区」。

## [P1] 验证两个账户并发修改备注时后写覆盖先写且不冲突拦截
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-SHARE-2003 同时关联 personal_13 与 corp_l1_13，初始共享备注为「共享设备」
  2. 两个账户已同时打开独立编辑页并加载相同初始备注
  3. personal_13 的分组为「个人组 A」，corp_l1_13 的分组为「企业组 B」
- 测试步骤
  1. personal_13 将备注改为「个人先写值」并先保存成功。
  2. corp_l1_13 在未刷新的旧页面将备注改为「企业后写值」并后保存。
  3. 两个账户与管理端分别刷新 DEV-SHARE-2003。
  4. 查询设备资料更新记录及两个账户的分组关系。
- 预期结果
  1. 服务端短暂保存「个人先写值」，personal_13 收到成功结果。
  2. corp_l1_13 的旧页面请求不因版本冲突被拒绝，后写值「企业后写值」覆盖先写值。
  3. 两个账户和管理端最终均显示「企业后写值」，不得各自保留不同备注。
  4. 更新记录按先后顺序可追溯，最终只有一份设备级备注；两个账户分组仍分别为「个人组 A」和「企业组 B」。

## [P2] 验证管理端改备注后客户端缓存不会继续冒充最新值
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-SHARE-2004 关联 personal_14、corp_l1_14，两个 APP 已缓存旧备注「缓存旧值」
  2. personal_14 当前停留设备列表，corp_l1_14 当前停留该设备详情抽屉
  3. 管理端有权编辑 DEV-SHARE-2004 备注
- 测试步骤
  1. 管理端将备注修改为「后台最新值」并保存。
  2. personal_14 执行列表刷新后搜索「后台最新值」。
  3. corp_l1_14 关闭并重新打开 DEV-SHARE-2004 详情抽屉。
  4. 结束两个 APP 进程后重新登录并查询 DEV-SHARE-2004。
- 预期结果
  1. 管理端写入同一设备级备注「后台最新值」，所有关联账户的读取真源随之更新。
  2. personal_14 列表标题更新且搜索命中 DEV-SHARE-2004，不继续使用「缓存旧值」。
  3. 抽屉按设备唯一标识请求最新详情并显示标题「后台最新值」，不展示旧缓存冒充最新数据。
  4. 冷启动后两端仍显示「后台最新值」，证明未建立账户独立备注副本或持久化脏缓存。
