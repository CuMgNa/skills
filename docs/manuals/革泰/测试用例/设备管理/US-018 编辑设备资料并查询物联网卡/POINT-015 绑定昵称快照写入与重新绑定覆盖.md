# US-018 编辑设备资料并查询物联网卡
> 口径依据：大纲第 3.1.5、5.8～5.9、9、10 章。首次绑定默认把当前绑定账号昵称快照写入设备级备注，账号昵称后续变化不回写；已有非空备注时另一类账户新增绑定仍由新绑定账号昵称覆盖，解绑后重绑同样重置并同步影响其他关联账户。

## [P1] 验证首次绑定写入当前账号昵称快照作为设备备注
- 测试类型
  - 功能
- 前置条件
  1. 已入库牛马定位器 DEV-BIND-3001 卡号为 898600100000003001，当前无任何个人或企业一级绑定，设备级备注为空
  2. 个人账号 personal_21 当前昵称为「青山牧场」，绑定配额充足
  3. personal_21 可用真实分组为「默认设备组」
- 测试步骤
  1. personal_21 扫描 DEV-BIND-3001 并进入绑定确认页。
  2. 保持 Device Name 默认值不修改，选择分组「默认设备组」。
  3. 提交绑定并等待成功。
  4. 在 APP 列表、详情抽屉、服务端设备资料接口和管理端查询 DEV-BIND-3001。
- 预期结果
  1. 确认页按设备唯一标识 DEV-BIND-3001 加载，Device Name 纯备注字段默认显示当前昵称快照「青山牧场」，不拼接卡号。
  2. 备注允许编辑但本次保持「青山牧场」，分组满足绑定保存条件。
  3. 建立 personal_21 的唯一直接绑定关系，服务端设备级纯备注字段写入「青山牧场」。
  4. APP 列表与详情抽屉完整标题均为「青山牧场（898600100000003001）」；服务端资料接口和管理端备注字段均为纯值「青山牧场」，不得保存或展示成同一字段格式。

## [P2] 验证账号昵称后续变化不回写既有设备备注
- 测试类型
  - 功能
- 前置条件
  1. DEV-BIND-3002 卡号为 898600100000003002，已首次绑定 personal_22，绑定时昵称快照和当前设备备注均为「河湾牧场」
  2. personal_22 有权限修改自己的账号昵称
- 测试步骤
  1. 将 personal_22 账号昵称从「河湾牧场」修改为「河湾牧场新版」。
  2. 刷新 DEV-BIND-3002 设备列表与详情抽屉。
  3. 退出 APP 后重新登录并进入设备编辑页。
  4. 查询设备资料更新记录与账号资料更新记录。
- 预期结果
  1. 账号昵称更新为「河湾牧场新版」，但不触发设备资料写请求。
  2. DEV-BIND-3002 APP 列表和详情抽屉完整标题仍为「河湾牧场（898600100000003002）」。
  3. 编辑页 Device Name 纯备注字段仍回显「河湾牧场」，不拼接卡号，也不被当前账号昵称动态替换。
  4. 仅存在账号昵称更新记录，服务端和管理端设备级纯备注字段无回写记录且值保持「河湾牧场」。

## [P1] 验证另一类账户新增绑定用新绑定账号昵称覆盖已有非空备注
- 测试类型
  - 功能
- 前置条件
  1. DEV-BIND-3003 卡号为 898600100000003003，已绑定 personal_23，设备级备注为个人侧编辑后的非空值「个人自定义备注」
  2. 企业一级账号 corp_l1_23 当前昵称为「远山企业」，企业直接绑定槽位和配额均可用
  3. corp_l1_23 可用真实分组为「企业设备组」
- 测试步骤
  1. corp_l1_23 发起绑定 DEV-BIND-3003 并进入确认页。
  2. 保持默认 Device Name「远山企业」，选择「企业设备组」后提交绑定。
  3. personal_23 刷新列表并打开 DEV-BIND-3003 详情抽屉。
  4. corp_l1_23 与管理端分别查询设备资料和绑定关系。
- 预期结果
  1. 个人绑定不阻断企业一级新增绑定，确认页 Device Name 纯备注字段默认使用新绑定账号昵称快照「远山企业」，不拼接卡号。
  2. 企业绑定成功后，服务端设备级纯备注字段由已有「个人自定义备注」覆盖为「远山企业」。
  3. personal_23 的 APP 列表与详情抽屉完整标题同步为「远山企业（898600100000003003）」，不得继续保留个人侧非空备注副本或只显示纯备注。
  4. 个人与企业一级两个绑定关系共存；两端 APP 标题均为「远山企业（898600100000003003）」，服务端资料接口和管理端备注字段均为纯值「远山企业」，各自分组关系保持独立。

## [P1] 验证解绑后重绑再次按当前昵称重置共享备注
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-BIND-3004 卡号为 898600100000003004，同时绑定 personal_24 与 corp_l1_24，当前设备级备注为「首次企业昵称」
  2. corp_l1_24 当前分组为「企业旧组」，personal_24 当前分组为「个人保留组」
  3. corp_l1_24 可正常解绑并仍有重绑配额
- 测试步骤
  1. corp_l1_24 解除与 DEV-BIND-3004 的绑定。
  2. 将 corp_l1_24 昵称修改为「重绑企业昵称」。
  3. corp_l1_24 重新绑定 DEV-BIND-3004，保持默认 Device Name 并选择真实分组「企业新组」后保存。
  4. personal_24、corp_l1_24 和管理端刷新该设备。
- 预期结果
  1. 仅企业侧绑定及其分组关系被清理，personal_24 的绑定与「个人保留组」关系继续有效；个人 APP 标题仍为「首次企业昵称（898600100000003004）」。
  2. 修改账号昵称本身不回写设备备注，重绑前服务端和管理端纯备注字段仍为「首次企业昵称」。
  3. 重绑确认页 Device Name 纯备注字段使用当次昵称快照「重绑企业昵称」；重绑成功后服务端设备级纯备注重置为该值，并建立企业侧「企业新组」关系。
  4. personal_24 与 corp_l1_24 的 APP 列表和详情抽屉完整标题均为「重绑企业昵称（898600100000003004）」；服务端资料接口和管理端备注字段均为纯值「重绑企业昵称」，personal_24 分组仍为「个人保留组」。
