# US-015 筛选设备并打开快捷操作

> 口径依据：唯一业务真源《革泰 APP 设备管理逻辑点梳理 plan.md》第 1.1～1.4、3.3～3.4、8～10 章。真源只定义各账号层级的最终级联边界，未定义解绑幂等键、重复请求响应、并发执行顺序、锁策略或审计次数；重试与并发结果仅作可靠性观察，通过标准以最终关系边界和无重复破坏为准。

## [P1] 验证解绑响应超时后重试不扩大个人解绑边界
- 测试类型
  - 稳定性
- 前置条件
  1. GT-DEV-0760 同时绑定 personal_0760 和 enterprise_l1_0760
  2. enterprise_l1_0760 已逐级分配给 enterprise_l2_0760、enterprise_l3_0760
  3. personal_0760 的分组「个人重试组」和围栏「个人重试围栏」关联 GT-DEV-0760
  4. GT-DEV-0760 存在设备主数据、库存、物联网卡 ICCID 8986040760000000060 和历史告警 ALM-0760
- 测试步骤
  1. personal_0760 提交解绑 GT-DEV-0760，在客户端未收到明确结果时模拟网络响应超时。
  2. 客户端恢复网络后，再次提交同一账号对同一设备的解绑操作。
  3. 记录两次请求的响应作为可靠性观察，并查询个人绑定、分组和围栏的最终状态。
  4. 刷新企业一级、二级、三级账号设备列表，并查询设备资产和 ALM-0760。
- 预期结果
  1. 两次请求的具体响应内容不作为本用例通过标准，系统最终状态可通过关系查询确认。
  2. personal_0760 的绑定、分组和围栏关联最终均不存在，不出现重复关系、半清理关系或扩大到其他账号的破坏。
  3. enterprise_l1_0760、enterprise_l2_0760、enterprise_l3_0760 仍可见 GT-DEV-0760，个人解绑未影响企业链。
  4. 设备主数据、库存、ICCID 8986040760000000060 和 ALM-0760 均保留。

## [P1] 验证并发移除同一二级关系最终只失效目标分支
- 测试类型
  - 可靠性
- 前置条件
  1. enterprise_l1_0761 绑定 GT-DEV-0761，并分配给 enterprise_l2_0761a、enterprise_l2_0761b
  2. enterprise_l2_0761a 已分配给 enterprise_l3_0761a1、enterprise_l3_0761a2，enterprise_l2_0761b 已分配给 enterprise_l3_0761b1
  3. enterprise_l2_0761a 分支存在分组和围栏关联
- 测试步骤
  1. 在同一时间窗口从 APP 设备管理和 Web 用户管理发起移除 enterprise_l2_0761a 的 GT-DEV-0761。
  2. 记录两个请求的响应和完成时间，仅作为可靠性观察。
  3. 查询 enterprise_l2_0761a 分支关系、分组和围栏的最终状态。
  4. 查询一级和 enterprise_l2_0761b 分支的最终关系。
- 预期结果
  1. 两个入口的响应组合和先后顺序不作为通过标准。
  2. enterprise_l2_0761a、enterprise_l3_0761a1、enterprise_l3_0761a2 的分配、分组和围栏关联最终失效，不残留重复或冲突关系。
  3. enterprise_l1_0761、enterprise_l2_0761b、enterprise_l3_0761b1 继续可见 GT-DEV-0761。
  4. 最终清理范围不超出目标二级及其下属三级分支。

## [P1] 验证一级解绑与下级移除并发后的最终关系不超出一级级联边界
- 测试类型
  - 可靠性
- 前置条件
  1. enterprise_l1_0762 绑定 GT-DEV-0762，并分配给 enterprise_l2_0762a、enterprise_l2_0762b
  2. enterprise_l2_0762a 已分配给 enterprise_l3_0762a，enterprise_l2_0762b 已分配给 enterprise_l3_0762b
  3. personal_0762 独立绑定 GT-DEV-0762
  4. GT-DEV-0762 存在设备主数据、库存、物联网卡 ICCID 8986040762000000062 和历史位置 POS-0762
- 测试步骤
  1. enterprise_l1_0762 发起一级解绑，同时 enterprise_l2_0762a 发起移除自己的设备。
  2. 记录两个请求的响应和完成时间，仅作为可靠性观察。
  3. 刷新企业全链与 personal_0762 的 APP、Web 列表。
  4. 查询企业链最终关系及设备资产、历史数据。
- 预期结果
  1. 两请求的执行先后与具体响应不作为通过标准。
  2. 最终一级绑定及 A、B 两个二级分支和各自三级分配全部失效，结果不残留局部有效的企业下游关系。
  3. 企业全链不可见 GT-DEV-0762，personal_0762 仍可见，个人链不受企业操作影响。
  4. 企业关系清理不超出一级企业链；设备主数据、库存、ICCID 8986040762000000062 和 POS-0762 均保留。

## [P1] 验证两个三级并发自移除后不影响父级或其他同级

  - 稳定性
- 前置条件

  2. enterprise_l3_0763a、enterprise_l3_0763b 最终不再可见，二者各自的分组、围栏和分配关系失效。
  3. enterprise_l1_0763、enterprise_l2_0763、enterprise_l3_0763c 继续可见 GT-DEV-0763。
  4. enterprise_l3_0763c 的分组、围栏和分配关系保持有效，不出现跨账号重复破坏。

## [P3][反向] 验证重复无权移除不改变目标关系边界
- 测试类型
  - 安全性
- 前置条件
  1. enterprise_l1_owner_0764 绑定 GT-DEV-0764，并分配给 enterprise_l2_owner_0764、enterprise_l3_owner_0764
  2. enterprise_l2_other_0764 与目标企业链无父子或设备关系
  3. GT-DEV-0764 存在设备主数据、库存和物联网卡 ICCID 8986040764000000064
- 测试步骤
  1. enterprise_l2_other_0764 连续三次提交移除 enterprise_l3_owner_0764 的 GT-DEV-0764 请求。
  2. 记录三次请求的返回和失败状态。
  3. 刷新目标企业链全部账号的设备列表。
  4. 查询绑定、分配、分组、围栏及设备资产记录。
- 预期结果
  1. 重复提交不使 enterprise_l2_other_0764 获得目标设备或目标三级的操作权限。
  2. 三次请求的精确响应文案与内部处理次数不作为通过标准。
  3. 目标一级、二级、三级均继续可见 GT-DEV-0764，既有绑定、分配、分组和围栏关系保持不变。
  4. 设备主数据、库存、ICCID 8986040764000000064 保持不变，重复无权操作不产生任何级联破坏。
