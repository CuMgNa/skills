# US-015 筛选设备并打开快捷操作

> 口径依据：唯一业务真源《革泰 APP 设备管理逻辑点梳理 plan.md》第 1.1～1.4、3.3、8～10 章。企业一级解绑会使该一级下所有二级、三级分配失效，但不影响独立个人绑定，也不删除设备本体、库存、物联网卡和历史数据。

## [P1] 验证企业一级在 APP 解绑时清除全部下级分支
- 测试类型
  - 功能
- 前置条件
  1. enterprise_l1_0710 直接绑定设备 GT-DEV-0710，个人账号 personal_0710 也独立绑定该设备
  2. enterprise_l1_0710 已将设备分配给 enterprise_l2_0710a 和 enterprise_l2_0710b
  3. enterprise_l2_0710a 已分配给 enterprise_l3_0710a1、enterprise_l3_0710a2，enterprise_l2_0710b 已分配给 enterprise_l3_0710b1
  4. 企业三级账号各自存在关联 GT-DEV-0710 的分组和围栏；personal_0710 的「个人保留组」和「个人保留围栏」也关联该设备
  5. GT-DEV-0710 存在设备主数据、库存记录、物联网卡 ICCID 8986040710000000010、历史位置 POS-0710 和告警 ALM-0710
- 测试步骤
  1. 记录 GT-DEV-0710 的个人链、企业全链、分组、围栏及资产数据快照。
  2. enterprise_l1_0710 在 APP 设备卡片更多中执行 Unbind Device。
  3. 刷新 enterprise_l1_0710、两个二级和三个三级的 APP 与 Web 列表。
  4. 刷新 personal_0710 的 APP 与 Web 列表，并查询「个人保留组」「个人保留围栏」。
  5. 查询全部企业分组、围栏、设备主数据、库存、物联网卡和历史数据。
- 预期结果
  1. 快照包含一个企业一级直接绑定、两条二级分配、三条三级分配及一条独立个人绑定，个人侧分组和围栏均为非空对照。
  2. 企业一级直接绑定解除，级联清理仅沿 enterprise_l1_0710 企业链向下执行。
  3. enterprise_l1_0710、enterprise_l2_0710a、enterprise_l2_0710b、enterprise_l3_0710a1、enterprise_l3_0710a2、enterprise_l3_0710b1 均在 APP 与 Web 不再可见 GT-DEV-0710。
  4. personal_0710 仍可见 GT-DEV-0710；「个人保留组」和「个人保留围栏」仍关联该设备。
  5. 企业全链分组和围栏关联被清除；设备主数据、库存、ICCID 8986040710000000010、POS-0710、ALM-0710 均保留。

## [P1] 验证企业一级在 Web 解绑与 APP 级联范围一致
- 测试类型
  - 兼容性
- 前置条件
  1. enterprise_l1_0711 直接绑定 GT-DEV-0711
  2. enterprise_l1_0711 已分配给 enterprise_l2_0711，enterprise_l2_0711 已分配给 enterprise_l3_0711
  3. 三层账号在 APP 与 Web 均可见 GT-DEV-0711
- 测试步骤
  1. enterprise_l1_0711 在监控平台 Web 设备管理中移除 GT-DEV-0711。
  2. 刷新三级账号的 Web 设备列表。
  3. 刷新三级账号的 APP 设备列表。
  4. 查询一级绑定、二级分配和三级分配关系。
- 预期结果
  1. Web 按企业一级绑定解绑处理，不将动作误判为仅移除一级列表项。
  2. 一级、二级、三级在 Web 均不可见 GT-DEV-0711。
  3. 一级、二级、三级在 APP 同步不可见 GT-DEV-0711，级联范围与 Web 一致。
  4. 一级绑定及其下二级、三级分配关系均失效，无端侧残留关系。

## [P1] 验证企业一级解绑后重绑只建立确认页选择的新分组
- 测试类型
  - 可靠性
- 前置条件
  1. enterprise_l1_0712 曾绑定 GT-DEV-0712 并分配给 enterprise_l2_0712 和 enterprise_l3_0712
  2. 企业一级、二级、三级账号曾分别将设备加入旧分组「一级车队」「二级车队」「三级车队」和旧围栏「一级围栏」「二级围栏」「三级围栏」
  3. enterprise_l1_0712 已解绑，企业链分配、旧分组和旧围栏关联均已失效
  4. enterprise_l1_0712 已存在空的新分组「一级重绑新组」
  5. GT-DEV-0712 存在设备主数据、库存、物联网卡 ICCID 8986040712000000012 和历史告警 ALM-0712
- 测试步骤
  1. enterprise_l1_0712 重新绑定 GT-DEV-0712，并在绑定确认页显式选择「一级重绑新组」。
  2. 刷新 enterprise_l1_0712 的 APP 与 Web 列表，查询新旧分组。
  3. 刷新 enterprise_l2_0712、enterprise_l3_0712 的 APP 与 Web 列表。
  4. 查询旧分组「二级车队」「三级车队」和三个旧围栏的设备关联。
  5. 查询设备主数据、库存、物联网卡和 ALM-0712。
- 预期结果
  1. 仅重新建立 enterprise_l1_0712 的企业一级直接绑定，并按确认选择建立「一级重绑新组」关系。
  2. enterprise_l1_0712 在 APP 与 Web 可见 GT-DEV-0712；「一级重绑新组」包含该设备，旧分组「一级车队」不自动恢复。
  3. enterprise_l2_0712、enterprise_l3_0712 默认仍不可见，需重新逐级分配。
  4. 「二级车队」「三级车队」及「一级围栏」「二级围栏」「三级围栏」均不自动恢复设备关联。
  5. 设备主数据、库存、ICCID 8986040712000000012 和 ALM-0712 均保留。

## [P3][反向] 验证非归属企业一级不能解绑其他一级的设备

- 前置条件

- 测试步骤
