# US-015 筛选设备并打开快捷操作

> 口径依据：设备管理大纲第 2.2、2.4、6.2、10 章。设备列表级「指令下发」进入多选模式，设备 More 菜单中的 `Send Command` 进入当前设备的单设备下发页；两个入口必须按设备唯一标识隔离，不能混用导航目标或选择上下文。批量指令参数、全选及执行闭环由指令专项覆盖。

## [P1] 验证设备列表级指令下发进入多选模式
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 GT-E1-1501 当前可见在线设备 GT-D-150101、离线设备 GT-D-150102、初始化未连接设备 GT-D-150103
  2. 当前设备列表选择虚拟「全部分组」，三台设备均在列表中展示
- 测试步骤
  1. 在设备列表操作区点击「指令下发」。
  2. 检查页面模式、设备卡片选择控件和已选数量。
  3. 依次选择 GT-D-150101、GT-D-150102。
  4. 核对当前选择集合中的设备唯一标识。
- 预期结果
  1. 当前设备列表进入批量选择模式，不跳转到任一设备的单设备下发页。
  2. 当前可见设备出现可选择控件，初始已选数量为 0。
  3. 已选数量依次变为 1、2，离线设备不会仅因通信状态被排除出选择入口。
  4. 选择集合只包含 GT-D-150101、GT-D-150102，各设备按 deviceId 记录一次，不使用备注或列表位置作为身份。

## [P1] 验证列表多选入口与单设备 More 入口导航目标相互隔离
- 测试类型
  - 功能
- 前置条件
  1. 个人账号 GT-P-1501 可见设备 GT-D-150111，卡号 898604121501000001，备注「东区定位器」，状态为在线
  2. 设备列表未进入多选模式，GT-D-150111 的 More 菜单包含 `Send Command`
- 测试步骤
  1. 点击设备列表级「指令下发」并记录页面模式后退出。
  2. 打开 GT-D-150111 的 More 菜单并点击 `Send Command`。
  3. 检查打开页面的类型和设备身份参数。
  4. 返回设备列表并检查是否残留上一次批量选择状态。
- 预期结果
  1. 列表级入口进入多选模式，不预先绑定单台设备。
  2. More 面板关闭并只执行一次单设备导航。
  3. 进入 deviceId=GT-D-150111 的单设备下发页，不进入批量选择模式。
  4. 返回后不残留步骤 1 的临时选择集合，两个入口的页面状态和导航参数相互隔离。

## [P3][反向] 验证同备注设备在多选模式下不会被合并或重复选择
- 测试类型
  - 可靠性
- 前置条件
  1. 企业二级账号 GT-E2-1501 可见 deviceId=GT-D-150121 和 deviceId=GT-D-150122
  2. 两台设备备注均为「北场牛群」，卡号分别为 898604121501000121、898604121501000122
  3. 服务端返回的当前可见设备列表中两台设备各有一条展示记录
- 测试步骤
  1. 从设备列表级「指令下发」进入多选模式。
  2. 搜索备注「北场牛群」并选择两条结果。
  3. 对 GT-D-150121 的选择控件连续点击两次。
  4. 核对选择集合和已选数量。
- 预期结果
  1. 页面进入多选模式并保留当前账号权限范围。
  2. 搜索结果分别展示 GT-D-150121、GT-D-150122，两台设备不因备注相同被合并。
  3. 同一设备的重复点击只切换其选中状态，不产生两个相同 deviceId 的选择项。
  4. 选择集合按 deviceId 去重，数量与最终处于选中状态的唯一设备数一致。

## [P3][反向] 验证退出多选模式不创建指令或改变设备业务状态
- 测试类型
  - 可靠性
- 前置条件
  1. 企业三级账号 GT-E3-1501 可见设备 GT-D-150131、GT-D-150132
  2. 两台设备当前无新增批量指令记录，设备归属、分组、通信状态和告警状态已记录
- 测试步骤
  1. 进入设备列表级指令多选模式并选择 GT-D-150131、GT-D-150132。
  2. 未进入参数确认或提交步骤，直接点击取消或返回退出多选模式。
  3. 查询两台设备的指令记录新增数。
  4. 核对设备归属、分组、通信状态和告警状态。
- 预期结果
  1. 页面仅形成包含两个 deviceId 的本地临时选择集合。
  2. 退出后恢复普通设备列表，临时选择集合被清除。
  3. 两台设备的指令记录新增数均为 0，不产生 SENDING、SENT、FAILURE 或 CANCEL 记录。
  4. 设备归属、分组、通信状态和告警状态均未因进入或退出多选模式发生变更。

## [P1] 验证批量入口对离线未连接设备的普通指令允许提交
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 GT-E1-1502 可见离线设备 GT-D-150141 和初始化未连接设备 GT-D-150142
  2. 测试指令契约将 NORMAL-01 配置为普通队列指令，两台设备关系、权限、型号、路由、参数、幂等键和队列容量均满足
- 测试步骤
  1. 从设备列表级指令下发进入多选模式，选择 GT-D-150141、GT-D-150142。
  2. 选择 NORMAL-01，填写合法参数 600 并提交批量指令。
  3. 查询服务端对两台设备的逐设备准入结果和指令记录。
  4. 返回列表核对两台设备基础通信状态。
- 预期结果
  1. 两台设备均可进入批量选择集合，不因离线或未连接被入口排除。
  2. 批量请求按两个唯一 deviceId 提交，普通指令不要求在线会话。
  3. 两台设备分别通过服务端校验并各创建一条普通队列任务，不合并、不漏建、不重复。
  4. 指令受理不把设备基础通信状态伪改为在线，列表继续展示各自实际状态。

## [P3][反向] 验证批量高危指令按每台设备提交时实时会话独立复检
- 测试类型
  - 安全性
- 前置条件
  1. 企业一级账号 GT-E1-1503 可见设备 GT-D-150151、GT-D-150152、GT-D-150153
  2. 三台设备页面快照均显示 HIGH-RISK-01 可选；提交前 GT-D-150151 保持有效在线会话、GT-D-150152 会话断开、GT-D-150153 设备关系被回收
  3. HIGH-RISK-01 使用相同合法参数，三台设备的其他校验条件满足
- 测试步骤
  1. 在批量模式选择三台设备并提交 HIGH-RISK-01。
  2. 查询服务端对每个 deviceId 的实时会话、关系与权限复检结果。
  3. 查询实际执行队列和设备侧接收记录。
  4. 刷新设备列表和批量结果页。
- 预期结果
  1. 批量请求携带三个唯一 deviceId，客户端旧快照不作为最终放行依据。
  2. GT-D-150151 通过实时复检；GT-D-150152 因无有效在线会话失败；GT-D-150153 因关系失效失败，结果逐设备可区分。
  3. 仅 GT-D-150151 进入高危指令实际执行队列并可发送到设备；另外两台不得进入执行链。
  4. 页面展示一条成功、两条对应原因的失败结果，刷新后失权设备退出可选范围，离线设备高危指令按最新状态置灰。
