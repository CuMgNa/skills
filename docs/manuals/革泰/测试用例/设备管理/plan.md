# 革泰 APP 设备管理测试用例集

## 依据文档

- 需求真源：`docs/manuals/革泰/逻辑大纲/革泰 APP 设备管理逻辑点梳理 plan.md`（v2.3，2026-10-12）。
- 正式口径：仅采用真源中已确认的账号权限、设备关系、列表状态、设备绑定、分组、详情、编辑、定位频率、SIM 查询、解绑级联和跨端一致性规则。
- 专项边界：告警产生与处理、围栏判定、轨迹回放、批量指令完整闭环及单设备具体指令参数仍由各专项大纲验收；本用例集只验证设备管理入口及已明确的联动边界。
- 缺失资料：真源引用的部分 Notion 确认稿、本地旧卡片大纲及平台说明书当前无同名本地副本，本用例集未推断或补造其内容。
- 格式参考：`docs/manuals/革泰/测试用例/地理围栏/` 仅用于 Markdown 层级、目录命名和表达方式，不作为设备管理业务规则来源。

## 测试对象与覆盖范围

### 覆盖范围

- 个人、企业一级、企业二级、企业三级的登录、直接绑定、逐级分配、设备可见和服务端授权边界。
- 设备列表全部、在线、离线、告警状态模型，未连接归离线，状态、分组、关键词组合筛选及计数守恒。
- 设备卡片标题、电量、告警叠加、最后确认定位频率、点击区域和 More 菜单导航。
- 设备列表级指令下发多选入口与单设备 More 指令入口的模式、身份和临时状态隔离。
- IoT SIM Query 的设备标识查询链、字段映射、空值/零值、ICCID 完整性、有效期、异常重试和权限变化。
- APP 绑定入口、校验优先级、设备库存与类型、双槽位、配额原子性、确认页、幂等及绑定后多端刷新。
- 「同步分组和设备」全量覆盖与「仅分配设备」保留原分组、进入「我的分组」的差异及跨端最新结果。
- 个人、企业一级、企业二级、企业三级解绑/移除的级联范围，后台改绑、历史保留和重复解除幂等。
- 分组数据源、虚拟/真实分组、初始化、零分组、名称边界、重命名、删除、选择器和设备改组。
- 详情抽屉、字段展示白名单、底部轨迹/追踪/编辑入口、经纬度校验与度分秒转换、时区、地图入口、缓存切换和失权处理。
- 设备备注、跨账号共享备注、绑定名称覆盖、编辑保存与取消。
- 定位频率四层值、1～1440 分钟边界、离线提交、幂等、顺序队列、乱序反馈、四态和部分成功。
- 告警入口移除、告警状态叠加、单设备指令入口、普通/高危指令通信准入和指令记录权限。
- APP、Web、管理后台的数据一致性、数量刷新、缓存隔离、冻结/到期边界和重新绑定生命周期。
- 新牛马定位器从库存到查询的完整接入、协议适配隔离及旧设备类型回归。

### 不覆盖或不写死的内容

- 不自行定义告警生成、处理状态同步、围栏判定、轨迹算法和批量指令业务规则。
- 不把配额测试夹具值写成产品正式上限；`bindingQuota`、`allocationQuota`、`visibleDeviceLimit` 的产品数值以最新配置和接口契约为准。
- 不写死设备列表默认排序、完整自动刷新触发时机、前后台切换刷新 SLA 或卡片告警角标具体视觉形态。
- 不写死流量字段来源、统一单位、套餐周期、舍入规则及连续刷新冷却倒计时。
- 不自行定义冻结账号和服务到期后的完整页面能力矩阵、错误码或精确提示文案。
- 不新增指令状态 `ACKED` 或独立超时状态；只使用 SENDING、SENT、FAILURE、CANCEL。

## 测试数据约定

### 账号和组织

- 个人账号：`personal_dm_01`、`personal_dm_02`。
- 企业一级账号：`corp_dm_l1_a`、`corp_dm_l1_b`。
- 企业二级账号：`corp_dm_l2_a1`、`corp_dm_l2_a2`。
- 企业三级账号：`corp_dm_l3_a11`、`corp_dm_l3_a12`。
- 跨企业、冻结、到期、并发等场景使用的其他账号必须在前置条件中写明组织归属和状态。

### 设备与关系

- 标准牛马定位器：`GT-DM-0001`、`GT-DM-0002`、`GT-DM-0003`。
- 标准卡号：`898604121000100001`、`898604121000100002`、`898604121000100003`。
- 同一设备最多同时存在 1 个个人直接绑定和 1 个企业一级直接绑定；企业二、三级只建立分配关系。
- 每条用例必须明确 deviceId、当前账号关系来源、设备通信状态、分组及是否存在告警。

### 分组

- 海外构建版本分组名称长度为 1～40 字符；国内构建版本为 1～15 字符，构建版本不随 UI 语言切换。
- 设备备注长度为 0～40 字符，保存时裁剪首尾空格；分组名称则保留首尾空格并按原值精确判重。
- 虚拟“全部分组”不得作为设备归属；真实组可使用同名“全部分组”。

### 定位频率与指令

- 合法频率：1～1440 的整数分钟；1、10、60 分钟分别转换为 60、600、3600 秒。
- 每次明确 Save 操作使用独立幂等键；首次提交创建 commandId 和 attemptId，重发保留 commandId 并创建新 attemptId。
- 同设备任务使用 configSequence 串行执行；乱序旧反馈不得覆盖更新目标或已确认值。

## 核心验收纪律

1. 登录资格、设备可见资格和直接绑定资格必须分别校验，APP 隐藏入口不能替代服务端鉴权。
2. 当前账号列表、状态数量、地图和分组数量均按设备唯一标识去重，不按关系记录数重复计算。
3. 在线与离线互斥且覆盖全部设备；未连接归入离线；告警与在线/离线叠加。
4. 设备事实和设备备注全局同源；分组、围栏和可见关系属于账号维度，不得跨账号串改。
5. 绑定配额校验与关系创建必须处于同一事务或等效原子边界；重复请求最多产生一条关系和一次配额变化。
6. APP 中删除设备只解除当前账号对应的直接绑定或分配关系，不删除设备本体、库存、SIM 和历史事实数据。
7. 企业一级关系解除会清除整条下游分配链；二级仅清除自身及其三级；三级只清除自身；无关个人槽位和企业分支不得受影响。
8. 每台设备在每个账号下必须且只能属于一个真实分组；删除分组不得级联删除子组或自动迁移设备。
9. 详情坐标和定位时间必须来自同一条最后有效定位；任一经纬度无效时经度、纬度、定位时间成组隐藏。
10. 卡片只显示 confirmedValue；编辑页按 localEditValue、desiredValue、confirmedValue、请选择的优先级展示。
11. 资料保存和频率任务相互独立，一方失败不得回滚另一方已成功结果。
12. 快速切换账号或设备时，旧缓存和晚到响应不得覆盖当前身份数据。
13. 待确认数值和交互不得写成正式验收通过线；测试夹具值必须明确为测试配置。
14. 所有用例步骤与预期结果逐条对应，失败路径同时验证正式数据、关系、配额、缓存和前端展示不得假成功。

## 待确认项与执行处理

| 待确认项 | 本用例集处理 |
| --- | --- |
| 列表默认排序和完整刷新机制 | 只验收手动刷新、返回上下文和已明确配置值；默认排序及前后台刷新时序仅记录现状。 |
| 告警角标具体视觉与读屏语义 | 只验收告警主体表达和在线/离线底层差异，不固定颜色以外的形状或读屏文案。 |
| 电量小数舍入、历史电量优先级 | 验收已确认的有效范围和 20% 阈值；小数舍入及历史值选择仅记录。 |
| 流量字段来源、单位、周期和舍入 | 使用接口声明的测试响应核对数值守恒，不固定 `data_usage`/`cycle_data_usage`、统一单位或换算基数。 |
| 绑定、分配和最终可见配额具体数值 | 使用明确测试夹具验证边界、并发和回收；不声明产品上限。 |
| 二维码载荷和标识映射错误码 | 只验收最终解析为已入库设备卡号及统一校验链，载荷类型和精确错误码待契约确认。 |
| 分组总量、单组容量及排序冲突 | 不写死容量上限；容量失败按服务端测试配置验证原子性，排序冲突只记录现状。 |
| 高危指令名称、快照有效期和队列超时细节 | 只验收设备管理入口、服务端实时复检和统一四态，不扩写专项规则。 |
| 冻结账号与服务到期能力矩阵 | 只验证确定的访问限制、设备上报继续入库和数据不丢失；页面能力与错误码待补充。 |
| 解绑后“重建”含义 | 正式验收旧分配、分组和围栏不自动恢复；新关系与围栏基线按对应专项规则重新建立。 |

## 合并与维护规则

- `all_cases.md` 按 `US-015`、`US-016`、`US-017`、`US-018`、`US-019`、`US-020`、`US-022`、`US-032` 顺序合并，各 US 内按 `POINT-xxx` 升序排列。
- 每个用户故事使用 `# US-xxx 用户故事名称`，每个测试点使用 `## POINT-xxx 测试点名称` 作为分隔标记。
- 修改任何 POINT 后必须重新生成 `all_cases.md`，并执行标题、测试类型、编号、占位符、重复标题及源文件嵌入完整性校验。
