# US-017 管理账户内设备分组
> 口径依据：大纲第 4.3、4.5、4.10 章。当前账号名下任意一级、二级、三级组均可在 APP 重命名；重命名只更新名称，不改变 groupId、层级、父子关系和设备归属，失败保留输入，同名自身不应被误判，同账户并发仍须满足名称唯一性。

## [P1] 验证有子组和直属设备的一级组可重命名
- 测试类型
  - 功能
- 前置条件
  1. ent_l1_12 有一级组「旧牧场」，groupId 为 G-L1-1201
  2. 「旧牧场」直属设备为 GT-D-0811，直接子组为二级「牛群一区」
- 测试步骤
  1. 在 APP 将「旧牧场」重命名为「新牧场」并保存。
  2. 刷新管理页并查看「牛群一区」的父组信息。
  3. 查询 G-L1-1201 的层级、设备关系和子组关系。
- 预期结果
  1. 即使存在直属设备和子组，重命名仍成功且名称变为「新牧场」。
  2. 「牛群一区」的直接父组名称同步显示为「新牧场」。
  3. groupId 仍为 G-L1-1201、Level 仍为 1，GT-D-0811 和「牛群一区」关系均不变。

## [P1] 验证 Web 创建的二三级组可在 APP 重命名
- 测试类型
  - 功能
- 前置条件
  1. ent_l2_12 在 Web 创建二级组「二级旧名」和三级组「三级旧名」
  2. 两组 groupId 分别为 G-L2-1202、G-L3-1203
- 测试步骤
  1. 在 APP 将 G-L2-1202 重命名为「二级新名」。
  2. 在 APP 将 G-L3-1203 重命名为「三级新名」。
  3. 在 APP 与 Web 分别重新加载分组结构。
- 预期结果
  1. 二级组重命名成功，层级与父组不变。
  2. 三级组重命名成功，层级与父组不变。
  3. 两端均读取新名称和原 groupId，不因创建端为 Web 限制 APP 管理能力。

## [P2] 验证名称未变化时不把当前分组自身判为重名
- 测试类型
  - 功能
- 前置条件
  1. personal12 存在一级组「保留原名」，groupId 为 G-L1-1210
  2. 账户内无其他精确同名组
- 测试步骤
  1. 打开 G-L1-1210 重命名弹窗，不修改名称并点击保存。
  2. 刷新分组管理页。
  3. 查询 personal12 下精确名称「保留原名」的记录。
- 预期结果
  1. 保存不会提示名称已存在，不把 G-L1-1210 自身计入冲突对象。
  2. 页面仍展示「保留原名」，结构和设备关系无变化。
  3. 账户内仍仅有 G-L1-1210 一条记录，不新增重复组。

## [P3][反向] 验证重命名失败保留用户输入和原正式关系
- 测试类型
  - 可靠性
- 前置条件
  1. personal12 存在一级组「网络前名称」，groupId 为 G-L1-1211
  2. 本次重命名请求模拟服务端失败
- 测试步骤
  1. 输入新名称「网络后名称」并点击保存。
  2. 查看失败后的重命名弹窗和管理页。
  3. 恢复网络后再次提交「网络后名称」。
- 预期结果
  1. 服务端失败时不显示重命名成功，并返回可读失败原因。
  2. 弹窗保留「网络后名称」供重试，正式数据仍为「网络前名称」且 groupId、关系不变。
  3. 重试成功后正式名称更新为「网络后名称」，不创建第二个分组。

## [P1] 验证两个不同分组并发改成同名时仅一个成功
- 测试类型
  - 可靠性
- 前置条件
  1. personal12 存在 G-L1-1212「并发原名A」和 G-L1-1213「并发原名B」
  2. APP-A、APP-B 分别打开两个分组的重命名弹窗，账户内尚无「统一并发名称」
- 测试步骤
  1. APP-A 与 APP-B 同时提交目标名称「统一并发名称」。
  2. 记录两个请求结果和各自弹窗状态。
  3. 查询 personal12 全部分组并按名称「统一并发名称」精确统计。
  4. 两端重新进入 Device Groups。
- 预期结果
  1. 服务端唯一性约束下恰好一个请求保存成功，另一个因分组名称已存在而失败。
  2. 成功端关闭弹窗；失败端保留「统一并发名称」输入和原 groupId，不伪造成功。
  3. 同一账户最终精确名称「统一并发名称」记录数为 1，G-L1-1212、G-L1-1213 均未被复制或合并。
  4. 两端刷新后显示一致的最终名称集合，失败分组仍保留其原正式名称。
