# US-017 管理账户内设备分组
> 口径依据：大纲第 4.2、4.9、4.10、5.8、9、10 章。设备改组选择真实一级、二级或三级 groupId，随设备资料整页保存生效；取消不变，目标删除等失败保留原归属，成功刷新相关直属数量与状态数量，且只影响当前账户。

## [P1] 验证目标组保存前改名仍按 groupId 完成整页改组
- 测试类型
  - 功能
- 前置条件
  1. personal18 的 GT-D-0841 当前归属一级组「牧场东区」，groupId 为 G-L1-1801
  2. 目标二级组初始名称「牛群A区」，groupId 为 G-L2-1802
- 测试步骤
  1. 从 GT-D-0841 详情抽屉进入独立编辑页并选择「牛群A区」。
  2. 保存前在 Web 将 G-L2-1802 重命名为「牛群A区新名」。
  3. 点击整页保存并抓取请求中的分组字段。
  4. 刷新详情、列表和分组选择器。
- 预期结果
  1. 选择后只更新本地表单，正式归属仍为 G-L1-1801。
  2. 服务端目标组名称变更但 groupId 仍为 G-L2-1802。
  3. 保存请求提交目标 groupId G-L2-1802，不以旧名称「牛群A区」作为身份；保存成功后设备唯一归属 G-L2-1802。
  4. 各页面展示服务端最新名称「牛群A区新名」，原组直属数减 1、目标组直属数加 1，相关状态数量刷新。

## [P2] 验证选择新分组后取消编辑不产生变更
- 测试类型
  - 功能
- 前置条件
  1. personal18 的 GT-D-0842 当前归属三级组「犊牛一区」
  2. 编辑页可选择一级组「牧场西区」
- 测试步骤
  1. 在编辑页把所属分组从「犊牛一区」改选为「牧场西区」。
  2. 不保存并执行取消返回。
  3. 重新打开 GT-D-0842 编辑页并查询服务端 groupId。
- 预期结果
  1. 新选择仅存在于当前本地表单。
  2. 取消后不提交设备资料或改组请求。
  3. GT-D-0842 仍归属「犊牛一区」，两个分组直属数量均不变化。

## [P3][反向] 验证目标分组保存前被删除时失败并保留原归属
- 测试类型
  - 可靠性
- 前置条件
  1. personal18 的 GT-D-0843 当前归属「原始牛群」，groupId 为 G-L1-1803
  2. 空目标组「临时目标组」groupId 为 G-L1-1804，可由 Web 删除
- 测试步骤
  1. 在编辑页选择「临时目标组」。
  2. 保存前在 Web 删除 G-L1-1804。
  3. APP 点击整页保存并查看失败后的编辑页。
  4. 查询 GT-D-0843 正式 groupId 及原组直属数量。
- 预期结果
  1. 选择只写入本地表单，尚未改变正式关系。
  2. G-L1-1804 删除后不再是当前账户可用真实组。
  3. 保存因目标分组已失效而失败并展示可读提示，编辑页保留用户输入供重新选择，不伪造成功。
  4. GT-D-0843 仍唯一归属 G-L1-1803，原组直属数量和状态数量不发生部分更新。

## [P3][反向] 验证目标组仍存在但当前账户失权时改组失败且不部分更新
- 测试类型
  - 可靠性
- 前置条件
  1. ent_l2_18 的 GT-D-0845 当前归属「二级原组」，groupId 为 G-L1-1805，原组直属设备数为 4
  2. 目标三级组「授权目标组」groupId 为 G-L3-1806，当前直属设备数为 2，初始对 ent_l2_18 可选且服务端记录持续存在
- 测试步骤
  1. 在编辑页选择 G-L3-1806，并将备注草稿改为「失权改组草稿」。
  2. 保存前撤销 ent_l2_18 对 G-L3-1806 的使用权限，但保留目标分组记录及其对其他有权账户的可见性。
  3. APP 点击整页保存并查看失败后的编辑页草稿。
  4. 查询 GT-D-0845 正式资料、正式 groupId、G-L1-1805 与 G-L3-1806 的直属设备数。
- 预期结果
  1. 分组和备注修改仅形成当前本地草稿，正式资料及归属尚未变化。
  2. G-L3-1806 仍存在，但已不是 ent_l2_18 有权使用的真实分组，不能仅凭 groupId 存在放行。
  3. 保存因目标组权限失效而拒绝，展示可读原因并保留「失权改组草稿」及目标选择供用户修正，不伪造成功。
  4. 正式备注不变，GT-D-0845 仍唯一归属 G-L1-1805；原组直属数仍为 4、目标组仍为 2，双方数量和状态数量均无部分更新。

## [P3][反向] 验证目标组达到测试配置容量上限时改组失败且不部分更新
- 测试类型
  - 可靠性
- 前置条件
  1. personal18 的 GT-D-0846 当前归属「容量原组」，groupId 为 G-L1-1807，原组直属设备数为 3
  2. 测试环境把单组容量配置为 2；目标组「容量目标组」groupId 为 G-L2-1808，已直属 GT-D-0851、GT-D-0852 共 2 台
  3. 容量 2 仅为本用例可调测试配置，不代表或写死产品固定上限
- 测试步骤
  1. 在编辑页选择已达测试配置容量的 G-L2-1808，并将备注草稿改为「容量失败草稿」。
  2. 点击整页保存并记录服务端容量校验结果。
  3. 核对失败后的分组和备注草稿。
  4. 查询 GT-D-0846 正式资料、正式 groupId 及两个分组的直属设备数。
- 预期结果
  1. 选择目标组和修改备注只形成本地草稿，不立即改组或更新正式资料。
  2. 服务端按当前测试配置拒绝超容量保存并展示可读原因；APP 不把数值 2 固化为产品上限。
  3. 编辑页保留 G-L2-1808 选择和「容量失败草稿」供用户修改或重试，不清空草稿、不假成功。
  4. 正式备注不变，GT-D-0846 仍唯一归属 G-L1-1807；原组直属数仍为 3、目标组仍为 2，双方数量和状态数量均无部分更新。

## [P1] 验证个人与企业账户并发改组同一设备保持确定隔离
- 测试类型
  - 可靠性
- 前置条件
  1. GT-D-0844 同时对 personal18 和 ent_l1_18 可见
  2. personal18 下归属「个人原组」，目标为「个人目标组」；ent_l1_18 下归属「企业原组」，目标为「企业目标组」
- 测试步骤
  1. personal18 与 ent_l1_18 同时分别提交各自目标 groupId 的整页保存。
  2. 等待两个保存请求均返回成功。
  3. 两个账户分别刷新设备编辑页、选择器数量和状态数量。
  4. 查询两个账户下 GT-D-0844 的分组关系记录。
- 预期结果
  1. 两个请求按各自账户上下文提交，不互相覆盖 groupId。
  2. personal18 成功归属「个人目标组」，ent_l1_18 成功归属「企业目标组」。
  3. 每个账户仅更新自己的原组和目标组直属数量及状态数量，另一账户数量不串改。
  4. 两个账户各恰好一条有效真实分组关系，分别指向各自目标 groupId。
