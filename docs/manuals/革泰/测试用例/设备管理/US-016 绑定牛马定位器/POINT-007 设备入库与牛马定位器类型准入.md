# US-016 绑定牛马定位器

> 口径依据：大纲第 3.1.3、3.2、第 8～10 章。APP 仅允许已在管理后台入库且后台类型字段为牛马定位器的设备进入绑定确认页；类型判断不得依赖设备名称或二维码文案，旧类型不因新类型接入而改变原有业务规则。

## [P1] 验证已入库牛马定位器通过准入校验
- 测试类型
  - 功能
- 前置条件
  1. 个人账号 person_inventory_01 已登录，配额和个人槽位可用
  2. 管理后台已入库 GT-CARD-3001，类型字段为牛马定位器，设备名称为「北区一号」
  3. person_inventory_01 未绑定 GT-CARD-3001
- 测试步骤
  1. 在 APP 绑定页输入 GT-CARD-3001 并提交。
  2. 查看服务端设备查询结果和 APP 页面流转。
  3. 选择真实分组「牛群 A 组」并确认绑定。
- 预期结果
  1. 系统取得设备卡号 GT-CARD-3001 并查询到已入库记录。
  2. 系统依据后台类型字段识别为牛马定位器，继续完成重复、配额和槽位校验并进入确认页。
  3. 建立一条 person_inventory_01 的直接绑定关系，设备归属「牛群 A 组」。

## [P3][反向] 验证有效格式但未入库设备卡号被拒绝
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 ent_l1_inventory_01 已登录且配额可用
  2. 设备卡号 GT-CARD-3999 符合输入格式但未在管理后台入库
- 测试步骤
  1. 手动输入 GT-CARD-3999 并提交绑定查询。
  2. 检查页面失败状态和接口失败字段。
  3. 查询设备主数据、绑定关系、账号设备数量和配额占用。
- 预期结果
  1. 卡号格式检查通过后，系统在入库查询阶段确认无对应设备。
  2. 页面展示设备不存在或未入库类别的可读原因，不进入确认页。
  3. 系统不自动创建设备主数据，不新增绑定关系，数量和配额占用不变。

## [P3][反向] 验证已入库北斗设备按类型不支持拒绝
- 测试类型
  - 兼容性
- 前置条件
  1. 个人账号 person_inventory_02 已登录且配额可用
  2. 管理后台已入库 GT-CARD-3101，类型字段为北斗设备，设备名称为「牛马定位器测试机」
- 测试步骤
  1. 在 APP 绑定页输入 GT-CARD-3101 并提交。
  2. 检查页面提示类别和接口返回的设备存在状态。
  3. 查询 GT-CARD-3101 的旧类型业务数据和新增绑定关系。
- 预期结果
  1. 系统查询到已入库设备，但依据后台类型字段判定当前 APP 绑定入口不支持。
  2. 展示设备类型不支持类别的可读原因，不误提示设备不存在，也不因名称包含「牛马定位器」而放行。
  3. 旧类型业务数据保持不变，不新增 person_inventory_02 的直接绑定关系。

## [P3][反向] 验证已入库星联卫士设备不因扫码文案被误判为牛马定位器
- 测试类型
  - 兼容性
- 前置条件
  1. 企业一级账号 ent_l1_inventory_02 已登录且配额可用
  2. 管理后台已入库 GT-CARD-3102，类型字段为星联卫士
  3. 测试二维码可被 APP 识别并最终取得设备卡号 GT-CARD-3102，二维码载荷格式和展示文案不纳入断言
- 测试步骤
  1. 在 APP 绑定页扫描测试二维码。
  2. 检查设备查询结果、后台类型字段和页面流转。
  3. 查询 ent_l1_inventory_02 的绑定数量、槽位和配额占用。
- 预期结果
  1. 扫码仅用于取得设备卡号 GT-CARD-3102，不以二维码内容直接决定设备类型。
  2. 系统确认设备已入库但后台类型不受支持，展示可读的类型失败原因并停止进入确认页。
  3. 不新增直接绑定关系，绑定数量、槽位和配额占用均不变化。

## [P3][反向] 验证 Web 与管理后台对未入库设备执行一致拦截
- 测试类型
  - 兼容性
- 前置条件
  1. 个人账号 person_inventory_web_01 可在监控平台 Web 直接绑定，企业一级账号 ent_l1_inventory_admin_01 可作为管理后台代绑目标
  2. 设备卡号 GT-CARD-3998 格式有效但未在管理后台入库
  3. 两个目标账号配额均有剩余且同类槽位为空
- 测试步骤
  1. person_inventory_web_01 在监控平台 Web 输入 GT-CARD-3998 并提交绑定。
  2. 后台管理员尝试将 GT-CARD-3998 代绑给 ent_l1_inventory_admin_01。
  3. 查询两次失败结果和设备查库记录。
  4. 查询目标账号关系、数量、配额和设备库存。
- 预期结果
  1. Web 在入库校验阶段拒绝绑定，提示设备不存在或未入库，不进入确认页。
  2. 管理后台同样拒绝代绑，不因操作主体为管理员绕过入库要求。
  3. 两次请求均命中同一未入库事实，不误报配额不足或槽位占用。
  4. 不自动创建设备库存或主数据，不新增任何绑定关系，两个账号数量和配额不变化。
