# US-016 绑定牛马定位器

> 口径依据：大纲第 3.1.3、3.1.5、3.2、3.4、第 8～10 章。确认页锁定前序设备身份；备注默认取账号昵称快照且允许为空；必须选择有权真实一至三级分组，无分组时创建一级组并自动回填；定位频率不进入绑定流程。

## [P1] 验证确认页只展示真实一二三级分组且不包含定位频率
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 ent_l1_confirm_01 已进入 GT-CARD-6001 的绑定确认页
  2. ent_l1_confirm_01 拥有一级分组「华北牧场」、二级分组「河北场」、三级分组「石家庄牛舍」
  3. GT-CARD-6001 后台当前确认定位频率为 10 分钟
- 测试步骤
  1. 检查确认页全部字段和可编辑控件，再打开分组选择器查看全部可选项。
  2. 选择「华北牧场」，查看待保存 groupId。
  3. 改选「河北场」，查看待保存 groupId。
  4. 改选「石家庄牛舍」并保存绑定，检查绑定请求、确认定位频率和待执行配置任务。
- 预期结果
  1. 确认页不展示 Location Interval 或其他定位频率填写、暂存控件；选择器只展示当前账号有权使用的真实一级、二级、三级分组，虚拟「全部分组」不在可选项中。
  2. 一级真实分组可选，待保存 groupId 对应「华北牧场」的真实唯一标识。
  3. 二级真实分组可选，待保存 groupId 更新为「河北场」的真实唯一标识。
  4. 三级真实分组可作为设备归属，GT-CARD-6001 成功保存到「石家庄牛舍」；请求不包含定位频率，原确认值仍为 10 分钟且不新增定位频率配置任务。

## [P3][反向] 验证篡改非法或虚拟 groupId 时服务端拒绝绑定
- 测试类型
  - 安全性
- 前置条件
  1. 企业一级账号 ent_l1_confirm_04 已分别进入 GT-CARD-6002、GT-CARD-6003 的绑定确认页
  2. ent_l1_confirm_04 拥有真实一级分组「合法归属组」
  3. 已准备虚拟「全部分组」对应的前端筛选标识，以及一个不存在、已删除或不属于当前账号的非法 groupId
- 测试步骤
  1. 使用调试代理将 GT-CARD-6002 确认请求中的真实 groupId 篡改为虚拟「全部分组」筛选标识并提交。
  2. 将 GT-CARD-6003 确认请求中的真实 groupId 篡改为非法 groupId 并提交。
  3. 查询两个设备的绑定关系、分组关系和同类槽位占用。
- 预期结果
  1. 服务端拒绝把虚拟「全部分组」作为设备归属，返回可读原因和明确失败态。
  2. 服务端按当前账号权限与真实分组有效性拒绝非法 groupId，不能仅依赖前端隐藏选项。
  3. GT-CARD-6002、GT-CARD-6003 均不产生绑定、分组关系或槽位占用，「合法归属组」不被错误写入。

## [P1] 验证设备备注默认取昵称快照且清空后仍可绑定
- 测试类型
  - 功能
- 前置条件
  1. 个人账号 person_confirm_01 的当前昵称为「牧场管理员小林」
  2. person_confirm_01 已进入 GT-CARD-6101 的绑定确认页
  3. person_confirm_01 拥有真实一级分组「默认分组」
- 测试步骤
  1. 查看确认页 Device Name 字段初始值。
  2. 清空 Device Name 字段并选择「默认分组」。
  3. 点击确认绑定并打开设备列表与详情资料。
  4. 查询设备级共享备注存储值。
- 预期结果
  1. Device Name 默认展示昵称快照「牧场管理员小林」。
  2. 字段允许清空，不因备注为空进入必填失败态。
  3. GT-CARD-6101 绑定成功，列表和详情对空备注使用同一数据源，不回填虚假默认备注。
  4. 设备级共享备注存储为空，不创建当前账号独立覆盖值。

## [P1] 验证无真实分组时创建一级组并自动回填
- 测试类型
  - 易用性
- 前置条件
  1. 企业一级账号 ent_l1_confirm_02 已进入 GT-CARD-6201 的绑定确认页
  2. ent_l1_confirm_02 当前不存在任何真实一级、二级或三级分组
- 测试步骤
  1. 打开 Group 选择器并查看可选项与引导操作。
  2. 按引导进入同一分组管理页，创建一级分组「新建牧场组」。
  3. 创建成功后返回绑定确认页。
  4. 保持自动选中结果并确认绑定。
- 预期结果
  1. 系统不把接口空结果当作可保存的「全部分组」，展示进入分组管理的可用引导。
  2. 成功创建真实一级分组「新建牧场组」，获得稳定 groupId。
  3. 返回原 GT-CARD-6201 确认页且设备身份不变，Group 自动选中「新建牧场组」。
  4. 绑定成功，GT-CARD-6201 在当前账号下归属「新建牧场组」。

## [P3][反向] 验证确认页不能切换为另一设备
- 测试类型
  - 安全性
- 前置条件
  1. 个人账号 person_confirm_02 已通过前序校验进入 GT-CARD-6301 确认页
  2. 管理后台另有已入库牛马定位器 GT-CARD-6302
  3. 已记录 GT-CARD-6301 与 GT-CARD-6302 的不同设备唯一标识
- 测试步骤
  1. 检查确认页是否存在设备卡号、设备唯一标识或重新扫码的可编辑切换入口。
  2. 使用调试代理将确认请求中的设备身份字段改为 GT-CARD-6302 对应值并提交。
  3. 查询两个设备与 person_confirm_02 的绑定关系和槽位。
- 预期结果
  1. 确认页设备身份为只读锁定状态，不提供切换到 GT-CARD-6302 的入口。
  2. 服务端拒绝与前序确认上下文不一致的设备身份，返回可读原因和明确失败态。
  3. GT-CARD-6301、GT-CARD-6302 均不因篡改请求产生错误绑定或槽位占用。
