# US-016 绑定牛马定位器

> 口径依据：大纲第 1.1～1.4、3.1.1～3.1.3、3.2、第 9～10 章。个人账号与企业一级账号可从「设备管理 → 绑定设备」发起直接绑定；企业二、三级无入口且服务端拒绝直接绑定；扫码与手输只验证最终取得同一已入库设备卡号，不固化二维码载荷格式。

## [P1] 验证个人账号扫码与手输取得同一已入库设备卡号
- 测试类型
  - 功能
- 前置条件
  1. 个人账号 person_bind_01 已登录 APP，存在「设备管理 → 绑定设备」入口
  2. 管理后台已入库牛马定位器，设备卡号为 GT-CARD-1001
  3. 测试二维码可被 APP 识别并关联到设备卡号 GT-CARD-1001，二维码载荷格式不纳入本用例断言
  4. person_bind_01 未绑定 GT-CARD-1001，配额和个人绑定槽位均可用
- 测试步骤
  1. 从设备管理页点击「绑定设备」，选择扫码并扫描测试二维码。
  2. 记录扫码查询返回的设备卡号和设备唯一标识，返回绑定方式选择页。
  3. 选择手动输入，输入设备卡号 GT-CARD-1001 并提交查询。
  4. 对比两种方式进入的绑定确认页设备身份信息。
  5. 选择真实一级分组「牧场设备」，将备注填写为「一号牛定位器」并确认绑定。
- 预期结果
  1. 扫码结果有效并进入 GT-CARD-1001 的绑定校验流程，不展示或要求用户理解底层编码映射。
  2. 扫码查询结果明确对应设备卡号 GT-CARD-1001，并取得稳定的设备唯一标识。
  3. 手动输入同样查询到设备卡号 GT-CARD-1001，未进入另一设备的确认页。
  4. 两种方式取得的设备卡号和设备唯一标识一致，确认页设备身份不可切换。
  5. person_bind_01 与该设备建立一条直接绑定关系，设备归属「牧场设备」。

## [P1] 验证企业一级账号通过唯一常规入口完成绑定
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 ent_l1_bind_01 已登录 APP
  2. 管理后台已入库牛马定位器 GT-CARD-1002
  3. ent_l1_bind_01 未绑定 GT-CARD-1002，企业一级配额和槽位均可用
  4. ent_l1_bind_01 拥有真实二级分组「北区牧场」
- 测试步骤
  1. 检查 APP 首页、无设备空状态和全局快捷区。
  2. 进入「设备管理」，点击「绑定设备」。
  3. 手动输入 GT-CARD-1002 并提交。
  4. 在确认页选择「北区牧场」并确认绑定。
- 预期结果
  1. 首页、无设备空状态和全局快捷区不新增绑定或扫码快捷入口。
  2. 设备管理页展示唯一常规「绑定设备」入口并可进入绑定流程。
  3. 系统按企业一级账号的配额和同类槽位校验 GT-CARD-1002，校验通过后进入确认页。
  4. 建立 GT-CARD-1002 到 ent_l1_bind_01 的一条企业一级直接绑定关系。

## [P3][反向] 验证企业二级和三级账号在 APP 无直接绑定入口
- 测试类型
  - 安全性
- 前置条件
  1. 企业二级账号 ent_l2_bind_01 已由直属一级分配设备 GT-CARD-1101
  2. 企业三级账号 ent_l3_bind_01 已由直属二级分配设备 GT-CARD-1102
- 测试步骤
  1. 使用 ent_l2_bind_01 登录 APP，检查首页、设备空状态、设备管理页和全局快捷区。
  2. 查看 ent_l2_bind_01 的设备列表。
  3. 使用 ent_l3_bind_01 登录 APP，检查相同入口区域。
  4. 查看 ent_l3_bind_01 的设备列表。
- 预期结果
  1. ent_l2_bind_01 可正常登录，但所有检查区域均不展示直接绑定入口或企业向下分配入口。
  2. 列表正常展示父级已分配的 GT-CARD-1101，该关系不显示为当前账号直接绑定。
  3. ent_l3_bind_01 可正常登录，但所有检查区域均不展示直接绑定入口或企业向下分配入口。
  4. 列表正常展示父级已分配的 GT-CARD-1102，该关系不占用直接绑定槽位或 bindingQuota。

## [P3][反向] 验证企业二级和三级构造直接绑定请求时服务端拒绝
- 测试类型
  - 安全性
- 前置条件
  1. 企业二级账号 ent_l2_bind_02 和企业三级账号 ent_l3_bind_02 均处于有效登录状态
  2. 管理后台已入库且可绑定的牛马定位器设备卡号分别为 GT-CARD-1201、GT-CARD-1202
  3. 已取得 APP 正常绑定请求的接口路径和必填字段定义，不修改服务端权限配置
- 测试步骤
  1. 携带 ent_l2_bind_02 的有效会话构造 GT-CARD-1201 直接绑定请求并提交。
  2. 查询 ent_l2_bind_02、直属一级账号和 GT-CARD-1201 的绑定及分配关系。
  3. 携带 ent_l3_bind_02 的有效会话构造 GT-CARD-1202 直接绑定请求并提交。
  4. 查询 ent_l3_bind_02、直属二级账号和 GT-CARD-1202 的绑定及分配关系。
- 预期结果
  1. 服务端拒绝企业二级直接绑定，响应包含可读的权限失败原因和明确失败态，不进入确认或建链流程。
  2. 不新增 ent_l2_bind_02 的直接绑定关系，也不替代父级创建分配关系或消耗 bindingQuota。
  3. 服务端拒绝企业三级直接绑定，响应包含可读的权限失败原因和明确失败态。
  4. 不新增 ent_l3_bind_02 的直接绑定关系，也不产生越级分配、设备计数增加或槽位占用。

## [P1] 验证个人账号在监控平台 Web 绑定牛马定位器并同步至 APP
- 测试类型
  - 兼容性
- 前置条件
  1. 个人账号 person_bind_web_01 可登录监控平台 Web 和 APP，bindingQuota 剩余 1
  2. 管理后台已入库牛马定位器 GT-CARD-1203，个人槽位为空，企业一级槽位状态不影响本次个人绑定
  3. 当前账号在 Web 拥有真实一级分组「个人 Web 组」
- 测试步骤
  1. 使用 person_bind_web_01 在监控平台 Web 通过绑定入口输入 GT-CARD-1203。
  2. 选择「个人 Web 组」并确认绑定。
  3. 查询服务端绑定关系和 Web 设备列表。
  4. 使用同一账号刷新 APP 设备列表、状态数量和分组数量。
- 预期结果
  1. Web 按个人直接绑定槽位、当前配额和统一准入顺序校验设备。
  2. 建立一条 person_bind_web_01 到 GT-CARD-1203 的个人直接绑定关系并归属「个人 Web 组」。
  3. Web 列表展示 GT-CARD-1203，配额占用增加 1，不创建 Web 独立授权副本。
  4. APP 读取同一绑定关系并展示该设备，设备总数、状态数量和分组直属数量同步更新且不重复计数。

## [P3][反向] 验证手工输入无法解析为有效设备卡号时不进入查库
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 ent_l1_bind_03 已登录 APP，配额和槽位可用
  2. 手工输入值 `@@INVALID-CARD@@` 无法解析为管理后台设备体系可识别的设备卡号
- 测试步骤
  1. 从设备管理进入绑定设备并选择手工输入。
  2. 输入 `@@INVALID-CARD@@` 后提交。
  3. 检查客户端请求日志和页面流转。
  4. 查询账号关系、设备数量和配额占用。
- 预期结果
  1. 页面接受用户输入操作但进入第一层设备卡号有效性校验。
  2. 展示输入结果无效类别的可读提示，不进入设备入库、类型、重复、配额或槽位校验。
  3. 不发起携带无效卡号的设备查库或绑定确认请求，不打开确认页。
  4. 不新增设备关系，账号设备数量和配额占用保持不变。
