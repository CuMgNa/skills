# US-016 绑定牛马定位器

> 口径依据：大纲第 3.1.3～3.1.4、3.2、第 8～10 章。bindingQuota 只用于个人与企业一级直接绑定并读取服务端当前配置；配额校验和关系创建必须处于同一事务或等效原子边界，企业二、三级分配不得复用 bindingQuota。

## [P1] 验证服务端配置配额边界内最后一个名额绑定成功
- 测试类型
  - 功能
- 前置条件
  1. 测试环境为个人账号 person_quota_01 配置 bindingQuota=2，仅作为测试夹具，不代表产品上限
  2. person_quota_01 已直接绑定 GT-CARD-4001，当前占用 1 个名额
  3. 管理后台已入库牛马定位器 GT-CARD-4002，个人槽位可用
  4. person_quota_01 拥有真实一级分组「配额测试组」
- 测试步骤
  1. 使用 person_quota_01 输入 GT-CARD-4002 并进入确认页。
  2. 选择「配额测试组」并确认绑定。
  3. 查询账号直接绑定关系、设备总数和配额占用。
- 预期结果
  1. 服务端读取 bindingQuota=2 和当前占用 1，允许进入确认页。
  2. GT-CARD-4002 绑定成功，不因客户端写死其他上限而拦截。
  3. 账号存在 GT-CARD-4001、GT-CARD-4002 两条直接绑定关系，设备总数与配额占用均为 2。

## [P3][反向] 验证达到服务端配额后新增绑定被拒绝
- 测试类型
  - 功能
- 前置条件
  1. 测试环境为企业一级账号 ent_l1_quota_01 配置 bindingQuota=2，仅作为测试夹具，不代表产品上限
  2. ent_l1_quota_01 已直接绑定 GT-CARD-4101、GT-CARD-4102
  3. 管理后台已入库牛马定位器 GT-CARD-4103，企业一级槽位可用
- 测试步骤
  1. 使用 ent_l1_quota_01 输入 GT-CARD-4103 并提交。
  2. 检查页面失败状态和接口配额校验结果。
  3. 查询账号绑定关系、设备总数、配额占用和 GT-CARD-4103 槽位。
- 预期结果
  1. 系统读取当前服务端 bindingQuota=2 并确认已无剩余名额。
  2. 展示可绑定设备数量不足类别的可读原因，不进入确认页或关系创建。
  3. 账号仍仅有两条直接绑定关系，总数和占用保持 2，GT-CARD-4103 槽位未被占用。

## [P1] 验证两个并发绑定竞争最后一个配额时仅一个事务成功
- 测试类型
  - 可靠性
- 前置条件
  1. 测试环境为个人账号 person_quota_02 配置 bindingQuota=2，仅作为测试夹具，不代表产品上限
  2. person_quota_02 已绑定 GT-CARD-4201，剩余 1 个名额
  3. 已入库牛马定位器 GT-CARD-4202、GT-CARD-4203，两个设备的个人槽位均可用
  4. 两个绑定请求均选择真实一级分组「并发配额组」
- 测试步骤
  1. 使用同一账号会话并发提交 GT-CARD-4202 和 GT-CARD-4203 的确认绑定请求。
  2. 等待两个请求均返回终态并记录成功与失败结果。
  3. 查询直接绑定关系、设备总数、配额占用和两个设备的个人槽位。
  4. 刷新 APP 与 Web 设备列表核对可见记录。
- 预期结果
  1. 两个请求在配额校验和关系创建的同一原子边界内竞争最后一个名额。
  2. 仅一个请求成功；另一个返回配额不足类别的可读原因和明确失败态，不出现两个均成功。
  3. person_quota_02 最终仅新增一条关系，总绑定数和配额占用均为 2；仅成功设备占用个人槽位。
  4. APP 与 Web 均只新增成功设备，不出现失败设备、重复设备或短暂超额后的残留记录。

## [P3][反向] 验证关系创建失败时配额占用同步回滚
- 测试类型
  - 可靠性
- 前置条件
  1. 测试环境为企业一级账号 ent_l1_quota_02 配置 bindingQuota=2，仅作为测试夹具，不代表产品上限
  2. ent_l1_quota_02 已绑定 GT-CARD-4301，当前占用 1 个名额
  3. 已入库牛马定位器 GT-CARD-4302，企业一级槽位可用
  4. 测试环境可对 GT-CARD-4302 的关系写入阶段注入一次数据库失败
- 测试步骤
  1. 输入 GT-CARD-4302，通过前置校验并在确认页提交绑定。
  2. 在关系写入阶段触发一次数据库失败并等待请求返回。
  3. 查询绑定关系、账号设备总数、配额占用和企业一级槽位。
  4. 关闭故障注入后再次提交同一绑定请求。
- 预期结果
  1. 请求进入关系创建事务，不提前永久扣减配额。
  2. 请求失败并展示可读原因和失败态，不显示绑定成功。
  3. GT-CARD-4302 无半成品关系或槽位残留，账号总数和配额占用仍为 1。
  4. 重试可正常使用剩余名额并成功建立一条关系，最终总数和配额占用均为 2。

## [P3][反向] 验证二三级接收分配不产生直接绑定且不复用 bindingQuota 拦截
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 ent_l1_quota_03 已直接绑定 GT-CARD-4401，记录分配前该一级账号的直接绑定关系与 bindingQuota 占用
  2. 企业二级账号 ent_l2_quota_01、企业三级账号 ent_l3_quota_01 当前均无 GT-CARD-4401 的直接绑定或分配关系
  3. 企业未配置 allocationQuota 和 visibleDeviceLimit
- 测试步骤
  1. ent_l1_quota_03 在 Web 将 GT-CARD-4401 分配给 ent_l2_quota_01。
  2. ent_l2_quota_01 在 Web 将 GT-CARD-4401 分配给 ent_l3_quota_01。
  3. 使用 ent_l2_quota_01、ent_l3_quota_01 分别登录 APP 并刷新设备列表。
  4. 查询三级账号的可见关系、直接绑定关系，并对比分配前后 ent_l1_quota_03 的直接绑定关系与 bindingQuota 占用。
- 预期结果
  1. ent_l2_quota_01 可见 GT-CARD-4401，关系类型为一级到二级分配。
  2. ent_l3_quota_01 可见 GT-CARD-4401，关系类型为二级到三级分配。
  3. ent_l2_quota_01、ent_l3_quota_01 均不产生直接绑定关系；分配前后 ent_l1_quota_03 的直接绑定关系和 bindingQuota 占用不变，分配不消耗直接绑定配额。
  4. allocationQuota、visibleDeviceLimit 未配置时，服务端不得复用 bindingQuota 拦截任一级分配。

## [P3][反向] 验证管理后台代绑目标一级配额已满时不产生部分关系
- 测试类型
  - 可靠性
- 前置条件
  1. 测试环境为企业一级账号 ent_l1_quota_admin_01 配置 bindingQuota=2，当前已直接绑定 GT-CARD-4501、GT-CARD-4502
  2. 管理后台已入库牛马定位器 GT-CARD-4503，企业一级槽位为空
  3. 后台管理员有代绑权限，目标明确选择 ent_l1_quota_admin_01
- 测试步骤
  1. 后台管理员提交将 GT-CARD-4503 代绑给 ent_l1_quota_admin_01 的请求。
  2. 检查服务端目标账号配额校验结果。
  3. 查询 GT-CARD-4503 企业一级槽位、目标账号关系和配额占用。
  4. 刷新目标账号 APP 与 Web 设备列表。
- 预期结果
  1. 请求按目标企业一级账号的 bindingQuota 校验，而不是使用管理员自身配额。
  2. 因目标账号配额已满，代绑失败并返回可读配额原因。
  3. GT-CARD-4503 不占用企业一级槽位，不产生半成品关系，目标账号配额仍为 2。
  4. APP 与 Web 均不展示 GT-CARD-4503，设备总数和分组数量不变化。
