# US-016 绑定牛马定位器

> 口径依据：设备管理大纲第 1.3～1.4、3.2、4.4、9、10 章。「同步分组和设备」与「仅分配设备」都会建立逐级分配关系，但分组副作用不同：一级向二级执行同步时，目标二级原有分组被全量覆盖；仅分配设备保留目标账号原分组，新设备进入精确名称为「我的分组」的真实一级组。两种方式均不产生直接绑定，也不消耗 bindingQuota。

## [P1] 验证同步分组和设备全量覆盖目标二级原有分组
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 GT-E1-1601 名下存在一级分组「总部牧场」和其二级分组「育肥区」，并直接绑定设备 GT-D-160101
  2. 直属企业二级账号 GT-E2-1601 原有一级分组「二级自建组」、二级分组「二级自建子组」，分别归属设备 GT-D-160102、GT-D-160103
  3. 已记录 GT-E2-1601 同步前的分组 ID、父子关系、设备归属和可见设备集合
- 测试步骤
  1. GT-E1-1601 在监控平台 Web 对 GT-E2-1601 执行「同步分组和设备」。
  2. 使用 GT-E2-1601 重新登录 APP 并打开分组选择器和分组管理页。
  3. 查询 GT-E2-1601 最新分组主数据、设备分配关系和设备所属 groupId。
  4. 核对 GT-E1-1601 与其他二级账号的分组和设备关系。
- 预期结果
  1. 同步操作成功建立一级到二级的设备分配关系，不把 GT-D-160101 记录为 GT-E2-1601 的直接绑定。
  2. GT-E2-1601 展示同步后的「总部牧场」「育肥区」结构，原「二级自建组」「二级自建子组」不再作为该账号当前分组结构保留。
  3. GT-E2-1601 的分组主数据和设备归属以本次同步结果为准，旧 groupId 不得继续承载设备或被客户端缓存恢复。
  4. GT-E1-1601 继续可见 GT-D-160101；其他二级账号及其分支不因本次目标同步被覆盖。

## [P1] 验证仅分配设备保留目标账号原分组并进入我的分组
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 GT-E1-1602 已直接绑定设备 GT-D-160111
  2. 直属企业二级账号 GT-E2-1602 已有一级分组「南区牧场」和二级分组「犊牛区」，当前没有精确名称为「我的分组」的真实分组
  3. GT-E2-1602 的现有分组 ID、父子关系及设备归属已记录
- 测试步骤
  1. GT-E1-1602 在监控平台 Web 对 GT-E2-1602 执行「仅分配设备」并选择 GT-D-160111。
  2. 使用 GT-E2-1602 打开 APP 分组选择器和设备列表。
  3. 查询 GT-E2-1602 最新分组主数据、GT-D-160111 的关系类型和 groupId。
  4. 对比操作前后的「南区牧场」「犊牛区」结构。
- 预期结果
  1. GT-E2-1602 获得 GT-D-160111 的分配关系，GT-E1-1602 继续可见该设备。
  2. 系统为 GT-E2-1602 创建普通一级真实分组「我的分组」，设备 GT-D-160111 归属该组。
  3. GT-D-160111 不产生二级账号直接绑定关系，也不占用 GT-E2-1602 的 bindingQuota。
  4. 原「南区牧场」「犊牛区」及其 groupId、父子关系和已有设备归属保持不变，未被全量覆盖。

## [P1] 验证仅分配设备复用精确同名我的分组而不新建重复组
- 测试类型
  - 可靠性
- 前置条件
  1. 企业二级账号 GT-E2-1603 已存在真实一级分组 groupId=GRP-1603-MY、名称精确为「我的分组」
  2. 同账号另有真实一级分组名称为「 我的分组 」和「我的分组A」，两者与精确名称不同
  3. 直属企业一级账号 GT-E1-1603 已绑定待分配设备 GT-D-160121
- 测试步骤
  1. GT-E1-1603 对 GT-E2-1603 执行「仅分配设备」并选择 GT-D-160121。
  2. GT-E2-1603 在 APP 重新获取分组主数据和设备列表。
  3. 查询名称精确为「我的分组」的分组数量和 GT-D-160121 的 groupId。
  4. 核对另外两个近似名称分组的设备归属。
- 预期结果
  1. 分配成功且父级继续可见 GT-D-160121。
  2. 服务端复用 groupId=GRP-1603-MY，不新增第二个精确同名「我的分组」。
  3. GT-D-160121 的所属 groupId 为 GRP-1603-MY，精确同名分组数量仍为 1。
  4. 「 我的分组 」和「我的分组A」不被误选、不被改名，原设备归属保持不变。

## [P1] 验证同步成功后 APP 读取最新全量结果且不恢复旧分组缓存
- 测试类型
  - 可靠性
- 前置条件
  1. 企业一级账号 GT-E1-1604 名下存在分组「一级同步组」及设备 GT-D-160131、GT-D-160132
  2. 直属企业二级账号 GT-E2-1604 的 APP 已缓存旧分组「二级旧组」和旧列表设备 GT-D-160133
  3. GT-E1-1604 已在监控平台 Web 对 GT-E2-1604 成功执行「同步分组和设备」
- 测试步骤
  1. 保持 GT-E2-1604 原 APP 会话，从后台切回设备列表并打开分组选择器。
  2. 进入分组管理页，核对当前分组结构。
  3. 查询 APP、监控平台 Web 和服务端返回的分组、设备关系及直属设备数。
  4. 关闭后再次打开分组选择器并核对数据来源。
- 预期结果
  1. APP 获取当前账号最新服务端数据，不继续展示缓存的「二级旧组」和 GT-D-160133 旧列表快照。
  2. 分组管理页展示同步后的「一级同步组」结构，旧分组不被客户端缓存恢复。
  3. APP、Web 与服务端对 GT-D-160131、GT-D-160132 的分配关系、所属分组和直属设备数一致，GT-E1-1604 继续可见两台设备。
  4. 再次打开仍读取同一最新结果，不建立 APP 独立分组或授权副本。
