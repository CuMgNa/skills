# US-016 绑定牛马定位器

> 口径依据：设备管理大纲第 1.1～1.2、1.4、3.1.4、3.2、9 节及第 10 节关键规则。同一设备最多同时占用 1 个个人直接绑定槽位和 1 个企业一级直接绑定槽位；同类账号互斥、个人与企业一级可双绑共存，bindingQuota 只约束个人和企业一级的直接绑定。

## [P1] 验证个人与企业一级双槽位可同时绑定同一设备
- 测试类型
  - 功能
- 前置条件
  1. 个人账号 GT-P-1101 状态为正常，直接绑定数量为 0，bindingQuota 为 2
  2. 企业一级账号 GT-E1-1101 状态为正常，直接绑定数量为 0，bindingQuota 为 3
  3. 牛马定位器 deviceId 为 GT-DEV-011001，卡号为 898604121000011001，已入库，备注为“双槽位红马”，通信状态为离线，个人槽位和企业一级槽位均为空
- 测试步骤
  1. 使用 GT-P-1101 在 APP 将卡号 898604121000011001绑定到真实分组“个人马群”，确认备注“双槽位红马”。
  2. 使用 GT-E1-1101 在监控平台 Web 绑定同一 deviceId GT-DEV-011001。
  3. 分别查询设备直接绑定关系、两个账号的设备列表和 bindingQuota 使用数量。
- 预期结果
  1. 建立 GT-P-1101与 GT-DEV-011001的个人直接绑定关系，个人直接绑定数量变为 1。
  2. 企业一级绑定不因个人槽位已占用而被拒绝，建立 GT-E1-1101与 GT-DEV-011001的企业一级直接绑定关系。
  3. 设备存在且仅存在 1 条个人绑定和 1 条企业一级绑定；两个账号各显示 1 台 deviceId GT-DEV-011001，GT-P-1101和 GT-E1-1101分别消耗 1 个 bindingQuota。

## [P3][反向] 验证个人槽位已占用时其他个人账号绑定被拒绝
- 测试类型
  - 功能
- 前置条件
  1. deviceId GT-DEV-011002、卡号 898604121000011002、备注“个人独占黑牛”、通信状态为在线，已由个人账号 GT-P-1101直接绑定
  2. 个人账号 GT-P-1102 状态为正常，直接绑定数量为 1，bindingQuota 为 3，剩余数量为 2
- 测试步骤
  1. 使用 GT-P-1102 在 APP 输入卡号 898604121000011002并提交绑定。
  2. 核对页面提示和 GT-P-1102的设备数量、剩余 bindingQuota。
  3. 查询 GT-DEV-011002的个人直接绑定关系数量和原绑定账号。
- 预期结果
  1. 系统在同类槽位校验阶段拒绝绑定，提示设备已被其他账号绑定。
  2. GT-P-1102设备数量保持为 1，剩余 bindingQuota 仍为 2，不打开绑定确认成功结果。
  3. GT-DEV-011002的个人直接绑定关系数量仍为 1，绑定账号仍为 GT-P-1101。

## [P3][反向] 验证企业一级槽位已占用时其他一级账号代绑被拒绝
- 测试类型
  - 安全性
- 前置条件
  1. deviceId GT-DEV-011003、卡号 898604121000011003、备注“企业独占白马”、通信状态为离线，已由企业一级账号 GT-E1-1101直接绑定
  2. 企业一级账号 GT-E1-1102 状态为正常，直接绑定数量为 2，bindingQuota 为 5，剩余数量为 3
  3. 管理后台运营账号 GT-OP-9001 状态为正常，准备将 GT-DEV-011003代绑给 GT-E1-1102
- 测试步骤
  1. 使用 GT-OP-9001在管理后台选择目标账号 GT-E1-1102和卡号 898604121000011003提交代绑。
  2. 核对代绑结果、GT-E1-1102设备数量和 bindingQuota 使用数量。
  3. 查询设备企业一级直接绑定关系及运营账号 GT-OP-9001名下关系。
- 预期结果
  1. 系统拒绝代绑并提示设备已被其他企业账号绑定。
  2. GT-E1-1102直接绑定数量保持为 2，剩余 bindingQuota 仍为 3。
  3. GT-DEV-011003仍仅绑定 GT-E1-1101，不新增 GT-E1-1102关系，也不把设备绑定到操作员 GT-OP-9001名下。

## [P3][反向] 验证 bindingQuota 满额边界拦截下一台直接绑定
- 测试类型
  - 可靠性
- 前置条件
  1. 个人账号 GT-P-1103 状态为正常，bindingQuota 为 2，已直接绑定 GT-DEV-011004和 GT-DEV-011005；两台设备均直属真实分组“个人马群”，当前直接绑定数量和该分组直属设备数均为 2
  2. 待绑定 deviceId GT-DEV-011006 已入库，卡号为 898604121000011006，备注为“配额外棕马”，通信状态为在线，个人槽位为空
- 测试步骤
  1. 使用 GT-P-1103 在 APP 输入卡号 898604121000011006并提交绑定。
  2. 核对拦截提示、设备列表总数和分组直属设备数量。
  3. 查询 GT-P-1103与 GT-DEV-011006的直接绑定关系及 bindingQuota 使用数量。
- 预期结果
  1. 系统在配额校验阶段拒绝绑定，提示可绑定设备数量不足，不进入成功确认结果。
  2. GT-P-1103设备列表总数和分组直属设备数量均保持为 2。
  3. 不建立 GT-P-1103与 GT-DEV-011006的关系，bindingQuota 使用数量保持为 2且不超过上限。

## [P1] 验证子账号接收分配不占直接绑定槽位和 bindingQuota
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 GT-E1-1103 已直接绑定 deviceId GT-DEV-011007，卡号 898604121000011007，备注“分配不占槽位牛”，通信状态为在线
  2. 企业二级账号 GT-E2-2111 状态为正常，直接绑定数量为 0，bindingQuota 未用于子账号分配，当前可见设备数量为 0
  3. GT-DEV-011007的个人槽位为空，企业一级槽位已由 GT-E1-1103占用
- 测试步骤
  1. 使用 GT-E1-1103在监控平台 Web 将 GT-DEV-011007分配给直属二级 GT-E2-2111。
  2. 使用 GT-E2-2111分别查询 APP 和监控平台 Web 设备列表。
  3. 查询 GT-DEV-011007的直接绑定槽位、分配关系和 GT-E2-2111的 bindingQuota 消耗数量。
- 预期结果
  1. 分配成功并建立 GT-E1-1103到 GT-E2-2111的设备分配关系。
  2. GT-E2-2111在 APP 和 Web 均显示 1 台 GT-DEV-011007，备注“分配不占槽位牛”、通信状态为在线。
  3. 设备仍只有 GT-E1-1103这一条企业一级直接绑定；GT-E2-2111直接绑定数量和 bindingQuota 消耗数量均为 0。

## [P3][反向] 验证管理后台不得代绑给个人账号
- 测试类型
  - 安全性
- 前置条件
  1. 管理后台运营账号 GT-OP-9002 状态为正常，具备企业一级代绑操作权限
  2. 个人账号 GT-P-1104 状态为正常，直接绑定数量为 1，bindingQuota 为 3，剩余数量为 2
  3. deviceId GT-DEV-011008 已入库，卡号为 898604121000011008，备注为“禁止后台代绑个人牛”，个人槽位和企业一级槽位均为空
- 测试步骤
  1. 使用 GT-OP-9002在管理后台进入代绑操作，查找并尝试选择个人账号 GT-P-1104作为目标账号。
  2. 若通过异常入口或构造请求提交 GT-P-1104与 GT-DEV-011008的代绑，核对服务端结果。
  3. 查询 GT-P-1104的设备数量、bindingQuota 使用数量及 GT-DEV-011008的两个直接绑定槽位。
- 预期结果
  1. 管理后台代绑目标范围不提供个人账号 GT-P-1104，无法通过正常页面提交代绑。
  2. 服务端拒绝将个人账号作为后台代绑目标，不建立 GT-P-1104与 GT-DEV-011008的直接绑定关系。
  3. GT-P-1104直接绑定数量仍为 1、剩余 bindingQuota 仍为 2；GT-DEV-011008的个人槽位和企业一级槽位均保持为空。
