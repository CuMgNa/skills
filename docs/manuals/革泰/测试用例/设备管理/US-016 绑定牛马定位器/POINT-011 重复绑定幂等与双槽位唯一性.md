# US-016 绑定牛马定位器

> 口径依据：大纲第 3.1.3～3.1.4、3.2、3.4、第 8～10 章。当前账号重复绑定、重复点击和网络重试不得新增关系或数量；同一设备允许 1 个个人槽位与 1 个企业一级槽位共存，但同类账号之间互斥。

## [P1] 验证当前账号重复绑定同一设备保持一条关系
- 测试类型
  - 功能
- 前置条件
  1. 个人账号 person_repeat_01 已直接绑定牛马定位器 GT-CARD-5001
  2. person_repeat_01 的设备列表仅有一条 GT-CARD-5001 记录，设备总数为 1
  3. 记录当前 bindingQuota 占用值和 GT-CARD-5001 的个人槽位关系 ID
- 测试步骤
  1. 使用 person_repeat_01 再次进入绑定页并输入 GT-CARD-5001。
  2. 提交绑定查询并观察重复绑定处理结果。
  3. 按页面可用路径返回设备列表并打开 GT-CARD-5001 详情。
  4. 查询绑定关系条数、关系 ID、设备总数和配额占用。
- 预期结果
  1. 系统识别当前账号已绑定该设备，不进入新的确认建链流程。
  2. 页面展示已绑定类别的可读原因和可处理状态，不显示新增绑定成功。
  3. 列表仍只有一条 GT-CARD-5001，详情对应原设备唯一标识。
  4. 绑定关系仍为原 1 条且关系 ID 不变，设备总数和配额占用均不增加。

## [P1] 验证重复点击和网络重试只产生一次绑定副作用
- 测试类型
  - 可靠性
- 前置条件
  1. 企业一级账号 ent_l1_repeat_01 未绑定已入库牛马定位器 GT-CARD-5002
  2. ent_l1_repeat_01 的配额和企业一级槽位可用
  3. 确认页已选择真实一级分组「重复请求组」并填写备注「重试设备」
  4. 测试代理可复制同一次确认绑定请求并制造首次响应超时
- 测试步骤
  1. 点击确认后立即连续点击 3 次，同时由测试代理令首次响应超时。
  2. 客户端按网络重试机制再次发送相同绑定操作并等待所有请求终态。
  3. 刷新 APP 与 Web 设备列表和状态数量。
  4. 查询 GT-CARD-5002 的绑定关系、槽位、分组关系和配额占用变化。
- 预期结果
  1. 客户端重复触发不会创建多次业务副作用，页面不出现多个成功设备卡片。
  2. 服务端对重复请求返回一致的成功或已处理结果，不生成第二条相同绑定关系。
  3. APP 与 Web 均只显示一条 GT-CARD-5002，设备总数仅增加 1。
  4. 仅有一条有效绑定关系、一个企业一级槽位和一条当前账号分组归属，配额占用仅增加 1。

## [P1] 验证同一设备个人与企业一级双绑定共存
- 测试类型
  - 功能
- 前置条件
  1. 已入库牛马定位器 GT-CARD-5101 已被个人账号 person_dual_01 直接绑定
  2. 企业一级账号 ent_l1_dual_01 未绑定 GT-CARD-5101，配额和企业一级槽位可用
  3. ent_l1_dual_01 拥有真实二级分组「企业双绑组」
- 测试步骤
  1. 使用 ent_l1_dual_01 在 APP 输入 GT-CARD-5101。
  2. 通过前置校验后选择「企业双绑组」并确认绑定。
  3. 分别使用 person_dual_01 和 ent_l1_dual_01 刷新 APP 与 Web 设备列表。
  4. 查询 GT-CARD-5101 的个人槽位、企业一级槽位和两账号分组归属。
- 预期结果
  1. 系统不因个人槽位已占用而单独拒绝企业一级绑定。
  2. ent_l1_dual_01 成功建立企业一级直接绑定关系。
  3. 两个账号均可见同一设备唯一标识，各自列表仅计一台。
  4. 个人槽位仅属于 person_dual_01，企业一级槽位仅属于 ent_l1_dual_01；两账号分组关系相互独立。

## [P1] 验证两个同类账号并发抢占同一设备槽位仅一个成功
- 测试类型
  - 可靠性
- 前置条件
  1. 已入库牛马定位器 GT-CARD-5201 的个人槽位为空
  2. 个人账号 person_slot_01、person_slot_02 均未绑定 GT-CARD-5201且各自配额可用
  3. 两个账号均已进入各自确认页并选择真实分组「个人设备组」
- 测试步骤
  1. 并发提交 person_slot_01 与 person_slot_02 对 GT-CARD-5201 的确认绑定请求。
  2. 等待两个请求返回终态并记录结果。
  3. 查询设备个人槽位、两账号绑定关系、设备总数和配额占用。
  4. 分别刷新两个账号的 APP 与 Web 设备列表。
- 预期结果
  1. 两个请求竞争同一个个人直接绑定槽位，不允许同时通过槽位校验并建链。
  2. 仅一个账号绑定成功；另一个展示同类槽位已被其他账号占用类别的可读原因和失败态。
  3. GT-CARD-5201 最终只有一个个人槽位和一条个人直接绑定关系，仅成功账号的数量与配额占用增加 1。
  4. 成功账号可见该设备，失败账号不可见该设备，不出现短暂双占后的残留关系。
