# US-016 绑定牛马定位器

> 口径依据：设备管理大纲第 1.1、1.3～1.4、3.1.1～3.1.2、3.2、9 节及第 10 节关键规则。企业设备只能在监控平台 Web 按“一级 → 直属二级 → 直属三级”逐级分配，分配是向下授权而非归属转移，父级继续可见且子级范围必须是直属父级范围的子集。

## [P1] 验证企业一级通过 Web 分配后直属二级跨端可见且父级保留
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 GT-E1-1201 状态为正常，已直接绑定 deviceId GT-DEV-012001，卡号 898604121000012001，备注“一级分配青牛”，通信状态为在线，当前可见设备数量为 1
  2. 企业二级账号 GT-E2-2201 状态为正常且直属 GT-E1-1201，当前可见设备数量为 0，allocationQuota 配置为 3；账号已有真实一级组“二级原有组”，不存在名称精确为“我的分组”的真实分组
- 测试步骤
  1. 使用 GT-E1-1201在监控平台 Web 将 GT-DEV-012001以“仅分配设备”方式分配给 GT-E2-2201。
  2. 分别使用 GT-E1-1201和 GT-E2-2201查询 Web 设备列表。
  3. 使用 GT-E2-2201查询 APP 设备列表，并核对关系类型、分组结果与配额使用数量。
- 预期结果
  1. 建立 GT-E1-1201到 GT-E2-2201的分配关系，不转移 GT-E1-1201的直接绑定归属。
  2. GT-E1-1201仍显示 1 台 GT-DEV-012001；GT-E2-2201显示同一台设备，备注“一级分配青牛”、通信状态为在线。
  3. GT-E2-2201在 APP 同步显示 1 台设备；关系类型为分配，原有分组“二级原有组”保留，系统创建普通一级组“我的分组”并使 GT-DEV-012001直属该组；allocationQuota 使用数量为 1，bindingQuota 消耗数量为 0。

## [P1] 验证企业二级继续分配后直属三级跨端可见
- 测试类型
  - 功能
- 前置条件
  1. GT-E1-1201已将 deviceId GT-DEV-012002、卡号 898604121000012002、备注“三级巡检白马”、通信状态为离线分配给直属二级 GT-E2-2201
  2. 企业三级账号 GT-E3-3201 状态为正常且直属 GT-E2-2201，当前可见设备数量为 0，visibleDeviceLimit 配置为 2
- 测试步骤
  1. 使用 GT-E2-2201在监控平台 Web 将 GT-DEV-012002分配给 GT-E3-3201。
  2. 分别查询 GT-E1-1201、GT-E2-2201、GT-E3-3201的 Web 设备列表。
  3. 使用 GT-E3-3201查询 APP 设备列表、设备关系类型和可见数量。
- 预期结果
  1. 建立 GT-E2-2201到 GT-E3-3201的分配关系，不新增三级直接绑定关系。
  2. 一级、二级、三级账号均显示同一 deviceId GT-DEV-012002，上游账号未因向下分配失去可见性。
  3. GT-E3-3201在 APP 显示 1 台设备，备注“三级巡检白马”、通信状态为离线；可见数量为 1且 direct binding 数量为 0。

## [P1] 验证同一设备按两种分配方式进入多个二级及各自直属三级
- 测试类型
  - 功能
- 前置条件
  1. 企业一级 GT-E1-1202 已直接绑定 deviceId GT-DEV-012003，卡号 898604121000012003，备注“多分支黑马”，通信状态为在线；一级账号存在真实分组“总部多分支组”
  2. GT-E2-2211和 GT-E2-2212均直属 GT-E1-1202；GT-E2-2211已有真实组“二级旧组A”，GT-E2-2212已有真实组“二级旧组B”且不存在“我的分组”；GT-E3-3211直属 GT-E2-2211，GT-E3-3212直属 GT-E2-2212
  3. 四个子账号初始可见设备数量均为 0，对应 allocationQuota 和 visibleDeviceLimit 剩余数量均不少于 1
- 测试步骤
  1. 使用 GT-E1-1202在监控平台 Web 以“同步分组和设备”将 GT-DEV-012003分配给 GT-E2-2211，并以“仅分配设备”将同一设备分配给 GT-E2-2212。
  2. 使用 GT-E2-2211将设备分配给 GT-E3-3211，使用 GT-E2-2212将设备分配给 GT-E3-3212。
  3. 查询五个账号的 APP 与 Web 设备列表、关系记录、分组结构和设备唯一标识。
- 预期结果
  1. 两个直属二级账号均获得分配关系且可见设备数量由 0变为 1；GT-E2-2211原分组被同步结果全量覆盖并取得“总部多分支组”，GT-E2-2212保留“二级旧组B”且设备进入自动创建的普通一级组“我的分组”；GT-E1-1202继续可见。
  2. 两个三级账号分别通过自己的直属二级获得设备，可见设备数量均由 0变为 1。
  3. 五个账号均读取同一 deviceId GT-DEV-012003和同一份在线状态事实；系统未复制物理设备，也未把任一分配关系记录为直接绑定。

## [P3][反向] 验证越级分配和超出父级可见范围均被拒绝
- 测试类型
  - 安全性
- 前置条件
  1. GT-E3-3221直属 GT-E2-2221，GT-E2-2221直属 GT-E1-1203，三个账号状态均为正常
  2. GT-E1-1203可见 deviceId GT-DEV-012004，卡号 898604121000012004，备注“禁止越级黄牛”，通信状态为在线，但尚未分配给 GT-E2-2221
  3. deviceId GT-DEV-012005、卡号 898604121000012005、备注“父级范围外灰马”、通信状态为离线，仅由另一企业一级 GT-E1-1299直接绑定
- 测试步骤
  1. 使用 GT-E1-1203在监控平台 Web 尝试绕过 GT-E2-2221直接将 GT-DEV-012004分配给 GT-E3-3221。
  2. 使用 GT-E2-2221尝试将尚未由自己获得的 GT-DEV-012004分配给 GT-E3-3221。
  3. 使用 GT-E2-2221尝试将父级范围外设备 GT-DEV-012005分配给 GT-E3-3221。
  4. 查询 GT-E2-2221、GT-E3-3221的可见设备数量和三次操作后的关系记录。
- 预期结果
  1. 越级分配被拒绝，不建立 GT-E1-1203到 GT-E3-3221的直接可见关系。
  2. 因 GT-E2-2221尚未拥有 GT-DEV-012004可见关系，向三级分配被拒绝。
  3. 因 GT-DEV-012005不在 GT-E2-2221及其直属一级的可见范围内，分配被拒绝且不泄露设备详情。
  4. GT-E2-2221和 GT-E3-3221可见设备数量均保持为 0，未新增直接绑定或分配关系。

## [P3][反向] 验证 APP 不提供企业向下分配入口
- 测试类型
  - 易用性
- 前置条件
  1. 企业一级 GT-E1-1204 状态为正常，已直接绑定 deviceId GT-DEV-012006，卡号 898604121000012006，备注“仅 Web 分配棕牛”，通信状态为在线，可见设备数量为 1
  2. 企业二级 GT-E2-2231直属 GT-E1-1204，当前可见设备数量为 0
- 测试步骤
  1. 使用 GT-E1-1204登录 APP，打开 GT-DEV-012006的列表卡片和设备详情。
  2. 核对 APP 的设备操作、分组操作和账号相关入口。
  3. 登录监控平台 Web，进入 GT-DEV-012006的分配操作并选择 GT-E2-2231。
- 预期结果
  1. APP 正常显示 GT-DEV-012006，备注“仅 Web 分配棕牛”、通信状态为在线。
  2. APP 不显示一级向二级的设备分配入口，也不把分配操作混入“绑定设备”。
  3. 监控平台 Web 提供逐级分配操作，选择直属二级 GT-E2-2231后可进入对应分配流程。

## [P3][反向] 验证测试夹具配置的 allocationQuota 满额时分配原子失败
- 测试类型
  - 可靠性
- 前置条件
  1. 企业一级 GT-E1-1205 已直接绑定待分配 deviceId GT-DEV-012007，卡号 898604121000012007，备注“分配配额外青牛”，通信状态为在线
  2. 直属企业二级 GT-E2-2241 的测试夹具配置 allocationQuota 为 2且已使用 2；visibleDeviceLimit 未配置，当前可见设备数量为 2
  3. GT-E2-2241已有真实一级组“配额满额原有组”，不存在名称精确为“我的分组”的真实分组，且尚无 GT-DEV-012007的关系或分组归属
- 测试步骤
  1. 使用 GT-E1-1205在监控平台 Web 以“仅分配设备”方式将 GT-DEV-012007分配给 GT-E2-2241。
  2. 核对分配提示、GT-E2-2241的可见设备数量和 allocationQuota 使用数量。
  3. 查询 GT-E1-1205到 GT-E2-2241的设备关系、GT-E2-2241的分组结构及 GT-DEV-012007的分组归属。
- 预期结果
  1. 系统按测试夹具当前配置识别 allocationQuota 已满，拒绝本次分配并提示分配设备数量已达上限；不据此认定产品存在固定数值上限。
  2. GT-E2-2241可见设备数量和 allocationQuota 使用数量均保持为 2。
  3. 不建立 GT-DEV-012007的分配关系，不创建“我的分组”，不写入设备分组归属；关系与分组不存在部分成功。

  2. 直属企业二级 GT-E2-2242 的测试夹具配置 visibleDeviceLimit 为 3且当前可见设备数量为 3；allocationQuota 未配置

## [P1] 验证分配限制均未配置时不复用已满 bindingQuota 拦截分配
- 测试类型
  - 功能
- 前置条件
  1. 企业一级 GT-E1-1207 已直接绑定待分配 deviceId GT-DEV-012009，卡号 898604121000012009，备注“绑定满额仍可分配棕牛”，通信状态为在线
  2. 直属企业二级 GT-E2-2243 的 allocationQuota 和 visibleDeviceLimit 均未配置；bindingQuota 测试夹具配置为 1且已使用 1，当前可见设备数量为 1
  3. GT-E2-2243已有真实一级组“二级旧组C”，不存在名称精确为“我的分组”的真实分组，且尚无 GT-DEV-012009的关系或分组归属
- 测试步骤
  1. 使用 GT-E1-1207在监控平台 Web 以“仅分配设备”方式将 GT-DEV-012009分配给 GT-E2-2243。
  2. 使用 GT-E2-2243分别查询 Web 和 APP 设备列表，核对可见设备数量。
  3. 查询分配关系、bindingQuota 使用数量及 GT-E2-2243的分组结构和设备归属。
- 预期结果
  1. 分配成功；系统不因 allocationQuota、visibleDeviceLimit 未配置而复用已满的 bindingQuota 拦截分配。
  2. GT-E2-2243在 Web 和 APP 均新增可见 GT-DEV-012009，可见设备数量由 1变为 2。
  3. 建立且仅建立一条分配关系，bindingQuota 使用数量仍为 1；保留“二级旧组C”，创建普通一级组“我的分组”并使 GT-DEV-012009直属该组，不产生直接绑定关系或其他部分写入。
