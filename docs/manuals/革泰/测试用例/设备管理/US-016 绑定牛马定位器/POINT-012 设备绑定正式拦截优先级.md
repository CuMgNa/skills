# US-016 绑定牛马定位器

> 口径依据：大纲第 3.1.3、3.2、第 8～10 章。APP 正式校验顺序为有效设备卡号、已入库、牛马定位器类型、当前账号重复、bindingQuota、同类槽位、确认页保存条件；同一请求命中多个失败条件时只返回顺序靠前的原因。

## [P3][反向] 验证无效扫码结果优先于设备查库和后续校验
- 测试类型
  - 功能
- 前置条件
  1. 个人账号 person_priority_01 已登录且 bindingQuota 已用满
  2. 准备一个 APP 无法取得有效设备卡号的测试二维码，二维码载荷内容不纳入断言
- 测试步骤
  1. 进入「设备管理 → 绑定设备」并扫描测试二维码。
  2. 观察页面失败状态和可执行操作。
  3. 查询设备查库、配额校验、槽位校验和绑定关系写入调用记录。
- 预期结果
  1. 系统在设备卡号解析阶段失败，不把扫码结果当作设备卡号继续处理。
  2. 页面展示扫码结果无效的可读原因和可重试失败态，不展示配额已满或槽位占用原因。
  3. 不发起后续设备查库、配额、槽位及关系创建操作，不新增设备或关系数据。

## [P3][反向] 验证设备未入库优先于配额已满
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 ent_l1_priority_01 已登录且 bindingQuota 已用满
  2. 设备卡号 GT-CARD-2999 未在管理后台入库
- 测试步骤
  1. 在绑定页手动输入 GT-CARD-2999 并提交。
  2. 检查接口响应失败字段和页面提示类型。
  3. 查询 ent_l1_priority_01 的绑定数量、配额占用和 GT-CARD-2999 关系记录。
- 预期结果
  1. 系统完成卡号有效性检查后，在入库检查阶段拒绝请求。
  2. 响应和页面展示设备不存在或未入库类别的可读原因，不以配额不足作为本次结果。
  3. 绑定数量与配额占用不变，GT-CARD-2999 不产生绑定关系。

## [P3][反向] 验证类型不支持及当前账号已绑定依次优先于后续条件
- 测试类型
  - 可靠性
- 前置条件
  1. 个人账号 person_priority_02 已登录，bindingQuota 已用满
  2. 管理后台已入库设备 GT-CARD-2101，后台类型为北斗设备，person_priority_02 已通过存量直接绑定关系持有该设备
  3. 管理后台已入库牛马定位器 GT-CARD-2102，person_priority_02 已直接绑定该设备
  4. 记录两个设备的关系数、person_priority_02 的设备数和配额占用
- 测试步骤
  1. 在 APP 绑定页输入 GT-CARD-2101 并提交。
  2. 检查 GT-CARD-2101 的响应失败字段和页面提示类型。
  3. 在 APP 绑定页输入 GT-CARD-2102 并再次提交。
  4. 检查 GT-CARD-2102 的响应失败字段，并查询两个设备的关系数、账号设备数和配额占用。
- 预期结果
  1. 系统在确认 GT-CARD-2101 已入库后，优先按后台类型判断当前入口不支持。
  2. 展示设备类型不支持类别的可读原因，不返回当前账号已绑定或配额不足类别结果，也不误报设备不存在。
  3. 系统识别 person_priority_02 已绑定牛马定位器 GT-CARD-2102，在配额校验前结束新增流程。
  4. GT-CARD-2102 返回已绑定或已添加类别的可读结果，不返回配额不足；两个设备的关系数、账号设备数和配额占用均保持不变。

## [P3][反向] 验证配额不足优先于同类槽位已占用
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 ent_l1_priority_02 的 bindingQuota 已用满
  2. 管理后台已入库牛马定位器 GT-CARD-2201
  3. GT-CARD-2201 已被另一企业一级账号 ent_l1_owner_01 直接绑定
- 测试步骤
  1. 使用 ent_l1_priority_02 在 APP 输入 GT-CARD-2201 并提交。
  2. 检查接口响应和页面失败状态。
  3. 查询两个企业一级账号的绑定关系、设备数量和配额占用。
- 预期结果
  1. 请求依次通过卡号、入库、类型和当前账号重复检查，在配额检查阶段失败。
  2. 展示可绑定设备数量不足类别的可读原因，不以企业同类槽位占用作为本次结果。
  3. ent_l1_owner_01 的原绑定保持有效，ent_l1_priority_02 不新增关系、数量或配额占用。

## [P3][反向] 验证确认页保存条件最后拦截且不建立关系
- 测试类型
  - 功能
- 前置条件
  1. 个人账号 person_priority_03 的配额和个人槽位可用
  2. 管理后台已入库牛马定位器 GT-CARD-2301
  3. person_priority_03 拥有真实一级分组「东区牧场」
- 测试步骤
  1. 输入 GT-CARD-2301 并通过卡号、入库、类型、重复、配额和槽位校验。
  2. 在确认页不选择真实分组并点击确认。
  3. 检查页面状态、绑定关系、设备数量和配额占用。
- 预期结果
  1. 系统进入 GT-CARD-2301 的绑定确认页，不提前创建绑定关系。
  2. 页面停留在确认页，真实分组字段进入失败态并展示可读的补全原因。
  3. person_priority_03 不新增绑定关系，设备数量和配额占用均不变化。
