# US-016 绑定牛马定位器
> 口径依据：设备管理逻辑大纲第 3.3～3.4、4.2、7、9～10 节。解绑和分配回收只清理当前失效链路的归属、分配、分组与围栏关系，设备本体及历史数据保留；后台改绑等价于解绑原企业一级再绑定新企业一级；重新绑定或重新分配不得自动恢复原分配、原分组和原围栏关联。

## [P1] 验证个人解绑后重新绑定保留历史但不自动恢复原分组和围栏
- 测试类型
  - 功能
- 前置条件
  1. 个人账号 GT-P-13401 已绑定 GT-D-13401，设备归属分组“旧个人组”并关联围栏 GF-P-13401
  2. GT-D-13401 已存在位置、轨迹、告警和指令历史记录
  3. 企业一级 GT-E1-13401 对同一设备存在独立有效绑定
- 测试步骤
  1. GT-P-13401 在 APP 对 GT-D-13401 执行 Unbind Device。
  2. 查询个人绑定、个人分组、个人围栏、企业绑定及历史数据存储状态。
  3. GT-P-13401 重新绑定 GT-D-13401，并在确认页明确选择新分组“新个人组”。
  4. 刷新设备、分组、围栏和历史数据查询结果。
- 预期结果
  1. 个人绑定关系删除，GT-P-13401 在 APP 与 Web 均不可见该设备。
  2. “旧个人组”归属和 GF-P-13401 设备关联被清除；企业绑定保持有效，设备本体及历史数据仍保留。
  3. 重新绑定建立新的个人绑定关系，设备仅按本次明确选择进入“新个人组”。
  4. 原“旧个人组”和 GF-P-13401 不自动恢复；历史数据仍存储，具体可见性按重新建立后的当前设备关系校验。

## [P1] 验证企业一级解绑及重新绑定不恢复原下级分配、分组和围栏
- 测试类型
  - 功能
- 前置条件
  1. GT-E1-13401 已绑定 GT-D-13402，并分配给 GT-E2-13401，再由二级分配给 GT-E3-13401
  2. 一级、二级、三级分别归属分组“一级旧组”“二级旧组”“三级旧组”，并各有关联围栏
  3. GT-D-13402 已存在历史位置、轨迹、告警和指令数据，另有个人账号独立绑定
- 测试步骤
  1. GT-E1-13401 在 Web 设备管理中解绑 GT-D-13402。
  2. 查询一级、二级、三级的设备关系、分组关系、围栏关系及个人绑定。
  3. GT-E1-13401 重新绑定 GT-D-13402，并明确选择一级新分组“一级新组”。
  4. 分别刷新一级、二级、三级设备列表并查询历史数据存储状态。
- 预期结果
  1. 一级直接绑定删除，一级及其下二级、三级企业链路立即失效。
  2. 企业链路内原分配、“一级旧组”“二级旧组”“三级旧组”归属和围栏设备关联全部清除；个人独立绑定不受影响。
  3. 重新绑定只恢复 GT-E1-13401 的企业一级直接绑定，并进入本次明确选择的“一级新组”。
  4. 二级、三级默认仍不可见，原分配、原分组和原围栏均不自动恢复；历史数据保留并按当前关系控制访问。

## [P1] 验证父级回收后重新分配不自动恢复子级原分组和围栏
- 测试类型
  - 功能
- 前置条件
  1. GT-E1-13402 已将 GT-D-13403 分配给直属二级 GT-E2-13402
  2. GT-E2-13402 将设备归属“二级南场”并关联围栏 GF-E2-13403，设备另已分配给直属三级 GT-E3-13402
  3. GT-D-13403 已存在二级和三级有权查看的历史记录
- 测试步骤
  1. GT-E1-13402 在 Web 用户管理中回收 GT-E2-13402 的 GT-D-13403。
  2. 查询二级、三级的分配、分组、围栏关系，并确认一级设备关系。
  3. GT-E1-13402 再次以“仅分配设备”方式将 GT-D-13403 分配给 GT-E2-13402。
  4. 刷新二级、三级设备列表、分组和围栏，并核对历史数据存储状态。
- 预期结果
  1. 一级继续可见；二级分配关系删除，并级联删除 GT-E3-13402 的三级分配关系。
  2. “二级南场”、GF-E2-13403 及三级失效链路内的分组和围栏关系清除，一级绑定不受影响。
  3. 二级重新获得分配关系；按“仅分配设备”规则进入当前真实“我的分组”，不恢复“二级南场”。
  4. GF-E2-13403 和原三级分配不自动恢复，三级仍不可见；历史数据仍保留并按重新建立后的当前关系鉴权。

## [P1] 验证后台将企业一级 A 改绑到 B 时按解绑加绑定处理且历史保留
- 测试类型
  - 功能
- 前置条件
  1. GT-D-13404 当前绑定企业一级 GT-E1-A-13404，并已逐级分配给 GT-E2-A-13404、GT-E3-A-13404
  2. A 链路各账号已有分组和围栏设备关联，GT-D-13404 已存在历史位置、轨迹、告警和指令数据
  3. 目标企业一级 GT-E1-B-13404 满足入库、配额和企业一级槽位条件，设备另有个人独立绑定
- 测试步骤
  1. 后台运营账号将 GT-D-13404 从 GT-E1-A-13404 改绑到 GT-E1-B-13404。
  2. 查询 A 一级及其二级、三级的绑定、分配、分组和围栏关系。
  3. 查询 B 一级及其下级账号的设备关系，并刷新 B 的 APP、Web。
  4. 查询个人绑定、设备本体和历史数据存储状态。
- 预期结果
  1. 后台改绑原子结果等价于解绑 A 加绑定 B，A 的企业一级绑定删除，B 获得企业一级绑定。
  2. A 下所有二级、三级分配立即失效，A 链路原分组与围栏设备关联清除。
  3. B 一级在 APP、Web 同步可见，B 的二级、三级默认不可见；A 的原分配、分组和围栏不迁移到 B。
  4. 个人独立绑定保持有效，设备本体和历史数据保留，历史访问继续按改绑后的当前设备关系鉴权。
