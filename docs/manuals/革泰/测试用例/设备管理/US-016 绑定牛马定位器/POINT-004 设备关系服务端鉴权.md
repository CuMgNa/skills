# US-016 绑定牛马定位器

> 口径依据：设备管理大纲第 1.2～1.4、3.1.1、3.2、9 节及第 10 节关键规则。服务端必须按账号身份和当前有效设备关系重新鉴权；客户端可登录或持有历史入口不代表拥有直接绑定权或范围外设备访问权，企业二级、三级构造绑定请求也必须被拒绝。

## [P1] 验证服务端允许账号访问当前有效关系内设备
- 测试类型
  - 安全性
- 前置条件
  1. 个人账号 GT-P-1401状态为正常，直接绑定 deviceId GT-DEV-014001，卡号 898604121000014001，备注“个人鉴权红马”，通信状态为在线，可见设备数量为 1
  2. 企业二级账号 GT-E2-2401状态为正常，直属一级已分配 deviceId GT-DEV-014002，卡号 898604121000014002，备注“企业鉴权青牛”，通信状态为离线，可见设备数量为 1
- 测试步骤
  1. 使用 GT-P-1401请求 GT-DEV-014001的设备列表项和详情数据。
  2. 使用 GT-E2-2401请求 GT-DEV-014002的设备列表项和详情数据。
  3. 核对两次请求命中的账号关系类型、返回 deviceId、备注和通信状态。
- 预期结果
  1. 服务端基于 GT-P-1401的个人直接绑定关系允许访问，返回 GT-DEV-014001且可见设备数量为 1。
  2. 服务端基于 GT-E2-2401的直属父级分配关系允许访问，返回 GT-DEV-014002且可见设备数量为 1。
  3. 两次请求分别命中直接绑定和分配关系；返回的设备唯一标识、备注及在线或离线状态与设备事实一致。

## [P3][反向] 验证企业子账号访问授权范围外设备被服务端拒绝
- 测试类型
  - 安全性
- 前置条件
  1. 企业二级账号 GT-E2-2402状态为正常，直属一级为 GT-E1-1402，当前仅可见 GT-DEV-014003，设备数量为 1
  2. 范围外 deviceId GT-DEV-014004由另一企业一级 GT-E1-1499绑定，卡号 898604121000014004，备注“范围外白马”，通信状态为在线
- 测试步骤
  1. 使用 GT-E2-2402的有效登录会话直接请求 GT-DEV-014004详情。
  2. 使用 GT-E2-2402请求当前设备列表，并按完整卡号 898604121000014004和备注“范围外白马”分别搜索。
  3. 核对响应内容、当前账号可见数量和设备关系记录。
- 预期结果
  1. 服务端拒绝 GT-E2-2402访问 GT-DEV-014004，不返回卡号、备注、位置、电量或在线状态。
  2. 当前设备列表只返回授权范围内的 GT-DEV-014003；按卡号或备注搜索均不返回范围外 GT-DEV-014004，也不暴露其受保护字段。
  3. GT-E2-2402可见设备数量保持为 1，不新增与 GT-DEV-014004的直接绑定、分配或临时授权关系。

## [P3][反向] 验证企业二级和三级构造直接绑定请求仍被服务端拒绝
- 测试类型
  - 安全性
- 前置条件
  1. 企业二级 GT-E2-2403和企业三级 GT-E3-3403状态均为正常，均已登录 APP，当前直接绑定数量为 0
  2. 已入库牛马定位器 deviceId GT-DEV-014005，卡号 898604121000014005，备注“禁止子账号绑定牛”，通信状态为离线，个人槽位和企业一级槽位均为空
  3. 两个账号当前获分配设备数量均为 0
- 测试步骤
  1. 绕过隐藏入口，使用 GT-E2-2403会话构造卡号 898604121000014005的直接绑定请求。
  2. 使用 GT-E3-3403会话构造同一 deviceId GT-DEV-014005的直接绑定请求。
  3. 查询设备直接绑定关系、两个账号的设备数量和 bindingQuota 消耗数量。
- 预期结果
  1. 服务端按账号身份拒绝 GT-E2-2403的直接绑定请求，不进入配额或确认成功流程。
  2. 服务端按账号身份拒绝 GT-E3-3403的直接绑定请求，不因设备槽位为空而放行。
  3. GT-DEV-014005不新增任何直接绑定关系；两个账号设备数量和 bindingQuota 消耗数量均保持为 0。

## [P3][反向] 验证分配关系回收后旧会话不能继续访问原设备
- 测试类型
  - 安全性
- 前置条件
  1. 企业一级账号 GT-E1-1404已将 deviceId GT-DEV-014006、卡号 898604121000014006、备注“回收鉴权棕马”、通信状态在线的设备分配给直属二级 GT-E2-2404
  2. GT-E2-2404当前可见设备数量为 1，已登录 APP 并保留分配有效期间取得的会话和 GT-DEV-014006详情入口
  3. GT-E1-1404具备在监控平台 Web 回收该二级设备分配关系的权限
- 测试步骤
  1. 使用 GT-E2-2404当前会话请求 GT-DEV-014006详情，确认回收前关系有效。
  2. 使用 GT-E1-1404在监控平台 Web 回收 GT-E2-2404的 GT-DEV-014006分配关系。
  3. 不重新登录，继续使用 GT-E2-2404原会话和历史详情入口请求 GT-DEV-014006，并刷新设备列表。
- 预期结果
  1. 回收前服务端按当前有效分配关系返回 GT-DEV-014006，卡号和备注与设备事实一致。
  2. 回收成功后 GT-E2-2404到 GT-DEV-014006的分配关系失效，GT-E1-1404仍保留上游可见性。
  3. 服务端按最新关系拒绝旧会话继续访问，不返回位置、电量、在线状态等受保护数据；GT-E2-2404设备列表数量更新为 0，不使用登录时权限快照继续放行。

## [P3][反向] 验证企业二三级构造监控平台 Web 绑定请求仍被服务端拒绝
- 测试类型
  - 安全性
- 前置条件
  1. 企业二级账号 GT-E2-2405 和企业三级账号 GT-E3-3405 均持有有效监控平台 Web 会话
  2. 已入库牛马定位器 GT-DEV-014007，个人和企业一级直接绑定槽位均为空
  3. 已取得企业一级 Web 绑定接口路径和请求结构，但不修改两个子账号的服务端角色
- 测试步骤
  1. 使用 GT-E2-2405 的 Web 会话构造 GT-DEV-014007 直接绑定请求。
  2. 使用 GT-E3-3405 的 Web 会话构造同一设备直接绑定请求。
  3. 查询设备绑定关系、两个账号的设备数量和 bindingQuota 占用。
- 预期结果
  1. 服务端按账号层级拒绝二级账号请求，不因接口路径有效或设备槽位为空而放行。
  2. 服务端按账号层级拒绝三级账号请求，不将请求转换为分配关系。
  3. GT-DEV-014007 不新增直接绑定或越级分配；两个账号设备数量和 bindingQuota 占用保持不变。
