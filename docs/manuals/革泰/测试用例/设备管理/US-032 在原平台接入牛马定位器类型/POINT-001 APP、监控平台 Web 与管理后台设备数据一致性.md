# US-032 在原平台接入牛马定位器类型
> 口径依据：设备管理逻辑大纲第 1.1～1.4、3.1、3.3、4.1～4.2、5.8、7、9～10 节。三端复用同一账号、设备归属和设备事实数据；设备备注为设备级共享字段，分组为账户级关系字段，SIM、在线状态和到期时间不得产生端侧独立副本。

## [P1] 验证个人账号在 APP 绑定后与监控平台 Web 使用同一归属关系
- 测试类型
  - 功能
- 前置条件
  1. 个人账号 GT-P-13001 在 APP 与监控平台 Web 均可正常登录
  2. 牛马定位器 GT-D-13001 已入库，未占用个人绑定槽位，账号仍有绑定配额
  3. GT-P-13001 已有真实一级分组“个人牧场”，绑定前 APP 与 Web 均无 GT-D-13001
- 测试步骤
  1. GT-P-13001 在 APP 输入设备卡号 GT-D-13001，选择“个人牧场”并确认绑定。
  2. 刷新 APP 设备列表并查询 GT-D-13001 的当前账号关系。
  3. 使用同一账号刷新监控平台 Web 设备列表并打开 GT-D-13001。
  4. 在管理端关系查询中核对 GT-D-13001 的个人绑定账号和绑定记录数。
- 预期结果
  1. APP 绑定成功，仅建立 GT-P-13001 与 GT-D-13001 的一条个人直接绑定关系。
  2. APP 列表可见 GT-D-13001，关系类型为直接绑定，不产生 APP 独立授权副本。
  3. Web 同步可见同一设备和同一个人绑定关系，不需要再次绑定。
  4. 管理端记录的个人绑定账号为 GT-P-13001，绑定记录数为 1，设备未绑定到任何后台操作员名下。

## [P1] 验证管理后台代绑企业一级后 APP 与 Web 同步且子级不自动获权
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 GT-E1-13001、直属二级 GT-E2-13001、直属三级 GT-E3-13001 均可登录
  2. 牛马定位器 GT-D-13002 已入库，未占用企业一级绑定槽位，GT-E1-13001 有剩余绑定配额
  3. 三个企业账号绑定前均不可见 GT-D-13002
- 测试步骤
  1. 后台运营账号 GT-OP-13001 将 GT-D-13002 代绑给 GT-E1-13001。
  2. 分别刷新 GT-E1-13001 的 APP 与 Web 设备列表。
  3. 分别刷新 GT-E2-13001、GT-E3-13001 的 APP 与 Web 设备列表。
  4. 查询管理后台中的设备归属、操作人和企业分配关系。
- 预期结果
  1. 代绑建立 GT-E1-13001 的企业一级直接绑定关系，不把设备绑定到 GT-OP-13001。
  2. GT-E1-13001 在 APP 与 Web 均同步可见 GT-D-13002。
  3. 未执行逐级分配前，GT-E2-13001、GT-E3-13001 在两端均不可见 GT-D-13002。
  4. 管理后台显示归属账号为 GT-E1-13001、操作人为 GT-OP-13001，且不存在二级或三级分配关系。

## [P1] 验证 Web 逐级分配结果在 APP 与 Web 同步且父级保持可见
- 测试类型
  - 功能
- 前置条件
  1. GT-E1-13001 已直接绑定 GT-D-13003，并在 APP 与 Web 可见
  2. GT-E2-13001 是 GT-E1-13001 的直属二级，GT-E3-13001 是 GT-E2-13001 的直属三级
  3. GT-E2-13001、GT-E3-13001 初始均不可见 GT-D-13003
- 测试步骤
  1. GT-E1-13001 在 Web 将 GT-D-13003 分配给 GT-E2-13001。
  2. 刷新一级与二级账号的 APP、Web 设备列表并核对关系类型。
  3. GT-E2-13001 在 Web 将 GT-D-13003 分配给 GT-E3-13001。
  4. 刷新三个层级账号的 APP、Web 设备列表并查询关系记录。
- 预期结果
  1. 一级到二级的分配成功，未新增二级直接绑定关系。
  2. 一级在两端继续可见，二级在两端同步可见；一级关系为直接绑定，二级关系为分配。
  3. 二级到三级的逐级分配成功，未新增三级直接绑定关系。
  4. 一级、二级、三级在两端均可见同一设备，每个账号列表按设备唯一标识只显示 1 条，关系链为一级绑定、二级分配、三级分配。

## [P1] 验证共享备注、账户级分组及 SIM 在线到期字段跨端口径一致
- 测试类型
  - 功能
- 前置条件
  1. GT-D-13004 同时绑定个人账号 GT-P-13001 与企业一级账号 GT-E1-13001
  2. 个人侧分组为“个人牧场”，企业侧分组为“企业总部”，共享备注为“南场定位器”
  3. 当前关联 ICCID 为 898600001300000004，active 为 false，account_status 为 02，设备在线，服务到期日期为 2026-12-31
- 测试步骤
  1. 在个人账号 APP 与企业账号 APP 分别打开 GT-D-13004 详情抽屉，核对 ICCID；再从各自设备卡片 More → IoT SIM Query 核对 Active / Inactive 和 account_status。
  2. 在个人账号 Web、企业账号 Web 与管理后台进入各自能够展示对应业务字段的页面，核对设备唯一标识、共享备注、ICCID、激活标识、卡状态、在线状态和到期日期。
  3. 按同一业务字段比较 APP、Web 与管理后台返回值，不要求各端字段位于相同页面或采用相同布局；同时核对个人与企业账号的所属分组及两个账户级 groupId。
  4. 在管理后台将共享备注修改为“南场定位器-已复核”，随后刷新个人与企业账号的 APP、Web。
- 预期结果
  1. 各端均以 GT-D-13004 唯一标识读取同一物理设备，不因备注相同或账号不同生成设备副本；APP 详情抽屉的 SIM 信息只核 ICCID，不要求展示 Active / Inactive 或 account_status。
  2. 两个 APP 账号均需从 More → IoT SIM Query 看到激活标识 Inactive 和卡状态“停机”；Web 与管理后台在各自既有页面展示对应字段，各端 ICCID 均为 898600001300000004 且完整不丢位。
  3. 同业务字段的语义一致：备注为“南场定位器”、设备在线、到期日期为 2026-12-31；个人账号两端归属“个人牧场”，企业账号两端归属“企业总部”，两个账户级 groupId 分别保存，各端不要求相同页面布局。
  4. 刷新后所有关联账号的 APP、Web 均显示“南场定位器-已复核”，搜索也使用新备注；分组、SIM、在线状态和到期日期不因备注修改而改变。
