# US-032 在原平台接入牛马定位器类型
> 口径依据：设备管理逻辑大纲第 5.4～5.8、7、9～10 节。协议不兼容时只隔离必要适配边界，不新增授权入口或独立设备事实库；适配结果仍进入统一设备身份、四态指令和原记录链，未确认的协议字段不作为验收条件。

## [P1] 验证新协议位置结果进入统一设备事实链
- 测试类型
  - 兼容性
- 前置条件
  1. 牛马定位器 DEV-ND-14201 已入库并绑定企业一级账号 GT-E1-1421
  2. 旧类型设备 DEV-OLD-14201 已绑定同一账号，两个设备均具备有效位置测试数据
  3. 测试环境可观察协议适配输入、统一位置事实查询和历史记录结果
- 测试步骤
  1. 让 DEV-ND-14201 通过新类型协议适配边界提交一条 2026-10-12 10:20:00 的有效位置。
  2. 让 DEV-OLD-14201 通过原协议链提交一条 2026-10-12 10:21:00 的有效位置。
  3. 分别从 APP 实时追踪、详情抽屉和历史轨迹查询两台设备。
  4. 检查两类协议处理后的设备身份、位置事实与历史记录存储链路。
- 预期结果
  1. 新协议仅在适配边界完成必要转换，结果关联 DEV-ND-14201 并写入原统一位置事实与历史记录链。
  2. 旧协议继续关联 DEV-OLD-14201 并按原链路处理，不被新适配器接管或改变默认行为。
  3. 两台设备均按各自唯一标识展示最近有效位置和历史点，页面不感知协议差异且不串设备。
  4. 新类型未建立独立设备身份或独立位置事实库，统一查询可以同时返回两类设备的标准业务结果。

## [P1] 验证协议适配结果不能绕过原账号授权和关系校验
- 测试类型
  - 安全性
- 前置条件
  1. 牛马定位器 DEV-ND-14202 已直接绑定企业一级账号 GT-E1-1422
  2. 企业二级账号 GT-E2-1422 尚未获得 DEV-ND-14202 的分配关系
  3. DEV-ND-14202 已通过协议适配产生在线状态和有效位置
- 测试步骤
  1. 以 GT-E2-1422 登录 APP，查询设备列表并直接请求 DEV-ND-14202 的详情、实时位置和历史记录。
  2. 检查 APP 是否出现新类型专属绑定入口、协议授权入口或向下分配入口。
  3. 以 GT-E1-1422 在监控平台 Web 将 DEV-ND-14202 分配给 GT-E2-1422。
  4. 再次以 GT-E2-1422 查询设备列表、详情、实时位置和历史记录。
- 预期结果
  1. 列表不返回 DEV-ND-14202，详情、实时位置和历史请求均按原服务端权限与设备关系拒绝，协议数据到达不自动授予可见权。
  2. APP 不新增任何专属授权或分配入口，二级账号仍无直接绑定权。
  3. 仅新增一级到二级的原平台分配关系，不创建协议层授权副本或二级直接绑定关系。
  4. 分配后四类查询均按同一有效关系开放，GT-E2-1422 读取统一事实与记录链中的 DEV-ND-14202 数据。

## [P1] 验证不兼容指令协议映射到统一四态和记录链
- 测试类型
  - 可靠性
- 前置条件
  1. 牛马定位器 DEV-ND-14203 对账号 GT-E1-1423 可见且允许提交普通队列指令
  2. 已准备四次独立操作 CMD-ND-14231、CMD-ND-14232、CMD-ND-14233、CMD-ND-14234
  3. 协议适配测试环境可分别模拟排队未写出、已写出、明确失败和确认取消四种业务结果
- 测试步骤
  1. 提交 CMD-ND-14231 并保持在服务端已受理但尚未写出的结果。
  2. 提交 CMD-ND-14232 并模拟协议适配后完成终端链路写出。
  3. 提交 CMD-ND-14233 并模拟协议适配返回明确失败。
  4. 提交 CMD-ND-14234 后执行取消并完成取消确认，再查询四条指令记录。
- 预期结果
  1. CMD-ND-14231 创建 1 条 SENDING 记录，状态由统一指令服务持久化，不新增协议专属中间状态。
  2. CMD-ND-14232 更新为 SENT，写出不被误判为终端已生效，记录仍可按原入口查询。
  3. CMD-ND-14233 更新为 FAILURE 并保留可读失败结果，不新增独立超时态或协议错误事实库。
  4. CMD-ND-14234 更新为 CANCEL 且取消结果可追踪；记录页只出现 SENDING、SENT、FAILURE、CANCEL 四态并统一关联 DEV-ND-14203。

## [P2] 验证协议重试保留统一任务身份且重放旧反馈不回退新确认值
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-ND-14204 已存在定位频率确认值 10 分钟
  2. 账号 GT-E1-1424 对 DEV-ND-14204 有编辑和指令权限
  3. 指令记录中存在按既有规则具备重发入口的 60 分钟 FAILURE 记录 CMD-ND-14241，可控制协议反馈并查询 commandId、attemptId、businessId、configSequence 和 confirmedValue
- 测试步骤
  1. 从记录页重发 CMD-ND-14241，查询其任务身份、新尝试记录和本次配置顺序。
  2. 返回 CMD-ND-14241 新尝试的可靠成功反馈，确认旧任务先完成并将 confirmedValue 更新为 60 分钟。
  3. 再提交 1 分钟任务 CMD-ND-14242，待其按更大 configSequence 执行后返回可靠成功反馈。
  4. 重放 CMD-ND-14241 已完成尝试的旧 businessId 成功反馈，并查询编辑页、设备卡片和指令记录。
- 预期结果
  1. 重发保持 CMD-ND-14241 的 commandId，创建新的 attemptId 与一一映射的 businessId，原失败尝试和重发尝试均保留在统一记录链。
  2. CMD-ND-14241 按顺序完成后 confirmedValue 为 60 分钟；新任务在旧任务完成前不得越过 configSequence 提前成功。
  3. CMD-ND-14242 后续成功后 confirmedValue 更新为 1 分钟，任务和尝试仍复用统一四态、配置序列与记录链。
  4. 重放旧 businessId 只能幂等关联已完成的旧尝试，不得把 confirmedValue 从 1 分钟回退到 60 分钟；卡片保持 1 分钟确认值，两条任务记录均可追踪且不重复新增。
