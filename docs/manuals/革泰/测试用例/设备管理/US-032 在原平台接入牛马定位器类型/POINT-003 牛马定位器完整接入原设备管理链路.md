# US-032 在原平台接入牛马定位器类型
> 口径依据：设备管理逻辑大纲第 1.2～1.4、2.2～2.4、3.1～3.2、4.1～4.9、5.1～5.3、7、9～10 节。新增类型必须完整走通库存、绑定、分组、列表和查询，并复用原账号权限、设备关系及跨端数据。

## [P1] 验证企业一级账号完整走通库存到查询链路
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 GT-E1-1401 的直接绑定配额剩余 2 台，名下存在真实一级分组“牧场一区”
  2. 管理后台尚不存在设备唯一标识 DEV-ND-14001、设备卡号 GT14001001
- 测试步骤
  1. 在管理后台将 DEV-ND-14001 以牛马定位器类型和 S18 型号入库，设置服务到期日为 2027-12-31。
  2. 以 GT-E1-1401 登录 APP，从“设备管理 → 绑定设备”手动输入 GT14001001。
  3. 在绑定确认页将设备备注设为“东区牛群定位器”，选择真实分组“牧场一区”并确认绑定。
  4. 返回设备列表，按设备编号 GT14001001 搜索，先核对设备卡片展示，再点击卡片本体打开详情抽屉。
  5. 分别在监控平台 Web 和管理后台查询 DEV-ND-14001 的归属、分组、型号和到期时间。
- 预期结果
  1. 库存中新增 1 台牛马定位器，设备唯一标识、卡号、型号和到期时间可被原设备主数据链查询。
  2. APP 识别已入库且类型受支持的设备并进入绑定确认页，不把新类型误判为不存在或仅替换显示名称。
  3. 只建立 DEV-ND-14001 与 GT-E1-1401 的 1 条企业一级直接绑定关系，设备归属“牧场一区”，绑定不自动创建下级分配、围栏关联或定位频率任务。
  4. 列表仅返回 DEV-ND-14001；卡片按设备唯一标识展示左侧类型 / 状态图标、第一行“东区牛群定位器（GT14001001）”、已定义的第二行与第三行（无对应有效值时按规则隐藏）及右上角 More，不在卡片要求展示型号 S18 或到期日。
  5. 详情抽屉按 DEV-ND-14001 唯一标识查询并展示型号 S18、到期日 2027-12-31；APP 详情、监控平台 Web 和管理后台读取同一设备与关系数据，企业一级归属、分组、型号和到期时间语义一致。

## [P1] 验证个人与企业一级双绑沿用原关系槽位和共享事实
- 测试类型
  - 功能
- 前置条件
  1. 牛马定位器 DEV-ND-14002 已入库，设备卡号为 GT14001002，当前未建立直接绑定
  2. 个人账号 GT-P-1401 和企业一级账号 GT-E1-1402 均有剩余直接绑定配额
  3. GT-P-1401 名下存在分组“个人设备”，GT-E1-1402 名下存在分组“北区牧场”
- 测试步骤
  1. 以 GT-P-1401 在 APP 绑定 GT14001002，选择“个人设备”。
  2. 以 GT-E1-1402 在监控平台 Web 绑定同一设备，选择“北区牧场”。
  3. 将 DEV-ND-14002 的在线状态设为在线、电量设为 76%，并产生一条 2026-10-12 09:30:00 的有效定位。
  4. 分别以 GT-P-1401 和 GT-E1-1402 查询设备列表与详情。
- 预期结果
  1. 建立 1 条个人直接绑定关系，消耗个人槽位和个人配额，设备仅归属个人侧“个人设备”。
  2. 建立 1 条企业一级直接绑定关系，个人与企业一级双绑共存且不互相占用同类槽位，企业侧分组为“北区牧场”。
  3. 在线状态、电量和最后有效定位写入统一设备事实链，不为两个账号复制独立事实。
  4. 两个账号均只看到 1 台 DEV-ND-14002，在线状态、电量和定位一致，分组分别保持“个人设备”和“北区牧场”。

## [P1] 验证新类型按企业层级逐级分配且 APP 不新增授权入口
- 测试类型
  - 安全性
- 前置条件
  1. 牛马定位器 DEV-ND-14003 已直接绑定企业一级账号 GT-E1-1403
  2. GT-E1-1403 的直属二级账号为 GT-E2-1403，GT-E2-1403 的直属三级账号为 GT-E3-1403
  3. DEV-ND-14003 尚未分配给任何子账号
- 测试步骤
  1. 分别以 GT-E2-1403、GT-E3-1403 登录 APP，查看设备列表和设备管理入口。
  2. 以 GT-E1-1403 在监控平台 Web 将 DEV-ND-14003 分配给 GT-E2-1403。
  3. 以 GT-E2-1403 在监控平台 Web 将 DEV-ND-14003 分配给 GT-E3-1403。
  4. 分别以 GT-E1-1403、GT-E2-1403、GT-E3-1403 在 APP 和 Web 查询 DEV-ND-14003。
- 预期结果
  1. 二级、三级初始均看不到 DEV-ND-14003，APP 不展示直接绑定入口或向下分配入口。
  2. 只新增一级到二级的分配关系，一级继续可见，二级在 APP 与 Web 同步可见，关系不记录为二级直接绑定且不消耗 bindingQuota。
  3. 只新增二级到三级的分配关系，三级在 APP 与 Web 同步可见，不允许一级绕过二级直接授权三级。
  4. 三个账号均按各自有效关系查询同一设备事实，各列表按 DEV-ND-14003 去重为 1 台，未生成 APP 独立授权副本。

## [P2] 验证新类型列表筛选和详情查询使用统一设备身份
- 测试类型
  - 功能
- 前置条件
  1. 账号 GT-E1-1404 可见牛马定位器 DEV-ND-14004、DEV-ND-14005，二者备注均为“牛群定位器”
  2. DEV-ND-14004 卡号为 GT14001004、状态为告警加在线；DEV-ND-14005 卡号为 GT14001005、状态为离线
  3. 两台设备均归属真实分组“南区牧场”
- 测试步骤
  1. 在 APP 选择“南区牧场”和“告警”状态筛选，搜索“牛群定位器”。
  2. 点击结果中的 GT14001004 卡片本体打开详情抽屉。
  3. 关闭抽屉后清空关键词，切换到“离线”状态筛选。
  4. 点击 GT14001005 的更多菜单进入物联网卡查询页，再返回设备列表。
- 预期结果
  1. 条件按状态、分组、关键词取交集，仅返回 DEV-ND-14004；告警作为优先展示状态并保留在线底层差异。
  2. 详情请求使用 DEV-ND-14004 唯一标识，不因两台设备备注相同而查询到 DEV-ND-14005。
  3. 列表仅返回 DEV-ND-14005，未连接或离线仍统一归入离线口径，不新增新类型专属状态。
  4. 物联网卡查询仍以 DEV-ND-14005 唯一标识解析当前关联卡；返回后保留离线状态、南区牧场分组和原滚动位置。
