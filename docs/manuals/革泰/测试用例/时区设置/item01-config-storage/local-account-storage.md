# 用户故事：本地账号级存储与多端独立

> 口径依据：大纲第 2 章「配置模型与存储」、结论 3。时区为纯本地账号级数据，以账号为单位保存在本设备，不随设备共享、不上服务端；多端各自独立、可以不同；无同步、无冲突提示。

## [P1] 验证本设备修改时区后其他设备登录同账号不受影响
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01（密码 Test@1234）已在手机 A、手机 B 两台设备同时登录
  2. 两台设备当前时区均为 Beijing（GMT+8:00）
- 测试步骤
  1. 手机 A 打开「我的 → 时区设置」，改选 Sydney 行。
  2. 手机 A 返回监控页，查看设备「最近更新时间」的展示。
  3. 手机 B 不做任何时区操作，下拉刷新监控页，查看「最近更新时间」的展示。
  4. 手机 B 打开「我的 → 时区设置」查看当前选中行。
- 预期结果
  1. 手机 A 选中行对勾移动到 Sydney，立即写入本地。
  2. 手机 A 时间字段按 Sydney 偏移（执行日为夏令时段则 +11:00，标准时段则 +10:00，以当日 tzdata 现查为准）展示。
  3. 手机 B 时间字段仍按 Beijing（GMT+8:00）展示，无任何同步变化、无冲突提示弹窗。
  4. 手机 B 选中行仍为 Beijing，未被手机 A 的修改波及。

## [P2] 验证双设备同账号各自设置不同时区后展示各自自洽
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01（密码 Test@1234）在手机 A、手机 B 两台设备登录
  2. 手机 A 已选 Sydney，手机 B 已选 Brisbane
- 测试步骤
  1. 手机 A 打开轨迹页查看同一条轨迹点的展示时间。
  2. 手机 B 打开轨迹页查看同一条轨迹点的展示时间。
  3. 两台设备各自截屏记录展示值，与工具计算的预期值对照（Python zoneinfo 现算）。
- 预期结果
  1. 手机 A 展示值 = UTC 时刻 + Sydney 当日偏移。
  2. 手机 B 展示值 = UTC 时刻 + Brisbane (+10:00) 偏移，与手机 A 差值恰为两地偏移差。
  3. 两端各自自洽，服务端存储的同一事件时刻不变（守恒量）。

## [P2] 验证 APP 时区与 Web 监控平台互不同步
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01（密码 Test@1234）已登录 APP 与 Web 监控平台
  2. APP 当前时区为 Beijing（GMT+8:00），Web 平台时区设置为 GMT+0:00
- 测试步骤
  1. APP 端改选时区为 London 行。
  2. Web 监控平台刷新页面，查看时间展示所按时区。
  3. APP 端查看任意告警的发生时间展示。
- 预期结果
  1. APP 端立即生效，展示按 London 偏移。
  2. Web 平台时间仍按 GMT+0:00 展示，不受 APP 修改影响，无任何同步提示。
  3. 两端各自独立保存（无服务端真源，无从同步），展示各自自洽。

## [P3][反向] 验证修改 APP 时区不产生任何服务端保存动作
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，抓包工具（如 Charles）已挂代理准备抓取 APP 请求
  2. 当前时区为 Beijing
- 测试步骤
  1. 开始抓包，打开「我的 → 时区设置」。
  2. 改选 Perth（GMT+8:00）行，等待 30 秒。
  3. 改选 Adelaide 行，返回「我的」页，再等待 30 秒。
  4. 检查抓包记录中与个人资料 / 配置保存相关的请求。
- 预期结果
  1. 设置页正常打开。
  2. 两次点选均即时生效（对勾移动），期间无保存类网络请求发出。
  3. 页面返回正常。
  4. 抓包中无任何时区保存 / 用户配置更新请求（时区为纯本地存储，不上服务端）。
