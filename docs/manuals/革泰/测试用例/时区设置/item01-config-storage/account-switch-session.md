# 用户故事：账号切换与会话保留

> 口径依据：大纲第 2 章、第 6 章。账号 B 首次在本设备登录取默认（系统时区），不继承账号 A 的已存时区；B 第二次登录带出 B 自己的保存值。会话失效 / 退出登录后，时区作为登录页回显偏好的一部分保留，重新登录可带出。

## [P3] 验证账号 B 首次登录不继承账号 A 的时区
- 测试类型
  - 功能
- 前置条件
  1. 手机系统时区为 Asia/Shanghai
  2. 账号 A（testuserA / Test@1234）已在本设备登录，时区已改为 Reykjavik（GMT+0:00）
  3. 账号 B（testuserB / Test@1234）从未在本设备登录过
- 测试步骤
  1. 账号 A 退出登录。
  2. 账号 B 在登录页登录。
  3. 账号 B 进入「我的 → 时区设置」查看选中行。
- 预期结果
  1. 退出成功，回到登录页。
  2. 账号 B 登录成功。
  3. 选中行为系统时区对应行 Beijing（GMT+8:00），不继承 A 的 Reykjavik（账号级本地数据互相隔离）。

## [P2] 验证账号 B 再次登录带出 B 自己的时区
- 测试类型
  - 功能
- 前置条件
  1. 账号 B 已在本设备登录过一次，且已把时区改为 Darwin（GMT+9:30）
- 测试步骤
  1. 账号 B 退出登录后再次登录。
  2. 进入「我的 → 时区设置」查看选中行。
- 预期结果
  1. 登录成功。
  2. 选中行为 Darwin，带出 B 上次保存值（B 自己的本地记录，非 A 的值）。

## [P2] 验证退出登录后时区偏好保留且重登可带出
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，时区为 Tokyo（GMT+9:00）
- 测试步骤
  1. 账号 testuser01 退出登录，回到登录页。
  2. 不登录，杀进程后重开 APP，查看登录页时区项。
  3. 用账号 testuser01 重新登录，进入「我的 → 时区设置」查看选中行。
- 预期结果
  1. 退出成功。
  2. 登录页时区回显保留 Tokyo（作为最后成功登录账号的偏好，不清空）。
  3. 重登后选中行为 Tokyo，偏好可正常带出。

## [P3] 验证双开 / 工作资料双实例时区互相隔离
- 测试类型
  - 功能
- 前置条件
  1. Android 测试机支持应用分身（或工作资料），已创建革泰 APP 双实例
  2. 实例 1 已登录账号 testuser01，时区为 Seoul
- 测试步骤
  1. 实例 2 登录账号 testuser02，进入「我的 → 时区设置」查看选中行。
  2. 实例 2 改选 Vancouver（Windows 视图对应 Pacific Time (US & Canada) 行）。
  3. 实例 1 打开「我的 → 时区设置」查看选中行。
- 预期结果
  1. 实例 2 选中行为系统时区默认（Beijing），不继承实例 1 的 Seoul。
  2. 实例 2 改选成功。
  3. 实例 1 选中行仍为 Seoul，双实例存储空间独立、时区互不串。
