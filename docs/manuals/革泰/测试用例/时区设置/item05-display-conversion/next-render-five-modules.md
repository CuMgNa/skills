# 用户故事：下次渲染生效与五模块走查

> 口径依据：大纲第 7 章。生效范围覆盖五模块（地图监控 / 轨迹 / 告警 / 指令 / 设备与物联网卡）；生效时机为下次渲染：切换后返回或进入页面时按新时区重新渲染，不承诺停留页面实时跳变（下拉刷新、30s/60s 自动刷新触发的更新不视为违反）。

## [P1] 验证切换时区后各业务页按新时区重新渲染
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，当前时区 Beijing，名下设备当天有定位上报、告警、指令记录
- 测试步骤
  1. 记录监控页「最近更新时间」当前展示值（Beijing 口径）。
  2. 进入「我的 → 时区设置」改选 Tokyo（GMT+9:00）。
  3. 返回监控页查看「最近更新时间」。
  4. 依次进入轨迹页、告警页、指令页，各查看一个时间字段。
- 预期结果
  1. 记录成功。
  2. 改选即时生效。
  3. 监控页按 Tokyo（+9）重新渲染，展示值 = 原值 +1h。
  4. 轨迹点时间、告警发生时间、指令提交时间均按 Tokyo 口径展示（返回 / 进入页面触发重渲染）。

## [P2] 验证五模块时间字段全量走查（跨大偏移时区）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，当前时区 Beijing
  2. 名下设备有：当天定位上报、历史轨迹、告警记录、指令记录、物联网卡（含服务到期 / 卡有效期）
- 测试步骤
  1. 记录五模块各一个时间字段在 Beijing 口径下的展示值。
  2. 改选 Kiritimati Island（GMT+14:00）。
  3. 依次重进监控页（最近更新时间、定位上报时间）、轨迹页（轨迹点时间）、告警页（发生时间 / 处理时间）、指令页（提交 / 发送 / 回复 / 过期时间）、设备与物联网卡页（创建时间、服务到期时间、卡有效期）。
  4. 与 Python zoneinfo 现算预期值逐项对照。
- 预期结果
  1. 记录成功。
  2. 改选成功。
  3. 五模块全部时间字段按 +14 重新渲染。
  4. 逐项与预期一致（服务到期等纯日期字段除外，见纯日期专项）。

## [P2] 验证停留页面不强制实时跳变（下次渲染口径）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，当前时区 Beijing，正停留在轨迹详情页
- 测试步骤
  1. 停留在轨迹详情页，切到「我的 → 时区设置」改选 Perth（同 +8:00 偏移，改选不影响数值）。
  2. 返回轨迹详情页（返回栈复现）。
  3. 再次改选 Adelaide（+9:30），这次停留在监控页不动，等待 65 秒（超过 60s 自动刷新周期）。
  4. 观察监控页时间展示变化。
- 预期结果
  1. 改选成功。
  2. 返回轨迹详情页按 Perth 重新渲染（返回栈复现触发重渲染）。
  3. 停留监控页在自动刷新到期前不要求时间跳变（不承诺实时跳变）。
  4. 65 秒内自动刷新触发后，监控页时间按 Adelaide 口径更新（自动刷新触发的准实时切换不视为违反「不承诺实时跳变」口径）。

## [P3][反向] 验证 Android 系统返回键回业务页无旧时区残留
- 测试类型
  - 功能
- 前置条件
  1. Android 测试机，账号 testuser01 已登录，当前时区 Beijing
  2. 已从监控页进入「我的 → 时区设置」（返回栈中存在监控页）
- 测试步骤
  1. 在时区设置页改选 Anchorage（Windows 视图 Alaska 行，GMT-9:00/-8:00 按当日）。
  2. 按系统返回键回到监控页。
  3. 检查「最近更新时间」展示口径。
  4. 再按返回键经过轨迹页（若在返回栈），检查其时间字段。
- 预期结果
  1. 改选成功。
  2. 返回监控页正常。
  3. 监控页按新时区重渲染，无旧时区渲染残留（契约 #15：返回栈失效化）。
  4. 轨迹页同样重渲染，无残留。
