# 用户故事：夏令时按事件日期逐点转换

> 口径依据：大纲 7.3 节、11.1 节 S5 / S8 数据集。每个时间戳按其自身日期的 DST 相位转换（端侧 IANA 逐点计算），不是按「查看时刻」的相位；非整点偏移（+5:45 / +12:45）分钟位不得抹零、跨日方向不得反。预期值按 2026-09-18 tzdata 预计算，执行时以设备当前 tzdata 现查为准。

## [P1] 验证标准时相位查看夏令时历史轨迹逐点正确（S5 数据集）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，已注入两点：P1（UTC 2026-01-15 00:30，存储 01-15 08:30）、P2（UTC 2026-01-15 13:30，存储 01-15 21:30）
  2. 执行窗口悉尼为标准时相位（2026-10-04 前）
- 测试步骤
  1. APP 时区选 Sydney，进轨迹页查看 P1 展示时间。
  2. 查看 P2 展示时间（跨日判别点）。
  3. 与 11.1 节预计算预期值对照。
- 预期结果
  1. P1 显示 2026-01-15 11:30（按事件日 1 月夏令 +11）；若显示 10:30 → 错用当前相位 +10，缺陷。
  2. P2 显示 2026-01-16 00:30（+11 跨日）；若显示 01-15 23:30 → 错 1h 且错一天，缺陷（黄金用例：按日分组统计点数会偏）。
  3. 两点均与预期一致，历史事件按各自发生日期的 DST 相位转换。

## [P1] 验证非整点偏移转换分钟位与跨日方向（S8 数据集）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，已注入三点：K1（UTC 2026-08-15 00:00，存储 08-15 08:00）、K2（UTC 2026-08-15 18:30，存储 08-16 02:30）、C1（UTC 2026-08-15 12:00，存储 08-15 20:00）
- 测试步骤
  1. APP 时区选 Kathmandu（GMT+5:45），进轨迹页查看 K1 展示时间。
  2. 查看 K2 展示时间。
  3. 改选 Chatham Islands（GMT+12:45），查看 C1 展示时间。
- 预期结果
  1. K1 显示 2026-08-15 05:45——分钟必须落 :45，不得抹零成整点。
  2. K2 显示 2026-08-16 00:15（+5:45 跨日）——跨日方向不得反。
  3. C1 显示 2026-08-16 00:45（+12:45 跨日）——45 分钟档 + 跨日双重验证通过。

## [P2] 验证同一时区下不同相位事件各自正确（混合相位列表）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，已注入同年三点：1 月点（UTC 2026-01-15 00:00）、7 月点（UTC 2026-07-15 00:00）、9 月点（UTC 2026-09-15 00:00），存储值分别为 08:00 / 08:00 / 08:00（UTC+8）
- 测试步骤
  1. APP 时区选 Sydney，进轨迹列表查看三点展示时间。
  2. 核对每点各自相位：1 月点（夏令 +11）、7 月 / 9 月点（标准 +10）。
  3. 同一列表内比较三点偏移差异。
- 预期结果
  1. 三点均正常展示。
  2. 1 月点显示 11:00，7 月点与 9 月点均显示 10:00。
  3. 同一列表内不同日期的点按各自事件日相位逐点计算（非按查看时刻统一相位）。

## [P2] 验证展示转换规则跨模块同法适用（告警 / 指令）

  - 功能

  3. 三模块同时刻事件展示值完全一致（APP 端转换为全局规则，同法适用）。
