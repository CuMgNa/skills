# 用户故事：动态偏移标注

> 口径依据：大纲第 4、5 章、结论 7、11.1 节 S7 数据集。列表行 GMT/UTC 偏移按访问当日该区实际偏移计算（含夏令时）；同一行不同季节访问标注不同（1 月访问 Sydney 显示 +11:00，7 月显示 +10:00）。2026-09-18 基准标注仅对 2026-10-04 前执行有效。

## [P1] 验证夏令时敏感行标注按访问当日相位显示
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录
  2. 执行时点在 2026-10-04 前（悉尼标准时相位），预期值按 11.1 节 S7 基准
- 测试步骤
  1. 进入「我的 → 时区设置」。
  2. 找到 Sydney 行，核对偏移标注。
  3. 找到 Adelaide 行与 Lord Howe Island 行，核对偏移标注。
  4. 找到 London 行，核对偏移标注。
- 预期结果
  1. 列表正常展示。
  2. Sydney 行标注 GMT+10:00（标准时相位；2026-10-04 起应变为 +11:00）。
  3. Adelaide 行标注 GMT+9:30、Lord Howe Island 行标注 GMT+10:30（均标准时相位）。
  4. London 行标注 GMT+1:00（9 月为夏令时；2026-10-25 起变 +0:00）——南北半球相位相反，标注各自正确。

## [P4] 验证 Chatham Islands 在执行窗口内翻相的标注变化
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录
  2. 可将设备系统日期分别调至 2026-09-26 与 2026-09-28（或等待真实日期跨 2026-09-27 新西兰夏令时切换）
- 测试步骤
  1. 系统日期 2026-09-26（切换前），进入「我的 → 时区设置」查看 Chatham Islands 行标注。
  2. 系统日期改为 2026-09-28（切换后），重新进入「我的 → 时区设置」查看 Chatham Islands 行标注。
  3. 对照查询窗口重进业务页（设备时间变更后以服务端时间为基准的功能不受影响，本用例仅看列表标注）。
- 预期结果
  1. 切换前标注 GMT+12:45。
  2. 切换后标注 GMT+13:45（45 分钟档 DST 翻相在本执行窗口内发生）。
  3. 偏移标注按访问当日实际相位动态计算，同一行不同日期标注不同。
