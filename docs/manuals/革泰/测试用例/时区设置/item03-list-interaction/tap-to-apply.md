# 用户故事：点选即生效交互

> 口径依据：大纲第 4 章。点选新行 → 对勾移动到新行 → 立即写入本地并生效；无保存按钮、无确认弹窗；单选互斥；返回仅退出页面、已点选变更不回滚。

## [P1] 验证点选新行对勾移动且单选互斥
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，当前时区为 Beijing（+8:00 档，带对勾）
- 测试步骤
  1. 进入「我的 → 时区设置」。
  2. 点选 Tokyo（GMT+9:00）行。
  3. 观察 Tokyo 行与 Beijing 行的对勾状态。
  4. 再点选 Seoul（GMT+9:00）行，观察对勾变化。
- 预期结果
  1. 列表正常展示，Beijing 行带对勾。
  2. 点选响应即时。
  3. 对勾从 Beijing 行移动到 Tokyo 行，原行对勾消失（单选互斥）。
  4. 对勾再移动到 Seoul 行，全程同一时刻仅一行有对勾。

## [P1] 验证点选立即写入本地无保存确认环节
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，当前时区为 Beijing
- 测试步骤
  1. 进入「我的 → 时区设置」，点选 Perth 行。
  2. 观察是否出现保存按钮 / 确认弹窗 / 二次询问。
  3. 不做任何额外操作，直接杀进程。
  4. 重开 APP，进入「我的 → 时区设置」查看选中行。
- 预期结果
  1. 点选成功，对勾移至 Perth。
  2. 无保存按钮、无确认弹窗、无任何二次询问。
  3. 进程被杀。
  4. 选中行仍为 Perth——点选即写入本地（无草稿态），杀进程不丢失。

## [P2] 验证重复点选当前已选行无副作用
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，当前时区为 Tokyo
- 测试步骤
  1. 进入「我的 → 时区设置」，再次点选 Tokyo 行（当前选中行）。
  2. 观察对勾与页面状态。
  3. 返回「我的」页查看资料页时区行。
- 预期结果
  1. 点选无异常反应。
  2. 对勾保持 Tokyo 行不变，无弹窗、无重复写入异常。
  3. 时区行仍显示 Tokyo，配置值不变。

## [P3][反向] 验证列表快速连续点选不产生错乱
- 测试类型
  - 稳定性
- 前置条件
  1. 账号 testuser01 已登录，当前时区为 Beijing
- 测试步骤
  1. 进入「我的 → 时区设置」。
  2. 快速连续点选 5 个不同行（Sydney → Perth → Adelaide → Darwin → Kathmandu）。
  3. 停止操作，等待 2 秒观察列表。
  4. 杀进程重开，查看最终选中行。
- 预期结果
  1. 列表加载正常。
  2. 连续点选过程无崩溃、无 UI 卡死。
  3. 最终对勾停留在最后点选的 Kathmandu 行，对勾唯一。
  4. 重开后选中行为 Kathmandu，与界面终态一致（最后一次写入胜出，无中间态残留）。
