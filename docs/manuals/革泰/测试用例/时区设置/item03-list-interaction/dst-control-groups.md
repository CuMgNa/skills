# 用户故事：DST 敏感对照组

> 口径依据：大纲 5.3 节（用例设计金料）、11.1 节 S5 / S9 / L 系数据集、10.1 节 B 系切换日数据。同标准偏移不同 DST 规则的城市必须可区分（验证存储 IANA 区域名而非偏移量的最小组）；DST 偏移差值不恒为 1h（Lord Howe 仅 30 分钟）；切换日回拨夜同一本地时刻出现两次。所有预期值按 2026-09-18 当前 tzdata 相位预计算，执行时以设备当前 tzdata 现查为准。

## [P1] 验证同偏移不同 DST 城市可区分（Brisbane vs Sydney 最小组）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，名下设备已在 UTC 2026-01-15 00:30（后端存储 2026-01-15 08:30，UTC+8 基准）注入轨迹点
  2. 已知 1 月悉尼为夏令时 +11:00、布里斯班恒定 +10:00
- 测试步骤
  1. APP 时区选 Brisbane，进轨迹页查看该轨迹点展示时间。
  2. 改选 Sydney（+10:00 档组行），返回轨迹页查看同一点展示时间。
  3. 比较两次展示值。
- 预期结果
  1. Brisbane 口径显示 2026-01-15 10:30。
  2. Sydney 口径显示 2026-01-15 11:30（按事件日 1 月为夏令 +11）。
  3. 两次展示差 1 小时——同标准偏移两城因 DST 规则不同而可区分，证明存 IANA 区域名而非偏移量。

## [P1] 验证 Lord Howe Island DST 仅 30 分钟档位正确（S9 数据集）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，已注入两点：LH1（UTC 2026-01-15 00:00，存储 01-15 08:00）、LH2（UTC 2026-07-15 00:00，存储 07-15 08:00）
  2. 已知 Lord Howe 夏令 +11:00 / 标准 +10:30，DST 偏移差仅 30 分钟
- 测试步骤
  1. APP 时区选 Lord Howe Island，进轨迹页查看 LH1 展示时间。
  2. 查看同一点 LH2 展示时间。
  3. 改选 Sydney，查看 LH1、LH2 展示时间作对照。
  4. 计算 Lord Howe 与 Sydney 两城对同一点的偏移差。
- 预期结果
  1. LH1 显示 2026-01-15 11:00（夏令 +11:00）。
  2. LH2 显示 2026-07-15 10:30（标准 +10:30）。
  3. Sydney 口径 LH1 显示 11:00（夏令 +11）、LH2 显示 12:00（标准 +10）。
  4. 两点偏移差均须为 30 分钟；若差 60 分钟 → 误套悉尼规则 / 偏移硬编码，缺陷。

  2. 执行窗口内伦敦为夏令时 +1:00
- 测试步骤
  1. APP 时区选 London（+0:00 档 Dublin 组行），查看 L1 展示时间。
  2. 查看 L2 展示时间。

  3. Reykjavik 口径 L1 显示 12:00（+0 恒定）——同标准偏移、DST 有无，北半球对照组成立。

  - 功能
- 前置条件

  3. 展示值与 zoneinfo 现算一致，回拨夜歧义时刻按各自 UTC 时刻正确归属。
