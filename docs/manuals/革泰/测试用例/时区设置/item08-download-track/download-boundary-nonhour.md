# 用户故事：下载点集边界与非整点偏移（RISK-TZ-02 / 04 / 05 取证）

> 口径依据：大纲 10.3 节、10.1 节 S4、第 12 章。RISK-TZ-02：下载「点集」边界可能也偏 1h（不止标签错），「屏幕 vs 文件点数」交叉核对一次定级——相等为轻形态 A（仅标签错），差边界小时的点为重形态 B（点集本身错）；RISK-TZ-05：非整点偏移区（+5:30 / +10:30 / +5:45）下载传参兼容性，一测便知；RISK-TZ-04：轨迹日历「有轨迹日」标记的日切口径。

## [P1] 验证屏幕点数与下载文件行数交叉核对（RISK-TZ-02 定级抓手）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，APP 时区选 Sydney（标准时相位）
  2. 某日（如 2026-01-15）已注入含边界时刻的轨迹若干点
  3. 抓包工具就绪，准备记录下载接口请求参数
- 测试步骤
  1. 轨迹页按「2026-01-15」筛选，统计屏幕展示点数。
  2. 下载同日轨迹，统计文件数据行数。
  3. 抓包记录下载接口的时间参数形态（UTC 起止范围 vs 日期 + 偏移）。
  4. 比较屏幕点数与文件行数。
- 预期结果
  1. 屏幕点数统计完成（设为 N）。
  2. 文件行数统计完成（设为 M）。
  3. 参数形态取证成功。
  4. 若 M = N → 下载传 UTC 范围（RISK-TZ-02 轻形态 A，仅标签错）；若 M 与 N 差边界小时的点 → 传日期 + 偏移（重形态 B，点集本身错）——一项核对完成定级，结论记入取证报告（待确认 #14）。

## [P4] 验证非整点偏移区下载不恒偏 30/45 分钟（RISK-TZ-05）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，已注入：UTC 2026-08-15 00:00 点（存储 08-15 08:00）
  2. APP 时区选 Kolkata（Chennai, Kolkata, Mumbai, New Delhi 组行，GMT+5:30）
- 测试步骤
  1. 下载 2026-08-15 当日轨迹。
  2. 核对文件内该点时间（正确值应为 08-15 05:30）。
  3. 换选 Kathmandu（+5:45）重复下载，核对（正确值应为 08-15 05:45）。
- 预期结果
  1. 两次下载均成功（若 +5:30/+5:45 传参被后端拒绝 / 解析失败，本身即 RISK-TZ-05 实锤）。
  2. Kolkata 文件值 = 05:30。
  3. Kathmandu 文件值 = 05:45——时间不得恒偏 30 / 45 分钟、不得抹零成整点（与 DST 无关的传参兼容性，一测便知，中等级风险）。

## [P4] 验证轨迹日历「有轨迹日」标记按 APP 时区点亮（RISK-TZ-04 取证）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，APP 时区选 Sydney
  2. 已注入单点：UTC 2026-01-15 13:30（悉尼本地 2026-01-16 00:30，跨日点）
- 测试步骤
  1. 打开轨迹日历，翻到 2026 年 1 月。
  2. 查看「有轨迹日」标记点亮的日期。
  3. 核对点亮的是 01-15 还是 01-16。
- 预期结果
  1. 日历正常展示。
  2. 该单点应点亮 01-16（按用户 APP 时区日切）。
  3. 若点亮 01-15 → 服务端按 UTC+8 日切聚合，RISK-TZ-04 实锤（非 UTC+8 用户日历标记系统性偏移），记录取证结论（待确认 #15），按已知风险挂账口径处置。
