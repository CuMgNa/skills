# 用户故事：跨午夜与 DST 切换日窗口

> 口径依据：大纲 10.3 节 RISK-TZ-03、11.1 节 S18 / S22 / S17 数据集、场景 17/18/22。跨午夜前后两次「今日」查询窗口整体前移；悉尼 2026-04-05 回拨日（25h）与 2026-10-04 跳变日（23h）的「今日」窗口边界；Havana 午夜切换 00:00 不存在的归属断言。预期值以当前 tzdata 现查为准、不手造。

## [P4] 验证跨午夜前后两次「今日」查询窗口整体前移（S18 数据集）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，APP 时区选 Sydney
  2. 令 D = 执行日的北京日历日，D 日白天一次性注入三点：P_a（UTC D-1 14:30，悉尼 D 日 00:30）、P_b（UTC D 13:30，悉尼 D 日 23:30）、P_c（UTC D 14:30，悉尼 D+1 日 00:30）
  3. 悉尼午夜 = 北京时间 22:00，无需熬夜
- 测试步骤
  1. 北京时间 D 日 21:59（悉尼 23:59），轨迹页查「今日」，核对点集。
  2. 北京时间 D 日 22:01（悉尼次日 00:01），再次查「今日」，核对点集。
  3. 比较两次窗口覆盖。
- 预期结果
  1. 第一次「今日」含 P_a、P_b，不含 P_c。
  2. 第二次「今日」仅含 P_c（窗口整体前移一天，以服务端时间为基准）。
  3. 两次查询均无丢点、无重复计入。

## [P4] 验证悉尼回拨日「今日」窗口含本地 00:30 首次点（RISK-TZ-03 取证）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，APP 时区选 Sydney
  2. 已注入：UTC 2026-04-04 13:30 点（悉尼本地 2026-04-05 00:30 首次，AEDT +11）
  3. 执行方式：将系统日期调至 2026-04-05 白天（或等真实日期），以服务端校时为「现在」
- 测试步骤
  1. 轨迹页查「今日 = 04-05」筛选结果。
  2. 核对该 00:30 首次点是否在结果内。
  3. 再查「昨日 = 04-04」筛选结果，核对该点不混入。
- 预期结果
  1. 查询正常返回。
  2. 该点必须出现在「今日 04-05」结果中（回拨日 25h，IANA 感知算法下 00:30 首次属 04-05）。
  3. 不得落进「昨日 04-04」——若用「当前偏移 +10」算边界导致起点晚 1h、该点落昨日，即 RISK-TZ-03 实锤，缺陷。

## [P4] 验证悉尼跳变日「今日」窗口不含前一日 23:30 点（RISK-TZ-03 取证）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，APP 时区选 Sydney
  2. 已注入：UTC 2026-10-03 13:30 点（悉尼本地 2026-10-03 23:30，AEST +10，属前一日）
- 测试步骤
  1. 在 2026-10-04 当天（调系统日期或等真实日期，以服务端校时为准）轨迹页查「今日 = 10-04」。
  2. 核对该 23:30 前日点是否混入。
  3. 查「昨日 = 10-03」确认该点归属。
- 预期结果

  2. 该点不得混入「今日 10-04」（跳变日 23h，窗口起点按 IANA 规则计算）。
  3. 该点应属「昨日 10-03」——若前日 23:30 的点混进「今日」，即 RISK-TZ-03 反向实锤，缺陷。

## [P4] 验证 DST 切换日按日统计窗口 25h / 23h 属预期（S22 数据集）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，APP 时区选 Sydney
  2. 已注入五点：R1（UTC 2026-04-04 13:30 → 本地 04-05 00:30 AEDT）、R2（UTC 2026-04-05 13:30 → 本地 04-05 23:30 AEST）、F1（UTC 2025-10-04 14:30 → 本地 10-05 00:30 AEST）、F2（UTC 2025-10-05 12:30 → 本地 10-05 23:30 AEDT）、F0（UTC 2025-10-05 13:30 → 本地 10-06 00:30，界外对照）
- 测试步骤
  1. 查 04-05 当日按日统计（点数 / 里程），核对 R1、R2 归属与 04-04、04-06 的计数。
  2. 查 10-05 当日统计，核对 F1、F2 计入、F0 不计入。
  3. 与常规日 24h 口径的统计对照，标注切换日窗口差异。
- 预期结果
  1. 04-05 统计含 R1 + R2 共 2 点，04-04 / 04-06 为 0（回拨日 25h 窗口）。
  2. 10-05 统计 = F1 + F2 共 2 点，F0 落 10-06（跳变日 23h 窗口）。
  3. 切换日统计窗口比常规日多 / 少 1 小时属预期，不按 24h 质疑点数（用例标注，不误报）。

## [P4] 验证 Havana 午夜切换日不丢点不重（S17 数据集）
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，APP 时区选 Havana（GMT-5:00）
  2. 已注入两点：H1（UTC 2026-03-08 04:30，存储 03-08 12:30 → 本地 03-07 23:30 切换前）、H2（UTC 2026-03-08 05:30，存储 03-08 13:30 → 本地 03-08 01:30 切换后）
  3. 已知 2026-03-08 当地 00:00–00:59 不存在（00:00 起夏令时）
- 测试步骤
  1. 查轨迹「03-07」日期筛选，核对含 H1 不含 H2。
  2. 查「03-08」日期筛选，核对含 H2 不含 H1。
  3. 「03-08 今日窗口起点」的取值不做手造预期，仅记录实际行为供时区库实现确认（场景 17 口径）。
- 预期结果
  1. 「03-07」含 H1、不含 H2。
  2. 「03-08」含 H2、不含 H1——两点归属不错日、不丢点、不重复。
  3. 跳变日 00:00 不存在时刻的窗口起点行为如实记录，不判缺陷、不手造预期。
