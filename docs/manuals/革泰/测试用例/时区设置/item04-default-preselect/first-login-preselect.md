# 用户故事：首登系统时区预选与兜底

> 口径依据：大纲第 6 章。首次登录 / 注册（本设备本账号无记录）预选手机系统当前时区（映射到列表对应城市行）；系统时区不可用 / 无法映射时兜底 GMT+0（实现待联调确认 #5，执行前先与开发确认兜底触发方式）。本条关闭登录篇 2.8「默认时区来源待确认」遗留项。

## [P1] 验证首次登录预选手机系统时区
- 测试类型
  - 功能
- 前置条件
  1. 测试机系统时区设为 Asia/Shanghai
  2. 账号 testuser01 在本设备无登录记录（首装或清除数据后）
- 测试步骤
  1. 打开 APP 进入登录页。
  2. 查看时区项默认预选值。
  3. 直接用预选值提交登录，进入「我的 → 时区设置」查看选中行。
- 预期结果
  1. 登录页正常展示。
  2. 时区项预选系统时区对应行 Beijing（GMT+8:00）。
  3. 登录后选中行为 Beijing，系统时区映射成功。

## [P2] 验证系统时区为非整点 / 非首城时的预选映射
- 测试类型
  - 功能
- 前置条件
  1. 测试机系统时区分别设为 Asia/Kathmandu、Australia/Adelaide（两次执行）
  2. 账号 testuser01 在本设备无登录记录
- 测试步骤
  1. 系统时区设为 Kathmandu，冷启动 APP 进登录页，查看时区项预选值。
  2. 清除数据，系统时区改为 Adelaide，再次冷启动进登录页查看预选值。
  3. 核对两次预选行的偏移标注。
- 预期结果
  1. 预选 Kathmandu（GMT+5:45）行。
  2. 预选 Adelaide 行。
  3. 偏移标注按访问当日动态相位显示（Adelaide 夏令期 +10:30 / 标准时 +9:30），映射按 IANA 区域名而非偏移量。

## [P3][反向] 验证系统时区不可用时兜底 GMT+0
- 测试类型
  - 功能
- 前置条件
  1. 执行前与开发确认兜底触发方式（待确认 #5：如系统返回异常时区 / 无法映射的 IANA 值时构造）
  2. 账号 testuser01 在本设备无登录记录
- 测试步骤
  1. 按确认的方式构造系统时区不可用 / 无法映射状态。
  2. 冷启动 APP 进登录页，查看时区项预选值。
  3. 提交登录后进入「我的 → 时区设置」查看选中行。
- 预期结果
  1. 构造成功（APP 能启动，不崩溃）。
  2. 时区项预选兜底值 GMT+0:00（不空白、不报错）。
  3. 登录后选中行为 +0:00 档对应行，用户可正常改选。

## [P2] 验证系统时区映射到 Windows 组行（非首城场景）
- 测试类型
  - 功能
- 前置条件
  1. 测试机系统时区设为 Asia/Chongqing（同组 Beijing, Chongqing, Hong Kong, Urumqi 的非首城成员）
  2. 账号 testuser01 在本设备无登录记录
- 测试步骤
  1. 冷启动 APP 进登录页，查看时区项预选值。
  2. 提交登录，进入「我的 → 时区设置」查看选中行。
- 预期结果
  1. 预选显示组首城 Beijing（GMT+8:00）行（同组城市选取结果等同整组）。
  2. 选中行为 Beijing 组行，配置实际存储 IANA 值（组内任一城市等价）。
