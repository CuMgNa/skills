# 用户故事：iOS 平台专项

> 口径依据：大纲 12A.2 章。整机备份恢复随备份带回（I1）；系统自动时区开启（基于定位）不跟随、首登预选取值时点待 UI 确认 #12；后台跨 DST 切换回前台按切换后相位重渲染（I3）；12/24 小时制与日期格式跟随系统区域设置、时间数值与时区由 APP 时区决定（两层分离断言，I4）；H5 时间字段待联调排查 #13（不立项）。

## [P2] 验证系统自动时区（定位）切换不跟随改写 APP 配置（I2）
- 测试类型
  - 兼容性
- 前置条件
  1. iPhone 开启「设置 → 日期与时间 → 自动时区」（基于定位）
  2. 账号 testuser01 已登录，APP 时区为 Beijing
  3. 可通过模拟定位 / 跨时区移动触发系统自动时区变化（如模拟定位到东京）
- 测试步骤
  1. 触发系统自动时区切换（系统时区由 Asia/Shanghai 变为 Asia/Tokyo）。
  2. 打开 APP 查看监控页时间展示口径与「我的 → 时区设置」选中行。
  3. 将 APP 切后台 10 分钟（期间系统自动时区再变一次），回前台复查。
- 预期结果
  1. 系统时区切换成功。
  2. APP 仍按 Beijing 口径展示、选中行仍为 Beijing（APP 配置不跟随系统自动时区，符合纯本地账号级拍板模型）。
  3. 回前台后依旧，无跳变、无改写。

## [P4] 验证后台停留跨 DST 切换回前台按新相位显示（I3 / 场景 24）
- 测试类型
  - 功能
- 前置条件
  1. iPhone，账号 testuser01 已登录，APP 时区为 Sydney
  2. 执行安排：悉尼 2026-10-04 02:00（AEST→AEDT）跳变时刻 APP 处于后台（北京 2026-10-04 00:00 前后，即 10-03 深夜）
- 测试步骤
  1. 跳变前进入时区设置页或业务页后切后台。
  2. 等待跨过跳变时刻（悉尼 +10 → +11）。
  3. 回前台，查看时区设置页 Sydney 行偏移标注与业务页时间展示。
  4. 核对历史数据点（如 9 月标准时相位点）展示是否仍按事件日相位。
- 预期结果
  1. 后台切换成功。
  2. 回前台触发重渲染。
  3. Sydney 行标注变为 GMT+11:00（切换后相位），当前时刻类字段按 +11，无旧相位 +10 残留。
  4. 历史点仍按各自事件日相位（9 月点 +10），当前与历史分层正确。

## [P4] 验证 12/24 小时制与日期格式两层分离（I4）
- 测试类型
  - 功能
- 前置条件
  1. iPhone，账号 testuser01 已登录，APP 时区为 Kathmandu（GMT+5:45）
  2. 系统区域设为「中文（中国）」、时间显示设为 12 小时制
- 测试步骤
  1. 在系统 12h 制 + 中文区域下，查看 APP 内任意时间字段（如告警发生时间）的数值与格式。
  2. 将系统时间显示改为 24 小时制（区域不变），重进页面查看。
  3. 将系统区域改为 English (US)，重进页面查看。
- 预期结果
  1. 时间数值按 Kathmandu 口径（含 :45 分钟位），格式按系统 12h 制（如 上午/下午 + hh:mm）。
  2. 数值不变，格式切换为 24h 制。
  3. 数值仍按 Kathmandu，格式跟随英文区域（如 5:45 AM / 日月顺序变化）——数值与时区由 APP 时区决定、格式跟随系统区域设置，两层分离各自正确（UI 自动化预期文案须按设备区域设置生成）。

  2. 已执行 iCloud / iTunes 整机备份，新 iPhone 可用
- 测试步骤

  2. 打开 APP 用 testuser01 登录。
  3. 进入「我的 → 时区设置」查看选中行。

  - 功能
- 前置条件
