# US-029 统一设置 APP 展示时区

> 这一组查的是：APP 按所选时区判断「某一天从几点到几点」时，轨迹点会不会被算到错误的那一天。对应大纲 RISK-TZ-03、场景 17 / 18 / 22。
>
> 先看懂这三件事，再往下测：
> 1. 所有要录入的时间都用北京时间。造数工具直接填这个时间。
> 2. 第 1 条不写死日期。先找到「当地下一个零点」对应的北京时间，后面叫它零点。今天测、明天测都按当天重新算一次。选布里斯班最省事：当地零点固定是北京时间 22:00。
> 3. 第 2 到第 5 条不点「今日」，在日历里选已经过去的日期。APP 的「今天」跟服务器时间走，改手机日期不会变成那一天。
>
> 悉尼夏天比冬天快 1 小时。2026-04-05 把钟往回拨，这一天有 25 小时；2026-10-04 把钟往前拨，这一天只有 23 小时。每条都在这一天的开头和结尾各放一个点。如果 APP 不管那天是夏天还是冬天，一律用「现在的时差」去算，就会差 1 小时，把点算到前一天或后一天。
>
> 下面的北京时间已经核算过。执行时如果手机系统更新了时区规则，用工具再对一次。
>
> 还没覆盖的：切换日当天真实点「今日」。下一次是 2027-04-04 和 2027-10-03，到那天再补。用日历选日期代替点「今日」，前提是这两种查法用同一套起止时间，需要开发确认。

## [P4] 验证过了当地零点后「今日」换成下一天
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录。APP 时区选一个全年不拨钟的城市，推荐布里斯班（当地零点 = 北京时间 22:00）。不想等到 22:00，可以改选离现在更近的：东京 23:00、新加坡 00:00、加德满都次日 02:15、加尔各答次日 02:30、迪拜次日 04:00、莫斯科次日 05:00。以设置页里实际有这个城市为准
  2. 看服务器时间，找到这个城市的下一个零点，记为「零点」（北京时间）。举例：选布里斯班，北京时间 2026-10-13 21:55 开始测，零点就是当天 22:00。每次执行按当天重算，不要照抄这个日期
  3. 准备 3 个轨迹点，时间都用北京时间：早班点 = 零点往前 23 小时 30 分（当地 00:30），晚班点 = 零点往前 1 小时（当地 23:00），次日点 = 零点往后 2 分钟（当地次日 00:02）。上例三个时间是 10-12 22:30、10-13 21:00、10-13 22:02
  4. 早班点和晚班点在零点前 55 分钟到前 5 分钟之间录入。次日点要等过了零点 3 分钟再录入。录入时，这个点的时间已经过去
- 测试步骤
  1. APP 时区设成所选城市。零点前 2 分钟打开轨迹页，点「今日」，记下有哪些点。
  2. 过了零点 3 分钟后，录入次日点。
  3. 过了零点 5 分钟，重新进入轨迹页，再点「今日」，记下有哪些点。
  4. 同一时间点「昨日」，记下有哪些点。
  5. 对比零点前、零点后两次「今日」。
- 预期结果
  1. 「今日」有早班点、晚班点，屏幕显示当地 00:30 和 23:00。次日点这时还没录入。
  2. 次日点录入成功。
  3. 「今日」只剩次日点，屏幕显示当地 00:02。早班点、晚班点不在里面。
  4. 「昨日」有早班点、晚班点，没有次日点。
  5. 过了零点后，「今日」整段换成下一天：原来的两点进了「昨日」，新的一点进了新的「今日」。三个点各只出现一次。

## [P4] 验证悉尼 2026-04-05 这一天开头和结尾的点没有算错天
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，APP 时区选悉尼。用专用设备 DEV-TZ-APR，这台设备上只有下面 4 个点
  2. 4 个点都按北京时间录入：R0 = 2026-04-04 20:30（悉尼显示 04-04 23:30）、R1 = 2026-04-04 21:30（悉尼显示 04-05 00:30）、R2 = 2026-04-05 21:30（悉尼显示 04-05 23:30）、R3 = 2026-04-05 22:30（悉尼显示 04-06 00:30）
  3. 在日历里选日期，不点「今日」。如果日历最早只能选到更晚的日期、选不到 2026-04-04，记下阻塞，换别的日期不算通过
- 测试步骤
  1. 轨迹页日历选 2026-04-04，看有哪些点、显示什么时间。
  2. 日历选 2026-04-05，看有哪些点、显示什么时间。
  3. 日历选 2026-04-06，看有哪些点、显示什么时间。
- 预期结果
  1. 只有 R0，显示 04-04 23:30。R1 如果出现在这一天，说明这一天的起点算晚了 1 小时，判缺陷。
  2. 有 R1 和 R2，显示 04-05 00:30 和 04-05 23:30。没有 R0、R3。R2 如果没出现，说明这一天的终点算早了 1 小时，判缺陷。
  3. 只有 R3，显示 04-06 00:30。没有 R2。

## [P4] 验证悉尼拨钟那天的点数是 25 或 23
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，APP 时区选悉尼。用两台专用设备 DEV-TZ-APR2、DEV-TZ-OCT2，和上面两台分开，避免点数加在一起
  2. DEV-TZ-APR2 每小时 1 个点，都落在整点后的 30 分（北京时间），从 2026-04-03 21:30 到 2026-04-05 22:30，一共 50 个点
  3. DEV-TZ-OCT2 同样每小时 1 个点，从 2026-10-02 22:30 到 2026-10-04 21:30，一共 48 个点
  4. 在日历里选日期看当天有多少个点
- 测试步骤
  1. 打开 DEV-TZ-APR2，依次选 2026-04-04、04-05、04-06，记下每天的点数。
  2. 打开 DEV-TZ-OCT2，依次选 2026-10-03、10-04、10-05，记下每天的点数。
  3. 把拨钟那天和前后正常的一天对比。
- 预期结果
  1. 三天点数是 24、25、1。04-05 把钟往回拨，这一天多出 1 个点。
  2. 三天点数是 24、23、1。10-04 把钟往前拨，这一天少 1 个点。
  3. 正常一天 24 个点，往回拨的那天 25 个点，往前拨的那天 23 个点，这是对的。三天都是 24 个点，说明没有按真实拨钟计算，判缺陷。

## [P4] 验证哈瓦那 2026-03-08 跳过凌晨后点没有丢、也没有重复
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录，APP 时区选哈瓦那。用专用设备 DEV-TZ-HAV
  2. 4 个点都按北京时间录入：H1 = 2026-03-08 12:30（哈瓦那显示 03-07 23:30）、H2 = 2026-03-08 13:30（哈瓦那显示 03-08 01:30）、H3 = 2026-03-09 11:30（哈瓦那显示 03-08 23:30）、H4 = 2026-03-09 12:30（哈瓦那显示 03-09 00:30）
  3. 2026-03-08 当地从 0 点直接跳到 1 点，0 点到 0 点 59 分这一小时不存在。在日历里选日期
- 测试步骤
  1. 轨迹页日历选 2026-03-07，看有哪些点、显示什么时间。
  2. 日历选 2026-03-08，看有哪些点、显示什么时间。
  3. 日历选 2026-03-09，看有哪些点、显示什么时间。
  4. 记下 03-08 这一天实际从几点开始算，先不判断对错。
- 预期结果
  1. 只有 H1，显示 03-07 23:30。没有 H2。
  2. 有 H2 和 H3，显示 03-08 01:30 和 03-08 23:30。没有 H1、H4。
  3. 只有 H4，显示 03-09 00:30。没有 H3。
  4. 当地没有 0 点，这一天从几点开始算，把实际结果记下来即可，先不算缺陷。4 个点各自只出现在正确的那一天。
