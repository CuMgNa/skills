> 口径依据：《革泰 APP 整群轨迹逻辑点梳理 plan.md》v1.2，第9、12、13、14节；失败提示验证业务状态和可重试性，不写死待确认UI文案。

## [P1] 验证OK与NO_DATA可在同批结果中独立处理

  - 功能
- 前置条件

- 测试步骤

  2. 查看三台设备选择、颜色和结果状态

- 预期结果
  1. 批次通过完整性和设备集合校验后原子提交
  2. 三台设备均保持已选和原颜色，DEV-GT-002显示当前范围无轨迹
  3. DEV-GT-001绘制多点折线，DEV-GT-003仅绘制单点，DEV-GT-002不绘制且不导致整批失败

## [P1] 验证OUT_OF_SCOPE仅移除对应设备并重查其余设备
- 测试类型
  - 功能
- 前置条件
  1. 已选择DEV-GT-001、DEV-GT-002和DEV-GT-003
  2. 服务端同一授权快照返回DEV-GT-002为OUT_OF_SCOPE，其余两台为OK
- 测试步骤
  1. 接收并处理本批结果
  2. 查看选择集合、标签、颜色和范围变化提示
  3. 查看后续查询设备集合
- 预期结果
  1. DEV-GT-002被识别为业务范围变化而非技术失败
  2. 仅DEV-GT-002从选择、标签、颜色和地图移除，其他两台保留并提供不泄露额外信息的范围变化提示
  3. APP使用DEV-GT-001和DEV-GT-003形成新查询指纹重新查询，不对DEV-GT-002反复技术重试

## [P3][反向] 验证单设备TECHNICAL_FAILED触发整批原子失败
- 测试类型
  - 可靠性
- 前置条件
  1. 已选择DEV-GT-001、DEV-GT-002和DEV-GT-003并保留各自颜色
  2. 新批次中DEV-GT-001和DEV-GT-003为OK，DEV-GT-002为TECHNICAL_FAILED
  3. 地图仍有上一查询指纹的旧轨迹
- 测试步骤
  1. 接收新批次的三个设备结果
  2. 查看暂存区校验和地图提交时机
  3. 查看失败后保留状态和重试入口
- 预期结果
  1. 任一TECHNICAL_FAILED使新批次判定为整批技术失败
  2. OK设备结果不会先局部上图，当前地图轨迹和历史图标全部清空，旧查询结果不得冒充当前结果
  3. 当前分组、已提交范围、设备顺序和颜色映射保持，页面提供可重试状态

## [P3][反向] 验证请求设备结果缺失不能当作NO_DATA
- 测试类型
  - 可靠性
- 前置条件
  1. 请求集合为DEV-GT-001、DEV-GT-002和DEV-GT-003
  2. 响应仅返回DEV-GT-001与DEV-GT-003的OK结果，缺少DEV-GT-002

  2. 缺失结果被判定为接口契约错误，不自动补成NO_DATA
  3. 本批不提交任何轨迹，地图按整批失败规则清空并保留选择供重试

## [P3][反向] 验证同一设备多结果触发契约错误
- 测试类型
  - 可靠性
- 前置条件
  1. 请求集合为DEV-GT-001和DEV-GT-002
  2. 响应返回DEV-GT-001两份结果，分别为OK和NO_DATA，并返回DEV-GT-002一份OK
- 测试步骤
  1. 接收包含重复deviceId结果的响应
  2. 查看结果唯一性校验
  3. 查看地图与可观测记录
- 预期结果
  1. APP识别DEV-GT-001存在互相冲突的多结果
  2. 不自行选择第一份、最后一份或更有利结果，整批判为契约失败
  3. 地图不提交本批数据，并记录clientRequestId和traceId用于定位且不记录完整token

## [P1] 验证技术失败后重试成功原子替换结果
- 测试类型
  - 可靠性
- 前置条件

  2. 页面保留两台设备选择顺序、颜色和2026-10-11 08:00至2026-10-11 09:00已提交范围
  3. 该查询指纹尚未有成功展示
- 测试步骤
  1. 点击失败状态提供的重试入口
  2. 让重试响应返回两台设备完整OK结果
