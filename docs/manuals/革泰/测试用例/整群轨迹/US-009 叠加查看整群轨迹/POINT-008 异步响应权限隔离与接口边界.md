# 用户故事：US-009 叠加查看整群轨迹 - POINT-008 异步响应权限隔离与接口边界
> 口径依据：《革泰 APP 整群轨迹逻辑点梳理 plan.md》v1.2，第3、9、12、13、14节；接口方法和路径以最终联调契约为准。

## [P3][反向] 验证旧轨迹响应版本不能覆盖最新设备集合
- 测试类型
  - 可靠性
- 前置条件
  1. 账号gt_group_01在G-L1-1001选择DEV-GT-001并发出轨迹请求V1
  2. V1未返回时又选择DEV-GT-002并发出集合DEV-GT-001与DEV-GT-002的请求V2
- 测试步骤
  1. 让V2先返回并完成展示
  2. 再让V1返回
  3. 查看地图、Selected、标签和缓存
- 预期结果
  1. V2因匹配当前查询指纹和最新requestVersion而展示两台设备结果
  2. V1因设备集合与版本过期被丢弃，不覆盖或删减V2结果
  3. 页面和缓存继续仅保存当前指纹结果，Selected为2且两台标签保持

## [P3][反向] 验证候选日历与状态资源分别隔离旧响应
- 测试类型
  - 稳定性
- 前置条件
  1. 候选设备、月份Calendar和当前状态分别维护独立resourceRequestVersion
  2. 已连续触发两次候选刷新、2026年9月后切到2026年10月、两次当前状态刷新
- 测试步骤
  1. 让三类资源的新版本响应先返回
  2. 再依次返回三类资源的旧版本响应
  3. 查看候选列表、当前月份绿色日期和状态图标
- 预期结果
  1. 各资源仅提交自身最新查询键匹配的响应，不共用单一轨迹版本判断
  2. 旧候选和旧月份响应不能覆盖最新候选或2026年10月日期数据
  3. 旧状态响应不能把较新的statusAsOf回退为更早快照

## [P3][反向] 验证切组后旧groupId响应不能写入新组

- 前置条件
  1. G-L1-1001候选与轨迹请求正在进行
  2. 用户随后切换到G-L2-2001并清空原选择
- 测试步骤
  1. 让G-L2-2001最新候选响应先返回
  2. 再返回G-L1-1001旧候选和旧轨迹响应
  3. 查看当前分组、候选、Selected和地图
- 预期结果
  1. 当前共享上下文和页面均保持真实groupId G-L2-2001
  2. G-L1-1001响应因groupScope或groupId不匹配被丢弃，不混入新候选
  3. Selected保持0，地图不恢复G-L1-1001设备轨迹

## [P3][反向] 验证账号切换隔离旧会话位置数据

## [P3][反向] 验证Authorization仅使用请求头且日志缓存保护隐私
- 测试类型
  - 安全性
- 前置条件
  1. 账号gt_group_01持有有效访问令牌token_gt_group_01_test
  2. 已启用网络抓包、客户端日志和缓存检查
- 测试步骤
  1. 发起候选、月份Calendar和整群轨迹请求
  2. 检查请求头、URL、clientRequestId和缓存键
  3. 检查业务日志、错误日志和HTTP缓存策略
- 预期结果
  1. 认证信息仅通过标准Authorization请求头发送
  2. URL查询参数、clientRequestId和共享缓存键均不包含token_gt_group_01_test
  3. 日志不记录完整token或未经授权的完整轨迹坐标，响应采用认证主体隔离且具备private、no-store等不共享策略

## [P3][反向] 验证groupScope互斥与越权设备不泄露存在性
- 测试类型
  - 安全性
- 前置条件
  1. 账号gt_group_01可见G-L1-1001及DEV-GT-001，不可见DEV-GT-025
  2. 准备三类异常请求：ALL_VISIBLE携带G-L1-1001、DIRECT_GROUP漏传groupId、DIRECT_GROUP携带他人分组
- 测试步骤
  1. 分别提交三类异常groupScope参数组合
  2. 在合法G-L1-1001请求中加入越权DEV-GT-025
  3. 检查服务端错误、响应数据和客户端处理
- 预期结果
  1. 服务端拒绝互斥或缺失参数组合，不把空groupId自动解释为全部分组
  2. DEV-GT-025不返回历史轨迹、设备摘要或当前状态，授权与轨迹读取使用不可绕过的同一范围约束
  3. 外部错误不区分DEV-GT-025真实存在、已删除或属于其他账号，客户端不渲染任何越权信息

## [P3][反向] 验证重复deviceId去重与容量超限显式失败
- 测试类型
  - 可靠性
- 前置条件
  1. 按当前暂定需求接口去重后最多接收20个稳定deviceId
  2. 第一组请求包含DEV-GT-001两次及DEV-GT-002一次
  3. 第二组请求包含去重后的DEV-GT-001至DEV-GT-021共21台
- 测试步骤
  1. 提交第一组重复deviceId请求
  2. 提交第二组21台容量超限请求
  3. 检查响应中的设备数、截断字段或机器可读错误
- 预期结果
  1. 第一组按稳定deviceId去重为DEV-GT-001和DEV-GT-002，不重复授权、查询或返回结果
  2. 第二组不得静默截取前20台或随机丢弃设备，应返回明确容量错误并保持客户端当前选择状态可恢复
  3. 若点数或响应容量触发截断，必须显式返回truncated、原始数、有效数、返回数及nextCursor，或返回稳定的查询过大错误，客户端不得把截断结果冒充完整轨迹
