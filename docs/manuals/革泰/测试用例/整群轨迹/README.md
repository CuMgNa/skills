# 整群轨迹测试用例集说明

## 规则真源

- 业务真源：`docs/manuals/革泰/逻辑大纲/革泰 APP 整群轨迹逻辑点梳理 plan.md` v1.2。
- 覆盖用户故事：US-009「叠加查看整群轨迹」、US-010「选择轨迹查询时间」。
- 20 台上限与 FIFO 为当前暂定需求，以最新正式需求版本为准；执行前核对真源第 6、14、16 章。
- 性能阈值、最终接口路径、UI 确切文案、20 色具体色板等待确认内容不得从本用例集反推为已定需求。

## Markdown v0.3 格式

每个 POINT 文件遵循固定树结构：

```text
# 用户故事：US-xxx ... - POINT-xxx ...
## [P1][可选反向标记] 验证……
- 测试类型
  - 12 种枚举之一
- 前置条件
  1. 具体条件
- 测试步骤
  1. 具体步骤
- 预期结果
  1. 与步骤一一对应的可验证结果
```

强制规则：

1. 用例标题必须包含 P1～P5，标题正文以“验证”开头；反向用例使用 `[反向]`。
2. 每条用例恰好包含“测试类型、前置条件、测试步骤、预期结果”四个同级字段。
3. 字段内容缩进两个空格；步骤和预期均从 1 连续编号且数量相等。
4. 测试类型只能取：功能、兼容性、易用性、性能、稳定性、安全性、可靠性、效果（AI类、资源类）、效果（硬件器件类）、可维护性、可移植性、埋点。
5. 测试数据必须具体，不使用 `{变量}`、`TODO`、“同上”等占位表达。
6. `all_cases.md` 的层级固定为：一级用户故事 → 二级 POINT → 三级用例 → 四字段及内容。

## 当前统计

- POINT 文件：13 个，其中 US-009 为 8 个，US-010 为 5 个。
- 测试用例：100 条，其中 US-009 为 60 条，US-010 为 40 条。
- 详细优先级、反向、类型和 POINT 分布见 `quality-report.md`。

## 执行提示

1. 先阅读 `plan.md` 的待确认项，再选择对应 POINT 执行；未确认内容不要写死预期。
2. 功能执行可按 POINT 文件分工；全量评审、导入思维导图或回归时使用 `all_cases.md`。
3. 需要抓包或接口直调的用例，应核对标准 Authorization 请求头、UTC 毫秒时间戳、IANA 时区、请求设备集合和请求版本。
4. 涉及 DST、非整点时区或硬编码 epoch 的用例，按 `quality-report.md` 中的 `zoneinfo` 校验基线复核运行环境时区数据库。
5. 暂定 20 台 / FIFO 用例执行前必须确认当前构建仍采用该规则；若正式需求回退或变更，应先更新真源和用例，不得仅修改执行结论。
6. 本目录不承载设备管理、登录注册和时区设置模块的完整基础回归，只验证这些能力与整群轨迹页面的联动。
