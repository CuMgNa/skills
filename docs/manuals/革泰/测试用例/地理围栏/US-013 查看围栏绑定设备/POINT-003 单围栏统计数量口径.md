# US-013 查看围栏绑定设备

> 口径依据：需求真源第 6.2～6.3 节、第 12.4 节、第 13.1 节。在线与离线互斥，在线数 + 离线数必须等于当前账号在该围栏中可见的绑定设备去重数；告警数按至少存在一条当前未处理围栏告警的设备去重，不按告警记录条数累计；统计加载失败不得用全 0 冒充真实结果。

## [P1] 验证在线数与离线数之和等于当前账号可见绑定设备去重数
- 测试类型
  - 功能
- 前置条件
  1. 企业二级账号 corp_level2_01 已登录，可查看围栏 GF-STAT-001
  2. GF-STAT-001 对当前账号可见的绑定设备为 D1001～D1006，其中 D1003 因共享关系命中 2 条账号关系，但设备唯一标识相同
  3. D1001、D1002、D1003 当前在线；D1004、D1005 当前离线；D1006 从未有效上报；D1007 已绑定该围栏但当前账号无设备可见权
- 测试步骤
  1. 从电子围栏列表进入 GF-STAT-001 统计页。
  2. 记录页面在线数、离线数及当前账号可见绑定设备总数。
  3. 展开在线和离线列表，按设备唯一标识核对设备集合。
- 预期结果
  1. 统计页加载 GF-STAT-001 的当前数据，不串入其他围栏设备。
  2. 在线数为 3，离线数为 3，二者之和为 6，等于 D1001～D1006 的去重数。
  3. 在线集合为 D1001、D1002、D1003；离线集合为 D1004、D1005、D1006；D1003 只计 1 次，D1007 不展示、不计数。

## [P1] 验证告警数按存在未处理围栏告警的设备去重
- 测试类型
  - 功能
- 前置条件
  1. 账号 corp_level2_01 已进入 GF-STAT-001 统计页
  2. D1001 有 3 条未处理围栏告警，D1002 有 1 条未处理围栏告警，D1003 有 4 条已处理围栏告警
  3. D1004 有 2 条未处理围栏告警，D1005、D1006 无围栏告警；D1001、D1002 在线，D1004 离线
- 测试步骤
  1. 刷新 GF-STAT-001 统计页。
  2. 记录告警统计数并进入告警状态设备列表。
  3. 对照告警中心中 GF-STAT-001 的未处理告警明细条数与设备唯一标识。
- 预期结果
  1. 统计数据刷新成功。
  2. 告警数为 3，告警设备列表仅包含 D1001、D1002、D1004，每台设备只出现 1 次。
  3. 告警中心未处理明细共 6 条，但统计页仍按 3 台设备计数；D1001、D1002 同时计入在线与告警，D1004 同时计入离线与告警。

## [P2] 验证处理告警后仅在设备无未处理告警时减少告警设备数
- 测试类型
  - 功能
- 前置条件
  1. GF-STAT-001 当前告警设备为 D1001、D1002、D1004，告警数为 3
  2. D1001 有 3 条未处理告警，D1002 有 2 条未处理告警，D1004 有 1 条未处理告警
- 测试步骤
  1. 在告警中心处理 D1001 的全部 3 条未处理告警，返回统计页刷新。
  2. 仅处理 D1002 的第 1 条未处理告警，返回统计页刷新。
  3. 再处理 D1002 剩余 1 条未处理告警，返回统计页刷新。
  4. 核对每次刷新后的告警设备列表。
- 预期结果
  1. D1001 不再计入告警，告警数由 3 降为 2。
  2. D1002 仍有 1 条未处理告警，告警数保持 2。
  3. D1002 不再有未处理告警，告警数由 2 降为 1。
  4. 最终告警设备列表仅有 D1004；历史已处理告警仍可在告警中心查询，但不计入统计页告警数。

## [P3][反向] 验证统计加载失败不以全零冒充真实数量
- 测试类型
  - 可靠性
- 前置条件
  1. GF-STAT-001 最近一次成功加载的统计值为在线 3、离线 3、告警 1
  2. 抓包工具可使统计接口返回 HTTP 500
- 测试步骤
  1. 在统计页显示在线 3、离线 3、告警 1 时触发下拉刷新。
  2. 使本次统计请求返回 HTTP 500。
  3. 查看统计区域、设备列表和失败反馈。
  4. 恢复接口并点击重试。
- 预期结果
  1. 页面发起最新统计请求。
  2. 请求失败，不生成新的有效统计快照。
  3. 页面保留上一次有效数据或显示明确的加载失败状态，并给出可读失败原因；不得显示在线 0、离线 0、告警 0 冒充真实结果。
  4. 重试成功后恢复服务端最新统计值，数量继续满足在线数 + 离线数 = 当前账号可见绑定设备去重数。
