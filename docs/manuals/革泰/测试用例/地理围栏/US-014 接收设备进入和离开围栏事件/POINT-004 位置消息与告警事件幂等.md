# US-014 接收设备进入和离开围栏事件

> 口径依据：地理围栏大纲 10.4、10.5、13.2、13.3。位置层先按设备 ID+原始消息 ID/序列号原子去重；告警层使用设备、围栏、原消息和首次判定配置版本构成幂等键，重复投递与补偿不得产生第二次副作用。

## [P1] 验证同一消息 ID 并发重复到达仅一个请求进入判定
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-GF-030 已绑定安全区 GF-IDEM-01并建立圆内基线
  2. 可并发发送 20 个完全相同的消息，原始消息 ID 均为 gf-dup-001，坐标位于圆外 600m
  3. 可查询报文幂等登记、围栏判定次数和事件数
- 测试步骤
  1. 同时发送 20 个 gf-dup-001 报文。
  2. 等待全部请求返回并查询报文幂等登记记录。
  3. 查询围栏判定日志、lastInside 和事件表。
- 预期结果
  1. 数据库唯一约束、原子插入或等价原子占位只允许 1 个请求抢占成功，其余请求幂等返回。
  2. gf-dup-001 仅有 1 条有效幂等登记，不出现“先查询再写入”导致的竞态重复。
  3. 仅执行 1 次围栏判定、更新 1 次基线并生成 1 条「离开安全区」事件。

## [P1] 验证相同坐标不同消息 ID 均作为新有效位置
- 测试类型
  - 功能
- 前置条件
  1. DEV-GF-031 已绑定禁入区 GF-IDEM-02并建立圆内基线
  2. 坐标 151.210000°E、33.869000°S 位于围栏圆内
- 测试步骤
  1. 依次注入 gf-static-001、gf-static-002、gf-static-003，三条消息坐标和定位时间间隔均合法。
  2. 查询三条消息的幂等登记和判定日志。
  3. 查询事件表。
- 预期结果
  1. 三个不同消息 ID 均登记成功，不因坐标相同被指纹去重。
  2. 三条消息均逐条参与禁入区判定。
  3. 每条消息各生成 1 条「进入禁入区」事件，共 3 条独立事件。

## [P3] 验证告警写入重试复用原幂等键与首次配置版本
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-GF-032 已绑定安全区 GF-IDEM-03，当前配置版本为 v7且已有圆内基线
  2. 可令首次事件写入失败，并在失败后将围栏配置更新为 v8
- 测试步骤
  1. 注入圆外消息 gf-retry-001，使 v7 判定产生告警但事件写入失败。
  2. 将 GF-IDEM-03 名称和半径更新为 v8。
  3. 执行告警补偿任务两次。
  4. 查询事件幂等键、配置快照和事件数量。
- 预期结果
  1. 失败任务锁定设备 DEV-GF-032、围栏 GF-IDEM-03、消息 gf-retry-001和首次判定版本 v7。
  2. v8 更新不使同一原报文按新版本重新执行围栏副作用。
  3. 两次补偿均复用原幂等键，最多一次写入成功。
  4. 最终只有 1 条事件，配置及围栏快照来自 v7，原始定位时间保持不变。

## [P3] 验证同一事件多次创建账号关系不复制物理事件
- 测试类型
  - 可靠性
- 前置条件
  1. 企业一级 E1、二级 E2、三级 E3 均拥有共享围栏 GF-IDEM-04和 DEV-GF-033 可见权
  2. DEV-GF-033 已建立安全区圆内基线
- 测试步骤
  1. 注入圆外消息 gf-account-rel-001。
  2. 并发执行两次账号告警关系建立任务。
  3. 查询物理事件、E1/E2/E3账号关系及去重键。
- 预期结果
  1. 同一设备×围栏×消息只生成 1 条物理告警事件。
  2. 重复关系任务按事件 ID+账号 ID 幂等，不复制事件或账号关系。
  3. 最终物理事件数为 1，E1、E2、E3各有且仅有 1 条可见/处理关系。
