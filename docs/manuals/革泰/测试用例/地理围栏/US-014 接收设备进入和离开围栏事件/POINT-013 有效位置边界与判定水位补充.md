# US-014 接收设备进入和离开围栏事件

> 口径依据：地理围栏大纲 10.2、11.10.2 E01/E02。经度有效范围 [-180,180]、纬度有效范围 [-90,90]，经度或纬度为 0 无效；缺少原始消息 ID 或报文序列号才按残缺报文丢弃；仅定位时间“早于”判定水位的报文跳过围栏链路，相同时间按接收顺序参与判定；无效或乱序旧位置对设备绑定的所有围栏同时生效。

## [P4] 验证经纬度有效范围边界值 ±180 与 ±90 被接受
- 测试类型
  - 功能
- 前置条件
  1. 安全区 GF-VAL-01 圆心 (116.397128°E, 39.916527°N)，半径 500m，DEV-GF-120 已绑定并有圆内基线
  2. 判定水位为 2026-10-12 08:00:00 UTC，以下消息定位时间依次为 08:01:00、08:02:00、08:03:00、08:04:00
- 测试步骤
  1. 注入 gf-edge-001，经度 180.0、纬度 10.0。
  2. 注入 gf-edge-002，经度 -180.0、纬度 10.0。
  3. 注入 gf-edge-003，经度 100.0、纬度 90.0。
  4. 注入 gf-edge-004，经度 100.0、纬度 -90.0，并查询最新有效位置、水位和事件。
- 预期结果
  1. gf-edge-001 通过有效位置校验，位于圆外，生成 1 条「离开安全区」事件。
  2. gf-edge-002 通过有效位置校验，生成第 2 条「离开安全区」事件。
  3. gf-edge-003 通过有效位置校验，生成第 3 条「离开安全区」事件。
  4. gf-edge-004 通过有效位置校验，生成第 4 条事件；最新有效位置为 (100.0, -90.0)，水位推进到 08:04:00。

## [P4][反向] 验证经纬度向外越界的另一方向与极端值不进入判定
- 测试类型
  - 功能
- 前置条件
  1. 安全区 GF-VAL-02，DEV-GF-121 已绑定并有圆内基线，当前事件数为 2
  2. 当前最新有效位置为圆内 (116.397128°E, 39.916527°N)
- 测试步骤
  1. 注入 gf-over-001，经度 -180.0001、纬度 10.0。
  2. 注入 gf-over-002，经度 100.0、纬度 90.0001。
  3. 注入 gf-over-003，经度 360.0、纬度 10.0，并查询位置、基线和事件。
- 预期结果
  1. 经度小于 -180 的报文被判为无效，不进入围栏判定。
  2. 纬度大于 90 的报文被判为无效，不进入围栏判定。
  3. 经度 360.0 的报文被判为无效；最新有效位置、lastInside 和水位均不变，事件数仍为 2。

## [P2] 验证仅含报文序列号的位置报文可作为有效位置并按序列号幂等
- 测试类型
  - 功能
- 前置条件
  1. 安全区 GF-VAL-03，DEV-GF-122 已绑定并有圆内基线；该设备报文无原始消息 ID，仅携带报文序列号
  2. 可查询报文幂等登记与事件
- 测试步骤
  1. 注入报文序列号 SEQ-20261012-0001，位于圆外 650m。
  2. 再次投递完全相同的序列号 SEQ-20261012-0001。
  3. 查询幂等登记、判定日志和事件。
- 预期结果
  1. 报文因携带序列号不被判为残缺，进入围栏判定并生成 1 条「离开安全区」事件。
  2. 第 2 次投递被幂等返回，不重新判定。
  3. 幂等登记以“设备 ID+序列号”只有 1 条，判定 1 次，事件共 1 条。

## [P4] 验证定位时间与判定水位相等时参与判定而更早时跳过
- 测试类型
  - 功能
- 前置条件
  1. 安全区 GF-VAL-04，DEV-GF-123 已绑定并有圆内基线，判定水位为 2026-10-12 12:00:00 UTC
  2. 三条消息均有不同消息 ID，位置均在圆外 700m
- 测试步骤
  1. 注入 gf-wm-001，定位时间 11:59:59。
  2. 注入 gf-wm-002，定位时间 12:00:00。
  3. 注入 gf-wm-003，定位时间 12:00:01。
  4. 查询历史轨迹、水位、lastInside 和事件。
- 预期结果
  1. gf-wm-001 早于水位，只可写入历史轨迹，不判定、不告警。
  2. gf-wm-002 与水位相同，不被视为乱序旧点，参与判定并生成 1 条「离开安全区」事件。
  3. gf-wm-003 晚于水位，继续参与判定并生成第 2 条事件。
  4. 事件共 2 条，水位推进到 12:00:01，lastInside 为圆外。

## [P3][反向] 验证无效位置对设备绑定的全部围栏同时不判定
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-GF-124 同时绑定安全区 A=GF-VAL-05A、安全区 B=GF-VAL-05B，二者均有圆内基线，当前事件数为 0
  2. 位置 O 区在两围栏圆外
- 测试步骤
  1. 注入缺少消息 ID/序列号、位于 O 区的报文。
  2. 注入 gf-multi-invalid-001，经纬度均为 0。
  3. 注入 gf-multi-invalid-002，经度 181.0、纬度 30.0。
  4. 注入合法消息 gf-multi-valid-003，位于 O 区。
- 预期结果
  1. 残缺报文不进入多围栏查询，A、B 基线与水位均不变。
  2. 零值报文不更新 A、B 基线，不生成事件。
  3. 越界报文不更新 A、B 基线，事件数仍为 0。
  4. 合法报文对 A、B 各生成 1 条「离开安全区」事件，共 2 条，说明此前无效报文未污染两个围栏的判定状态。

## [P3][反向] 验证历史补传位置对设备绑定的全部围栏均不更新基线
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-GF-125 同时绑定安全区 A=GF-VAL-06A、安全区 B=GF-VAL-06B，二者均有圆内基线，当前判定水位为 2026-10-12 12:00:00 UTC
  2. 位置 O 区在两围栏圆外
- 测试步骤
  1. 注入 gf-late-001，定位时间 11:20:00，位于 O 区。
  2. 查询历史轨迹、A、B 基线与水位、事件。
  3. 注入 gf-late-002，定位时间 12:01:00，位于 O 区，并查询事件。
- 预期结果
  1. gf-late-001 作为历史补传点进入历史轨迹。
  2. A、B 的 lastInside 仍为圆内，水位仍为 12:00:00，事件数为 0。
  3. gf-late-002 作为新有效位置对 A、B 各生成 1 条「离开安全区」事件，共 2 条。
