# US-014 接收设备进入和离开围栏事件

> 口径依据：地理围栏大纲 10.5、10.6。事件至少保存事件唯一标识、幂等键、设备、围栏、围栏名称与类型快照、圆心半径或配置版本快照、方向、发生位置、原始定位时间/服务端首次接收时间/最终写入时间、处理状态关系和有权账号关系；事件命名只有「离开安全区」「进入禁入区」，不额外保存或展示“跨界触发/持续异常触发”来源字段。

## [P1] 验证安全区事件保存全部必需字段
- 测试类型
  - 功能
- 前置条件
  1. 安全区 GF-EVT-01，名称“悉尼安全区”，圆心 (151.209300°E, 33.868800°S)，半径 500m，配置版本 v5
  2. DEV-GF-110（设备标识 867123450000110）已绑定，E1、E2 对围栏和设备均可见，已用 gf-evt-000 建立圆内基线
  3. 可直接查询事件库、事件详情接口和告警中心列表
- 测试步骤
  1. 注入 gf-evt-001，坐标 (151.216880°E, 33.868800°S)，距圆心约 700m，定位时间 2026-10-12 16:00:00 UTC，服务端 16:00:05 接收。
  2. 查询事件库中该事件的全部字段。
  3. 查询事件的处理状态关系和有权账号关系。
  4. 分别以 E1、E2 打开告警中心该事件详情。
- 预期结果
  1. 生成 1 条事件，名称为「离开安全区」，方向为离开。
  2. 事件保存唯一事件 ID、幂等键“DEV-GF-110+GF-EVT-01+gf-evt-001+v5”、设备标识 867123450000110、围栏 ID、名称快照“悉尼安全区”、类型快照“安全区”、圆心与 500m 半径快照及配置版本 v5、发生坐标 (151.216880, -33.868800)。
  3. 原始定位时间 16:00:00、服务端首次接收时间 16:00:05、最终写入时间三个字段分别保存且不为空；E1、E2 各有 1 条处理状态为未处理的关系。
  4. E1、E2 详情展示同一事件 ID、同一名称与类型快照。

## [P2] 验证禁入区外→内与内→内事件同名且不含触发来源字段
- 测试类型
  - 功能
- 前置条件
  1. 禁入区 GF-EVT-02 半径 300m，DEV-GF-111 已绑定并用 gf-evt-100 建立圆外基线
  2. E1 对围栏和设备可见
- 测试步骤
  1. 注入 gf-evt-101，位于圆内 100m（外→内）。
  2. 注入 gf-evt-102，位于圆内 110m（内→内）。
  3. 查询两条事件的库表字段、事件详情、告警中心列表和接口响应。
- 预期结果
  1. gf-evt-101 生成 1 条事件，名称为「进入禁入区」，方向为进入。
  2. gf-evt-102 生成第 2 条事件，名称同为「进入禁入区」，方向为进入，与第 1 条互相独立。
  3. 两条事件均不存在“跨界触发”“持续异常触发”等触发来源字段或文案，也不出现“持续告警”标签。

## [P2] 验证围栏配置变更后新旧事件快照互不覆盖
- 测试类型
  - 功能
- 前置条件
  1. 安全区 GF-EVT-03，名称“悉尼仓库”，半径 500m，配置版本 v5，DEV-GF-112 已有圆内基线
  2. DEV-GF-112 已因 gf-evt-200（圆外 700m）生成 1 条事件，快照为“悉尼仓库”、半径 500m、v5
- 测试步骤
  1. 将 GF-EVT-03 名称改为“悉尼总仓”，半径改为 800m 并保存，确认版本变为 v6 且基线清空。
  2. 注入 gf-evt-201，位于圆外 1000m，建立新基线。
  3. 注入 gf-evt-202，位于圆外 1010m。
  4. 查询 gf-evt-200 和 gf-evt-202 对应事件的快照。
- 预期结果
  1. 配置保存成功，新配置版本为 v6。
  2. gf-evt-201 只建立圆外基线，不生成事件。
  3. gf-evt-202 生成 1 条「离开安全区」事件。
  4. 旧事件仍保留“悉尼仓库”、500m、v5；新事件保存“悉尼总仓”、800m、v6，旧快照不被改写。

## [P3] 验证设备延迟上报时发生时间使用原始定位时间
- 测试类型
  - 可靠性
- 前置条件
  1. 禁入区 GF-EVT-04 半径 300m，DEV-GF-113 已建立圆外基线
  2. 位置处理模块判定下述报文为新的有效位置，且定位时间晚于当前判定水位
- 测试步骤
  1. 注入 gf-evt-300，设备定位时间 2026-10-12 17:00:00 UTC，位于圆内 100m，服务端实际于 17:00:45 接收。
  2. 查询事件的发生时间、首次接收时间和最终写入时间。
  3. 在告警中心按发生时间排序查看该事件。
- 预期结果
  1. 生成 1 条「进入禁入区」事件。
  2. 发生时间为 17:00:00，首次接收时间为 17:00:45，最终写入时间不早于首次接收时间，三个字段不互相替代。
  3. 告警中心使用 17:00:00 作为发生时间排序和展示。
