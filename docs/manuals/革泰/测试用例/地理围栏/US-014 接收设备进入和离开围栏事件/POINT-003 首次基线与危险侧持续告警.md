# US-014 接收设备进入和离开围栏事件

> 口径依据：地理围栏大纲正式结论 8、10.3、10.4。首次有效位置只建立基线；已有基线后，安全区圆外和禁入区圆内的每条新有效位置均独立告警，不以是否跨界为前提。

## [P1] 验证新绑定设备首条危险侧位置只建立基线
- 测试类型
  - 功能
- 前置条件
  1. 安全区 GF-BASE-01 半径 500m，DEV-GF-010 尚未建立设备×围栏物理关系
  2. 绑定前设备最新位置在圆内，历史轨迹中另有圆外点
- 测试步骤
  1. 将 DEV-GF-010 绑定到 GF-BASE-01。
  2. 绑定后注入首条新有效消息 gf-base-first-001，位置在圆外 650m。
  3. 查询 lastInside、判定时间水位和告警事件。
- 预期结果
  1. 新建设备×围栏物理关系，lastInside 初始为空，不使用绑定前最新位置或历史点建基线。
  2. 首条新有效位置计算为圆外，仅写入圆外基线和本次定位时间水位。
  3. gf-base-first-001 不生成告警事件。

## [P1] 验证安全区已有基线后连续圆外逐条告警
- 测试类型
  - 功能
- 前置条件
  1. 安全区 GF-BASE-01 已绑定 DEV-GF-010
  2. gf-base-first-001 已建立圆外基线
- 测试步骤
  1. 依次注入消息 gf-safe-out-002、gf-safe-out-003、gf-safe-out-004，三个位置均在圆外 650m。
  2. 查询三次判定后的 lastInside 和水位。
  3. 查询三条消息对应的事件明细。
- 预期结果
  1. 三条消息 ID 不同，均作为新的有效位置逐条处理。
  2. lastInside 始终为圆外，水位按三条消息处理顺序推进。
  3. 每条消息各生成 1 条「离开安全区」事件，共 3 条，不合并、不因已有未处理告警而抑制。

## [P1] 验证禁入区已有基线后连续圆内逐条告警
- 测试类型
  - 功能
- 前置条件
  1. 禁入区 GF-BASE-02 半径 300m，DEV-GF-011 已用 gf-forbid-base-001 建立圆内基线
- 测试步骤
  1. 依次注入消息 gf-forbid-in-002、gf-forbid-in-003、gf-forbid-in-004，三个位置均在圆内 120m。
  2. 查询三次判定后的 lastInside。
  3. 查询三条消息对应的事件明细。
- 预期结果
  1. 三条消息均逐条进入围栏判定。
  2. lastInside 保持圆内。
  3. 每条消息各生成 1 条「进入禁入区」事件，共 3 条；内→内仍使用该事件名称，不增加未定义的触发来源文案。

## [P2] 验证基线重置场景的下一条位置仍只建基线
- 测试类型
  - 功能
- 前置条件
  1. DEV-GF-012 分别绑定 GF-RESET-01、GF-RESET-02、GF-RESET-03、GF-RESET-04
  2. 四个围栏分别准备修改圆心、修改半径、安全区切禁入区、关闭后重新启用
- 测试步骤
  1. 依次提交四种影响判定的配置变化，并确认各设备×围栏基线已清空。
  2. 对每个围栏注入一条位于新规则危险侧的新有效消息，ID 依次为 gf-reset-001 至 gf-reset-004。
  3. 查询四个围栏的基线和事件。
- 预期结果
  1. 圆心、半径、类型变化及重新启用均与基线清空在各自事务内生效。
  2. 四条消息分别只为对应围栏建立新基线，不把配置变化视为设备跨界。
  3. 四条首次消息均不生成告警；后续新的危险侧有效位置才开始逐条告警。
