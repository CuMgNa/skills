# US-014 接收设备进入和离开围栏事件

> 口径依据：地理围栏大纲 10.2、11.10.2、12.3。消息 ID、坐标合法性、设备归属和判定时间水位共同决定位置能否进入围栏链路；未来超过 10 分钟的时间只按位置处理模块规则处理，本用例不自行写死校正或拒绝策略。

## [P3][反向] 验证缺少或空消息 ID 的位置不进入围栏链路
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-GF-020 已绑定安全区 GF-VALID-01，lastInside=圆内，判定水位为 2026-10-12 10:00:00 UTC
  2. 可查询最新有效位置、lastInside、水位和事件表
- 测试步骤
  1. 注入一条不含原始消息 ID/序列号、定位时间 10:01:00、位于圆外 700m 的报文。
  2. 注入一条消息 ID 为空字符串、定位时间 10:02:00、位于圆外 710m 的报文。
  3. 查询位置、基线、水位和事件变化。
- 预期结果
  1. 第一条按残缺报文丢弃，不使用时间窗口或坐标指纹补造幂等标识。
  2. 第二条同样丢弃，不进入多围栏查询与判定。
  3. 最新有效位置、lastInside 和 10:00:00 水位均不变，新增围栏事件为 0。

## [P3][反向] 验证空坐标、零值、越界和无法归属位置均不判定
- 测试类型
  - 功能
- 前置条件
  1. DEV-GF-021 已绑定禁入区 GF-VALID-02，lastInside=圆外
  2. 判定前事件数为 6，水位为 2026-10-12 11:00:00 UTC
- 测试步骤
  1. 依次注入 gf-invalid-001 空经纬度对象、gf-invalid-002 经度 0、gf-invalid-003 纬度 0。
  2. 依次注入 gf-invalid-004 经度 180.0001、gf-invalid-005 纬度 -90.0001。
  3. 注入 gf-invalid-006，坐标合法但设备标识 UNKNOWN-9001 无法归属。
  4. 查询 DEV-GF-021 的位置、基线、水位和事件数。
- 预期结果
  1. 空坐标和经纬度为 0 的三条报文均被判为无效。
  2. 经度、纬度越界报文均被判为无效。
  3. 无法归属到当前设备的报文不进入 DEV-GF-021 或其他设备的围栏链路。
  4. DEV-GF-021 的最新有效位置、lastInside、水位保持不变，事件数仍为 6。

## [P3][反向] 验证历史补传与乱序旧点只入轨迹不更新实时判定
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-GF-022 已绑定安全区 GF-VALID-03，lastInside=圆内
  2. 当前围栏判定水位为 2026-10-12 12:00:00 UTC
- 测试步骤
  1. 注入消息 gf-history-001，定位时间 2026-10-12 11:30:00 UTC，位置在圆外 800m。
  2. 注入消息 gf-disorder-002，定位时间 2026-10-12 11:59:59 UTC，位置在圆外 810m。
  3. 查询历史轨迹、最新有效位置、lastInside、水位和事件。
- 预期结果
  1. 历史补传点可按 11:30:00 写入历史轨迹，但跳过实时围栏判定。
  2. 乱序旧点可进入历史轨迹，但同样不更新 lastInside 和判定水位。
  3. 两条旧点均不成为最新有效位置、不生成围栏事件，水位保持 12:00:00。

## [P2] 验证未来超 10 分钟与同定位时间报文遵循既定处理顺序
- 测试类型
  - 功能
- 前置条件
  1. DEV-GF-023 已绑定安全区 GF-VALID-04，当前服务端时间为 2026-10-12 13:00:00 UTC
  2. 位置处理模块已配置正式的未来时间处理规则，并可查询其处理结果
  3. DEV-GF-023 已有圆内基线
- 测试步骤
  1. 注入 gf-future-001，定位时间 13:10:01 UTC，位置在圆外 620m。
  2. 核对位置处理模块对该报文的校正、拒绝或其他正式处理结果，再核对围栏是否仅消费其输出。
  3. 依次接收 gf-same-time-001（圆外 620m）和 gf-same-time-002（圆内 100m），两者定位时间均为 13:20:00 UTC。
  4. 查询两条同时间报文的判定顺序、最终基线和事件。
- 预期结果
  1. 未来超过 10 分钟的报文先交由位置处理模块处理。
  2. 围栏模块不自行写死“必拒绝”或“必校正”，只对位置处理模块认定的新有效位置执行判定。
  3. 相同定位时间但消息 ID 不同的两条有效报文按服务端实际接收顺序逐条处理。
  4. 先处理圆外消息并生成 1 条「离开安全区」，再处理圆内消息且不告警，最终基线为圆内。
