# US-014 接收设备进入和离开围栏事件

> 口径依据：地理围栏大纲 10.5、10.6、12.4。物理事件与账号关系分离；事件写入失败必须可靠补偿；返回正常侧、人工处理、离线、SOS 和通知限流均不得改变后续危险侧事件生成口径。

## [P1] 验证共享围栏单物理事件建立多账号关系
- 测试类型
  - 功能
- 前置条件
  1. 企业三级创建共享安全区 GF-ALARM-01，E3、E2、E1均有围栏关系
  2. DEV-GF-040 对 E3、E2、E1均可见并已建立圆内基线
- 测试步骤
  1. 注入消息 gf-alarm-001，位置在圆外 900m。
  2. 查询围栏事件表。
  3. 分别以 E1、E2、E3查询告警详情和关系记录。
- 预期结果
  1. 本次定位进入危险侧判定。
  2. 只生成 1 条「离开安全区」物理事件，不按账号执行三次判定。
  3. E1、E2、E3均通过各自关系看到同一事件 ID，每个账号仅 1 条关系。

## [P1] 验证告警写入失败后可靠补偿且不丢不重
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-GF-041 已绑定禁入区 GF-ALARM-02并建立圆外基线
  2. 可模拟事件库首次写入失败，消息 ID 为 gf-alarm-retry-001，原始定位时间为 2026-10-12 14:20:00 UTC
- 测试步骤
  1. 注入位于圆内的 gf-alarm-retry-001并触发首次写入失败。
  2. 核对失败任务是否进入可靠重试队列。
  3. 恢复事件库并执行补偿。
  4. 查询最终事件时间字段和数量。
- 预期结果
  1. 围栏判定结果不被静默丢弃。
  2. 重试任务保存原报文幂等键、原定位时间和首次判定配置版本。
  3. 补偿成功生成 1 条「进入禁入区」事件，重复执行补偿不新增第二条。
  4. 发生时间为 14:20:00，首次接收时间和最终写入时间分别记录，不用补偿时间替代发生时间。

## [P2] 验证返回正常侧和人工处理不抑制后续危险侧事件
- 测试类型
  - 功能
- 前置条件
  1. DEV-GF-042 已绑定安全区 GF-ALARM-03并建立圆内基线
- 测试步骤
  1. 注入圆外消息 gf-link-001并人工处理其告警。
  2. 注入圆内消息 gf-link-002。
  3. 注入圆外消息 gf-link-003，再注入圆外消息 gf-link-004。
  4. 查询四条消息对应状态、历史事件和未处理关系。
- 预期结果
  1. gf-link-001 生成 1 条事件，人工处理只改变该事件处理关系。
  2. gf-link-002 更新为圆内，不生成恢复事件，也不删除历史事件。
  3. gf-link-003、gf-link-004各生成 1 条新事件，不受旧事件已处理或当前位置曾恢复影响。
  4. 共保留 3 条独立事件，当前状态与历史处理状态相互独立。

## [P2] 验证离线、SOS 与通知限流不减少围栏事件
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-GF-043 已绑定禁入区 GF-ALARM-04并建立圆内基线
  2. 设备当前同时标记为 SOS，且存在 2 条未处理围栏告警
  3. 通知模块已开启限流，可查询事件库与外部通知记录
- 测试步骤
  1. 将设备连接状态切换为离线，核对已有未处理告警。
  2. 注入三条可被位置处理模块认定为新有效的圆内消息 gf-sos-001 至 gf-sos-003。
  3. 查询围栏事件、SOS 状态和未处理关系。
  4. 查询外部通知发送结果并与物理事件数对照。
- 预期结果
  1. 离线不删除或自动处理原有 2 条未处理围栏告警。
  2. 三条危险侧有效位置各生成 1 条「进入禁入区」事件。
  3. SOS 状态保持，不被围栏事件覆盖；围栏未处理关系按新增事件正常建立。
  4. 通知模块可按自身规则限流，但事件库仍新增 3 条，不得反向合并、丢弃或减少物理事件。
