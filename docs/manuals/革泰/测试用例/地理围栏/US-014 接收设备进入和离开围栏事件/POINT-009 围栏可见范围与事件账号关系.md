# US-014 接收设备进入和离开围栏事件

> 口径依据：地理围栏大纲正式结论 4、6、7及 11.10.1。同一位置对同一设备×围栏只生成一个物理事件；账号必须同时拥有围栏可见权和设备可见权，才建立对应事件关系。

## [P1] 验证企业三级共享围栏只生成一条物理事件
- 测试类型
  - 功能
- 前置条件
  1. E3创建禁入区 GF-VIS-01并向 E2、E1共享
  2. DEV-GF-070 对 E1、E2、E3均可见且已建立圆外基线
- 测试步骤
  1. 注入圆内消息 gf-vis-001。
  2. 查询物理事件表。
  3. 查询 E1、E2、E3的事件账号关系。
- 预期结果
  1. 本次位置只对 DEV-GF-070×GF-VIS-01执行一次物理判定。
  2. 生成 1 条「进入禁入区」物理事件。
  3. E1、E2、E3分别建立 1 条指向同一事件 ID 的关系，不复制三条事件。

## [P1] 验证缺少设备可见权的共享账号不获得事件关系
- 测试类型
  - 安全性
- 前置条件
  1. E3创建安全区 GF-VIS-02，围栏对 E3、E2、E1可见
  2. DEV-GF-071仅对 E2、E1可见，E3无设备可见权
  3. 设备×围栏已有圆内基线
- 测试步骤
  1. 注入圆外消息 gf-vis-002。
  2. 分别以 E1、E2、E3查询事件。
  3. 查询物理事件和账号关系列表。
- 预期结果
  1. 生成 1 条「离开安全区」物理事件。
  2. E1、E2可查询该事件，E3不得通过列表、搜索、缓存或直链读取。
  3. 仅建立 E1、E2两条账号关系，E3关系不存在。

## [P2] 验证不同归属围栏的事件关系相互隔离
- 测试类型
  - 安全性
- 前置条件
  1. 同一设备 DEV-GF-072绑定企业围栏 A=GF-CORP-01和个人围栏 B=GF-PERSON-01
  2. A 对企业账号 corp_admin 可见，B 对个人账号 person01 可见，两个围栏均已有基线
  3. 本次位置同时命中 A、B危险侧
- 测试步骤
  1. 注入消息 gf-scope-001。
  2. 以 corp_admin 和 person01分别查询告警中心。
  3. 查询两个物理事件及账号关系。
- 预期结果
  1. A、B各生成 1 条独立物理事件，共 2 条。
  2. corp_admin 只能看到 A 事件，person01只能看到 B 事件。
  3. 两个围栏不因共用物理设备而共享围栏、事件关系或处理权限。

## [P2] 验证部分账号解绑保留物理关系与唯一基线
- 测试类型
  - 功能
- 前置条件
  1. E1、E2、E3均关联安全区 GF-VIS-03与 DEV-GF-073
  2. 设备×围栏已有圆内唯一基线
- 测试步骤
  1. E3从围栏解绑 DEV-GF-073。
  2. 查询物理关系、基线和三个账号关系。
  3. 注入圆外消息 gf-vis-unbind-001。
  4. 查询物理事件和账号可见关系。
- 预期结果
  1. 仅删除 E3账号关系，E1、E2关系保留。
  2. 物理关系与原圆内基线保持，不因部分解绑重置。
  3. 新位置按已有基线生成 1 条「离开安全区」物理事件。
  4. 仅为仍有围栏权和设备权的 E1、E2建立事件关系，E3不再可见。
