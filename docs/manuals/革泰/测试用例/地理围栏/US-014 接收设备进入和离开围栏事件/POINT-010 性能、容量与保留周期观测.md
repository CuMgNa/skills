# US-014 接收设备进入和离开围栏事件

> 口径依据：地理围栏大纲正式结论 13及第 14 章待确认项。围栏数、单围栏设备数和持续告警生成层不设固定业务上限。本 POINT 只记录性能与容量观测数据；正式通过阈值以已批准的性能方案和接口 SLA 为准，未确认的容量档位、存储预算和保留周期不得写成验收通过标准。

## [P2] 验证围栏列表大数据量分页行为可观测
- 测试类型
  - 性能
- 前置条件
  1. 性能账号 perf_user01可见 100、500、1000、5000个圆形围栏四档数据
  2. 服务端分页大小使用当前接口契约配置，已接入请求耗时、错误率、重复 ID和内存监控
- 测试步骤
  1. 分别在四档数据下执行首次加载、连续翻页、关键词搜索和下拉刷新各 20轮。
  2. 记录各接口响应时间分位数、错误率、分页游标和资源占用。
  3. 核对翻页去重、稳定排序和最终加载总数。
- 预期结果
  1. 四档结果均形成完整观测记录，不因客户端固定最大条数静默截断。
  2. 响应时间、错误率和资源占用与已批准性能方案/接口 SLA 对照；本文中的 100至5000仅为施压档位，不直接定义通过线。
  3. 围栏 ID无重复、无遗漏，排序保持“更新时间倒序+围栏 ID倒序”；任何偏差均可追溯到具体请求。

## [P2] 验证单围栏大设备量关系提交与统计查询可观测
- 测试类型
  - 性能
- 前置条件
  1. GF-PERF-01准备绑定 100、1000、5000、10000台设备四档数据
  2. 具备关系事务耗时、失败回滚、统计查询、APP渲染和资源监控
- 测试步骤
  1. 分别执行四档设备的绑定提交、解绑提交和统计页加载。
  2. 记录事务耗时、回滚耗时、接口分位数、错误率、服务端资源和端侧渲染指标。
  3. 抽查物理关系、账号关系、基线数量和统计守恒。
- 预期结果
  1. 每档均输出可复现的观测数据，失败事务不留下部分关系。
  2. 是否达标只按已批准性能方案/接口 SLA判定；10000台是观测档位，不声明为产品容量上限或正式通过标准。
  3. 成功档位满足关系去重，在线数+离线数等于当前账号可见绑定设备去重数。

## [P2] 验证单设备命中大量围栏时判定与补偿可观测
- 测试类型
  - 性能
- 前置条件
  1. DEV-GF-PERF-01分别绑定 10、100、500、1000个已有基线的有效围栏
  2. 注入位置可同时命中全部围栏危险侧，事件库可模拟 5%写入失败
- 测试步骤
  1. 各档注入 100条不同消息 ID的新有效位置。
  2. 记录位置处理、逐围栏判定、成功事件写入和补偿队列耗时及吞吐。
  3. 恢复事件库并执行补偿，核对最终事件守恒。
- 预期结果
  1. 各围栏独立判定，单围栏异常不阻断其他围栏；不因数量较大主动合并或丢弃事件。
  2. 所有性能指标与已批准方案/SLA对照；10至1000围栏仅为观测档位，不作为未确认容量承诺。
  3. 补偿后每条消息×每个有效危险侧围栏最多 1 条事件，最终成功数与应生成数守恒且无重复。

## [P2] 验证持续告警存储增长与保留周期仅做容量观测
- 测试类型
  - 性能
- 前置条件
  1. DEV-GF-PERF-02已在禁入区 GF-PERF-02圆内建立基线
  2. 可按每分钟 1、10、60条三档速率持续注入不同消息 ID，并监控事件表、索引、查询分页和归档任务
- 测试步骤
  1. 三档速率各运行 60分钟，记录事件增长、写入吞吐、查询分位数和存储增量。
  2. 对累计事件执行告警列表分页、设备去重统计和按时间范围查询。
  3. 记录现有归档或清理配置，但不修改保留周期。
- 预期结果
  1. 已有基线后每条危险侧有效位置均生成独立事件，实际增量与有效输入数一致。
  2. 查询和写入指标形成容量报告，并仅按已批准性能方案/接口 SLA判断性能结论。
  3. 保留周期、归档周期和存储预算作为待确认容量项记录，不把任一当前值或本次 60分钟观测结果写成正式业务验收标准。
