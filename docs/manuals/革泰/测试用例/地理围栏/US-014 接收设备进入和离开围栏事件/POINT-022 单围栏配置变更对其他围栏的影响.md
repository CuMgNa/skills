# US-014 接收设备进入和离开围栏事件

> 口径依据：地理围栏大纲 11.9 C01～C09。编辑、解绑或删除围栏 A 只影响 A 自身的基线，同设备其他围栏 B 保持基线并按自身危险侧继续判断；不要求跨围栏事务原子，单围栏内部配置更新与基线清空必须原子生效。C01、C03、C04、C07 已由 POINT-008 覆盖，本 POINT 补充其余行。
>
> 几何约定（相交）：A 圆心 (116.397128°E, 39.916527°N)，B 圆心在 A 正东 600m (116.404155°E, 39.916527°N)，半径均 500m。沿东西轴取点：O 区 = A 圆心西 800m (116.387758°E)，X 区 = A 圆心东 300m (116.400642°E)。

## [P1] 验证 C02 安全区切换为禁入区只清空 A 基线而 B 保持
- 测试类型
  - 功能
- 前置条件
  1. DEV-GF-220 绑定安全区 A=GF-C02-A 和禁入区 B=GF-C02-B，几何为相交约定
  2. A、B 均已用 c02-base（X 区）建立圆内基线，事件数为 0
- 测试步骤
  1. 将 A 由安全区切换为禁入区并保存。
  2. 查询 A、B 的 lastInside。
  3. 注入 c02-001，位于 X 区。
  4. 注入 c02-002，位于 X 区，并查询事件。
- 预期结果
  1. 类型切换与 A 基线清空原子生效。
  2. A lastInside 为空，B 仍为圆内。
  3. c02-001 对 A 只建立圆内基线，B 生成「进入禁入区」1 条事件，A 不补发历史告警。
  4. c02-002 对 A 生成「进入禁入区」1 条、对 B 再生成 1 条，累计 3 条事件。

## [P2] 验证 C05 解绑最后一个账号关系后重绑 A，B 不受影响
- 测试类型
  - 功能
- 前置条件
  1. DEV-GF-221 绑定安全区 A=GF-C05-A（仅 E1 一个账号关系）和安全区 B=GF-C05-B，几何为相交约定
  2. A、B 均已用 c05-base（X 区）建立圆内基线，事件数为 0
- 测试步骤
  1. E1 将 DEV-GF-221 从 A 解绑，确认 A 物理关系被删除。
  2. 重新将 DEV-GF-221 绑定到 A。
  3. 注入 c05-001，位于 O 区。
  4. 注入 c05-002，位于 O 区，并查询事件。
- 预期结果
  1. A 的物理关系和基线删除，B 的物理关系和圆内基线保留。
  2. 重绑后 A 新建物理关系，lastInside 为空。
  3. c05-001 对 A 只建立圆外基线，B 生成「离开安全区」1 条事件。
  4. c05-002 对 A 生成「离开安全区」1 条、对 B 再生成 1 条，累计 3 条事件。

## [P2] 验证 C06 仅解绑部分账号关系时 A、B 均保持基线并按区域判定
- 测试类型
  - 功能
- 前置条件
  1. DEV-GF-222 同时绑定安全区 A=GF-C06-A（E1、E2 均有关系）和安全区 B=GF-C06-B，几何为相交约定
  2. A、B 均已有圆内基线，事件数为 0
- 测试步骤
  1. E2 从 A 解绑 DEV-GF-222。
  2. 查询 A、B 的物理关系和 lastInside。
  3. 注入 c06-001，位于 O 区，并查询事件和账号关系。
- 预期结果
  1. 仅删除 E2 与 A 的账号关系，A 的物理关系保留。
  2. A、B 的圆内基线均保持，不被清空。
  3. A、B 各生成 1 条「离开安全区」事件共 2 条，A 事件仅 E1 有关系，E2 不再可见。

## [P2] 验证 C08 仅改名不重置 A、B 且新事件使用新名称
- 测试类型
  - 功能
- 前置条件
  1. DEV-GF-223 绑定安全区 A=GF-C08-A（名称“北区安全区”）和安全区 B=GF-C08-B，几何为相交约定
  2. A、B 均已有圆内基线，A 已有 1 条名称快照为“北区安全区”的历史事件
- 测试步骤
  1. 将 A 名称改为“北区总安全区”并保存。
  2. 查询 A、B 的 lastInside。
  3. 注入 c08-001，位于 O 区。
  4. 查询 A 的新旧事件快照。
- 预期结果
  1. 名称保存成功，A 的圆心、半径、类型和设备关系不变。
  2. A、B 的圆内基线均保持。
  3. c08-001 对 A、B 各生成 1 条「离开安全区」事件，共 2 条。
  4. A 新事件名称快照为“北区总安全区”，历史事件仍为“北区安全区”。

## [P3] 验证 C09 同时编辑 A、B 且位置落在两个事务提交之间时各取已提交版本
- 测试类型
  - 可靠性
- 前置条件
  1. DEV-GF-224 绑定安全区 A=GF-C09-A（半径 500m，版本 v5）和安全区 B=GF-C09-B（版本 v3），几何为相交约定，A、B 均有圆内基线
  2. 可暂停 B 的编辑事务，使 A 的事务先提交
  3. 用于本用例的 O 区点改为 A 圆心西 1000m (116.385416°E, 39.916527°N)
- 测试步骤
  1. 同时发起 A 半径改为 800m、B 类型改为禁入区的两个编辑事务，A 先提交（v6），B 暂停在提交前。
  2. 在两个提交之间注入 c09-001，位于 O 区（西 1000m）。
  3. 恢复并提交 B（v4），注入 c09-002，位于 O 区（西 1000m）。
  4. 查询 A、B 的基线、事件和配置版本。
- 预期结果
  1. A 的 v6 配置与基线清空原子生效；B 仍为 v3 已提交配置。
  2. c09-001 对 A 只建立圆外基线；对 B 按已提交 v3 生成 1 条「离开安全区」事件，事件快照为 v3。
  3. B 提交 v4 后基线清空；c09-002 对 A 按 v6 生成「离开安全区」1 条，对 B 只建立圆外基线。
  4. 每个围栏只使用自身已提交版本，事件总数 2 条，无读取半提交配置或基线残留。
