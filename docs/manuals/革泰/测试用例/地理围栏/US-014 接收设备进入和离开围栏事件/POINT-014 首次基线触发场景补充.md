# US-014 接收设备进入和离开围栏事件

> 口径依据：地理围栏大纲 10.3。新设备首次绑定只接受绑定成功后新上报的第一条有效位置建立基线，不使用绑定前最新位置或历史补传点；管理端执行明确的围栏判定状态初始化也会让下一条有效位置只建基线。圆心、半径、类型、关闭重启和解绑重绑场景已由 US-011 POINT-009、US-012 POINT-004 覆盖，本 POINT 只补其余触发场景。

## [P1] 验证绑定后到达的历史补传点不建立基线
- 测试类型
  - 功能
- 前置条件
  1. 安全区 GF-BASE-10 圆心 (116.397128°E, 39.916527°N)，半径 500m
  2. DEV-GF-130 于 2026-10-12 15:00:00 UTC 绑定成功，此前不存在设备×围栏物理关系
  3. 位置处理模块可将定位时间早于绑定时间的报文标记为历史补传
- 测试步骤
  1. 绑定成功后注入 gf-base-hist-001，定位时间 14:40:00，位于圆外 650m。
  2. 查询历史轨迹、lastInside、水位和事件。
  3. 注入 gf-base-new-002，定位时间 15:05:00，位于圆外 700m。
  4. 注入 gf-base-new-003，定位时间 15:06:00，位于圆外 710m。
- 预期结果
  1. gf-base-hist-001 可写入 14:40:00 的历史轨迹，不作为新有效实时位置。
  2. lastInside 和水位仍为空，事件数为 0。
  3. gf-base-new-002 是绑定后第一条新有效位置，只写入圆外基线，不生成事件。
  4. gf-base-new-003 生成 1 条「离开安全区」事件。

## [P2] 验证管理端判定状态初始化后下一条位置只建基线
- 测试类型
  - 功能
- 前置条件
  1. 安全区 GF-BASE-11 半径 500m，DEV-GF-131 已绑定并有圆内基线，已有 2 条历史围栏事件
  2. 管理端已提供按围栏执行判定状态初始化的入口或接口
- 测试步骤
  1. 对 GF-BASE-11 执行围栏判定状态初始化。
  2. 查询 DEV-GF-131 的 lastInside、历史事件和绑定关系。
  3. 注入 gf-init-001，位于圆外 650m。
  4. 注入 gf-init-002，位于圆外 660m。
- 预期结果
  1. 初始化执行成功。
  2. lastInside 被清空，2 条历史事件保留，物理绑定关系保留。
  3. gf-init-001 只建立圆外基线，不生成事件。
  4. gf-init-002 生成 1 条「离开安全区」事件。

## [P3] 验证绑定后首条报文无效时基线保持为空
- 测试类型
  - 可靠性
- 前置条件
  1. 禁入区 GF-BASE-12 半径 300m，DEV-GF-132 刚绑定成功，lastInside 为空
- 测试步骤
  1. 注入 gf-base-bad-001，经纬度均为 0。
  2. 查询 lastInside 和事件。
  3. 注入 gf-base-ok-002，位于圆内 100m。
  4. 注入 gf-base-ok-003，位于圆内 110m。
- 预期结果
  1. 零值报文按无效位置丢弃。
  2. lastInside 仍为空，事件数为 0。
  3. gf-base-ok-002 是第一条有效位置，只建立圆内基线，不生成事件。
  4. gf-base-ok-003 生成 1 条「进入禁入区」事件。

## [P2] 验证同一围栏下新绑定设备的基线与已有设备相互独立
- 测试类型
  - 功能
- 前置条件
  1. 安全区 GF-BASE-13 半径 500m，DEV-GF-133 已有圆内基线
  2. DEV-GF-134 刚绑定 GF-BASE-13，lastInside 为空
- 测试步骤
  1. 为 DEV-GF-133 注入 gf-ind-133，位于圆外 650m。
  2. 为 DEV-GF-134 注入 gf-ind-134，位于圆外 650m。
  3. 查询两台设备的基线和事件。
- 预期结果
  1. DEV-GF-133 已有基线，生成 1 条「离开安全区」事件。
  2. DEV-GF-134 只建立圆外基线，不生成事件。
  3. 两台设备的 lastInside 与水位各自维护，DEV-GF-133 的基线不影响 DEV-GF-134 的首次判定。
