## 测试对象与边界

### 覆盖范围

- 唯一主入口、列表卡片、名称搜索、服务端分页、刷新与失败态。
- 圆形围栏新增、范围确认、地址解析、草稿、事务、字段边界及名称唯一性。
- 单围栏统计、筛选、设备搜索、地图点位与实时追踪下钻。
- 编辑回显、配置生效、唯一基线重置矩阵和共享账号并发覆盖。
- 企业账号向上共享、共享同权、设备绑定扩散、解绑向下级联和设备管理级联。
- 删除围栏、账号冻结/删除、缓存清理、历史数据保留和幂等并发。
- WGS84 圆形判定、边界归圆内、首次基线、危险侧持续告警、有效位置、水位与消息幂等。
- 多围栏组合、部分基线缺失、账号可见关系、异常隔离及模块联动。
- 请求异常、并发竞态、缓存一致性、性能容量观测、兼容性和易用性。

### 不覆盖或不写死的内容

- 不覆盖多边形围栏、独立“区域围栏”类型及 WGS84→GCJ02 转换。
- 不定义微信、短信、电话、邮件、紧急联系人和通知频控。
- 不把地图首页全局数量等同于单围栏统计口径。
- 不自行定义未在真源明确的精确错误文案；统一断言“展示可读原因并明确字段/操作失败”。
- 不把第 14 章待确认项写成正式通过预期。

## 测试数据约定

### 账号与组织

- 企业一级账号：`ent_l1`
- 企业二级账号：`ent_l2`
- 企业三级账号：`ent_l3`
- 个人账号：`personal01`
- 如 POINT 为验证跨企业分支、性能或账号删除而使用其他具体账号，必须在前置条件中明确所属关系，不得使用占位符。

### 设备

- 标准定位设备：`GT-S10U-0001`、`GT-S10U-0002`、`GT-S10U-0003`
- 每条用例必须明确设备对各账号的可见范围、是否支持定位、是否已绑定围栏及是否已有 `lastInside`。

### 围栏与坐标

- 标准圆心：WGS84 `(116.397128, 39.916527)`。
- 标准半径：`500m`。
- 圆形边界注入：模拟器返回球面距离 `499.9m`、`500.0m`、`500.1m`，分别验证圆内、边界圆内、圆外。
- 业务边界：名称 `1～30` 字符；半径必须为整数且范围 `50～20000m`。
- 地理判定统一使用 WGS84；`距离 ≤ 半径` 为圆内，`距离 > 半径` 为圆外。

### 位置与幂等

- 每条定位报文使用具体的原始消息 ID 或报文序列号，并记录设备 ID、坐标、定位时间、服务端接收顺序和预期配置版本。
- 同消息 ID 重复投递用于验证原子幂等；坐标相同但消息 ID 不同用于验证“新有效定位”语义。
- 历史补传或乱序旧点可进入历史轨迹，但不得更新实时判定水位、`lastInside` 或生成围栏告警。
- 定位时间超前服务器当前时间 10 分钟以上，仅验证按位置处理模块规则处理后再决定是否进入围栏链路，不在本用例集自行规定校正算法或拒绝策略。

## 核心验收纪律

1. 同一 `设备 × 围栏` 只有一条有效物理关系、一份 `lastInside` 和最近判定时间水位。
2. 同一条新有效定位对同一围栏至多生成 1 条物理告警事件，再建立多账号可见/处理关系。
3. 新建物理绑定、全部解绑后重绑、影响判定的配置变更及关闭后启用，第一条有效位置只建立基线。
4. 已有基线后，安全区圆外、禁入区圆内的每条新有效定位均生成独立告警；外→外或内→内不被抑制。
5. 部分账号解绑不重置唯一基线；最后一个账号关系删除后才删除物理关系并清空基线。
6. 地址解析成功是正式保存前置；失败时围栏、账号关系和设备关系整单不落库，并保留草稿供重试。
7. 共享围栏并发编辑采用整份快照最后写入覆盖；已删除围栏的旧编辑页不得恢复围栏或关系。
8. 删除围栏不删除设备本体、历史位置、轨迹和历史告警；删除后不得继续幽灵判定。
9. 位置报文先按 `设备 ID + 原始消息 ID / 序列号` 原子去重，再进入多围栏判断。
10. 测试步骤与预期结果逐条一一对应，失败路径同时验证服务端正式数据与前端展示不得假成功。
