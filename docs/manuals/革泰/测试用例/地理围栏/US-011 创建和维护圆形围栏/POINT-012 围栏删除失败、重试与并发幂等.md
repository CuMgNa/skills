# US-011 创建和维护圆形围栏

> 口径依据：地理围栏大纲 9.3、13.1～13.3 章。删除失败不得提前移除卡片或清理关系；超时重试和共享账号并发删除只允许一次真实删除；删除与位置上报、编辑并发时以删除事务提交边界裁决，禁止部分清理和幽灵恢复。

## [P3][反向] 验证删除请求失败时围栏关系和基线完整保留
- 测试类型
  - 可靠性
- 前置条件
  1. GF-A-0550 已关联三级、二级、一级账号并绑定 GT-D-000101
  2. GT-D-000101×GF-A-0550 的 lastInside = true
  3. 服务端将本次删除请求模拟为事务失败
- 测试步骤
  1. 以 GT-E1-1001 确认删除 GF-A-0550。
  2. 查看当前账号列表卡片并由另外两个共享账号刷新列表。
  3. 查询围栏本体、账号关系、设备账号关系、物理关系和 lastInside。
  4. 上报一条位于安全区圆外的新有效位置 LOC-0550-0002。
- 预期结果
  1. 删除返回失败结果，客户端不展示删除成功态。
  2. 三个账号的 GF-A-0550 卡片均保留，不因前端乐观更新提前消失。
  3. 围栏本体及全部关系保持原状，lastInside 仍为 true，不出现部分删除。
  4. 新位置沿用原基线继续判定并生成 1 条“离开安全区”事件。

## [P1] 验证网络超时后重复删除只执行一次真实清理
- 测试类型
  - 可靠性
- 前置条件
  1. GF-A-0551 存在完整账号关系、设备关系、物理关系、基线和缓存
  2. 首次删除请求使用业务对象 GF-A-0551，服务端已提交删除但客户端响应超时
  3. 可核对删除事务次数和关系清理结果
- 测试步骤
  1. 发起首次删除并在服务端提交后模拟响应超时。
  2. 客户端对 GF-A-0551 再次提交删除请求。
  3. 查询两次响应、真实删除事务执行次数和各类关系剩余数量。
  4. 再刷新列表、地图和统计入口。
- 预期结果
  1. 首次请求虽未收到成功响应，但服务端只完成一次原子删除。
  2. 重试返回可识别的已删除或不存在结果，不触发第二次删除副作用。
  3. 真实删除事务次数为 1，围栏本体、关系、物理基线和缓存均为完整清理态，无重复审计副作用。
  4. 各入口最终均不再展示 GF-A-0551，不把幂等结果显示成未删除。

## [P1] 验证两个共享账号并发删除同一围栏保持幂等
- 测试类型
  - 可靠性
- 前置条件
  1. GF-A-0552 由 GT-E3-3101 创建，GT-E2-2101、GT-E1-1001 同权可删除
  2. GF-A-0552 已绑定 GT-D-000102 并建立唯一基线
  3. 已准备并发请求控制工具
- 测试步骤
  1. 让 GT-E2-2101 与 GT-E1-1001 同时确认删除 GF-A-0552。
  2. 记录两个请求的响应和服务端异常日志。
  3. 查询围栏本体、全部账号关系、设备关系、物理关系与基线。
  4. 三个共享账号分别刷新列表并通过 GF-A-0552 直访。
- 预期结果
  1. 两个请求并发到达时仅一个执行真实删除，另一个获得幂等成功或已不存在结果。
  2. 两个请求均不返回未处理的服务端异常，不产生重复删除副作用。
  3. 所有目标数据处于一致的全删除态，不出现围栏本体已删但关系或基线残留。
  4. 三个账号均不再显示或访问 GF-A-0552。

## [P3] 验证删除与位置上报及旧编辑保存并发不产生幽灵关系
- 测试类型
  - 可靠性
- 前置条件
  1. 安全区 GF-A-0553 已建立基线，GT-E2-2101 已打开该围栏编辑页
  2. GT-D-000103 准备上报圆外有效位置 LOC-0553-0002
  3. GT-E1-1001 准备删除 GF-A-0553
- 测试步骤
  1. 在删除事务提交前让 LOC-0553-0002 完成判定并记录结果。
  2. 提交并完成 GF-A-0553 删除事务。
  3. 删除提交后再上报圆外有效位置 LOC-0553-0003。
  4. GT-E2-2101 在旧编辑页修改名称后点击保存并刷新列表。
- 预期结果
  1. 删除提交前已形成的合法 LOC-0553-0002 事件可以保留，事件使用发生时配置快照。
  2. 删除完成后围栏本体、关系、物理基线和缓存一致清理。
  3. LOC-0553-0003 不再进入 GF-A-0553 判定，不产生删除后的幽灵事件。
  4. 旧编辑页保存失败，不能恢复原围栏、创建新围栏或重建设备关系；刷新后仍无 GF-A-0553。
