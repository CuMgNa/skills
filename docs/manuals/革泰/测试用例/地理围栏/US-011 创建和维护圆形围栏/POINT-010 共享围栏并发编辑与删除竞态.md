# US-011 创建和维护圆形围栏

> 口径依据：需求真源第 7.2 节、第 9.3 节、第 13.2～13.4 节。共享围栏并发编辑不使用配置版本阻止旧页面提交，而采用整份配置快照最后写入覆盖；后保存请求整体覆盖名称、圆心、半径、类型和设备选择，不做字段合并；围栏删除后任何旧页面保存必须失败，不得复活原围栏、创建新围栏或重建幽灵关系。

## [P1] 验证后保存的旧快照整份覆盖先保存配置
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号 corp_level1_01 与二级账号 corp_level2_01 同时可编辑共享围栏 GF-RACE-001
  2. 初始配置版本 12：名称“共享仓库”、圆心（121.4737，31.2304）、半径 500 米、类型安全区、绑定 D6101、D6102
  3. 两个账号均已打开编辑页并加载版本 12 的完整快照
- 测试步骤
  1. 一级账号将名称改为“共享仓库-A”，设备改为 D6101、D6103，其他字段保持快照值并先保存成功。
  2. 二级账号在旧页面仅把半径改为 800 米，页面中名称仍为“共享仓库”、设备仍为 D6101、D6102，随后保存。
  3. 两端重新加载 GF-RACE-001 最新配置。
  4. 查询配置版本、设备关系和基线重建结果。
- 预期结果
  1. 一级账号整份快照先写入，服务端短暂为名称“共享仓库-A”、半径 500 米、绑定 D6101、D6103。
  2. 二级账号旧版本请求不因版本 12 被冲突拦截，后保存的整份快照覆盖当前配置。
  3. 最终名称为“共享仓库”、半径 800 米、类型安全区、绑定 D6101、D6102；不得合并成“共享仓库-A”加 800 米加 D6103。
  4. 配置版本递增且仅半径变化对应的设备判定基线按新范围重建；D6103 正式关系已被后写快照移除。

## [P1] 验证最后写入覆盖在类型圆心和设备字段上同样整体生效
- 测试类型
  - 功能
- 前置条件
  1. corp_level1_01 与 corp_level3_01 同时打开共享围栏 GF-RACE-002，加载初始版本 20
  2. 初始配置为名称“园区围栏”、圆心（120.1551，30.2741）、半径 600 米、类型关闭、绑定 D6201
- 测试步骤
  1. 三级账号将名称改为“园区围栏-三级”，设备改为 D6201、D6202并先保存成功。
  2. 一级账号基于旧快照将圆心改为（120.1600，30.2800）、类型改为禁入区，页面名称仍为“园区围栏”、设备仍仅 D6201，并后保存。
  3. 重新进入编辑页核对最终全部字段。
  4. 上报 D6201 在新圆心范围内的第一条有效位置 M6201-01。
- 预期结果
  1. 三级账号保存后服务端短暂显示名称“园区围栏-三级”并绑定 D6201、D6202。
  2. 一级账号后保存成功，旧版本仅用于追溯，不阻止整份最后写入。
  3. 最终名称恢复为“园区围栏”，圆心为（120.1600，30.2800）、半径 600 米、类型禁入区、仅绑定 D6201；D6202 不保留。
  4. 圆心和类型变化已清空 D6201 基线，M6201-01 只建立新基线，不因并发覆盖补发告警。

## [P1][反向] 验证删除先提交后旧编辑页保存失败且不复活围栏
- 测试类型
  - 可靠性
- 前置条件
  1. corp_level1_01 与 corp_level2_01 共享围栏 GF-RACE-003，绑定 D6301、D6302
  2. 一级账号停留在 GF-RACE-003 旧编辑页，已将名称草稿改为“已删除围栏重命名”但尚未保存
- 测试步骤
  1. 二级账号确认删除 GF-RACE-003 并等待删除成功。
  2. 一级账号在旧编辑页点击 Save。
  3. 查询围栏本体、账号关系、设备关系、lastInside 和缓存。
  4. 在两个账号的列表、统计入口及告警历史中核对结果。
- 预期结果
  1. GF-RACE-003 本体及有效账号关系、设备关系、判定基线被删除。
  2. 旧编辑页保存失败，展示围栏已不存在或不可访问的可读原因；不得显示保存成功。
  3. 原 ID GF-RACE-003 不存在，不创建新围栏 ID，不恢复 D6301、D6302 关系、lastInside 或旧缓存。
  4. 两个账号列表与统计入口均无该围栏；历史告警按事件快照保留，但设备后续上报不触发 GF-RACE-003 幽灵告警。

## [P1] 验证编辑先成功后删除仍以删除为最终状态
- 测试类型
  - 可靠性
- 前置条件
  1. corp_level1_01 与 corp_level2_01 共享围栏 GF-RACE-004，初始名称“并发围栏”、绑定 D6401
  2. 一级账号准备保存名称“并发围栏-新版”及追加设备 D6402，二级账号已打开删除确认弹窗
- 测试步骤
  1. 一级账号先提交编辑并确认保存成功。
  2. 二级账号随后确认删除 GF-RACE-004。
  3. 一级账号在原编辑结果页再次修改半径为 900 米并尝试保存。
  4. 查询数据库、缓存、设备关系及 D6401、D6402 后续位置上报结果。
- 预期结果
  1. 编辑事务先完整生效，名称与设备关系不存在半提交。
  2. 删除事务随后删除最新版本 GF-RACE-004 及 D6401、D6402 的全部围栏关系和基线。
  3. 删除后的再次保存失败并给出可读原因，不得恢复最新版本或旧版本围栏。
  4. 数据库和缓存均不存在 GF-RACE-004 及幽灵设备关系，D6401、D6402 后续位置不再执行该围栏判定；历史告警保持可查。
