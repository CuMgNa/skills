# US-011 创建和维护圆形围栏

> 口径依据：地理围栏大纲 7.2、7.4、13.2、13.4。共享围栏并发编辑采用整份最后成功写入覆盖；删除、绑定、解绑与位置上报按事务提交边界裁决；缓存携带配置版本且不得复活已删数据。

## [P1] 验证两个共享账号并发编辑按整份最后写入覆盖
- 测试类型
  - 功能
- 前置条件
  1. E1、E2同时打开共享围栏 GF-CON-01，初始配置为名称 Fence-Old、半径 500m、安全区、绑定 DEV-GF-110
  2. E1页面改为名称 Fence-E1、半径 600m、仍绑定 DEV-GF-110
  3. E2页面改为名称 Fence-E2、半径 900m、禁入区、改绑 DEV-GF-111
- 测试步骤
  1. E1先提交整份快照并成功。
  2. E2后提交其旧页面中的整份快照并成功。
  3. E1、E2刷新列表、编辑页和设备关系。
- 预期结果
  1. E1快照短暂成为正式配置。
  2. E2作为后成功写入者整体覆盖，不做字段合并，也不因旧配置版本直接拦截。
  3. 最终两账号均看到 Fence-E2、900m、禁入区、绑定 DEV-GF-111；DEV-GF-110不因 E1先保存而残留。

## [P1] 验证编辑或删除与位置上报按提交边界裁决
- 测试类型
  - 可靠性
- 前置条件
  1. GF-CON-02为安全区且已有基线，准备将半径从 500m改为 800m
  2. GF-CON-03准备删除，两围栏均可控制事务提交时刻
- 测试步骤
  1. 在 GF-CON-02编辑事务提交前注入 gf-con-old-001，提交后注入 gf-con-new-002。
  2. 核对两条消息使用的配置版本和基线结果。
  3. 在 GF-CON-03删除提交前注入 gf-before-del-001，提交后注入 gf-after-del-002。
  4. 查询事件、关系和缓存。
- 预期结果
  1. gf-con-old-001使用旧配置；编辑提交后新配置与基线清空原子生效。
  2. gf-con-new-002使用新配置且只建立新基线，不出现新配置配旧基线的混合状态。
  3. 删除提交前已合法形成的事件可保留；提交后 GF-CON-03关系已删除，gf-after-del-002不得再生成该围栏事件。
  4. 删除后缓存同步失效，不残留幽灵关系或判定。

## [P1] 验证并发绑定、解绑和删除保持唯一关系
- 测试类型
  - 可靠性
- 前置条件
  1. E1、E2均可管理共享围栏 GF-CON-04和设备 DEV-GF-112
  2. 可并发提交关系操作
- 测试步骤
  1. E1、E2同时绑定 DEV-GF-112。
  2. 查询物理关系、账号关系和基线初始化次数。
  3. E1执行最后账号解绑的同时，E2提交删除围栏。
  4. 查询最终围栏、关系、基线及两请求结果。
- 预期结果
  1. 并发绑定后设备×围栏只有 1 条物理关系，账号关系按有效可见范围去重。
  2. 基线只初始化一次，不产生重复空基线记录。
  3. 解绑和删除按事务顺序幂等完成，只允许一次实际关系清理。
  4. 最终围栏已删除且无物理关系、账号关系和基线，不出现服务端异常或部分残留。

## [P2] 验证缓存版本落后、加载异常和已删除缓存均被隔离
- 测试类型
  - 可靠性
- 前置条件
  1. GF-CON-05数据库配置版本为 v12，缓存人为设置为 v11
  2. GF-CON-06缓存可模拟读取异常，GF-CON-07已在数据库删除但保留旧缓存副本
  3. DEV-GF-113同时绑定 GF-CON-05、GF-CON-06和有效围栏 GF-CON-08
- 测试步骤
  1. 注入 gf-cache-001并触发三围栏查询。
  2. 查询 GF-CON-05实际使用版本。
  3. 查询 GF-CON-06异常处理和 GF-CON-08判定结果。
  4. 查询 GF-CON-07是否被旧缓存重新判定。
- 预期结果
  1. 位置处理继续逐围栏执行，不因单缓存问题整体失败。
  2. GF-CON-05发现版本落后后以数据库 v12为准并重建缓存。
  3. GF-CON-06异常被记录并仅影响自身，GF-CON-08正常完成判定。
  4. GF-CON-07旧缓存不得复活已删围栏、关系或事件。
