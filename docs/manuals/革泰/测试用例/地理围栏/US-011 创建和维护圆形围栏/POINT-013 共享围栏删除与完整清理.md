# US-011 创建和维护圆形围栏

> 口径依据：地理围栏大纲 3.3、9.1～9.2、12.2～12.4 章。共享链内任一有权账号删除围栏均对所有关联账号全局生效；删除需清理围栏本体、账号关系、设备账号关系、物理关系、基线及缓存，但保留设备本体、设备关系、历史轨迹和历史告警。

## [P1] 验证非创建共享账号删除围栏后全局生效
- 测试类型
  - 功能
- 前置条件
  1. GF-A-0540“东区放牧场”由 GT-E3-3101 创建，GT-E2-2101、GT-E1-1001 已获得同一围栏关系
  2. 三个账号均可见围栏且 GT-E2-2101 不是创建者
- 测试步骤
  1. 以 GT-E2-2101 从围栏卡片发起删除并取消一次。
  2. 核对三个账号的围栏列表与 GF-A-0540 数据。
  3. 再次以 GT-E2-2101 发起删除并确认。
  4. 分别以 GT-E3-3101、GT-E2-2101、GT-E1-1001 通过列表和围栏 ID 查询 GF-A-0540。
- 预期结果
  1. 取消删除不产生任何数据变化。
  2. 三个账号仍可查看同一 GF-A-0540，账号关系保持。
  3. 非创建共享账号有权删除该围栏，删除针对同一围栏本体执行一次。
  4. 三个账号均无法再查询或访问 GF-A-0540，围栏从整条共享链全局消失。

## [P1] 验证删除清理围栏本体关系基线和缓存且不再幽灵判定
- 测试类型
  - 可靠性
- 前置条件
  1. GF-A-0541 已关联 GT-E1-1001、GT-E2-2101、GT-E3-3101
  2. GF-A-0541 已绑定 GT-D-000101、GT-D-000102，存在账号关系、物理关系、lastInside、判定水位、地址缓存、缩略图缓存和配置缓存
  3. 两台设备均可继续上报位置
- 测试步骤
  1. 删除 GF-A-0541 并等待删除事务成功。
  2. 查询围栏本体、围栏账号关系、围栏设备账号关系、设备×围栏物理关系、lastInside 和判定水位。
  3. 从原列表缓存、地图缩略图和统计页入口刷新并尝试访问 GF-A-0541。
  4. 让 GT-D-000101、GT-D-000102 各上报一条新的有效危险侧位置。
- 预期结果
  1. 删除事务完成，围栏不再作为有效配置存在。
  2. GF-A-0541 本体、全部账号关系、全部设备账号关系、物理关系、lastInside 和判定水位均被清理，不残留部分关系。
  3. 地址、缩略图和配置缓存失效，旧入口不能继续展示或恢复已删围栏。
  4. 新位置不进入 GF-A-0541 判定，不生成已删围栏的幽灵告警。

## [P1] 验证删除围栏保留设备数据并不影响其他围栏
- 测试类型
  - 功能
- 前置条件
  1. GT-D-000103 同时绑定 GF-A-0542 和 GF-A-0543，两套物理关系与基线均已建立
  2. GT-D-000103 在设备管理中绑定 GT-E1-1001，存在分组“牛群一组”、10 条位置轨迹和 3 条历史告警
  3. 待删除围栏为 GF-A-0542
- 测试步骤
  1. 删除 GF-A-0542。
  2. 查询 GT-D-000103 设备本体、账号绑定、设备分组和物联网卡关系。
  3. 查询 10 条历史轨迹、3 条历史告警及其详情。
  4. 查询 GF-A-0543 的账号关系、设备关系和基线并上报一条新有效位置。
- 预期结果
  1. GF-A-0542 及其有效关系被删除。
  2. 设备本体、GT-E1-1001 绑定、“牛群一组”和物联网卡关系保持不变。
  3. 10 条历史轨迹和 3 条历史告警均保留且可按当前权限读取。
  4. GF-A-0543 的关系和基线不受影响，新位置继续按 GF-A-0543 当前配置判定。

## [P2] 验证删除不生成围栏事件且历史告警按快照继续展示
- 测试类型
  - 功能
- 前置条件
  1. GF-A-0544“西门安全区”已有 1 条已处理和 1 条未处理历史告警
  2. 两条事件均保存围栏名称、类型、圆心、半径和配置版本快照
  3. 删除前告警事件总数为 2
- 测试步骤
  1. 删除 GF-A-0544 并记录删除前后告警事件总数。
  2. 打开已处理历史告警详情。
  3. 打开未处理历史告警详情并核对处理状态。
  4. 查询删除时间点是否新增进入或离开围栏事件。
- 预期结果
  1. 删除完成后历史告警事件总数仍为 2，删除动作不清理历史事件。
  2. 已处理事件继续按发生时快照展示“西门安全区”及对应类型、范围版本。
  3. 未处理事件仍保持未处理，不因围栏删除被自动改为已处理。
  4. 删除动作本身不新增“进入禁入区”或“离开安全区”事件。
