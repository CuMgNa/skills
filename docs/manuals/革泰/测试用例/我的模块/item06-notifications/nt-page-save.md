# 用户故事：通知提醒页面与切换即保存

> 口径依据：大纲 10.1–10.3 章。页面标题「通知提醒」，单白色圆角卡片，仅「告警 Sound」「手机振动」两开关，无类型过滤开关、无保存按钮；默认全开；切换即保存即生效，退出不回滚，下次登录保持；保存接口幂等。

## [P1] 验证页面仅展示两项开关且无类型过滤入口
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已登录
- 测试步骤
  1. 进入「我的 → 通知提醒」。
  2. 查看页面标题、卡片数量、开关清单与说明文案。
  3. 检查是否存在离开围栏 / 进入围栏 / 低电量类型开关、分组标题、保存按钮。
  4. 点击左上返回。
- 预期结果
  1. 页面标题为「通知提醒」，返回指向「我的」。
  2. 单张白色圆角卡片，含「告警 Sound（推送通知时播放声音）」和「手机振动（收到推送通知时振动）」两项及对应图标。
  3. 不存在三类告警类型开关、分组标题、保存按钮（类型过滤能力整体移除，所有设备告警类型默认推）。
  4. 返回我的页。

## [P1] 验证新注册账号两开关默认全开
- 测试类型
  - 功能
- 前置条件
  1. 新注册账号 newuser01 首次登录，无通知提醒配置记录
- 测试步骤
  1. 进入通知提醒页。
  2. 查看两个开关状态。
  3. 退出重登后再次查看。
- 预期结果
  1. 页面加载服务端配置。
  2. 告警 Sound、手机振动均为开启（新账号默认全开）。
  3. 重登后仍为全开。

## [P1] 验证拨动开关成功后切换即保存且退出不回滚
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 两开关当前全开
  2. 抓包工具就绪
- 测试步骤
  1. 将告警 Sound 从开切为关。
  2. 观察网络请求、开关终态与是否有保存按钮。
  3. 立即返回我的页，再进入通知提醒页。
  4. 退出重登后再次查看。
- 预期结果
  1. 拨动后立即调用保存接口。
  2. 保存成功后开关保持关，无保存按钮（切换即保存即生效）。
  3. 重进仍为关（返回不回滚）。
  4. 重登保持关（账号级服务端配置持久化）。

## [P2] 验证一次拨动只 PATCH 对应独立字段
- 测试类型
  - 功能
- 前置条件
  1. 告警 Sound = 开，手机振动 = 关
  2. 抓包工具就绪
- 测试步骤
  1. 仅将告警 Sound 切为关。
  2. 检查请求体字段。
  3. 查看手机振动状态。
- 预期结果
  1. 保存请求发出。
  2. 请求仅 PATCH 告警 Sound 对应字段，不整表覆盖振动字段（契约 #1）。
  3. 手机振动仍为关，互不影响。

## [P4] 验证拨动后立即退出保存语义不丢失
- 测试类型
  - 可靠性
- 前置条件
  1. 两开关全开，网络正常
- 测试步骤
  1. 将手机振动切为关后立即按返回退出页面。
  2. 等待 2 秒后重进通知提醒页。
  3. 抓包核对保存请求结果。
- 预期结果
  1. 已发出的保存请求不因退出而丢失语义。
  2. 重进以服务端真值为准显示关。
  3. 服务端值与 UI 一致，无假成功。
