# 用户故事：通知提醒账号隔离与多端并发

> 口径依据：大纲 10.2 / 10.4 / 12 章。通知提醒为服务端账号级配置：每人独立，账号切换不混用，退出重登保持；双端同一开关后写覆盖；双端不同开关因独立字段各自保存互不覆盖；各端进入页面从服务端拉取真值。

## [P1] 验证账号切换后通知配置按账号隔离
- 测试类型
  - 功能
- 前置条件
  1. 账号 A：Sound = 开、振动 = 关
  2. 账号 B：新注册账号，两开关默认全开
- 测试步骤
  1. 账号 A 登录，进入通知提醒页核对状态。
  2. 退出 A，登录 B，进入通知提醒页。
  3. 再退出 B、重登 A 核对状态。
- 预期结果
  1. A 显示开 / 关。
  2. B 显示开 / 开，不继承 A 的关闭振动配置。
  3. A 重登仍为开 / 关（账号级独立，退出重登保持）。

## [P2] 验证双端拨同一开关后写覆盖
- 测试类型
  - 功能
- 前置条件
  1. testuser01 在手机 A、手机 B 同时登录，Sound 初始为开
- 测试步骤
  1. A 将 Sound 关并保存成功。
  2. B 随后将 Sound 开并保存成功。
  3. A 重进通知提醒页重新拉取服务端状态。
  4. 检查是否有冲突提示。
- 预期结果
  1. 服务端 Sound 变为关。
  2. B 后写覆盖，服务端 Sound 变为开。
  3. A 重进显示开（以下次服务端拉取为准）。
  4. 无冲突提示（后写覆盖规则）。

## [P1] 验证双端拨不同开关互不覆盖
- 测试类型
  - 功能
- 前置条件
  1. testuser01 在手机 A、手机 B 同时登录，两开关初始全开
  2. 抓包工具就绪
- 测试步骤
  1. A 将 Sound 关闭并保存。
  2. B 同时将振动关闭并保存。
  3. 两端重进页面拉取服务端状态。
  4. 查看两个请求体。
- 预期结果
  1. Sound 变为关。
  2. 振动变为关，未把 Sound 回写为开。
  3. 两端最终均显示关 / 关（两开关独立字段）。
  4. A 请求只 PATCH Sound，B 请求只 PATCH 振动，不整表覆盖，互不踩值。

## [P3] 验证本地缓存与服务端不一致时以服务端真值为准
- 测试类型
  - 可靠性
- 前置条件
  1. APP 本地缓存：Sound = 开、振动 = 开
  2. 后台直接将服务端配置改为 Sound = 关、振动 = 开
- 测试步骤
  1. 杀进程重开 APP，进入通知提醒页。
  2. 观察首屏配置加载后的开关状态。
  3. 下拉 / 重进再次核对。
- 预期结果
  1. 页面从服务端拉取配置。
  2. 加载完成后显示 Sound = 关、振动 = 开，不信任旧本地缓存冒充真值。
  3. 重进仍与服务端一致。
