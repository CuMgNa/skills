# 用户故事：通知提醒作用边界

> 口径依据：大纲 10.2 章。两开关仅控制设备告警类推送的提醒表现（响铃 / 振动）；全关不等于免打扰——推送本身、告警记录、告警中心列表、处理状态均不受影响；所有设备告警类型默认推；APP 其他类型推送不受控；服务端站内 / 微信渠道不受控。

## [P1] 验证两开关全关后告警仍推送且记录照常产生
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 将告警 Sound、手机振动均关闭
  2. 测试手机未开启系统级免打扰，设备 DEV0001 可触发低电量告警
- 测试步骤
  1. 触发 DEV0001 低电量告警。
  2. 观察手机是否收到推送、是否响铃 / 振动。
  3. 打开告警中心查看记录与处理状态。
  4. 处理该告警，查看状态变化。
- 预期结果
  1. 告警事件产生。
  2. 推送照常到达，但不响铃、不振动（全关 ≠ 免打扰，仅表现形式关闭）。
  3. 告警记录正常产生并在列表显示，初始处理状态正常。
  4. 处理状态可正常更新，不受开关影响。

## [P2] 验证告警 Sound 关闭仅关闭声音而保留振动
- 测试类型
  - 功能
- 前置条件
  1. 告警 Sound = 关，手机振动 = 开
  2. 设备 DEV0001 可触发进入围栏告警
- 测试步骤
  1. 触发进入围栏告警。
  2. 观察通知到达、声音与振动。
  3. 查看告警中心记录。
- 预期结果
  1. 推送到达。
  2. 无声音、有振动。
  3. 告警记录正常产生。

## [P2] 验证振动关闭仅关闭振动而保留声音
- 测试类型
  - 功能
- 前置条件
  1. 告警 Sound = 开，手机振动 = 关
  2. 设备 DEV0001 可触发离开围栏告警
- 测试步骤
  1. 触发离开围栏告警。
  2. 观察通知到达、声音与振动。
  3. 查看告警记录。
- 预期结果
  1. 推送到达。
  2. 有声音、无振动。
  3. 告警记录正常产生。

## [P2] 验证三类设备告警均默认推送无类型过滤
- 测试类型
  - 功能
- 前置条件
  1. 两开关全开
  2. 可分别触发离开围栏、进入围栏、低电量三类告警
- 测试步骤
  1. 依次触发三类告警。
  2. 观察每类推送到达情况。
  3. 查看告警中心记录。
- 预期结果
  1. 三类事件均触发。
  2. 三类推送均到达并按两开关表现（无类型过滤入口，全部默认推）。
  3. 告警中心三类记录齐全。

## [P3][反向] 验证非设备告警推送不受两开关控制
- 测试类型
  - 功能
- 前置条件
  1. 两开关全关
  2. 有一种 APP 其他类型推送（如系统公告）可触发
- 测试步骤
  1. 触发系统公告推送。
  2. 观察到达与提醒表现。
  3. 与设备告警推送结果比较。
- 预期结果
  1. 其他类型推送正常触发。
  2. 其提醒表现按自身业务 / 系统规则执行，不由告警 Sound / 振动两开关决定。
  3. 两开关事件范围仅设备告警类推送。

## [P3][反向] 验证服务端站内 / 微信渠道不受两开关影响
- 测试类型
  - 功能
- 前置条件
  1. 两开关全关，账号已配置站内 / 微信告警渠道
- 测试步骤
  1. 触发设备低电量告警。
  2. 查看 APP 推送、站内消息、微信渠道到达情况。
  3. 核对两开关是否改变服务端渠道路由。
- 预期结果
  1. 告警产生。
  2. APP 推送到达但无声无振；站内 / 微信渠道按原配置照常到达。
  3. 服务端渠道路由不读取这两字段（渠道边界，契约 #4）。
