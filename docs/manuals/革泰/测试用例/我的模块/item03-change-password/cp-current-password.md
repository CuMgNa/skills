# 用户故事：当前密码校验与新旧相同拦截

> 口径依据：大纲 6.3 / 6.4 / 6.7 章。新密码 = 当前密码时前端拦截、服务端再校验；当前密码错误由服务端校验、框下提示、输入保留、可无限重试（不限次）；本地 1–4 层全部通过才发请求。

## [P3][反向] 验证新密码等于当前密码时本地拦截
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 当前密码 Test@1234，已登录
  2. 抓包工具就绪
- 测试步骤
  1. 当前密码、新密码、确认密码均输入 Test@1234。
  2. 点 Save。
  3. 查看提示位置与三框内容。
  4. 检查网络请求。
- 预期结果
  1. 三字段非空、长度合法、一致性通过。
  2. 新旧相同校验命中。
  3. 新密码框下提示不能与当前密码相同，三框输入保留。
  4. 前端不发修改密码请求（服务端仍须有相同校验防绕过，契约 #4）。

## [P3][反向] 验证当前密码错误由服务端提示且输入保留
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 当前密码 Test@1234，已登录
- 测试步骤
  1. 输入错误当前密码 Wrong@123、新密码 / 确认 NewPass56。
  2. 点 Save。
  3. 等待服务端响应，查看提示位置。
  4. 查看三框内容与按钮状态。
- 预期结果
  1. 本地 1–4 层校验通过，请求发出。
  2. 服务端判定当前密码错误。
  3. 当前密码框下显示错误提示（非 Toast、非提示在新密码框）。
  4. 三框内容全部保留，按钮恢复可点。

## [P3] 验证当前密码错误可无限重试不锁定
- 测试类型
  - 安全性
- 前置条件
  1. 账号 testuser01 当前密码 Test@1234，已登录
- 测试步骤
  1. 连续使用 5 个错误当前密码 Wrong001 至 Wrong005，分别搭配 NewPass56 提交。
  2. 每次响应后查看提示与账号状态。
  3. 第 6 次输入正确当前密码 Test@1234、新密码 NewPass56 提交。
- 预期结果
  1. 5 次均提示当前密码错误、输入保留，无次数限制 / 锁定提示。
  2. 账号保持可用，页面允许继续提交。
  3. 第 6 次正确提交成功（PRD 未定义限次锁定，拍板不限次）。

## [P3][反向] 验证绕过前端提交新旧相同仍被服务端拒绝
- 测试类型
  - 安全性
- 前置条件
  1. 账号 testuser01 当前密码 Test@1234
  2. 可使用抓包重放 / 接口工具绕过前端，直接请求改密接口
- 测试步骤
  1. 构造请求：currentPassword=Test@1234、newPassword=Test@1234、confirmPassword=Test@1234。
  2. 发送请求并查看响应。
  3. 用 Test@1234 登录验证密码状态。
- 预期结果
  1. 请求绕过前端成功发出。
  2. 服务端拒绝新旧相同（必须再校验，不能仅靠前端）。
  3. 原密码 Test@1234 仍可正常登录，密码未被无效改写。
