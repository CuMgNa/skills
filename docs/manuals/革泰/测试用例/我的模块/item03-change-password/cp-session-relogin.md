# 用户故事：改密成功后的会话处理与重登

> 口径依据：大纲 6.5 / 6.7 章。成功后当前端踢回登录页；全端（另一手机 / Web）会话失效；旧密码立即失效，新密码可登录；手动输入新密码，不静默重登；账号标识可带出、密码留空；账户身份 / 权限 / 数据范围不变；密码落库 + token 失效原子。

## [P1] 验证改密成功后旧密码立即失效、新密码可登录
- 测试类型
  - 安全性
- 前置条件
  1. 账号 testuser01 当前密码 Test@1234，已登录
- 测试步骤
  1. 将密码修改为 NewPass56，等待踢回登录页。
  2. 用旧密码 Test@1234 登录。
  3. 用新密码 NewPass56 登录。
  4. 查看账户身份、设备权限与数据范围。
- 预期结果
  1. 修改成功并回登录页。
  2. 旧密码登录报「密码错误」（立即失效，安全硬断言）。
  3. 新密码登录成功。
  4. 账户身份 / 权限 / 数据范围与改密前一致（只改密码）。

## [P1] 验证改密成功后其他 APP 端与 Web 会话全部失效
- 测试类型
  - 安全性
- 前置条件
  1. testuser01 在手机 A、手机 B、Web 监控平台同时登录
  2. 当前密码 Test@1234
- 测试步骤
  1. 手机 A 将密码改为 NewPass56。
  2. 手机 B 发起任意需要认证的请求（如刷新设备列表）。
  3. Web 监控平台刷新页面 / 发起查询。
  4. 手机 B、Web 分别用 NewPass56 重登。
- 预期结果
  1. 手机 A 修改成功、当前端回登录页。
  2. 手机 B 下次请求被踢回登录页。
  3. Web 会话同样失效并要求登录（全 issued token 覆盖，非仅当前端）。
  4. 两端用新密码可重登。

## [P2] 验证回登录页账号带出、密码留空且不静默重登
- 测试类型
  - 功能
- 前置条件
  1. 账号 testuser01 已完成改密为 NewPass56
- 测试步骤
  1. 查看改密成功后回到的登录页。
  2. 检查账号输入框与密码输入框。
  3. 不输入密码等待 10 秒，观察是否自动登录。
  4. 手动输入 NewPass56 登录。
- 预期结果
  1. 显示登录页。
  2. 账号标识 testuser01 按保存偏好带出，密码框为空（不回填旧密码 / 新密码）。
  3. 不发生静默重登。
  4. 手动输入新密码后登录成功。

## [P3] 验证密码落库与全端 token 失效的原子性
- 测试类型
  - 安全性
- 前置条件
  1. testuser01 当前密码 Test@1234，在手机 A、手机 B 登录
  2. 可高频轮询 B 端鉴权接口
- 测试步骤
  1. B 端持续每 100ms 调用一个鉴权接口并记录状态。
  2. A 端提交改密为 NewPass56。
  3. 记录密码修改成功响应时刻前后 B 端 token 状态。
  4. 改密成功后立即用旧 / 新密码分别登录。
- 预期结果
  1. 轮询正常执行。
  2. 改密完成。
  3. 成功语义建立后 B 端旧 token 不再有效，不允许「密码已改、旧 token 仍可访问」窗口（同一事务语义）。
  4. 旧密码失败、新密码成功，状态一致无分裂。
