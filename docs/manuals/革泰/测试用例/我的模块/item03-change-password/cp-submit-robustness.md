# 用户故事：修改密码提交健壮性

> 口径依据：大纲 6.3 / 6.6 / 6.7 章。Save 点击后 loading + 禁用防重复；服务端幂等；断网 / 超时提示失败、输入保留、按钮恢复，不得半提交；双端同时改密先提交成功、后提交自然失败；token 失效时走统一认证流程，不误报当前密码错误。

## [P3][反向] 验证快速连点保存只发一次请求
- 测试类型
  - 可靠性
- 前置条件
  1. 账号 testuser01 当前密码 Test@1234，已登录
  2. 抓包工具就绪
- 测试步骤
  1. 输入合法三字段 Test@1234 / NewPass56 / NewPass56。
  2. 快速连续点击 Save 10 次。
  3. 观察按钮状态与抓包请求数。
  4. 查看最终结果。
- 预期结果
  1. 输入完成。
  2. 首次点击后按钮立即 loading + 禁用，后续点击不响应。
  3. 仅发出 1 次改密请求。
  4. 修改成功一次，无重复提示 / 重复踢线（客户端防重 + 服务端幂等）。

## [P3][反向] 验证提交中断网不发生半提交
- 测试类型
  - 可靠性
- 前置条件
  1. 账号 testuser01 当前密码 Test@1234，已登录
  2. 抓包工具可在请求途中断网
- 测试步骤
  1. 输入合法三字段 Test@1234 / NewPass56 / NewPass56，点 Save 后立即断网。
  2. 等待超时，查看提示、三框内容与按钮状态。
  3. 恢复网络并退出到登录页。
  4. 分别用旧密码 Test@1234、新密码 NewPass56 尝试登录。
- 预期结果
  1. 请求中断。
  2. 提示失败，三框内容全部保留，按钮恢复可点。
  3. 网络恢复。
  4. 若服务端未落库则旧密码可登录、新密码不可登录；不得出现「两者都不能登录」或密码已改但旧 token 仍长期有效的半提交态。若服务端已原子完成则按成功态处理并全端失效，不能状态分裂。

## [P3] 验证双端同时改密仅先提交者成功
- 测试类型
  - 安全性
- 前置条件
  1. 账号 testuser01 当前密码 Test@1234，在手机 A、手机 B 同时登录
  2. A 准备新密码 NewPass56，B 准备新密码 OtherPass78
- 测试步骤
  1. 两端同时点击 Save（均填当前密码 Test@1234）。
  2. 记录两端响应先后与结果。
  3. 用成功端的新密码登录验证。
  4. 用失败端的新密码登录验证。
- 预期结果
  1. 两请求并发提交。
  2. 先到服务端者成功；后到者因旧密码已失效而当前密码验证失败，无双改成功（同一账号数据快照防 TOCTOU）。
  3. 成功端新密码可登录。
  4. 失败端新密码不可登录。

## [P3][反向] 验证改密页停留期间 token 失效走统一认证流程
- 测试类型
  - 安全性
- 前置条件
  1. 手机 A、手机 B 同时登录 testuser01，当前密码 Test@1234
  2. 手机 B 停留在修改密码页并已填三字段
- 测试步骤
  1. 手机 A 完成改密为 NewPass56，使全端 token 失效。
  2. 手机 B 点击 Save 提交（其 token 已失效）。
  3. 查看 B 端提示与页面去向。
- 预期结果
  1. A 修改成功并触发全端会话失效。
  2. B 请求返回认证失效。
  3. B 走统一认证流程并被踢回登录页，不显示为「当前密码错误」（避免混淆认证状态与业务校验）。
