# 用户故事：指令记录排序键与只读约束

> 口径依据：大纲 7.5 章。下发时间 = 首次提交时刻并用于排序；补发只更新最近投递信息，旧记录不置顶；首次提交相同时按稳定次级键；切换时区 / 收到回复仅更新展示字段、不改排序键；查询只读不重发 / 取消 / 改状态。

## [P1] 验证按首次提交时间倒序且补发不置顶
- 测试类型
  - 功能
- 前置条件
  1. 三条记录：R1 首次提交 10:00、R2 11:00、R3 12:00，初始顺序 R3/R2/R1
- 测试步骤
  1. 打开列表记录当前顺序。
  2. 对 R1 触发一次补发，最近投递时间变为 13:00。
  3. 刷新指令记录列表。
  4. 查看 R1 排序位置与时间字段。
- 预期结果
  1. 顺序为 R3/R2/R1（首次提交倒序）。
  2. R1 最近投递时间更新为 13:00。
  3. 刷新成功。
  4. R1 仍在末位，不因补发置顶；下发时间仍为 10:00（排序键不变）。

## [P2] 验证切换 APP 时区只改展示时间不改排序
- 测试类型
  - 功能
- 前置条件
  1. 指令记录列表当前按 Beijing 时区展示，含 R1/R2/R3
- 测试步骤
  1. 记录列表顺序与三条首次提交展示时间。
  2. APP 时区切为 Hawaii（GMT-10:00）。
  3. 重进指令记录页查看顺序与展示时间。
- 预期结果
  1. 记录成功。
  2. 时区切换成功。
  3. 三条展示时间按 Hawaii 转换（可跨日），但顺序完全不变（时区不影响首次提交排序键，US-029 关联边界）。

## [P2] 验证收到设备回复后状态展示更新但排序不变
- 测试类型
  - 功能
- 前置条件
  1. R1 首次提交 10:00、当前 QUEUED/SENT，排在比它更新的 R2 后面
- 测试步骤
  1. 让设备回复 R1，整体状态更新为 COMPLETED、最近结果 ACKED。
  2. 刷新列表。
  3. 查看 R1 状态、回复时间与排序位置。
- 预期结果
  1. 回复完成。
  2. 列表更新。
  3. R1 状态 / 回复时间更新，但仍按首次提交 10:00 原位置排序，不因回复置顶。

## [P3][反向] 验证查询页面只读不产生重发取消或状态修改
- 测试类型
  - 安全性
- 前置条件
  1. 账号 testuser01 有多条不同状态指令记录
  2. 抓包工具就绪
- 测试步骤
  1. 在指令记录页打开 / 滚动 / 筛选 / 清除筛选多次。
  2. 点击记录卡可能的非交互区域。
  3. 查看抓包请求类型与服务端记录状态。
- 预期结果
  1. 仅产生查询请求。
  2. 不触发重发、取消、编辑动作。
  3. 无任何指令状态被修改（页面为只读查询）；「设备离线，发送失败」仅原因展示，不提供新建待执行命令能力。

## [P4] 验证首次提交相同时排序稳定
- 测试类型
  - 可靠性
- 前置条件
  1. 构造 R4、R5 两条记录首次提交时间均为 2026-09-24 12:00:00，接口定义了稳定次级键（如 recordId）
- 测试步骤
  1. 连续刷新列表 10 次。
  2. 每次记录 R4/R5 相对顺序。
  3. 退出重进再次核对。
- 预期结果
  1. 刷新均成功。
  2. R4/R5 相对顺序始终一致（按接口明确次级键）。
  3. 重进后同样稳定，无随机抖动。
