# 用户故事：指令记录两层状态模型

> 口径依据：大纲 7.4 章。整体状态（QUEUED / COMPLETED / REJECTED / CANCELLED / EXPIRED）是筛选依据；最近结果（NOT_SENT / SENT / ACKED / TIMEOUT）独立展示；不能用成功/失败图标合并；整体 QUEUED + 最近 TIMEOUT 必须同时保留两种含义；CR 有回复不等于新位置已更新。

## [P1] 验证整体状态与最近结果分别展示
- 测试类型
  - 功能
- 前置条件
  1. 记录 R1：整体 COMPLETED、最近 ACKED
  2. 记录 R2：整体 QUEUED、最近 SENT
  3. 记录 R3：整体 REJECTED、最近 NOT_SENT
- 测试步骤
  1. 打开指令记录页查看 R1–R3 记录卡。
  2. 核对整体状态与最近结果的展示区域 / 文案。
  3. 检查是否被合并为单一成功 / 失败图标。
- 预期结果
  1. 三条记录正常显示。
  2. 每条的整体状态与最近结果分别表达（两层状态均可见）。
  3. 不合并为单一成功 / 失败图标，不丢失语义。

## [P1] 验证整体 QUEUED + 最近 TIMEOUT 同时展示且按 QUEUED 筛选命中
- 测试类型
  - 功能
- 前置条件
  1. 记录 R4：整体状态 QUEUED、最近一次结果 TIMEOUT
- 测试步骤
  1. 列表查看 R4 状态展示。
  2. 筛选整体状态「已受理/待投递（QUEUED）」并应用。
  3. 核对 R4 是否命中。
  4. 检查是否被误归整体失败。
- 预期结果
  1. R4 同时显示「整体 QUEUED」与「最近 TIMEOUT」。
  2. 查询成功。
  3. R4 出现在 QUEUED 结果中（整体状态是筛选依据）。
  4. 不误归 REJECTED / EXPIRED / 失败类。

## [P2] 验证已投递与已回复语义分离
- 测试类型
  - 功能
- 前置条件
  1. 记录 R5：整体 QUEUED、最近 SENT（已投递无回复）
  2. 记录 R6：整体 COMPLETED、最近 ACKED（有有效回复）
- 测试步骤
  1. 查看 R5 记录卡的最近投递时间、回复时间与结果。
  2. 查看 R6 对应字段。
  3. 比较两者。
- 预期结果
  1. R5 有最近投递时间、无回复时间，结果 SENT（已投递 = 发送动作）。
  2. R6 有投递时间 + 回复时间，结果 ACKED（已回复 = 有效回复）。
  3. 两种状态不混淆、不把已投递文案当作已回复。

## [P3][反向] 验证 CR 指令有回复不宣称新位置已更新
- 测试类型
  - 功能
- 前置条件
  1. 有一条 CR 指令已收到协议回复（最近结果 ACKED），但设备尚未产生新的定位上报
- 测试步骤
  1. 查看该 CR 指令记录卡。
  2. 查看监控页最新位置时间。
  3. 核对页面文案是否宣称已获取新位置。
- 预期结果
  1. 记录仅表达指令已有有效回复。
  2. 最新位置仍为旧上报时间（直至新定位数据真正到达）。
  3. 不据 ACKED 回复宣称「已获取新位置」（协议回复 ≠ 新位置已更新）。
