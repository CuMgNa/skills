# US-034-C 归属隔离与联动

> 口径依据：指令记录大纲 §5。记录数据归属 = 下发账号 + 设备 ID，可见性跟随入口：设备解绑后批量记录仍可查，L2 中该设备明细保留、操作按钮隐藏、卡片标记“已解绑 / 无权限”；设备指令记录在 APP 内不可达（入口挂在设备上），数据仅后台保留；原账号重新绑定同设备恢复历史（下发账号 + 设备 ID 双匹配）；换新账号绑定同设备看不到旧账号记录；查看保留、操作拦截，存量操作由服务端复核兜底拒绝。
>
> 数据约定：GT-REC-E1 对 D001 通过 Send Command 下发过 R-S1（已发送）、R-S2（失败），并在批量记录 B-E1 中对 D001、D003 下发过上报间隔 600 秒（D001 失败、D003 失败）。

## [P1] 验证设备解绑后批量页仍可查且明细保留
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-E1 已将 D001 解绑，D003 仍绑定
- 测试步骤
  1. 进入“我的 → 批量下发指令记录”，查看 L1 是否仍有 B-E1。
  2. 点击 B-E1 进入 L2，查看 D001 与 D003 明细。
- 预期结果
  1. L1 仍显示 B-E1，台数仍为“2台”。
  2. L2 仍有 D001、D003 两张卡，D001 状态与失败原因、时间等字段保持解绑前内容。

## [P1] 验证解绑设备明细操作按钮隐藏并标记已解绑或无权限
- 测试类型
  - 功能
- 前置条件
  1. B-E1 中 D001 失败、D003 失败；D001 已解绑，D003 仍绑定
- 测试步骤
  1. 进入 B-E1 的 L2，查看 D001 卡片。
  2. 查看 D003 卡片。
- 预期结果
  1. D001 卡片显示“已解绑 / 无权限”标记，无“重新发送”按钮，字段仍完整展示。
  2. D003 卡片无该标记，保留“重新发送”按钮。

## [P1] 验证解绑设备发送中卡片同样隐藏取消按钮
- 测试类型
  - 功能
- 前置条件
  1. 批量记录 B-E2 中 D001 为发送中；随后 D001 被 GT-REC-E1 解绑
- 测试步骤
  1. 进入 B-E2 的 L2，查看 D001 卡片。
- 预期结果
  1. D001 卡片显示“已解绑 / 无权限”标记，无“取消发送”按钮，状态仍为发送中。

## [P1][反向] 验证解绑后设备指令记录在APP内不可达
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-E1 已解绑 D001
- 测试步骤
  1. 进入设备管理设备列表，查找 D001。
  2. 在设备列表中检索全部入口，寻找 D001 的设备指令记录页入口。
  3. 通过后台查询 D001 在 GT-REC-E1 名下的单设备记录。
- 预期结果
  1. 设备列表中无 D001。
  2. APP 内无任何入口可进入 D001 的设备指令记录页。
  3. 后台仍可查到 R-S1、R-S2，数据未被清理。

## [P1] 验证原账号重新绑定同设备恢复设备指令记录
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-E1 已解绑 D001，随后用同一账号重新绑定 D001
- 测试步骤
  1. 进入 D001 的设备指令记录页，查看卡片。
  2. 进入批量 L1，查看 B-E1。
- 预期结果
  1. R-S1、R-S2 恢复显示，状态、时间、失败原因与解绑前一致。
  2. B-E1 仍显示，D001 明细不再标记“已解绑 / 无权限”，失败卡恢复“重新发送”按钮。

## [P1][反向] 验证换新账号绑定同设备看不到旧账号记录
- 测试类型
  - 安全性
- 前置条件
  1. GT-REC-E1 已解绑 D001；GT-REC-P02 绑定 D001，且 P02 未对 D001 下发过指令
- 测试步骤
  1. 使用 GT-REC-P02 登录，进入 D001 设备指令记录页。
  2. 进入批量 L1。
- 预期结果
  1. 页面显示“暂无指令记录”，不含 R-S1、R-S2。
  2. 批量 L1 不含 B-E1。

## [P2] 验证新账号绑定后原账号重新绑定仍恢复自己的记录
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-E1 已解绑 D001；GT-REC-P02 绑定 D001 并下发 1 条查找设备（R-P2）
  2. P02 解绑 D001 后 GT-REC-E1 重新绑定 D001
- 测试步骤
  1. 使用 GT-REC-E1 登录，进入 D001 设备指令记录页。
- 预期结果
  1. 仅显示 R-S1、R-S2，不含 R-P2。

## [P1][反向] 验证页面打开期间解绑后批量L2存量操作被拒
- 测试类型
  - 安全性
- 前置条件
  1. GT-REC-E1 停留在 B-E1 的 L2，D001 失败、D003 发送中；页面打开期间 D001 被 E1 在另一终端解绑
- 测试步骤
  1. 点击 D001 卡片的“重新发送”（页面尚未刷新，按钮仍在）并确认。
  2. 查看提示与 D001 状态。
  3. 点击 D003 卡片的“取消发送”并确认。
- 预期结果
  1. 请求提交至服务端。
  2. 服务端复核拒绝，提示无权限，D001 保持“失败”，不新增 attempt。
  3. D003 仍绑定，取消正常提交并先置为已取消，不受 D001 解绑影响。

## [P2] 验证上级撤回分配后下级失权设备明细保留但不可操作
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-E2 在批量 B-E2U 中对 D001、D003 下发过指令，D001 失败；随后 GT-REC-E1 撤回对 E2 的 D001 分配，D003 仍分配
- 测试步骤
  1. 使用 GT-REC-E2 登录，进入 B-E2U 的 L2，查看 D001 与 D003。
  2. 进入 E2 的 D001 设备指令记录页入口检查。
- 预期结果
  1. D001 明细保留，操作按钮隐藏，标记“已解绑 / 无权限”；D003 无标记，按钮按状态正常显示。
  2. D001 已不在 E2 的设备列表，APP 内无入口进入其设备指令记录页。
