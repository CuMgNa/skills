# US-034-C 归属隔离与联动

> 口径依据：指令记录大纲 §7。批量 L1 统计与 L2 明细允许短暂不一致、最终一致，CANCEL → SENT 时取消数 -1、已发送数 +1，重复回调不重复计数；指令状态仅依赖契约四态（发送中/已发送/失败/已取消），出现契约外状态属后端缺陷；服务过期设备记录正常展示，记录内不提供新的下发入口；长期 SENDING 普通五类记录正常显示、取消恒可用；回文按 businessId → attemptId → commandId 关联，无法可靠关联时只展示反馈内容，旧 attempt 回文不得覆盖更新目标；大批量设备卡分页/按需加载，一键重发按钮固定在可见区；反馈内容与发送状态分离。同步时限数值待后端确认，用例按“同步时限内最终一致”断言。

## [P1] 验证L1统计与L2明细在同步时限内最终一致
- 测试类型
  - 可靠性
- 前置条件
  1. GT-REC-E1 批量下发 5 台（D001～D005）上报间隔 600 秒，当前 3 台已发送、1 台发送中、1 台失败
- 测试步骤
  1. 进入 L1，查看该记录统计。
  2. 进入 L2，统计 5 张设备卡各状态数量。
  3. 对发送中的 1 台取消并确认，等待至同步时限，返回 L1 查看统计。
- 预期结果
  1. L1 统计为“发送中 1 · 已发送 3 · 失败 1 · 已取消 0”。
  2. L2 各状态数量与 L1 一致：发送中 1、已发送 3、失败 1、已取消 0。
  3. 同步时限内 L1 统计更新为“发送中 0 · 已发送 3 · 失败 1 · 已取消 1”，且与 L2 各状态数量一致。

## [P1] 验证CANCEL回写SENT时L1取消数减1已发送数加1
- 测试类型
  - 可靠性
- 前置条件
  1. 批量记录 B-C1 的 L1 统计为“发送中 1 · 已发送 1 · 失败 0 · 已取消 0”，发送中设备 D001 被取消后 L1 统计为“发送中 0 · 已发送 1 · 失败 0 · 已取消 1”；网关随后回写 D001 为已发送
- 测试步骤
  1. 等待同步时限后进入 L1，查看统计。
  2. 通过测试桩对该回写重复投递 3 次，再次进入 L1 查看统计。
- 预期结果
  1. L1 统计为“发送中 0 · 已发送 2 · 失败 0 · 已取消 0”。
  2. 统计保持“发送中 0 · 已发送 2 · 失败 0 · 已取消 0”，不重复计数，台数总和仍为 2。

## [P1] 验证接口返回状态仅在四态契约内
- 测试类型
  - 兼容性
- 前置条件
  1. GT-REC-E1 的批量与单设备记录覆盖发送中、已发送、失败、已取消各状态，且存在重发与取消修正的记录
- 测试步骤
  1. 抓取 L1 列表、L2 明细、设备指令记录列表三类接口的响应。
  2. 遍历响应中所有记录和设备明细的状态字段值。
- 预期结果
  1. 接口响应成功。
  2. 所有状态值均属于 SENDING、SENT、FAILURE、CANCEL 四态之一；若出现其他值，判定为后端缺陷并记录缺陷，APP 不应定义“未知状态”展示。

## [P2] 验证服务过期设备记录正常展示且无新的下发入口
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-E1 的 D003 服务已过期，此前通过 Send Command 下发过 R-EXP，并在批量记录 B-EXP 中下发过
- 测试步骤
  1. 进入 D003 设备指令记录页，查看 R-EXP。
  2. 进入 B-EXP 的 L2，查看 D003 明细。
  3. 查看两个页面内是否有新的下发指令入口。
- 预期结果
  1. R-EXP 正常展示，字段完整。
  2. D003 明细正常展示，字段完整。
  3. 两个页面内均无新建下发指令的入口。

## [P2] 验证长期发送中普通指令记录正常显示且取消可用
- 测试类型
  - 稳定性
- 前置条件
  1. GT-REC-E1 对离线 D004 下发的设置上传间隔记录 R-WAIT 已排队 20 天，状态发送中
- 测试步骤
  1. 进入 D004 设备指令记录页，查看 R-WAIT。
  2. 点击“取消发送”并确认。
- 预期结果
  1. R-WAIT 正常显示“发送中”，创建时间为 20 天前，按钮为“取消发送”。
  2. R-WAIT 先置为“已取消”。

## [P1] 验证重发后旧attempt的迟到回文不覆盖新attempt
- 测试类型
  - 可靠性
- 前置条件
  1. D001 的记录 R-ATT 首个 attempt（A1，businessId=BIZ-A1）已发送，用户随后重发产生 A2（businessId=BIZ-A2），卡片显示 A2 的状态“已发送”，发送时间 2026-10-12 15:20:05，反馈内容“—”
- 测试步骤
  1. 通过测试桩投递 A1 的迟到回文“OLD-REPLY”（businessId=BIZ-A1）。
  2. 下拉刷新，查看 R-ATT 卡片。
  3. 投递 A2 的回文“NEW-REPLY”（businessId=BIZ-A2）。
  4. 再次下拉刷新，查看 R-ATT 卡片。
- 预期结果
  1. 回文被后端归入 A1，不更新当前展示的最新 attempt。
  2. 卡片反馈内容仍为“—”，不显示“OLD-REPLY”，发送时间仍为“2026-10-12 15:20:05”。
  3. 回文归入 A2。
  4. 卡片反馈内容显示“NEW-REPLY”，反馈时间为 A2 回文时间。

## [P2] 验证无法可靠关联的回文只展示不更新确认值
- 测试类型
  - 安全性
- 前置条件
  1. D001 当前确认值为 10 分钟；设备指令记录页有一条发送中的 UPLOAD 3600 秒记录 R-UP；设备发来一条无法通过 businessId 可靠关联的回文“ACK-UNKNOWN”
- 测试步骤
  1. 投递该回文。
  2. 查看设备详情页定位频率与 R-UP 卡片。
- 预期结果
  1. 回文被后端接收。
  2. 详情页定位频率仍显示确认值 10 分钟（目标值继续标记“设置中”），确认值未被该回文更新；R-UP 状态不因回文改变，回文仅作为反馈内容展示。

## [P2] 验证反馈内容与发送状态分离
- 测试类型
  - 功能
- 前置条件
  1. D001 的记录 R-FB 已发送，写出时间 2026-10-12 15:00:23，暂无回文
- 测试步骤
  1. 查看 R-FB 卡片状态与反馈内容。
  2. 投递成功关联的回文“OK”，下拉刷新后再次查看。
- 预期结果
  1. 状态“已发送”，反馈内容“—”。
  2. 状态仍为“已发送”，反馈内容“OK”，反馈时间显示回文到达时间，发送时间不变。

## [P2] 验证大批量设备卡分页加载且一键重发按钮固定
- 测试类型
  - 性能
- 前置条件
  1. GT-REC-E1 批量下发 200 台设备，其中 30 台失败
- 测试步骤
  1. 进入该批次 L2，观察首屏加载。
  2. 持续上滑到底。
  3. 查看底部“重发全部失败”按钮。
- 预期结果
  1. 首屏按分页大小加载卡片，不一次性加载 200 张，响应在可接受时间内且页面不卡死。
  2. 追加加载直至 200 张全部可见，无重复无遗漏。
  3. 按钮始终固定在可见区，显示“重发全部失败（30）”。
