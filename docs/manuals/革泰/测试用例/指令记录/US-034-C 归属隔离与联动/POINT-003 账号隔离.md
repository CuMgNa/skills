# US-034-C 归属隔离与联动

> 口径依据：指令记录大纲 §2.4。两页均只能看到当前登录账号自己下发的记录；父级看不到下级发的，下级看不到父级发的，个人与企业互不可见，企业树不做记录共享；记录归属 = 下发账号 + 设备 ID，换账号绑定设备不继承历史。
>
> 数据约定：账号 GT-REC-E1（企业一级）→ GT-REC-E2（二级）→ GT-REC-E3（三级）逐级分配 GT-REC-D001；个人账号 GT-REC-P01 同时绑定 GT-REC-D001（个人 + 企业一级双槽位）。

## [P1][反向] 验证个人账号看不到企业账号下发的记录
- 测试类型
  - 安全性
- 前置条件
  1. GT-REC-E1 对 D001 通过 Send Command 下发 1 条查询版本（R-E1S），并通过批量流程对 D001 下发 1 条上报间隔 600 秒（R-E1B）
  2. GT-REC-P01 对 D001 通过 Send Command 下发 1 条查找设备（R-P1S），并通过批量流程下发 1 条上报间隔 300 秒（R-P1B）
- 测试步骤
  1. 使用 GT-REC-P01 登录，进入 D001 设备指令记录页。
  2. 进入“我的 → 批量下发指令记录”。
  3. 退出后使用 GT-REC-E1 登录，进入 D001 设备指令记录页并进入批量 L1。
- 预期结果
  1. 设备指令记录页仅显示 R-P1S，不显示 R-E1S。
  2. 批量 L1 仅显示 R-P1B，不显示 R-E1B。
  3. 设备指令记录页仅显示 R-E1S，批量 L1 仅显示 R-E1B，均不含 P01 的记录。

## [P1][反向] 验证企业父级与下级账号互不可见
- 测试类型
  - 安全性
- 前置条件
  1. GT-REC-E1、E2、E3 均对 D001 各通过 Send Command 下发 1 条记录（分别为 R-E1、R-E2、R-E3），并各自通过批量流程下发 1 条记录（分别为 B-E1、B-E2、B-E3）
- 测试步骤
  1. 使用 GT-REC-E1 登录，查看 D001 设备指令记录页与批量 L1。
  2. 使用 GT-REC-E2 登录，查看 D001 设备指令记录页与批量 L1。
  3. 使用 GT-REC-E3 登录，查看 D001 设备指令记录页与批量 L1。
- 预期结果
  1. E1 仅看到 R-E1 与 B-E1，看不到下级 E2、E3 的记录。
  2. E2 仅看到 R-E2 与 B-E2，看不到父级 E1 和下级 E3 的记录。
  3. E3 仅看到 R-E3 与 B-E3，看不到上级 E1、E2 的记录。

## [P1] 验证换账号登录不继承上一账号的页面数据
- 测试类型
  - 安全性
- 前置条件
  1. 同一手机，GT-REC-E1 已查看过 D001 设备指令记录页与批量 L1
- 测试步骤
  1. 退出 GT-REC-E1，使用 GT-REC-P01 登录。
  2. 立即进入 D001 设备指令记录页，观察首屏加载过程。
  3. 进入批量 L1，观察首屏加载过程。
- 预期结果
  1. 登录成功，回到设备列表。
  2. 加载过程中不闪现 E1 的记录，最终仅显示 P01 自己的记录。
  3. 加载过程中不闪现 E1 的批量记录，最终仅显示 P01 自己的批量记录。

## [P1][反向] 验证越权接口不返回他人记录
- 测试类型
  - 安全性
- 前置条件
  1. GT-REC-E1 的批量记录 B-E1（batchId 为 BATCH-E1-001）和单设备记录 R-E1（commandId 为 CMD-E1-001）存在
  2. GT-REC-P01 已登录，持有自己的有效 token
- 测试步骤
  1. 使用 P01 的 token 调用批量记录详情接口，传入 BATCH-E1-001。
  2. 使用 P01 的 token 调用设备指令记录列表接口，传入 D001 的设备 ID，查询范围包含 R-E1。
  3. 使用 P01 的 token 调用记录详情接口，传入 CMD-E1-001。
- 预期结果
  1. 接口拒绝或返回空，不返回 B-E1 的任何设备明细。
  2. 返回结果只含 P01 自己的记录，不含 R-E1。
  3. 接口拒绝或返回空，不返回 R-E1 的任何字段。

## [P1][反向] 验证越权取消与重发被服务端拒绝
- 测试类型
  - 安全性
- 前置条件
  1. GT-REC-E1 的批量记录 B-E1 中 D001 为发送中（CMD-E1-001）、D003 为失败（CMD-E1-002）
  2. GT-REC-E2 已登录，持有有效 token
- 测试步骤
  1. 使用 E2 的 token 调用取消接口，传入 CMD-E1-001。
  2. 使用 E2 的 token 调用单台重发接口，传入 CMD-E1-002。
  3. 查看 E1 账号下该两条记录状态。
- 预期结果
  1. 请求被拒绝，返回无权限。
  2. 请求被拒绝，返回无权限，未创建新 attempt。
  3. CMD-E1-001 仍为发送中，CMD-E1-002 仍为失败，重发次数不变。

## [P2] 验证同账号不同设备记录各归各设备页
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-E1 对 D001 通过 Send Command 下发 2 条记录，对 D003 通过 Send Command 下发 1 条记录
- 测试步骤
  1. 进入 D001 设备指令记录页，查看记录数。
  2. 进入 D003 设备指令记录页，查看记录数。
- 预期结果
  1. D001 页显示 2 条。
  2. D003 页显示 1 条，且不含 D001 的记录。

## [P2] 验证账号切换后筛选条件与列表状态不残留
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-E1 在 D001 设备指令记录页应用筛选“状态=失败”，并在批量 L2 应用筛选“卡号精确 106480001234”
  2. GT-REC-P01 对 D001 已有至少 1 条单设备记录和 1 条批量记录
- 测试步骤
  1. 退出 GT-REC-E1，使用 GT-REC-P01 登录。
  2. 进入 D001 设备指令记录页，打开筛选弹窗。
  3. 进入任意批量 L2，打开筛选弹窗。
- 预期结果
  1. 登录成功。
  2. 筛选弹窗为空，列表显示 P01 的全部记录。
  3. 筛选弹窗为空，无 E1 的卡号条件残留。
