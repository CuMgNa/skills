# US-034-B 设备指令记录

> 口径依据：指令记录大纲 §4.5。沿用批量操作语义，两处差异：无“一键重发全部失败”；操作经服务端复核权限与设备状态。取消：发送中恒可取消 + 二次确认 + 乐观取消 + 局部更新；取消未生效修正为已发送并提示“取消未生效，指令已下发”，RESET/POWEROFF 高优先级提醒；重发：仅失败卡、二次确认、后台新增 attempt、前台原地更新 + “已重发 N 次”、普通五类离线可重发、高危两类按钮可点但服务端复检、创建时间不变、无次数上限；确认后按钮 loading 防重；接口失败回滚 + Toast。
>
> 数据约定：GT-REC-D001 在线，GT-REC-D004 离线；记录以 Send Command 下发。

## [P1] 验证取消发送二次确认选否不改变状态
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-D001 有 1 条发送中的设置上传间隔记录 R1
- 测试步骤
  1. 点击 R1 的“取消发送”。
  2. 点击确认弹窗的取消（选否）。
- 预期结果
  1. 弹出二次确认弹窗，未直接提交取消。
  2. 弹窗关闭，R1 仍为“发送中”，保留“取消发送”按钮，未发起取消请求。

## [P1] 验证取消确认后卡片先置已取消且网关确认未写出则维持
- 测试类型
  - 功能
- 前置条件
  1. R1 发送中，网关确认未写出且队列删除成功
- 测试步骤

- 预期结果

  2. R1 先局部更新为“已取消”，无按钮，其他卡片不重载。
  3. R1 维持“已取消”，发送时间“—”。

## [P2] 验证取消与重发loading防重
- 测试类型
  - 可靠性
- 前置条件
  1. 取消与重发接口响应延迟 3 秒；GT-REC-D001 有发送中记录 R1 和失败记录 R4
- 测试步骤
  1. 点击 R1 的“取消发送”并确认，响应返回前连续点击 3 次。
  2. 点击 R4 的“重新发送”并确认，响应返回前连续点击 3 次。
- 预期结果
  1. 仅发出 1 次取消请求，R1 最终为“已取消”。
  2. 仅发出 1 次重发请求，仅新增 1 个 attempt，R4 标记为“已重发 1 次”。

## [P1][反向] 验证页面打开期间设备被解绑后存量操作被拒
- 测试类型
  - 安全性
- 前置条件
  1. GT-REC-E1 停留在 GT-REC-D001 的设备指令记录页，页面有发送中记录 R1 与失败记录 R4
  2. 页面打开期间，GT-REC-D001 被 GT-REC-E1 在另一终端解绑
- 测试步骤
  1. 点击 R1 的“取消发送”并确认。
  2. 点击 R4 的“重新发送”并确认。
  3. 通过后台查看两条记录。
- 预期结果
  1. 服务端复核后拒绝，提示无权限，R1 保持“发送中”（回滚）。
  2. 服务端复核后拒绝，提示无权限，R4 保持“失败”，不新增 attempt。
  3. 两条记录状态未被修改，无新的取消请求或重发 attempt。
