# US-034-B 设备指令记录

> 口径依据：指令记录大纲 §4.3。范围仅当前账号通过单设备入口对该设备下发的记录；创建时间倒序，同秒按服务端返回序列（前端不自排）；进入页面刷新 + 下拉刷新；后台恢复刷新并接收迟到状态修正；上滑分页；下拉刷新保留当前筛选；离开页面筛选清空；新记录下发确认后立即可见；新记录初始状态以后端返回为准。

## [P1] 验证列表范围仅含单设备入口下发的记录
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-E1 对 GT-REC-D001：通过 Send Command 下发 1 条查询版本（R-S1），通过设备详情定位频率保存 1 条 UPLOAD 300 秒（R-S2），通过批量流程下发 1 条上报间隔 600 秒且包含 D001、D003（R-B1）
  2. GT-REC-E1 对 GT-REC-D003 另有 Send Command 记录 R-S3
- 测试步骤
  1. 进入 GT-REC-D001 的设备指令记录页，查看卡片。
  2. 进入 GT-REC-D003 的设备指令记录页，查看卡片。
- 预期结果
  1. D001 页仅显示 R-S1、R-S2 两张卡，不显示 R-B1。
  2. D003 页仅显示 R-S3 一张卡，不显示 R-B1，也不显示 D001 的记录。

## [P1] 验证按创建时间倒序排列
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-D001 有 3 条记录，创建时间分别为 2026-10-12 15:00:21（R1）、2026-10-12 15:05:40（R2）、2026-10-12 14:50:10（R3）
- 测试步骤
  1. 进入设备指令记录页，查看卡片顺序。
  2. 下拉刷新后再次查看顺序。
- 预期结果
  1. 顺序为 R2、R1、R3。
  2. 刷新后顺序仍为 R2、R1、R3。

## [P2] 验证同秒记录按服务端返回序且前端不自排
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-D001 有 2 条创建时间同为 2026-10-12 15:00:21 的记录 RX、RY，接口返回顺序为 RX、RY
- 测试步骤
  1. 进入设备指令记录页，查看 RX、RY 顺序。
  2. 通过测试桩将接口返回顺序调换为 RY、RX，下拉刷新后查看。
- 预期结果
  1. 页面顺序与接口返回一致：RX 在前、RY 在后。
  2. 页面顺序随接口调整为 RY 在前、RX 在后，前端不按状态、内容或本地 ID 自行重排。

## [P1] 验证进入页面与下拉刷新均拉取最新数据
- 测试类型
  - 功能
- 前置条件
  1. 已进入 GT-REC-D001 的设备指令记录页，页面显示 2 条记录
  2. 同一账号可在另一终端对 GT-REC-D001 执行 Send Command（用于新增记录）
- 测试步骤
  1. 点击返回回到单设备下发页。
  2. 在另一终端对 GT-REC-D001 下发 1 条查询版本（R-NEW1）。
  3. 在本终端点击底部“指令记录”重新进入。
  4. 在另一终端再下发 1 条查找设备（R-NEW2），本终端在记录页执行下拉刷新。
- 预期结果
  1. 返回下发页。
  2. 另一终端提交成功。
  3. 进入页面即刷新，显示 3 条记录，R-NEW1 置顶。
  4. 下拉刷新后显示 4 条记录，R-NEW2 置顶，R-NEW1 次之。

## [P1] 验证后台恢复刷新并接收迟到状态修正
- 测试类型
  - 可靠性
- 前置条件
  1. GT-REC-D001 的记录 R1 发送中，用户取消后卡片显示已取消；网关实际已写出，后台将 R1 回写为已发送，APP 此时在后台
- 测试步骤
  1. 将 APP 切到后台 1 分钟后切回前台，停留在设备指令记录页。
  2. 查看 R1 卡片与提示。
  3. 另一条已取消记录 R2 在页面停留期间被后台修正为已发送，等待推送或轮询周期。
- 预期结果
  1. 切回前台时页面自动刷新。
  2. R1 显示“已发送”和实际发送时间，提示“取消未生效，指令已下发”。
  3. R2 在推送到达或下一轮询周期后自动更新为已发送，不长期停留在已取消。

## [P2] 验证上滑分页无重复无遗漏
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-D001 有 45 条记录，创建时间严格不同，接口分页大小以当前契约为准
- 测试步骤
  1. 进入设备指令记录页，查看首屏。
  2. 持续上滑到底，触发后续分页，直至无更多数据。
- 预期结果
  1. 首屏按分页大小加载卡片，底部有加载提示。
  2. 每次上滑追加下一页，直至 45 条全部加载，无重复、无遗漏，整体按创建时间倒序。

## [P1] 验证下拉刷新保留当前筛选条件
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-D001 有失败记录 2 条、已发送记录 3 条；已应用筛选“状态=失败”，列表显示 2 条
- 测试步骤
  1. 下拉刷新。
  2. 查看列表。
  3. 打开筛选弹窗查看回显。
- 预期结果
  1. 刷新按当前筛选重新查询。
  2. 列表仍仅显示 2 条失败记录，不恢复为全部 5 条。
  3. 弹窗回显状态“失败”。

## [P1] 验证离开页面后筛选清空
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-D001 有失败记录 2 条、已发送记录 3 条；已应用筛选“状态=失败”
- 测试步骤
  1. 点击返回回到单设备下发页。
  2. 再次点击底部“指令记录”进入。
  3. 查看列表和筛选弹窗。
- 预期结果
  1. 返回下发页。
  2. 重新进入设备指令记录页。
  3. 列表显示全部 5 条记录，筛选弹窗为空，无历史条件残留。

## [P1] 验证下发确认后新记录立即可见并置顶
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-D001 在线，记录页已有 2 条记录
- 测试步骤
  1. 在单设备下发页提交“查找设备”指令并确认成功受理。
  2. 点击底部“指令记录”进入。
  3. 查看第一张卡。
- 预期结果
  1. 提交成功，Toast 提示后停留在下发页。
  2. 进入设备指令记录页，无需手动刷新。
  3. 第一张卡为刚下发的“查找设备”记录，创建时间为本次提交时间，其余 2 条记录顺延。

## [P2] 验证新记录初始状态以后端返回为准
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-D001 在线，通过测试桩使下一次“查询版本”在提交返回时已快速流转为已发送（写出时间 2026-10-12 15:00:23）
  2. 通过测试桩使再下一次“查找设备”在提交返回时已直接为失败（原因“当前型号不支持该指令”）
- 测试步骤
  1. 提交“查询版本”后进入设备指令记录页，查看新卡状态。
  2. 提交“查找设备”后进入设备指令记录页，查看新卡状态。
- 预期结果
  1. 新卡状态显示“已发送”，发送时间“2026-10-12 15:00:23”，不强制显示“发送中”。
  2. 新卡状态显示“失败”，失败原因“当前型号不支持该指令”，按钮为“重新发送”。
