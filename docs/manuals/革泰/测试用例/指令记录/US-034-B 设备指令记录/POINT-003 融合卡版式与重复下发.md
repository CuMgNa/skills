# US-034-B 设备指令记录

> 口径依据：指令记录大纲 §4.2 版式口径。卡片高度不固定、内容不截断，任何文字字段超出宽度完整换行（与批量 L1 行 1 的两行截断不同）；反馈内容超长默认收起，点击在卡内原地展开/收起，是唯一有折叠机制的字段；重复下发（含相同指令相同参数）各自独立成卡，不合并。折叠阈值字数不写死，仅用明显超长/明显短文本验证。

## [P1] 验证文字字段超长完整换行不截断
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-D001 有 1 条失败记录，失败原因为 150 个字符的文本，结尾为“END-OF-REASON”
  2. GT-REC-D001 有 1 条设置设备时区记录，指令内容含较长语义文本
- 测试步骤
  1. 进入设备指令记录页，查看失败卡的失败原因。
  2. 查看设置设备时区卡的指令内容。
  3. 对比不同卡片高度。
- 预期结果
  1. 失败原因完整换行显示，可见结尾“END-OF-REASON”，不出现省略号截断。
  2. 指令内容完整换行显示，不出现省略号截断。
  3. 各卡片高度随内容自适应，不固定，不出现“最多两行”截断。

## [P1] 验证反馈内容超长默认收起并可展开收起
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-D001 有 1 条已发送记录，回文为 400 个字符，结尾为“END-OF-FEEDBACK”
- 测试步骤
  1. 进入设备指令记录页，查看该卡反馈内容。
  2. 点击反馈内容的展开控件或文本区域。
  3. 再次点击收起。
- 预期结果
  1. 反馈内容默认收起，仅显示部分文本，“END-OF-FEEDBACK”不可见，有展开提示。
  2. 卡内原地展开，显示全文含“END-OF-FEEDBACK”，页面不跳转，列表其他卡片位置顺延。
  3. 反馈内容恢复收起状态。

## [P2] 验证短反馈内容无展开控件
- 测试类型
  - 易用性
- 前置条件
  1. GT-REC-D001 有 1 条已发送记录，回文为“OK”
- 测试步骤
  1. 进入设备指令记录页，查看该卡反馈内容。
  2. 点击反馈内容文本。
- 预期结果
  1. 反馈内容完整显示“OK”，无展开/收起控件。
  2. 卡片无变化。

## [P2] 验证仅反馈内容有折叠机制
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-D001 有 1 条失败记录，失败原因 150 个字符；另有 1 条已发送记录，回文 400 个字符
- 测试步骤
  1. 进入设备指令记录页，查看失败卡的失败原因是否有展开控件。
  2. 查看已发送卡的反馈内容。
- 预期结果
  1. 失败原因全文直接显示，无展开/收起控件。
  2. 仅反馈内容存在展开/收起机制。

## [P1] 验证重复下发相同指令相同参数各自独立成卡
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-D001 在线，记录页当前为空
- 测试步骤
  1. 通过 Send Command 向 GT-REC-D001 连续 3 次下发“设置上传间隔 600 秒”，每次确认并成功提交。
  2. 进入设备指令记录页，查看卡片数量与内容。
  3. 对比 3 张卡的创建时间。
- 预期结果
  1. 3 次提交均成功受理。
  2. 页面显示 3 张独立卡片，指令类型与内容均为“设置上传间隔 / 上报间隔 600 秒”，未合并为 1 张。
  3. 3 张卡创建时间各自为各次提交时间，按倒序排列。

## [P3] 验证失败原因与反馈内容同时超长时布局不遮挡按钮
- 测试类型
  - 兼容性
- 前置条件
  1. GT-REC-D001 有 1 条失败记录，失败原因 150 个字符，已重发 3 次
- 测试步骤
  1. 在小屏设备（宽度 360dp）上进入设备指令记录页，查看该卡。
  2. 滚动到该卡底部。
- 预期结果
  1. 卡片内文字完整换行，不超出卡片边界。
  2. “已重发 3 次”标记和“重新发送”按钮完整可见、可点击，未被文字遮挡。
