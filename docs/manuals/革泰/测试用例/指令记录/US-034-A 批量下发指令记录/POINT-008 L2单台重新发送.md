# US-034-A 批量下发指令记录

> 口径依据：指令记录大纲 §3.4 重新发送（单台）。仅失败卡片有按钮；二次确认；原地更新（页面不新增记录），commandId 不变，后台生成新 attemptId 并由 S10U 分配 businessId；失败 → 发送中 → 已发送/失败；卡片保留“已重发 N 次”；创建时间不变；新 attempt 写出时更新 sentAt，写出前失败则发送时间保持“—”并更新 failedAt；反馈内容/反馈时间/失败原因只展示最新值；普通五类离线也可重发；高危两类按钮保持可点，确认后服务端复检当前可写会话，失败直接 FAILURE 且次数增加；复用首次校验；无次数上限；loading 防重。
>
> 数据约定：BATCH-H01 为上报间隔 600 秒 3 台，创建时间 2026-10-12 15:00:21；D004=106480003456（离线、失败，原因“S10U 路由缺失，无法下发”）、D005=106480007890（在线、失败，失败时间 15:00:25）、D003 已发送。BATCH-H02 为“重启设备”（RESET）2 台：D001 在线失败、D004 离线失败。

## [P1] 验证失败卡片才有重新发送按钮
- 测试类型
  - 功能
- 前置条件
  1. BATCH-H01 含失败、发送中、已发送、已取消四种状态的设备各 1 台
- 测试步骤
  1. 进入 BATCH-H01 的 L2，逐张查看四种状态卡片的按钮。
- 预期结果
  1. 仅失败卡片显示“重新发送”；发送中显示“取消发送”；已发送、已取消无任何按钮。

## [P1] 验证重发后原卡更新不新增记录且创建时间不变
- 测试类型
  - 功能
- 前置条件
  1. BATCH-H01 的 D005 失败，D005 在线，L1 中仅有该一条 BATCH-H01 记录
- 测试步骤
  1. 点击 D005 的“重新发送”并确认。
  2. 查看 D005 卡片、汇总卡。
  3. 等待 D005 变为已发送（写出时间 2026-10-12 15:20:05），查看卡片。
  4. 返回 L1，查看列表条数和 BATCH-H01 的创建时间。
- 预期结果
  1. 重发请求提交。
  2. D005 在原卡上由“失败”变为“发送中”，设备卡数量保持 3 张，汇总卡发送中数加 1、失败数减 1，卡片出现“已重发 1 次”。
  3. D005 显示“已发送”，发送时间“2026-10-12 15:20:05”，保留“已重发 1 次”，不再显示失败原因，无按钮。
  4. L1 不新增记录，BATCH-H01 创建时间仍为“2026-10-12 15:00:21”。

## [P2] 验证重发loading防重
- 测试类型
  - 可靠性
- 前置条件
  1. 重发接口响应延迟 3 秒，D005 失败
- 测试步骤
  1. 点击“重新发送”并确认。
  2. 在响应返回前快速连续点击同一卡片 3 次。
  3. 查看实际发出的重发请求数和重发标记。
- 预期结果
  1. 重发请求提交，卡片进入 loading 或不可操作态。
  2. 后续点击无响应，不弹出重复确认。
  3. 仅发出 1 次重发请求，仅新增 1 个 attempt，标记为“已重发 1 次”。
