# US-034-A 批量下发指令记录

> 口径依据：指令记录大纲 §3.4 取消发送。仅发送中卡片有“取消发送”；恒可取消（无时间窗口）；二次确认；乐观取消：点取消后卡片先置“已取消”（表示取消请求进入处理，不代表绝对未写出）；网关确认未写出且删除成功则维持已取消；实际已写出则回调修正为已发送，并提示“取消未生效，指令已下发”；RESET/POWEROFF 使用高优先级提醒并说明设备仍可能执行；取消后先局部更新设备卡，迟到修正后再更新卡片、筛选结果和 L1 汇总；后台保留 cancelRequestedAt / cancelResolvedAt / cancelOutcome / statusCorrectedAt。
>
> 数据约定：BATCH-G01 为上报间隔 600 秒（UPLOAD）3 台，D001=106480001234 发送中、D002=106480005678 发送中、D003=106480009012 已发送；BATCH-G02 为“重启设备”（RESET）2 台，D001 发送中、D003 发送中。

## [P1] 验证取消发送二次确认选否不改变状态
- 测试类型
  - 功能
- 前置条件
  1. 已进入 BATCH-G01 的 L2，GT-REC-D001 发送中
- 测试步骤
  1. 点击 D001 卡片的“取消发送”。
  2. 查看确认弹窗。
  3. 点击取消（选否）关闭弹窗。
  4. 查看 D001 卡片和汇总卡。
- 预期结果
  1. 弹出二次确认弹窗。
  2. 弹窗提供确认与取消两个选项，不直接提交取消请求。
  3. 弹窗关闭，未发起取消请求。
  4. D001 仍为“发送中”且保留“取消发送”按钮，汇总卡仍为“发送中 2 · 已发送 1 · 失败 0 · 已取消 0”。

## [P1] 验证取消发送确认后卡片先置已取消且网关确认未写出则维持
- 测试类型
  - 功能
- 前置条件
  1. 已进入 BATCH-G01 的 L2，GT-REC-D001 发送中，网关确认未写出且队列删除成功
- 测试步骤
  1. 点击 D001 的“取消发送”并在二次确认中确认。
  2. 立即查看 D001 卡片与汇总卡。
  3. 等待网关回调到达后下拉刷新，查看 D001 与汇总卡。
  4. 查看 D001 的按钮区。
- 预期结果
  1. 取消请求提交。
  2. D001 卡片先置为“已取消”，汇总卡变为“发送中 1 · 已发送 1 · 失败 0 · 已取消 1”。
  3. D001 维持“已取消”，发送时间“—”，汇总卡不变。
  4. 已取消卡片无操作按钮。

## [P1] 验证取消未生效时修正为已发送并提示
- 测试类型
  - 功能
- 前置条件
  1. 已进入 BATCH-G01 的 L2，GT-REC-D002 发送中
  2. 取消请求提交前，网关已完成 TCP 写出，实际写出时间为 2026-10-12 15:00:23
- 测试步骤
  1. 点击 D002 的“取消发送”并确认。
  2. 查看 D002 卡片。
  3. 等待网关回调将 D002 修正为已发送，查看页面提示、卡片和汇总卡。
- 预期结果
  1. 取消请求提交。
  2. D002 卡片先置为“已取消”。
  3. 提示“取消未生效，指令已下发”；D002 卡片更新为“已发送”，发送时间“2026-10-12 15:00:23”，汇总卡已取消数减 1、已发送数加 1，最终为“发送中 1 · 已发送 2 · 失败 0 · 已取消 0”。

## [P1] 验证高危指令取消未生效时使用高优先级提醒
- 测试类型
  - 功能
- 前置条件
  1. 已进入 BATCH-G02 的 L2，D001 的 RESET 发送中
  2. 取消请求提交前，网关已完成 TCP 写出
- 测试步骤
  1. 点击 D001 的“取消发送”并确认。
  2. 等待网关回调将 D001 修正为已发送。
  3. 对比 BATCH-G01 中普通 UPLOAD 取消未生效时的提示形式。
- 预期结果
  1. 取消请求提交，D001 先置为“已取消”。
  2. 页面弹出高优先级提醒，说明“取消未生效，指令已下发”并提示设备仍可能执行重启；D001 更新为“已发送”。
  3. 高危提醒在优先级和说明文案上强于普通指令的 Toast 提示。

## [P2] 验证后台追溯字段完整保留
- 测试类型
  - 可靠性
- 前置条件
  1. BATCH-G01 的 D002 已完成“取消未生效，修正为已发送”，D001 已取消且网关确认未写出
  2. 已具备后台或接口查询记录详情的权限
- 测试步骤
  1. 通过后台或接口查询 D002 的记录详情。
  2. 查看取消相关字段。
  3. 同样查询取消后维持已取消的 D001。
- 预期结果
  1. 记录详情可查询。
  2. D002 含 cancelRequestedAt、cancelResolvedAt、cancelOutcome（表示取消未生效）、statusCorrectedAt，且 cancelRequestedAt 不晚于 cancelResolvedAt。
  3. D001 含 cancelRequestedAt、cancelResolvedAt 与表示取消成功的 cancelOutcome，无状态修正时间值。

## [P2] 验证重复取消回调不重复计数
- 测试类型
  - 可靠性
- 前置条件
  1. BATCH-G01 的 D001 已取消，汇总卡为“发送中 1 · 已发送 1 · 失败 0 · 已取消 1”
- 测试步骤
  1. 通过测试桩对 D001 重复投递同一取消结果回调 3 次。
  2. 下拉刷新，查看汇总卡和 D001。
- 预期结果
  1. 回调被幂等处理。
  2. 汇总卡仍为“发送中 1 · 已发送 1 · 失败 0 · 已取消 1”，D001 仍为已取消，台数总和仍为 3，不重复计数。

## [P2] 验证发送中恒可取消含临近30天
- 测试类型
  - 功能
- 前置条件
  1. 普通指令 BATCH-G03 的 D004 离线排队中，创建时间距当前 29 天 23 小时，状态为发送中
- 测试步骤
  1. 进入 BATCH-G03 的 L2，查看 D004 卡片按钮。
  2. 点击“取消发送”并确认。
- 预期结果
  1. D004 卡片仍显示“取消发送”，无时间窗口限制。
  2. 取消请求提交，D004 先置为已取消，不提示“已超过可取消时间”。

## [P2] 验证取消接口失败回滚并Toast
- 测试类型
  - 可靠性
- 前置条件
  1. 已进入 BATCH-G01 的 L2，D001 发送中
  2. 取消接口返回失败，接口返回信息“取消请求失败，请稍后重试”
- 测试步骤
  1. 点击 D001 的“取消发送”并确认。
  2. 等待接口失败响应，查看卡片、汇总卡和提示。
  3. 再次点击“取消发送”并确认（接口恢复）。
- 预期结果
  1. 取消请求提交，卡片先局部更新。
  2. D001 回滚为“发送中”，汇总卡恢复为取消前数值，出现 Toast“取消请求失败，请稍后重试”。
  3. 取消成功，D001 为“已取消”。

## [P2] 验证取消按钮loading防重
- 测试类型
  - 可靠性
- 前置条件
  1. 取消接口响应延迟 3 秒，D001 发送中
- 测试步骤
  1. 点击“取消发送”并确认。
  2. 在响应返回前快速连续点击同一卡片 3 次。
  3. 查看实际发出的取消请求数和 D001 最终状态。
- 预期结果
  1. 取消请求提交，卡片进入 loading 或不可操作态。
  2. 后续点击无响应，不弹出重复确认。
  3. 仅发出 1 次取消请求，D001 最终为“已取消”，汇总卡已取消数只加 1。
