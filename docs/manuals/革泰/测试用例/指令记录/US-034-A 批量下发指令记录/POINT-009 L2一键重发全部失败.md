# US-034-A 批量下发指令记录

> 口径依据：指令记录大纲 §3.2 / §3.4 一键重发全部失败。仅批量 L2 有；存在失败设备时显示“重发全部失败（N）”；一次二次确认 → 批量重发 N 台；普通指令允许离线设备进入队列；高危指令由服务端逐台复检当前会话；每台设备在原卡更新并独立返回结果；复用首次下发的校验；设备指令记录页无此按钮。
>
> 数据约定：BATCH-I01 为上报间隔 600 秒 5 台：D001 在线失败、D002 离线失败、D003 已发送、D004 发送中、D005 在线失败；BATCH-I02 为“重启设备”（RESET）3 台：D001 在线（有可写会话）失败、D002 离线失败、D005 在线（有可写会话）失败。

## [P1] 验证存在失败设备时显示按钮且N为失败台数
- 测试类型
  - 功能
- 前置条件
  1. BATCH-I01 含 3 台失败设备（D001、D002、D005）
- 测试步骤
  1. 进入 BATCH-I01 的 L2，查看底部按钮。
  2. 对 D001 单台重发并确认，等其变为发送中后再查看底部按钮。
- 预期结果
  1. 底部显示“重发全部失败（3）”。
  2. 失败台数变为 2，按钮文案更新为“重发全部失败（2）”。

## [P1] 验证无失败设备时按钮不显示
- 测试类型
  - 功能
- 前置条件
  1. BATCH-I03 的 3 台设备状态为已发送 2、发送中 1，无失败
- 测试步骤
  1. 进入 BATCH-I03 的 L2，查看底部区域。
  2. 将发送中设备变为失败（后台模拟），下拉刷新后再次查看底部区域。
- 预期结果
  1. 底部不显示“重发全部失败”按钮。
  2. 刷新后底部显示“重发全部失败（1）”。

## [P1] 验证一次二次确认后批量重发普通指令含离线设备
- 测试类型
  - 功能
- 前置条件
  1. BATCH-I01 含 3 台失败设备（D001 在线、D002 离线、D005 在线）
- 测试步骤
  1. 点击“重发全部失败（3）”。
  2. 查看确认弹窗次数与内容。
  3. 点击确认。
  4. 查看三台设备卡与汇总卡。
- 预期结果
  1. 弹出二次确认弹窗。
  2. 仅弹出 1 次确认，未对每台设备分别弹窗，内容包含重发台数 3。
  3. 批量重发请求提交。
  4. D001、D002、D005 均在原卡变为“发送中”，各自显示“已重发 1 次”，D002 离线也进入队列；汇总卡为“发送中 4 · 已发送 1 · 失败 0 · 已取消 0”。

## [P1] 验证高危指令一键重发逐台复检各自独立结果
- 测试类型
  - 功能
- 前置条件
  1. BATCH-I02 含 3 台失败设备：D001、D005 有可写会话，D002 离线无可写会话
- 测试步骤
  1. 点击“重发全部失败（3）”并确认。
  2. 查看三台设备卡与汇总卡。
  3. 查看 D002 的失败原因。
- 预期结果
  1. 批量重发请求提交，服务端逐台复检当前可写会话。
  2. D001、D005 变为“发送中”；D002 保持“失败”，三台均显示“已重发 1 次”。
  3. D002 失败原因为“无当前可写会话”，汇总卡为“发送中 2 · 已发送 0 · 失败 1 · 已取消 0”，D002 不影响 D001、D005 的重发。

## [P2] 验证一键重发每台独立返回结果部分成功
- 测试类型
  - 功能
- 前置条件
  1. BATCH-I01 含 3 台失败设备；接口模拟 D001 成功、D002 返回“S10U 路由缺失，无法下发”、D005 成功
- 测试步骤
  1. 点击“重发全部失败（3）”并确认。
  2. 查看三台设备卡。
- 预期结果
  1. 批量重发请求提交。
  2. D001、D005 在原卡变为“发送中”；D002 保持“失败”，失败原因更新为“S10U 路由缺失，无法下发”，失败时间更新；三台均“已重发 1 次”。

## [P2] 验证重发全部失败按钮固定在可见区
- 测试类型
  - 易用性
- 前置条件
  1. BATCH-J01 含 60 台设备，其中 5 台失败，需滚动列表
- 测试步骤
  1. 进入 BATCH-J01 的 L2，查看底部按钮。
  2. 滚动到列表最后一张卡片、再滚回顶部。
- 预期结果
  1. 底部显示“重发全部失败（5）”。
  2. 滚动全程按钮固定在底部可见区，不被列表内容遮挡或随列表滚走。

## [P2] 验证一键重发loading防重
- 测试类型
  - 可靠性
- 前置条件
  1. 批量重发接口响应延迟 3 秒，BATCH-I01 含 3 台失败设备
- 测试步骤
  1. 点击“重发全部失败（3）”并确认。
  2. 在响应返回前快速连续点击按钮 3 次。
  3. 查看实际请求数与各设备重发标记。
- 预期结果
  1. 批量重发请求提交，按钮进入 loading 或置灰。
  2. 后续点击无响应，不弹出重复确认。
  3. 仅发出 1 次批量重发请求，每台设备仅新增 1 个 attempt，标记均为“已重发 1 次”。

## [P2][反向] 验证一键重发含已解绑设备时服务端拒绝该台
- 测试类型
  - 安全性
- 前置条件
  1. BATCH-I01 含 3 台失败设备（D001、D002、D005），其中 D002 在失败后被当前账号解绑，D002 卡片标记“已解绑 / 无权限”且无按钮
  2. 批量重发请求仍携带 D001、D002、D005 三台失败设备（通过接口调用模拟）
- 测试步骤
  1. 调用批量重发接口提交 D001、D002、D005。
  2. 在 L2 下拉刷新，查看 D001、D005、D002 卡片。
  3. 通过后台查看 D002 的 attempt。
- 预期结果
  1. 批量重发请求被处理，D001、D005 的重发正常处理，D002 返回拒绝结果。
  2. D001、D005 变为“发送中”；D002 保持“失败”，无按钮，保持“已解绑 / 无权限”标记。
  3. 后台无 D002 的新 attempt，指令未下发给已解绑设备。
