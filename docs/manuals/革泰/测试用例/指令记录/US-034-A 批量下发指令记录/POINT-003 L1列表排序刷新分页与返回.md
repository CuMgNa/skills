# US-034-A 批量下发指令记录

> 口径依据：指令记录大纲 §3.1、§4.6。L1 按创建时间倒序；进入页面刷新、下拉刷新、后台恢复刷新并通过推送或低频轮询接收迟到状态修正；上滑分页；无手动筛选；自 L2 返回保留滚动位置并自动刷新一次；空态“暂无指令记录”。首屏与刷新异常按真源 §1.1“两页共通”并参照 §4.6，文案不写死。

## [P1] 验证L1按创建时间倒序且新批次置顶
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-E1 有 BATCH-C01（创建 2026-10-12 15:00:21）、BATCH-C02（2026-10-12 14:00:00）、BATCH-C03（2026-10-12 10:00:05）
- 测试步骤
  1. 进入 L1，记录卡片顺序。
  2. 发起新批量下发 BATCH-C04，创建时间 2026-10-12 15:30:00，并点击“查看记录”。
  3. 查看卡片顺序。
- 预期结果
  1. 顺序为 BATCH-C01、BATCH-C02、BATCH-C03。
  2. 进入 L1 并刷新全量记录。
  3. 顺序为 BATCH-C04、BATCH-C01、BATCH-C02、BATCH-C03，最新在上。

## [P1] 验证进入下拉后台恢复与迟到修正四种刷新
- 测试类型
  - 功能
- 前置条件
  1. BATCH-C05（5 台）当前行 2 为“发送中 2 · 已发送 3 · 失败 0 · 已取消 0”
  2. 后台可将其中 1 台发送中设备改为已发送，并可再将 1 台已取消回写为已发送
- 测试步骤
  1. 后台将 1 台发送中改为已发送，然后重新进入 L1。
  2. 后台再将 1 台发送中改为失败，在 L1 下拉刷新。
  3. 将 APP 切到后台 1 分钟，期间后台将 1 台已发送改为失败，再切回前台。
  4. 保持页面停留，后台模拟迟到状态修正，等待状态推送或低频轮询周期。
- 预期结果
  1. 进入页面即刷新，行 2 为“发送中 1 · 已发送 4 · 失败 0 · 已取消 0”。
  2. 下拉刷新后行 2 为“发送中 0 · 已发送 4 · 失败 1 · 已取消 0”。
  3. 从后台恢复时自动刷新，行 2 为“发送中 0 · 已发送 3 · 失败 2 · 已取消 0”。
  4. 迟到修正在推送到达或下一个轮询周期后反映到卡片，不需要手动退出重进。

## [P2] 验证上滑分页加载无重复无遗漏
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-E1 有 45 条批量记录，创建时间严格不同，接口分页大小以当前契约为准
- 测试步骤
  1. 进入 L1，记录首屏卡片数。
  2. 持续上滑到底，触发后续分页，直至无更多数据。
  3. 核对全部加载的卡片编号和顺序。
- 预期结果
  1. 首屏按分页大小加载卡片，底部有加载提示。
  2. 每次上滑追加下一页，直至 45 条全部加载。
  3. 45 条记录无重复、无遗漏，整体仍按创建时间倒序。

## [P2] 验证L1不提供手动筛选入口
- 测试类型
  - 功能
- 前置条件

- 测试步骤

  2. 点击页面各区域，查看是否能弹出筛选面板。

## [P2] 验证自L2返回保留滚动位置并自动刷新一次且L2筛选从空开始
- 测试类型
  - 功能
- 前置条件
  1. GT-REC-E1 有 30 条批量记录，BATCH-C06 位于第 20 条附近，其 L2 有 1 台发送中设备
  2. 在 BATCH-C06 的 L2 已应用筛选“状态=发送中”
- 测试步骤
  1. 在 L1 滚动到 BATCH-C06 所在位置，点击进入 L2。
  2. 在 L2 取消该发送中设备并确认。
  3. 点击返回 L1，统计返回后产生的列表刷新请求次数。
  4. 再次进入 BATCH-C06 的 L2，查看筛选条件。
- 预期结果
  1. 进入 L2。
  2. 该设备卡变为已取消。
  3. L1 保留滚动位置，自动刷新 1 次，BATCH-C06 行 2 反映已取消数加 1、发送中数减 1。
  4. 再次进入 L2 时筛选为空，列表显示该批量记录全部设备。
