# US-001 启动并加载账户数据

## [P1][反向] 验证登录成功后网络中断时显示失败原因和重试入口
- 测试类型
  - 功能
- 前置条件
  1. 个人账号ranch_owner_01已通过登录校验并进入设备加载页，设备DEV-P-001有访问权限，测试设备随后断开网络
- 测试步骤
  1. 在Loading devices...页面断开Wi-Fi和移动网络
  2. 等待本次设备加载请求失败
  3. 检查失败页面的提示、操作入口和当前会话
- 预期结果
  1. 本次加载请求因网络不可用而失败，不进入地图首页
  2. 页面显示可识别的网络失败原因并提供重试入口
  3. 保持ranch_owner_01当前登录会话和设备加载上下文，不退回登录页且不展示缓存业务数据

## [P1] 验证网络恢复后点击重试沿用同一加载流程并进入首页
- 测试类型
  - 功能
- 前置条件
  1. 账号ranch_owner_01已登录，设备加载因网络中断失败并显示重试入口，授权设备为DEV-P-001和DEV-P-002
- 测试步骤
  1. 恢复可访问服务端的网络
  2. 点击重试并观察页面流转
  3. 等待加载完成后检查地图首页数据
- 预期结果
  1. 页面保留当前登录会话并具备重新请求条件
  2. 从失败状态重新进入同一设备加载流程，不返回登录页、不要求重新输入凭证
  3. 进入地图首页且仅显示DEV-P-001和DEV-P-002，每台设备只出现一次

## [P3][反向] 验证设备加载达到服务端配置的加载超时阈值后停止无限等待
- 测试类型
  - 可靠性
- 前置条件
  1. 账号ranch_owner_01已登录并进入设备加载页，测试环境将设备聚合接口保持无响应，服务端配置的加载超时阈值需在执行前核对配置
- 测试步骤
  1. 保持设备聚合接口无响应并开始设备加载
  2. 等待达到服务端配置的加载超时阈值
  3. 检查超时后的页面状态和可执行操作
- 预期结果
  1. 页面显示Loading devices...加载反馈且不提前进入地图首页
  2. 达到服务端配置的加载超时阈值后结束本次等待，不无限转圈
  3. 页面显示明确的加载超时失败原因并提供重试入口，当前登录会话保持有效

## [P3][反向] 验证服务端返回503时展示明确失败信息且不写入不完整数据
- 测试类型
  - 功能
- 前置条件
  1. 企业一级账号enterprise_l1_01已登录，测试环境将设备聚合接口配置为返回HTTP 503，旧账号缓存已清理
- 测试步骤
  1. 进入enterprise_l1_01的设备加载页并触发加载
  2. 等待接口返回HTTP 503
  3. 检查失败提示、地图跳转和本地业务缓存
- 预期结果
  1. APP使用enterprise_l1_01当前Token发起数据加载请求
  2. 页面显示服务不可用对应的明确失败原因和重试入口
  3. 不进入地图首页，不把不完整的设备、围栏或告警结果写入当前展示缓存

## [P3][反向] 验证连续点击重试不会产生重复数据或并发覆盖
- 测试类型
  - 可靠性
- 前置条件
  1. 账号ranch_owner_01已登录且首次加载失败，授权设备仅有DEV-P-001，重试入口可用，测试工具可记录设备加载请求数
- 测试步骤
  1. 连续快速点击重试入口3次
  2. 等待有效重试请求返回DEV-P-001
  3. 检查请求并发控制、页面数据和加载状态
- 预期结果
  1. 重试操作被防重复处理，同一时刻仅保留一个有效加载流程
  2. 成功结果只写入一次并进入地图首页
  3. DEV-P-001仅显示一次，不出现重复设备、旧失败提示覆盖成功页面或加载状态反复跳变

## [P2] 验证加载失败页面的信息与重试操作清晰可识别
- 测试类型
  - 易用性
- 前置条件
  1. 账号ranch_owner_01已登录，测试环境将设备加载请求配置为失败并返回可展示的失败原因“网络连接不可用”
- 测试步骤
  1. 触发设备加载失败
  2. 观察失败原因和重试入口的展示
  3. 点击重试并观察操作反馈
- 预期结果
  1. 页面结束持续加载状态并切换到失败反馈状态
  2. “网络连接不可用”失败原因与重试入口均清晰可见，用户能够区分失败与仍在加载
  3. 点击后立即给出重新加载反馈且保持在设备加载流程，不误跳登录页
