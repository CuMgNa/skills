# US-031 退出并清理当前会话

## [P1] 验证账号冻结或删除后立即强制下线并清理当前会话
- 测试类型
  - 安全性
- 前置条件
  1. 海外版企业二级账号 ranch_staff_01（accountId=E201）已登录，WebSocket 已连接，设备列表含 GT-S10U-E201；管理端可将该账号改为冻结或删除状态
- 测试步骤
  1. 保持 APP 在前台并确认实时数据正常
  2. 在管理端将 accountId=E201 状态改为冻结并触发状态通知
  3. 观察 APP 页面、WebSocket 和本地会话
  4. 在登录页使用 ranch_staff_01 和正确密码重新登录
- 预期结果
  1. 当前 Token、WebSocket 和业务数据均属于 accountId=E201
  2. APP 收到失效信号后立即执行强制下线，不继续接受业务操作
  3. 返回登录页，WebSocket 断开，Access Token、Refresh Token 和 GT-S10U-E201 展示数据不再作为当前会话使用
  4. 服务端按冻结状态拦截重新登录，不恢复旧会话

## [P1] 验证已登录账号过期后直接强制下线且重新登录被拦截
- 测试类型
  - 安全性
- 前置条件
  1. 国内版企业账号（手机号 13900139000，accountId=E139，密码 China@2026）已登录，管理端可将服务到期时间改为 2026-10-11 23:59:59
- 测试步骤
  1. 保持账号 E139 在地图首页并确认当前时间为 2026-10-12
  2. 触发一次需要服务端鉴权的设备列表刷新
  3. 观察账号过期后的 APP 处理
  4. 在登录页选择“企业”并使用手机号 13900139000 和正确密码重新登录
- 预期结果
  1. 当前账号已超过服务到期时间且旧页面暂未产生新的授权结果
  2. 服务端返回过期状态，APP 不降级进入只读业务页
  3. APP 直接强制下线并返回登录页，清理当前会话、长连接和展示数据
  4. 重新登录被过期状态直接拦截，不签发新 Token、不进入业务首页

## [P1] 验证 Access Token 失效后不得使用 Refresh Token 静默恢复业务访问
- 测试类型
  - 安全性
- 前置条件
  1. 海外版个人账号 ranch_owner_01（accountId=P001）已登录，Access Token 为 AT-P001-01，Refresh Token 为 RT-P001-01，可模拟服务端返回 HTTP 401 TOKEN_INVALID
- 测试步骤
  1. 使 AT-P001-01 失效并请求设备列表
  2. 服务端返回 HTTP 401 和 TOKEN_INVALID
  3. 观察 APP 是否尝试静默续期及页面流转
  4. 未重新输入凭证时再次请求围栏列表
- 预期结果
  1. 设备请求携带的旧 Access Token 已不可用
  2. APP 识别登录态失效，不把 401 当作普通加载失败无限重试
  3. 不使用 RT-P001-01 静默恢复访问，清理当前会话并返回登录页
  4. 围栏请求被本地认证门禁拦截，不携带旧 Token 访问业务接口

## [P1] 验证退出或强制下线时断开 WebSocket 并清理分页游标和在途请求
- 测试类型
  - 可靠性
- 前置条件
  1. 海外版账号 accountId=P001 已登录，WebSocket 连接 WS-P001，告警分页游标为 CURSOR-P001-02，设备详情请求 REQ-P001-09 正在等待响应
- 测试步骤
  1. 触发主动退出或服务端强制下线
  2. 检查 WS-P001 的连接状态
  3. 检查 CURSOR-P001-02、REQ-P001-09 和本地当前会话标识
  4. 登录账号 accountId=P002 并加载首屏告警数据
- 预期结果
  1. 当前会话进入终止状态，不再接受新的 P001 业务请求
  2. WS-P001 立即断开且不自动以旧身份重连
  3. P001 的分页游标失效，在途请求被取消或其回包被丢弃，不能写入展示层
  4. P002 从自己的首屏游标开始加载，不复用 CURSOR-P001-02 或 REQ-P001-09 的结果

## [P1] 验证后台或息屏期间会话失效后恢复前台直接返回登录页
- 测试类型
  - 可靠性
- 前置条件
  1. 海外版个人账号 ranch_owner_02（accountId=P002）已登录并停留在设备详情 GT-S10U-0002，可在 APP 后台期间使 Token 失效
- 测试步骤
  1. 将 APP 切到后台并息屏
  2. 使 accountId=P002 的当前 Token 失效
  3. 亮屏并将 APP 恢复到前台
  4. 检查页面、网络请求和设备详情缓存
- 预期结果
  1. APP 进入后台后不把页面快照视为持续有效的认证依据
  2. 当前会话被标记为失效
  3. 恢复前台时先校验会话并直接返回登录页，不短暂展示可交互的设备详情
  4. 不继续请求或展示 GT-S10U-0002 数据，重新认证前业务接口不可访问

## [P3][反向] 验证弱网下强制下线不滞留加载页且迟到回包不恢复旧会话
- 测试类型
  - 可靠性
- 前置条件
  1. 国内版个人账号（手机号 13700137000，accountId=P137）已登录，网络设置为 30% 丢包和 1500ms 延迟，设备分页请求 REQ-P137-03 正在进行
- 测试步骤
  1. 在弱网下将 APP 切到后台
  2. 服务端使当前会话失效并关闭 WebSocket
  3. 将 APP 恢复前台并等待 10 秒
  4. 让 REQ-P137-03 的迟到响应到达并检查最终页面
- 预期结果
  1. 后台前的请求明确绑定 accountId=P137 和旧会话
  2. 会话失效事件触发本地清理，不能依赖弱网请求完成后才下线
  3. APP 在可判定失效后返回登录页，不持续停留在“Loading devices...”或无限转圈
  4. 迟到响应被丢弃，最终仍为登录页且不恢复 P137 的 Token、设备数据或 WebSocket

## [P3][反向] 验证强制下线不对未确认的其他端会话策略作客户端推断
- 测试类型
  - 兼容性
- 前置条件
  1. 账号 ranch_owner_03（accountId=P003）已在当前 APP 登录，另一个 Web 或 APP 客户端是否在线由测试环境记录但多端名额与互踢策略未配置为本用例断言
- 测试步骤
  1. 在当前 APP 触发明确的 accountId=P003 Token 失效事件
  2. 观察当前 APP 的下线处理
  3. 检查当前 APP 是否展示“其他设备登录”或固定在线名额提示
  4. 记录其他客户端实际状态但不据此判定当前用例通过或失败
- 预期结果
  1. 当前 APP 仅依据收到的 Token 失效事实处理本端会话
  2. 当前 APP 返回登录页并清理本端 Token、WebSocket 和展示数据
  3. 未获得服务端明确原因时不臆造多端互踢原因、不写死“1 个 Web + 1 个 PC”或 APP 占用名额规则
  4. 当前用例只验证本端会话清理，其他端状态留待多端策略确认后单独验证
