# S10U 虚拟终端协议收发工具实施计划

> 版本：V0.3（文件级实施版）
> 状态：首版本地实现与验收已完成（2026-09-09）：Python 149项、前端34项、真实localhost端到端7项通过；未连接真实平台验证。
> 交付位置：`services/s10u-tcp-tool/`；运行方法见该目录`README.md`，实际验证与限制见`VALIDATION.md`。
> 定位：供测试工程师使用的本地 TCP 协议收发工具，不是终端硬件／固件仿真器。
> 本版优先于前期讨论中的周期上报、自动心跳、AL 自动重发等旧方案。未明确的协议细节不由工具自行编造。

## 1. 背景、目标与验证边界

当前没有实体终端，也没有可连接的测试平台。后续开发提供不同测试环境后，需要快速切换环境，以虚拟终端身份与平台进行 TCP 双向通信。

核心目标：

1. 根据 S10U 消息类型编辑字段，按照协议拼接报文。
2. 同时查看拼接详情、实际原始报文、HEX 字节和逐字段解析。
3. 手动向平台发送上行报文，持续接收平台回复及下行指令。
4. 对平台下行指令模拟正常回执、拒绝回执、不回复以及延迟回复。
5. 保存常用数据样本，导出通信证据，减少重复填写和人工解读长报文的成本。
6. 在没有真实平台时，通过可选本地演练服务端验证工具收发和操作流程。

### 1.1 严格区分三类结果

| 结果 | 证明范围 |
|---|---|
| TCP 已连接 | 与目标地址、端口建立连接，不直接代表平台已识别设备或显示在线 |
| 本地发送完成／实际收到数据 | 记录工具实际提交发送的字节或收到的字节，不直接代表平台解析、入库成功 |
| 平台业务处理成功 | 需要平台页面、接口或服务端日志证明，例如位置入库、acked、rejected、timeout |

不验证真实设备是否定位、关机、重启、响铃、修改上传参数或执行其他动作。平台通信业务状态仍是联调核对对象。

## 2. 首版范围

### 2.1 已纳入

- 本地网页操作，本地后端建立原生 TCP 长连接。
- 多环境、多设备档案；同一时间只运行一个设备连接。
- 上行五类：LK、iccid、UD、UD2、AL。
- 上行一个动态表单，按类型显示字段，复杂字段分组折叠。
- 默认协议样本参考和一键填入；命名保存自定义样本。
- 表单编码、双向解析、原始文本／HEX 编辑、原始报文确认填表。
- 所有上行均手动单次发送。
- 下行七项：UPLOAD、ZONE、VERNO、CR、POWEROFF、RESET、FIND。
- 下行自动处理与手动覆盖，正常／拒绝／不回复策略，可选延迟回复。
- 手动连接／断开，可选定时断开，可配置异常重连且默认手动。
- 会话内日志查看、筛选、手动导出。
- 可选本地演练服务端。

### 2.2 明确不纳入

- 自动心跳、周期上报、指定次数发送、上行任务持续时长。
- 上行应答等待倒计时、上行定时超时判定、AL 自动重发。
- 离线位置自动采样、缓存、重连后自动补传。
- 真实设备动作、运动模型、GPS 定位或硬件状态机。
- LTE／WCDMA／TDSCDMA／CDMA 消息变种的首版专用表单与解析。
- 北斗完整接入链路、短信或 AT 通道。
- 多设备并发、压测、网络黑洞等专项故障注入。
- 自动读取数据库或自动判定真实平台业务验收通过。
- 关闭程序后可查询的自动持久化历史日志。

说明：取消的是上行自动发送及其定时任务。TCP 定时断开、可选异常重连、下行延迟回执是分别确认保留的功能，不应误删，也不得借此恢复自动上行。

## 3. 页面结构

### 3.1 公共连接栏

展示环境、目标地址／端口、设备档案、连接状态、连接标识、实际连接时长，以及连接／断开按钮。

连接控制、上行和下行共用同一条 TCP 连接，不能分别建立连接。

### 3.2 上行板块

只展示一个动态编辑表单，不为 UD、UD2、AL 建立三套并列页面。

操作路径：

**选择类型 → 编辑或加载样本 → 查看拼接与解析 → 点击发送一次 → 查看通信记录。**

| 区域 | 说明 |
|---|---|
| 类型选择 | LK 链路保持、iccid、UD 位置、UD2 补传、AL 报警 |
| 动态表单 | 仅展示所选类型所需字段；复杂内容分组折叠 |
| 拼接详情 | 外层结构、字段顺序、分隔符、LEN 计算范围与结果 |
| 原始报文 | 当前生成的完整文本与 HEX，可复制 |
| 字段解析 | 字段名、实际原始值、解释、单位、检查提示 |
| 右侧协议样本 | 对应文档示例及解析说明，与当前编辑结果明确区分 |
| 单次发送 | 每次点击发起一次发送；切换类型、加载样本均不触发发送 |

切换类型时如将覆盖未保存编辑，应明确提示；样本加载覆盖已有编辑同样需要提示，不静默丢失输入。

### 3.3 下行板块：接收与回执

展示收到的指令列表、选中指令的原文与字段解析、当前回复策略、回复预览及本地处理状态。

平台实际下发由平台操作入口发起。真实联调时，不能在工具界面伪造一条下行记录就声称验证了平台下发。

### 3.4 公共通信日志区

统一记录上行、下行、回执和连接事件；按环境、设备、连接标识区分。

支持方向、命令及异常筛选；点击记录查看实际原始字节和字段解析。

## 4. 上行五类消息

| 类型 | 命令／依据 | 操作与平台回复处理 |
|---|---|---|
| 链路保持 | LK | 编辑步数、翻滚次数、电量等协议字段，手动发送；收到 LK 回复后展示，不设置应答超时定时器 |
| ICCID 指令 | iccid | 设备档案保存 ICCID，提供专用表单、预览和手动发送；命令保持文档的小写；未明确回复，不因无回复判失败 |
| 位置上报 | UD，附录一 | 完整字段编辑，固定位置；时间支持实时／固定，默认实时；手动发送，协议不要求回复 |
| 盲点补传 | UD2，附录一 | 完整历史位置字段，保留指定定位时间；手动单次发送，协议不要求回复；不增加离线缓存或自动补传 |
| 报警上报 | AL，附录一 | 编辑位置及状态字，选择协议报警位，支持组合；手动发送，实际收到 AL 回复后展示；不自动重发 |

### 4.1 共同行为

- 点击一次发送一次，不要求等待平台回复后才能继续操作。
- 发送结束不关闭 TCP；平台随后回复或下发指令，接收监听继续运行。
- 正常表单的设备 ID 默认使用当前设备档案。
- 发送前固定本次实际内容，日志保存这一份字节和解析结果，不能事后用当前表单重新生成日志。
- 无自动心跳时，平台可能因空闲关闭连接。工具展示实际状态，不偷偷补发心跳以维持连接。
- 不通过上行报文名称推断上线鉴权或自动改变连接状态。
- 对重复同类报文的回复，不在缺少流水号的情况下强行认定一一对应。

### 4.2 UD／UD2／AL 的字段表单

按附录一组织完整字段，不只实现经纬度和电量：

| 分组 | 内容 |
|---|---|
| 报文头 | 厂商标识、设备 ID；LEN 正常模式自动计算 |
| 时间与位置 | 日期、时间、定位有效性 A/V、经纬度及半球、速度、方向、海拔 |
| 设备数据 | 卫星数、信号、电量、步数、翻滚次数 |
| 状态字 | 原始 HEX、按附录一解释的状态位／报警位 |
| 基站 | 数量、TA、MCC、MNC、基站记录；正常表单支持增删记录与数量联动 |
| Wi-Fi | 数量、名称、MAC、信号强度；正常表单支持增删记录与数量联动 |
| 尾部 | 附录一中的定位精度等字段 |

保留 MNC 等字段的前导零。无线制式与厂商头分开理解，不把文档中的 `3G` 自动改成 `4G`。

状态位只是可编辑的报文内容，不据此创建运动／静止状态机或自动控制发送。取消某个报警位不自动解释成平台报警已解除。

### 4.3 定位时间

- UD：实时／固定两种模式，默认在实际发送时生成日期和时间。
- 实时模式预览需标明发送时会更新，最终日志记录实际发送值。
- UD2：使用指定历史日期和时间，发送时不替换成当前时间。
- 日志区分报文内定位时间与工具实际发送时间。
- 定位时间时区按明确配置和后续平台契约处理，不能把协议未明确的信息当成既定事实。
- UD2 描述的是未登录平台时产生的历史位置；发送 UD2 本身仍需已建立 TCP 连接。

### 4.4 与真实设备协议行为的差异

文档描述 LK 无回复后重新连接，以及 AL 无回复后再次上报一次。本工具按最终确认的调测范围不自动执行这两项；需要再次发送时由测试人员手动操作。

这属于明确的工具行为边界，不应在测试报告中声称已验证设备的自动重连或报警重发机制。

## 5. 样本、原始报文与异常编辑

### 5.1 协议默认样本

- 右侧按当前消息类型展示文档样本、字段解释和已发现的异常。
- 支持参考、复制和一键填入表单；加载不自动发送。
- 填入时保留当前设备 ID，明确提示与示例设备 ID 的区别。
- 文档样本只读，不被自定义数据覆盖。
- 样本原文与正常表单重新生成的报文分别保留，不能用修正后的文本冒充原文。

### 5.2 自定义样本

- 支持命名保存多组数据，按 LK／iccid／UD／UD2／AL 类型分类。
- 保存字段值与时间模式；UD 实时模式不能被保存动作固化为某个历史时间。
- 保存到本机，提示可能包含 ICCID、位置等信息，不自动上传。
- 加载前提示已有编辑的覆盖范围；使用当前设备 ID，不自动改变连接或发送。

### 5.3 原始报文导入与反向填表

- 支持文本／HEX 输入，识别首版五种上行类型。
- 展示原始输入、解析字段和检查结果，确认后才填入表单。
- 原文单独保留；无法完整解析、有布局歧义或存在无法映射字段时，不丢弃字段后强制转换。
- 导入设备 ID 与当前设备不同，必须提示；填入正常表单采用当前设备 ID，并展示变化。
- 原始模式发送保持预览字节，不擅自修改 LEN、设备 ID、大小写、分隔符或追加换行。
- 原始设备 ID 与当前档案不同也必须显著提示，不暗中建立新连接或宣称平台会接受该身份。

### 5.4 表单异常处理

正常模式自动维护协议结构、字段顺序、数量和 LEN。

能够生成确切字节、但字段值异常时：定位字段、说明原因、预览实际报文，允许确认后发送，日志保留检查提示。

无法确定如何编码的输入不猜测、不静默替换。非法 HEX 等无法转换为字节的输入不能发送。

故意错误长度、缺字段或破坏分隔符等场景，通过原始报文模式实现。

## 6. 下行接收与回执

### 6.1 首版七项正常模板

下表内容不含外层 `[3G*设备ID*LEN*内容]`：

| 下行内容 | 字段解释 | 正常回复内容 |
|---|---|---|
| UPLOAD,间隔 | 上传间隔及单位 | UPLOAD |
| ZONE,时区 | 时区参数 | ZONE |
| VERNO | 查询版本 | VERNO,预设版本号 |
| CR | 定位请求 | CR |
| POWEROFF | 关机请求 | POWEROFF |
| RESET | 重启请求 | RESET |
| FIND | 查找设备请求 | FIND |

外层字段及 LEN 按已确认规则生成，发送前可查看原文、HEX 和解析。

其他命令仍接收和记录，解析可识别的外层，标记“暂无专用模板”，不自动编造成功应答。

### 6.2 回复控制

- 默认自动处理，支持按命令手动覆盖。
- 处理内容：正常回执、拒绝回执、不回复。
- 处理方式：自动处理、手动处理。
- 发送时机：立即或延迟，默认立即。
- 手动处理必须选择具体接收记录，再决定发送或忽略。
- 延迟回复绑定原连接及原接收记录，可取消；断连取消尚未发送的回复。
- 实现时明确命令专属策略优先于全局默认，防止同一指令被重复应答。
- 尚待发送的回复策略及报文应可查看；配置变化不应静默改变已排队回复。

本地状态可使用“已接收、待手动处理、等待延迟、回复已发送、已忽略、发送失败、已取消”，不直接冒用平台的 acked／rejected／timeout。

### 6.3 拒绝回执

已确认保留自定义模板入口，但文档未明确七项指令的拒绝格式。

- 不预置猜测的 REJECT、错误码或拒绝原因字段。
- 支持输入完整报文、预览实际字节，并保存为对应命令的自定义回复模板。
- 未配置模板时不自动发送拒绝回执。
- 开发确认原因码、编码、适用命令及关联方式后，再增加专用字段编辑。
- 模板中的设备标识或其他固定值不匹配当前上下文时提示，不盲目自动复用。
- 日志区分选择了拒绝策略、实际发出的报文与平台是否进入 rejected。

拒绝只模拟报文，不需要真的降低电量或执行硬件条件判断。

### 6.4 不执行实际动作

- UPLOAD 不改变工具的发送设置。
- ZONE 不擅自改变工具的时间配置。
- CR 不启动 GPS 或自动产生位置上报。
- RESET／POWEROFF 不触发工具重启或断连。
- FIND 不执行真实响铃。
- VERNO 返回预设测试版本，不代表真实固件版本。

## 7. TCP 连接生命周期

- 保存环境名称、主机／IP、TCP 端口；VPN、白名单、TLS／鉴权等按实际接入契约补充。
- 保存多个设备档案，同一时间只建立一个活动设备连接。
- 支持手动连接、取消连接尝试、手动断开。
- 连接保持可选持续连接／指定时长后断开，默认持续连接；定时从 TCP 建立成功开始计算。
- 连接可能被平台或网络提前中断，配置的时长不是保证存活时长。
- 显示实际连接时长；无法确定的断开原因明确为未知，不猜测。
- 手动或到期断开，不自动重连。
- 异常重连可配置、默认手动；开启时设置重试间隔和次数上限。
- 重连不自动发送 LK、iccid、UD、UD2、AL，不补发旧连接数据。
- 切换环境或设备前先停止旧连接的待发操作并断开；不会将旧回执发送到新环境。
- 页面刷新读取后端真实状态，不建立第二条连接。
- 关闭网页不等于断开 TCP，页面明确提示；退出本地服务时关闭连接及待发任务。

## 8. 编码、解析与日志

### 8.1 编码与协议歧义

- 正常模式按实际编码后的内容字节数生成 LEN，不按界面字符数随意计算。
- ASCII 内容可先依据文档实现；非 ASCII 字段的编码与特殊字符转义需核对契约。
- 文档多个 LEN 示例与内容不一致，不能直接照抄为标准正确报文。
- 状态字解释采用附录一并注明依据；保留原始 HEX，正文与附录矛盾作为警告及待确认项。
- 基站数为零时的关联字段布局等未明确边界，不以猜测宣称兼容。
- 数值、格式检查用于报文构造，不代表设备功能有效性判断。

### 8.2 TCP 接收

- 一次接收不等于一条报文，必须处理拆包和粘包。
- 区分原始接收字节、完整协议报文、不完整片段和格式异常。
- 设置接收缓冲容量限制及异常恢复规则；未闭合内容不能无限积累。
- 保留无法解析的原始内容，不因解析失败丢失通信证据。
- 若内部使用不完整帧保护性超时，应明确它不是上行 ACK 超时，也不能触发自动上行或改变平台业务结论。
- 协议没有统一流水号；本地记录编号只辅助界面操作，不加入线上报文、不证明平台关联关系。

### 8.3 日志与导出

每条记录包含：环境、设备、连接标识、本地记录编号、时间、方向、原始文本、HEX、字段解析、长度检查、异常提示及处理结果。

- 日志保存实际收发快照，不事后用当前编辑值重算。
- 可查看最近实际收到的心跳回复时间，但不运行上行心跳应答倒计时。
- 运行会话内保留日志；切换环境或重连不立即清空，以连接标识区分。
- 页面刷新不清空后端本次会话记录。
- 提供手动导出当前连接或选中记录，可读与结构化格式至少各一种。
- 本地程序退出后未导出的日志不保留，界面明确提示。
- 设定容量限制，到达限制时提示，并明确记录是否被截断，不能静默宣称全量保留。
- 日志仅本地处理、手动导出，不自动上传；分享前提示设备信息和位置数据的敏感性。

## 9. 可选本地演练

提供独立、可选的本地 TCP 演练服务端，默认只在本机使用。

能力：

1. 接收并展示五类上行报文。
2. 对 LK、AL 返回文档规定的回复；对 iccid 不编造回复，对 UD、UD2 不增加应答。
3. 提供首版七项下行的发送入口，通过真实本地 TCP 发送到虚拟终端。
4. 实际接收并展示虚拟终端返回的回执。
5. 可演练不回复、延迟回复及已配置的自定义报文发送，不伪造真实平台业务状态。

演练与真实环境醒目标识、互斥连接；切换时断开旧连接。

本地两端互通不能证明真实平台兼容，特别是自定义拒绝报文，本地服务端收到字节不代表真实平台会识别为 rejected。

## 10. 实现建议与实施顺序

### 10.1 技术建议

| 层次 | 建议 | 职责 |
|---|---|---|
| 页面 | Vue 3＋TypeScript＋Element Plus＋Vite | 一个动态表单、预览、样本、回执策略、日志 |

| 协议模块 | 独立编码器／解析器 | 五类上行、七项下行、字段定义及格式检查 |
| 本地存储 | SQLite（标准库sqlite3） | 保存环境、设备、命名样本和回复配置；通信日志仅会话内，不写入数据库 |
| 测试 | pytest／pytest-asyncio、Vitest、Playwright | 协议、TCP、API、存储、前端及本地端到端验证 |

已批准按上述选型实施，源码位于 `services/s10u-tcp-tool/`。仓库未发现可直接复用的对应技术栈应用；采用独立服务结构，不修改其他流水线。后端使用独立 `.venv`，前端使用本服务依赖与锁文件，不修改默认Hermes Python环境。

本地服务只监听回环地址，单进程单worker；精确检查Host、Origin及启动令牌，防止任意网页调用本地发包接口。前端以HTTP权威快照展示状态，WebSocket仅作失效通知，连接恢复和页面刷新重新取快照，不依赖无遗漏的增量日志投递。

用户档案数据库默认位于 `%LOCALAPPDATA%/S10UTcpTool/`，测试使用独立数据目录。日常启动由后端提供已构建的前端，无需同时运行Node服务。

## 11. 验收清单

### 11.1 本地工具验收

- 五类消息均可通过一个动态表单编辑、拼接、解析及手动单次发送。
- 不操作发送时，不产生自动 LK／iccid／UD／UD2／AL；AL 无回复也不自动重发。
- UD 实时／固定时间及 UD2 历史时间行为正确，日志与实际字节一致。
- 默认样本原文可查看，LEN错误和异常字段不被静默修正文档；正常生成的 LEN 与实际字节匹配。
- 自定义样本可命名保存和加载；覆盖提示明确，不引发发送。
- 原始报文可解析、确认填表；无法完整映射时保留原文，不丢字段。
- 异常字段可确认发送；无法转换为字节的输入不发送；raw保持预览字节。
- 七项下行解析和正常回复准确；无拒绝模板时不发送猜测回执。
- 正常／拒绝／不回复、手动处理及可选延迟行为可观察。
- 收到 RESET／POWEROFF 等不执行真实动作或意外断连。
- 手动断开、可选定时断开及异常重连行为符合设置，重连不自动上报。
- 断连取消旧延迟回执，页面刷新及重复点击不产生重复连接或重复应答。
- 拆包、粘包、未知命令、错误长度、不完整报文可处理并保留证据。
- 日志会话内可查、手动可导出；容量限制和退出不保留的提示清楚。
- 演练确实经 TCP 通信，不能用界面虚构日志代替网络接收。
- 正确性测试使用独立核对的样例及字节断言，不只依赖“自己编码再自己解析”。

### 11.2 真实平台验收

| 场景 | 工具证据 | 平台侧证据 |
|---|---|---|
| 心跳 | 实发 LK、实收回复 | 在线状态及平台接收日志 |
| ICCID | 实际上报字段与字节 | SIM信息接收、归属或更新 |
| UD／UD2 | 实际位置、定位时间及发送时间 | 实时／历史位置的正确处理 |
| AL | 实际报警位及回复 | 报警记录和业务归属 |
| 正常回执 | 下行接收与正常回复字节 | acked及历史记录 |
| 不回复 | 已收指令、未发送回执 | timeout |
| 拒绝回执 | 已确认格式的实际拒绝报文 | rejected及拒绝原因 |
| 延迟回复 | 接收时间、计划及实际发送时间 | 迟到回执与超时处理 |
| 离线下发 | 已断连；由平台另行确认离线 | 拒发且不进入pending |

截图中的30秒ACK窗口以最新需求版本为准；核对位置为“远程指令从下发到回执”需求及服务端计时起点。工具接收／发送时间不能冒充平台计时起点。

## 12. 外部依赖与待确认协议

以下是接入或协议事实缺口，不通过增加猜测功能解决：

1. 测试TCP地址、端口、VPN／白名单及额外TLS／鉴权要求。
2. 测试设备登记、首包、设备ID与连接绑定及平台在线判定规则。
3. 七项下行的拒绝报文、原因码／文本编码、适用命令及关联方式。
4. S10U文档LEN错误、状态字描述冲突、可变字段布局及非ASCII编码／转义规则。
5. 目标平台对本版基本UD／UD2／AL的支持；不能仅因实际网络为4G而擅自改用LTE变种。
6. 平台超时计时起点、同类重复指令关联方式及迟到回执处理。

拒绝格式未确认前可用自定义入口准备测试输入，但不能标记拒绝业务已验证。没有真实测试环境时，只出本地验证结论。
