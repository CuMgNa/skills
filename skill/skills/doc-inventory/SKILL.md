# 文档盘点技能 (doc-inventory)

## 真实痛点（本技能要解决什么）

给一个目录，从**测试工程师资料**角度回答：

- **计划/方案**多少份（文件名含「计划」或「方案」）
- **报告**多少份（文件名含「报告」）
- **说明书**多少份
- **XMind**多少份（`.xmind` / `.mm`）
- **项目总结**多少份（文件名含「总结」/「项目总结」等）
- 可按时间筛选（本周 / 本月 / 今年 / `2026/07/01-2026/07/27` 等）
- 每一类内**按文件格式分组**，全量列出：**文件名 + 完整绝对路径 + 创建时间 + 修改时间**

不是「把目录里所有 .xsd/.py 扫一遍堆成长表」——那不实用。

---

## 输入契约

| 参数 | 必填 | 默认 | 说明 |
|------|------|------|------|
| 文件夹路径 | ✅ | — | 要盘点的目录 |
| 时间筛选 | ❌ | 不限 | `本周`/`本月`/`今年`/`最近30天` 或 `2026/07/01-2026/07/27` |
| 时间字段 | ❌ | 修改时间 | `Created` / `Modified` |
| 关键词 | ❌ | 空=全量 | 可选，仅文件名子串；少用，五类分类已覆盖主需求 |
| 全量文件 | ❌ | 否 | 用户明确说「连代码/素材也要」时才加 `-AllFiles` |

**问法**：路径必问；时间用一句：「要按时间筛吗？例如本月、今年、或 2026/07/01-2026/07/27（不要就全量）」

---

## 同名去重（默认开启）

同一**文件名**（忽略大小写，不含路径）出现多份时：

- **只保留一份**：取 `max(创建时间, 修改时间)` 最新的那份  
- 若仍并列：优先**修改时间**更新的；再并列则取创建时间更新的  
- 被去掉的路径写入 JSON `warnings.dedupDropped`，报告异常区注明「同名去重丢弃 N 份」  
- 统计与五类汇总、明细均基于**去重后**集合（守恒）  
- 若用户明确要求保留全部副本：脚本加 `-KeepDuplicates`

---

## 默认范围：文档白名单

**默认只统计**这些扩展名（可在脚本 `-DocExts` 调整）：

`md, markdown, docx, doc, pdf, xlsx, xls, pptx, ppt, txt, xmind, mm`

排除：`node_modules`、`.git`、`output` 等噪音目录，以及 `文档盘点报告-*` / `文档盘点数据-*`（防自我污染）。

需要旧行为（扫全部后缀）时：脚本加 `-AllFiles`，且须用户明确要求。

---

## 五类分类（`classification-rules.json`）

| 类型 | 规则 | 优先级 |
|------|------|--------|
| 报告 | 文件名含「报告」 | 10 |
| 说明书 | 使用说明/说明书/用户手册/操作手册/使用手册 | 10 |
| 项目总结 | 项目总结 / 总结 / 年终总结 / 年中总结 | 9 |
| 计划/方案 | 文件名含「计划」**或**「方案」 | 8 |
| XMind | 扩展名 `.xmind` / `.mm` | 5 |
| 其他/未分类 | 未命中以上 | — |

互斥归类：一个文件只进一类；「总结报告」优先归**报告**；业务词优先于纯 XMind。

## 交付形态（钉死）

### 1）对话里先给五类汇总（必须）

从 JSON 的 `summary.focusCounts` 读取（缺类为 0）：

```text
计划/方案：N 份
报告：N 份
说明书：N 份
XMind：N 份
项目总结：N 份
（时间：… · 目录：… · 同名去重丢弃 M 份）
报告路径：<被盘点目录>\文档盘点报告-YYYY-MM-DD-HHmm.md
```

### 2）Markdown 报告写到**被盘点目录下**

文件名：`文档盘点报告-YYYY-MM-DD-HHmm.md`  
副产物：`文档盘点数据-YYYY-MM-DD-HHmm.json`

### 3）报告结构（实用版）

```markdown
# 文档盘点报告

> 生成时间 / 盘点目录 / 时间筛选 / 时间口径 / 文档白名单

## 一、五类汇总
| 类型 | 数量 |
| 计划/方案 | N |
| 报告 | N |
| 说明书 | N |
| XMind | N |
| 项目总结 | N |
| 其他/未分类 | N |
| **合计** | **N** |

## 二、明细（按类型 → 按格式分组，全量）

### 计划/方案（N 个）
...

### 报告 / 说明书 / XMind / 项目总结 / 其他/未分类
...（同类结构；某类为 0 可写「无」）

## 三、异常警示（如有）
同名去重丢弃 / 空文件 / 超大 / 跳过
（去重明细见 JSON `warnings.dedupDropped`：name、path、keptPath）
```

**硬约束：**

1. 五类汇总必须出现在报告最前；对话也必须先报五类数字  
2. 明细：**完整绝对路径**；**创建时间 + 修改时间**都要；显示 `YYYY-MM-DD HH:mm`  
3. 类内**按格式分小节**全量罗列（格式内排序随意）  
4. **禁止截断**文件列表；文件名列禁止省略  
5. 统计守恒：各类数量之和 = 命中总数  
6. 「完整路径」列给出 `path` 字段全文（用户明确要求绝对路径，不做 `...\` 缩略）

---

## 执行流程

1. 确认路径；确认时间筛选（可选）  
2. 跑脚本：
   ```powershell
   powershell -ExecutionPolicy Bypass -File "<技能目录>/scripts/scan_docs.ps1" `
     -Path "<目录>" -TimeFilter "<可选>" -OutFile "<目录>/文档盘点数据-YYYY-MM-DD-HHmm.json"
   ```
   默认文档白名单 + **同名去重**；勿加 `-AllFiles` / `-KeepDuplicates` 除非用户要求。  
3. 读 JSON → 写 Markdown；对话先报 focusCounts，并顺带一句「同名去重丢弃 N 份」（`summary.dedupDroppedCount`）  
4. 报告写到被盘点目录；回报报告路径与合计

脚本关键字段：`summary.focusCounts`、`summary.byCategory`（含 `byExt`）、`files[].path/created/modified/category/ext`。

---

## 边界

- 只做文件名/扩展名级分类，**不读正文**  
- 不自动删除、移动文件（盘点 ≠ 清理）  
- 上千文件时报告可很长，写到磁盘即可，勿把全文塞进对话  

---

## 与旧版差异（实用化）

| 旧默认 | 现默认 |
|--------|--------|
| 扫进 .xsd/.py/.ttf 等 | 仅文档白名单 |
| 同名多份全进统计 | **同名去重，保留最近创建/修改的一份** |
| 对话易淹没在长报告里 | 先五类业务汇总 |
| 类型名「测试报告/用例」 | 「报告 / 计划/方案 / 说明书 / XMind」 |
| 路径可缩略 | 明细必须完整绝对路径 |
| 时间可只显示修改 | 创建 + 修改都展示 |
